# 模块深挖卡模板

> **模块** = 一个知识域的完整覆盖。**主线** = 这个域在回答的几个大问题。**母题** = 最小学习单位。
> 层级：一个模块 = 3–7 条主线 = 8–20 个母题。**模块卡是地图，主线是路，母题是脚步。**
> 铁律：**一次只推进一个模块；模块内母题全部通过证据验收才算闭环；未闭环不进下一个模块。**

**为什么主线优先（2026-09-10 修订）**：题单驱动会退化成"背 N 个答案"，因为题单面对的是零散名词；主线面对的是问题，天然带出因果与取舍。**先看线，再落点，最后用题单查漏。**

用法：复制本模板 → 填第 0 节边界 → 拆第 2 节主线 → 逐条主线落母题（第 3 节）→ 走母题法（闭卷 → 补断点 → 费曼 → 证据验收 → 1/3/7/14/30 复训）→ 过第 6 节验收门。

**另一个栈的模块卡**：当你同时有「岗位栈」和「项目栈」两套技术时（例如岗位问 MySQL、项目用 PostgreSQL），**不要写一张对照表桥接，而是建两张同构的模块卡**——主线同名，内容各自成体系；差异集中在各卡的「最容易说错的几处」短表里，作为面试安全底线。对照表会让人偷懒只背结论，两张卡才会逼出两套完整的机制。

## 4. 八股题单（覆盖度校验：不是学习入口，是查漏清单）

> **用法**：串完整条主线后，拿这张表自查覆盖率。**不要从这张表开始学。**
> 表里没覆盖到的题，要么补母题，要么明确降级为「了解」并写下理由。
> 题单要**对着真实的题库整理**（搜到的面试题集 / 目标公司真题），但只留比较可能问到的。

优先级定义：
- **必背** = 闭卷 3 分钟 + 追问 + 一个项目案例
- **理解** = 讲清原理与取舍，能被追问一层
- **了解** = 知道名词、适用边界和常见误区，不深究实现

| | | 一 | | 必背 / 理解 / 了解 | 能背 / 能讲 / 卡住 / 空白 | |

## 6. 验收门（全勾才算闭环）

- [ ] 模块内每个母题：闭卷讲 3 分钟 + 追问
- [ ] 每个母题能给一个**真实**项目案例（无案例的母题降级为「了解」）
- [ ] **判断力测试**：给一段有缺陷的方案（AI 生成的），能说出问题在哪、会怎么炸
- [ ] 第 4 节题单「必背」项全部能背说，未覆盖项已明确降级并写明理由
- [ ] 跨栈差异能脱口而出（岗位栈 vs 项目栈，最容易说错的几处）
- [ ] 全量快速召回：空白纸画出本模块知识树（按主线分支），红色断点回炉
- [ ] 复训日全部执行，无跳票

> 手撕代码**不在本卡的验收范围**，走独立日课——它练的是肌肉记忆，与模块理解是两件事。
