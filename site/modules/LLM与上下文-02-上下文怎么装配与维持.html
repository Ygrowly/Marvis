骨架：先纠正前提（窗口 = 容量 ≠ 质量）→ n² 与 attention budget → context rot → "最小高信号 token 集"这个目标 → 四种手段及各自边界 → 成本平方增长的算式 → 缓存与压缩的分工 → Claude Code 的混合策略实例 → 收束到"上下文是视图，不是仓库"

一句话结论：上下文窗口是容量不是质量——Transformer 的注意力是 n² 关系，token 越多这份预算越被摊薄，实测表现为 context rot。所以目标不是"塞满窗口"，而是找到最小的那组高信号 token。工程上是四种手段的组合：选择（只放当前步骤所需）、压缩（摘要 + 外部持久化指针）、隔离（子任务独立窗口，只回传 1–2K）、缓存（稳定前缀复用）。另外成本是平方增长的——每轮都要重发全部历史，40 轮 × 15K 的会话累计输入 12.3M，是最后一轮 prompt 的 20.5 倍。缓存能把重复内容降到 0.1× 计价但不改占用；要真正降占用只能靠压缩。

主线：上下文是"一次调用的视图"，不是状态本身——它每一轮都要重新装配、重新付钱、重新争夺注意力。 所以任何"把上下文当仓库用"的做法（塞满、只靠摘要、只靠预检索）都会在三个维度上同时付代价：注意力、成本、可恢复性。

1. 压缩和缓存到底谁解决什么？

压缩解决占用（有损，必须留指针），缓存解决价格（无损，只对稳定前缀有效）。两者互补，不可互相替代。

2. 子 Agent 为什么能省上下文？

它在自己的干净窗口里探索，可能烧几万 token，但只把 1,000–2,000 token 的浓缩结论回传。搜索过程的噪声全部隔离在子 Agent 内部。

3. 摘要里必须保留什么？

目标与约束、已确认事实及其来源 ID、已完成/未完成步骤、关键决策与原因、副作用执行记录、未决问题与剩余预算。前几项丢了大不了重做，副作用记录丢了会重复执行写操作。

4. 窗口会一直涨，这套还有用吗？

有用。Anthropic 的判断是"对所有尺寸的窗口，上下文污染和信息相关性问题都会持续存在"；而且平方成本来自"重发"这个机制，不来自窗口大小。

5. 什么情况下反而不该做 RAG？

数据小、稳定、无权限差异、不需要引用溯源时，直接放长上下文更简单也可能更好。决策由质量、成本、延迟、权限的评测驱动，不由架构偏好驱动。

6. CLAUDE.md 该写多长？

轻。写清楚仓库是干什么的，然后把大部分 token 花在代码库里的坑（gotchas）上，不要写"看文件系统就知道"的显然内容；需要多条验证指令时，做个 verification skill 让它在需要时被调用（渐进披露）。

主线：降本不是"少放内容"，是"让放进去的内容被认出来"。 命中率是唯一一个改错了也不会变坏的杠杆（最差就是回到原价）；其余三个都有下行风险。所以正确的顺序是先做无损的、再做双赢的、最后做有损的——这个顺序就是"先量后砍"。

1. 命中率怎么监控？

平台提供 cache diagnostics，能比较相邻两次请求、指出前缀从哪个位置开始分叉。要盯的是命中率和 usage 里的 cache 字段（两个都是 0 说明根本没缓存上，通常是不够长）。

2. 缓存为什么没命中？

按概率排查：前缀里有易变值（时间戳 / ID / 每轮变化的上下文）→ 落到了断点之后还好，落在断点之前就全崩；工具定义被重排；中途改了模型或 effort（设置渲染在前缀里）；TTL 过期（同步工具调用 / 子 Agent 跑超 5 分钟）；一轮新增超过 20 个 block，断点被推出回看窗口。

3. 工具太多，上下文塞不下怎么办？

用延迟加载：全部声明但把少用的标 defer_loading，它们留在缓存前缀之外，用到时再通过工具搜索加载。代价从"每轮都付"变成"用到才付"，而且不打断缓存。

4. 什么时候该用 1 小时 TTL？

有长同步工具调用或子 Agent时。默认 5 分钟的 TTL 从请求开始算，工具跑超 5 分钟，回来时缓存已过期，下一轮变成 1.25× 重写。1 小时 TTL 的写价是 2×，所以要算一下切换频率。

5. 什么时候做模型 / effort 切换最划算？

在缓存本来就要失效的时刻。比如 compaction 之后：对话被重写，缓存本来就要重建，那正是顺便切模型或调 effort 的好时机——你反正在付 miss 的钱。

6. 压缩的阈值该设多少？

平台默认 150,000 输入 token（可配，最小 50,000）。但更该问的是"我的注意力从什么时候开始明显稀释"——那个量级往往远小于窗口上限（[[母题-C1-上下文组装与窗口预算]]）。

收口一句话：上下文是视图，不是仓库——权威状态在数据库和结构化状态里，上下文是从它装配出来的。

这道题属于母题 C6 · 一次 Agent 调用到底花在哪些 token 上？成本怎么降才不伤质量？ · 下面挂它的完整回答（学的时候看）
