乐观锁和悲观锁不是"快慢"之别，而是把代价花在不同地方：悲观锁在动手前排队（并发被压成串行，但不浪费工作），乐观锁在提交时校验（并发不受限，但冲突时白干）。

判据可以算：期望尝试次数 = 1/(1−冲突率 p)——p = 10% 只要 1.11 次；p = 50% 就要 2 次（等于白干一遍）；p = 90% 要 10 次。所以冲突率低用乐观，冲突率过半或重试代价很高或临界区本身很短时换悲观。顺序上：先想能不能改成条件更新，再想缩临界区，最后才换锁。

数据库里两种实现：版本号（UPDATE ... SET ..., version = version + 1 WHERE id = ? AND version = N，看影响行数）和条件更新（UPDATE ... SET n = n − 1 WHERE id = ? AND n ≥ 1）。最好的答案往往既不是乐观也不是悲观，而是条件更新——把判断和写入合成一条原子语句，不排队也不重试。

一个关键纠正：乐观锁在数据库里同样要拿行锁，只是只拿一条语句的时间——真正的差别是持锁时间。失败处理：限次（2–3 次）+ 指数退避 + 抖动，先区分"版本冲突"与"业务条件不满足"（后者重试一万次也没用）。

主线：并发控制的一切手段都是在给"出错"定价，而不是消灭它。 悲观锁把"出错"定价成"排队时间"，乐观锁定价成"白干的工作量"，条件更新则把定价降到最低（因为它让数据库在一条语句里解决竞争）。而定价的依据永远是一个可算的量——冲突率。

1. 什么情况该换悲观锁？

冲突率过半之后（1/(1−p) ≥ 2，白干的工作量已经超过一次），或者重试代价很高（重试要做昂贵计算 / 有外部调用），或者临界区本身很短（排队不痛）。注意顺序：先想能不能改成条件更新，再想缩临界区，最后才换锁。

2. 乐观锁失败怎么重试？

限次（2–3 次）+ 指数退避 + 抖动，并在失败后返回"稍后重试"而不是无限重试。还要先区分"版本冲突"与"业务条件不满足"——后者重试一万次也没用。

3. 防超卖该怎么做？

条件更新：UPDATE ... SET stock = stock − 1 WHERE id = ? AND stock ≥ 1，看影响行数。别用"先查再改"，也别一上来就 FOR UPDATE。真要极致吞吐再上"Redis 预扣 + 异步落库 + 幂等"（[[母题-M17-排行榜与防超卖]]）。

4. 乐观锁真的不会有死锁吗？

单条 UPDATE 不容易死锁，但一次事务里更新多行、加锁顺序不同样会死锁（[[母题-M10-锁与死锁]]）。"乐观"指的是并发控制策略，不是"没有锁"。

5. 冲突率怎么测？

三个来源：① 更新影响 0 行的比例（最直接，版本冲突会体现在这里）；② 版本号 / 业务键的热点分布（同一个 key 被多少请求打）；③ 压测时对比"实际尝试次数 / 成功次数"。有了这个数才能谈选型，否则都是感觉。

乐观锁和悲观锁不是"快慢"之别，而是把代价花在不同地方：悲观锁在动手前排队（并发被压成串行，但不浪费工作），乐观锁在提交时校验（并发不受限，但冲突时白干）。

判据可以算：期望尝试次数 = 1/(1−冲突率 p)——p = 10% 只要 1.11 次；p = 50% 就要 2 次（等于白干一遍）；p = 90% 要 10 次。所以冲突率低用乐观，冲突率过半或重试代价很高或临界区本身很短时换悲观。顺序上：先想能不能改成条件更新，再想缩临界区，最后才换锁。

数据库里两种实现：版本号（UPDATE ... SET ..., version = version + 1 WHERE id = ? AND version = N，看影响行数）和条件更新（UPDATE ... SET n = n − 1 WHERE id = ? AND n ≥ 1）。最好的答案往往既不是乐观也不是悲观，而是条件更新——把判断和写入合成一条原子语句，不排队也不重试。

一个关键纠正：乐观锁在数据库里同样要拿行锁，只是只拿一条语句的时间——真正的差别是持锁时间。失败处理：限次（2–3 次）+ 指数退避 + 抖动，先区分"版本冲突"与"业务条件不满足"（后者重试一万次也没用）。

分层要点追问深挖时用

  • 结论：代价位置不同；判据 1/(1−p)；最好答案是条件更新而不是乐观/悲观二选一。
  • 推导链：排队 vs 校验 → 期望尝试次数 → 换锁的三个条件 → 实现（版本号/条件更新）→ 失败重试的纪律。
  • 量化：p=10% → 1.11 次、p=50% → 2 次、p=90% → 10 次；高冲突下乐观 N² vs 悲观 N。
  • 边界与常见误解："乐观锁不加锁"×（差别在持锁时间）；"先查再改 + 事务"防不住并发窗口；单条 UPDATE 不易死锁，但事务里多行且加锁顺序不同照样会。
