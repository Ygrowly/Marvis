骨架：先给"Linux 不区分线程和进程、差别在共享了什么" → 从"共享了什么"推出三组差异（通信 / 切换 / 隔离）→ 一次切换的六步 + "第 ⑥ 步是唯一直接差别" → 给切换成本的量级区间与数据性质（1–5 μs；重载 10–50 μs），说明线程与进程只差两三成、真正的差在间接成本 → 说明 PCID 与 TLB 容量的边界 → 调度与自愿/非自愿切换的判据 → 内存账（虚拟 8MB vs 内核二三十 KB vs 上限是谁） → 共享的代价：竞态 → 死锁四条件与破法 → 自旋 vs 互斥 → 用户态/内核态与系统调用 → 边界与误解

一句话结论：进程和线程的区别，在 Linux 上可以一句话说清——它们都是 task_struct，线程只是"共享得更多的任务"（clone() 带上 CLONE_VM 等标志，共享地址空间、文件表、信号处理器，只独占寄存器和栈）。这个"共享了什么"直接推出全部差异：共享地址空间 → 线程间通信便宜但没有隔离；独立地址空间 → 跨进程切换要写 CR3、TLB 失效。切换成本是微秒量级（公开测量 1–5 μs，重载含间接成本可到 10–50 μs），其中大头是间接的——TLB 失效与缓存污染，单看直接成本线程只比进程快约 20–30%，但因为跨进程要换地址空间，并发高时这部分会把成本推高一个数量级，这就是"高吞吐服务端普遍多线程而非多进程"的依据。内存侧要纠正一个流行错说法：Linux 线程默认栈是 8MB（由 ulimit -s 决定）而不是 1MB，而且是虚拟预留、按需提交；真正的常驻成本是内核侧二三十 KB/线程（16KB 内核栈 + task_struct，不计入 RSS）；先撞上的通常不是内存，而是 pid_max / ulimit -u / 容器 pids.max。共享的代价是竞态，死锁要同时满足四个条件（互斥、持有并等待、不可剥夺、循环等待），破任一个就够，工程上首选"固定加锁顺序"（破循环等待）。

主线："共享了什么"决定了"付什么代价"——线程共享地址空间换来通信便宜，代价是切换要换页表（贵）和没有隔离（危险）；不共享换来隔离，代价是通信与切换都贵。而"该开几个执行单元"永远由"切换成本 ÷ 每个单元的工作量"决定，不由"越多越并发"决定。

1. 线程切换和进程切换差在哪一步？

只差"写 CR3 + TLB 失效"这一步（跨进程），同进程的线程整个跳过。直接成本只差两三成，但跨进程会让缓存与 TLB 冷掉，并发高时这一部分能把成本推高一个数量级——所以答案是"差在地址空间，不是差在寄存器"。⚠️ 不要说"贵 19 倍"这种精确倍数，测量值只能给区间。

2. 为什么线程不是越多越好？

两个原因：① 每线程内核侧约 25KB 且要占一个 pid（上限是 pid_max / pids.max）；② 超过核数后多出来的执行单元只在"等"或"抢"——抢就会推高非自愿切换，等就没有收益。要按"每个单元的工作量 ÷ 切换成本"算。

3. 死锁的四个条件是什么、怎么破？

互斥 / 持有并等待 / 不可剥夺 / 循环等待，破任一个即可；首选固定加锁顺序破循环等待（免费）；超时重试（破不可剥夺）有活锁与"重复副作用"的风险。

4. malloc 之后不写会不会占内存？

不会。malloc 只拿到虚拟地址空间，物理页在首次访问（缺页）时才分配——这就是 overcommit 的机制（详见 [[母题-O2-虚拟内存与缺页]]）。

5. 容器里被 OOM 杀了，怎么看？

要分清两类 OOM：整机 OOM（内核挑 oom_score 最高的）和 cgroup OOM（撞 memory.max）。日志前缀不同，排查方向也不同（详见 [[母题-O2-虚拟内存与缺页]] 第 5 节）。

进程和线程的区别在 Linux 上可以一句话说清——它们都是 task_struct，线程只是"共享得更多的任务"（clone() 带上 CLONE_VM 等标志，共享地址空间、文件表、信号处理器，只独占寄存器和栈）。

分层要点追问深挖时用

  • 结论：进程与线程都是 task_struct，差别在共享了什么；切换成本大头是间接的（TLB/缓存）。
  • 推导链：clone 标志 → 共享内容 → 通信 vs 隔离 → 切换的直接/间接成本 → 死锁四条件与破法 → 与协程的调度对照。
  • 量化：切换 1–5 μs（重载含间接成本 10–50 μs）；线程直接成本只比进程快约 20–30%。
  • 边界与常见误解："线程一定比进程快很多"×（直接成本只差 20–30%，差距在 TLB/缓存）；协程不是"更轻的线程"，是调度者不同。
