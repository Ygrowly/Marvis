C4幻觉是怎么产生的？哪些手段真的能压住它、哪些只是心理安慰？

骨架：先拆词（四类来源，各自的成因）→ 用"拼写会消失、生日不会"说明统计结构这一层 → 用 SimpleQA 数据说明评测激励这一层 → 上下文两类的工程对策 → 逐个对策的代价与边界 → 错误/弃答分开定价的算式 → RAG 只治一类的辨析 → 收束到"分层管理，不是消灭"

一句话结论：幻觉不是一个 bug，是四件不同的事叠加：① 预训练只有流畅语言的正例、没有真假标签，所以任意低频事实（比如生日）从统计上就学不出来，而拼写这类有规律的错误会随规模消失；② 评测只按准确率排名时，"猜"的期望收益为正、"弃答"稳定为零，模型被训成应试高手；③ 上下文里根本没有那条信息；④ 信息给了却被稀释、冲突或忽略。对策必须按来源分开：给证据 + 先摘录再作答 + 引用绑定（治③④）、允许弃答 + 改评分（治②）、上下文管理（治④）。最关键的一个换算：错误和弃答不能同价——实测数据里，准确率更低（22% vs 24%）的模型，错误率只要 26% vs 75%，按业务成本算总成本只有对方的 38%。

  • 准确率口径奖励猜测（1/365 > 0）

C5模型怎么选？贵模型一定更好吗？effort 是不是越高越好？

骨架：先立四维（能力/延迟/单价/effort）→ 输出比输入贵 5 倍这个结构事实 → 用"每个正确结果的全成本"统一口径 → effort 曲线的凸性与两个方向的失败模式 → 强模型+低 effort 的实测 → 训练集饱和与 held-out 的分辨力 → 降级链路的设计要求 → 收束到"选一组配置，不是一个模型"

一句话结论：选型不是挑最强的，是在（模型 × effort）二维空间里、用每个正确结果的全成本这一个指标来搜：

  • 四维：能力·延迟·单价·effort
  • 输出比输入贵 5 倍
  • 缓存读价差异会改变成本排序
  • 每个正确结果的全成本 =（单次 + 失败率×失败代价）÷ 成功率
  • effort 曲线凸，边际 > 平均
  • HLE 最后一档 +0.5 分 +46% 成本，在噪声里
  • 低 effort 的坑是"看起来完整"
  • 强模型+低 effort ≥ 弱模型+高 effort
  • 训练集饱和后失去分辨力（98.9% vs 98.9%，held-out 90.5% vs 78.6%）
  • 降级要验证过、要可观测

选型不是挑跑分最高的，是在（模型 × effort）二维空间里、用每个正确结果的全成本这一个指标来搜。跑分是那些评测上的表现，不是你的任务分布上的——从 SimpleQA 看，准确率高和错误率低可以是相反方向（24% vs 22% 的准确率，对应 75% vs 26% 的错误率）。

effort 怎么定：跑一次 sweep（对几个档位各跑一遍你的评测集），看曲线——平坦就说明任务不受思考算力约束，加 effort 没收益；陡峭且你需要跨过门槛，就加。effort 曲线是凸的：边际每分成本（$0.704）高于低档平均（$0.465），最后一档多 0.5 分要多花 46%，落在噪声里。effort 太低则会证据不足就收手，而且答案看起来是完整的。

降级链路三个要求：已验证（备用配置要在 held-out 上过门禁）、有明确质量底线（降级保的是可用性不是质量）、可观测（降级要打点报警——不知道自己在降级比降级更危险）。

选型不是一次性决策：模型迭代、缓存定价变化、effort 参数引入都会让最优解移动。

主线：幻觉的可治程度取决于它的来源，而"来源"和"模型强弱"几乎无关。 属于工程的（没给信息、给了没用上）可以压到接近零；属于统计与激励的（无模式的事实、评测奖励猜测）只能管理——而管理它的代价，远低于消除它的代价。

1. 怎么让模型愿意说"我不知道"？

两层：prompt 层显式给许可（"不确定就说不确定"）；评分层把"自信的错误"罚得比"承认不确定"更重，给恰当的弃答部分分。第二层更根本——因为第一层只是措辞，第二层才改激励。

2. 长文档怎么做 grounding？

对超过 20k token 的文档，先要求逐字摘出相关原文（找不到就明说"没找到"），再基于摘录作答。生成完成后再自查一遍：每条结论找支撑引用，找不到的直接撤掉。

3. Best-of-N 值不值得？

对高价值、低频次的判定值得（发布前复核、高风险决策）；对每次调用不值得——成本 ×N，而且还需要一个仲裁策略处理不一致。别把它当常规防线。

4. 怎么向业务方汇报幻觉治理的效果？

用错误率，不用准确率。原因见 Q1：准确率对"弃答"和"错误"一视同仁，看不出差别；而业务的成本是错误数的函数。"准确率 +5.3%"听起来平淡，"错误率减半"是同一件事的另一种说法（[[母题-C3-Prompt版本管理与回归]]）。

5. RAG 和幻觉是什么关系？

RAG 降低的是"无据可依"这一类，代价是上下文变长可能加剧"有据不依"。所以 RAG 是必要不充分——接完 RAG 以后，还要做引用绑定和答案级的评测。

6. 怎么设计评测集才能反映幻觉？

三个要点：指标里区分错误与弃答；答案级评测要和检索级评测分开（别拿召回率冒充正确率）；held-out 集合（[[母题-C3-Prompt版本管理与回归]]）。

1. 便宜模型能不能扛？

取决于任务形状和失败代价。先算"每个正确结果的全成本"；如果便宜模型的失败率把失败代价放大到超过节省，就不划算。上面的案例里，便宜模型配好 prompt 之后反而更准——所以"降级"要连 prompt 一起调，不是单独换模型。

2. effort 怎么定？

跑一次 sweep（对几个档位各跑一遍你的评测集），看曲线。判据：平坦就说明任务不受思考算力约束，加 effort 没收益；陡峭且你需要跨过门槛，就加。

3. 降级链路怎么设计？

三个要求：① 已验证（备用配置必须在 held-out 上过过门禁，不能是"顺手切一个"）；② 有明确的质量底线（降级的目标是保住可用性，不是保住质量，所以要知道降级后能接受什么）；③ 可观测（降级本身要打点报警——不知道自己在降级，比降级更危险）。

4. 多模型路由的代价是什么？

路由本身有成本和风险：要维护多套 prompt 与评测（每个模型都要单独消融调优）、路由判错会两头不讨好、排障复杂度上升（同一个 bug 在不同模型上表现不同）。所以路由要基于实测收益，不是"看起来更省"。

5. 模型换代了怎么处理？

当成一次完整的选型重做：换模型 + 重新消融清拐杖（[[母题-C3-Prompt版本管理与回归]]）+ 重跑门禁 + held-out 验收。同时别忘了重算缓存定价的影响——读价变化会让长会话场景的成本排序改变。

选型不是挑跑分最高的，是在（模型 × effort）二维空间里、用每个正确结果的全成本这一个指标来搜。跑分是那些评测上的表现，不是你的任务分布上的——从 SimpleQA 看，准确率高和错误率低可以是相反方向（24% vs 22% 的准确率，对应 75% vs 26% 的错误率）。

effort 怎么定：跑一次 sweep（对几个档位各跑一遍你的评测集），看曲线——平坦就说明任务不受思考算力约束，加 effort 没收益；陡峭且你需要跨过门槛，就加。effort 曲线是凸的：边际每分成本（$0.704）高于低档平均（$0.465），最后一档多 0.5 分要多花 46%，落在噪声里。effort 太低则会证据不足就收手，而且答案看起来是完整的。

降级链路三个要求：已验证（备用配置要在 held-out 上过门禁）、有明确质量底线（降级保的是可用性不是质量）、可观测（降级要打点报警——不知道自己在降级比降级更危险）。

选型不是一次性决策：模型迭代、缓存定价变化、effort 参数引入都会让最优解移动。
