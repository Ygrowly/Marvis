主线：可观测性的目标不是"记录得多"，是"出事时能定位到具体哪一步"。 所以它有两个取舍，而不是一个：记什么粒度（按"有业务意义"筛）、留哪些样本（按"信息价值"筛）——两个都做错，记录再全也定位不了。

1. Trace 和日志有什么区别？

日志是事件流，Trace 是调用树。树有父子关系，所以能算"这一步占多少时间""这一步的失败是谁引起的"——日志算不出来。两者互补，不是替代关系（细节还是要看日志）。

2. Trace 里最少要有哪些字段？

层级（trace / run / span 的父子关系 + trace_id）；每个 span：类型、开始结束时间、版本（model / prompt / tool）、Artifact 引用、幂等键、token 用量、错误码。检索 span 还要带 query / candidates / 索引版本（[[母题-G5-RAG评测与幻觉率]] 的三岔路归因需要它）。

3. 怎么定位一个 RAG Agent 答错？

按三岔路走：① 正确证据进 TopK 了吗（没进 → 召回问题）② 进最终 Context 了吗（没进 → 重排 / 预算 / 去重）③ 都进了还是错（→ 生成 / Prompt / 引用）。前提是 Trace 把这些都留下来了——否则只能猜。

4. Trace 存不下怎么办？

① 控制粒度（只记有业务意义或有副作用的 span）② 按信息价值采样（失败全采 + 成功抽样）③ 分级存储（近期的全量、历史的聚合或降采样）。但安全事件永远全采。

5. 怎么验证 Trace 本身没坏？

用 Replay 反向验：随便挑一条失败的 Trace，看能不能从它复现出当时的行为（[[母题-E3-回归门禁与发布卡口]] 的 Mock replay）。复现不出来，说明 Trace 缺字段。

1. 模型输出非确定，CI 怎么做？

① 看 pass^k 而不是单次（[[母题-E1-评测集设计与pass^k]]：0.9 的单次、pass^5 只有 59%）② 固定环境 fixture 与随机种子（[[母题-A8-动态计划下的可靠执行]] 的"可重置环境"）③ 门禁报"通过率 + 置信区间"，不是"这一次过没过"④ Mock replay 隔离变量，让比较只受一个因素影响。

2. 门禁该卡哪些指标，阈值怎么定？

红线（越权、未确认副作用、跨租户泄露）必须为 0；统计阈值（成功率、P95、成本、新能力最低线）按评测集分辨率定。而且这两类要分开报。

3. 单步指标好但端到端差，为什么？

可能的原因有三类：① 错误会累积（每步 95%，10 步就是 60%）② 优化某个子指标伤害了总目标（典型：召回更多文档提高 Recall，但上下文噪声增加让最终正确率下降——[[母题-G5-RAG评测与幻觉率]]）③ 评测口径不一致（单步用 Mock、端到端用 Sandbox，两者的环境不同）。"错误会累积"这条原文明确点过。

4. 新模型要不要切？

同一套 holdout 上比三件事：pass^k、P95 延迟、单任务成本；而且要重跑消融（prompt 是针对旧模型写的，[[母题-C3-Prompt版本管理与回归]]、[[母题-C5-模型选型与降级三角]]）。

5. 怎么保证 Replay 是确定的？

Mock replay 固定了工具结果，所以剩下的变量只有模型和 Prompt；Sandbox replay 要保证环境 fixture 可重置（否则两次运行的初始状态不同，结果没法比）。

Trace 是树，日志是线：日志回答"发生了什么"，Trace 回答"谁导致了谁"。三类信号分工——指标看分布与趋势、Trace 看因果与归因、日志看细节与原文；跨步、跨服务的因果链靠日志只能人工对着时间戳猜，而 Agent 天然多步，这个成本随步数急剧上升。

数据模型是 Request → Run → Model / Retrieval / Tool / Approval Span。每个 span 必须带：版本（model / prompt / tool / rule）、Artifact 引用、幂等键、latency、token 用量、错误码——少了版本就复现不出来（和 Agent 侧 Step 记录是同一套字段）。检索 span 还要带 query / candidates / 索引版本。

存储要控：50 span × 2 KB × 1 万 run = 约 1 GB/天。手段三条：控制粒度（只记有业务意义或有副作用的 span）、按信息价值采样（失败全采 + 成功抽样）、分级存储（近期全量、历史聚合或采样）。

怎么用：按三岔路定位 RAG 答错——① 正确证据进 TopK 了吗（召回）；② 进最终 Context 了吗（重排/预算/去重）；③ 都进了还是错（生成/Prompt/引用）。前提是 Trace 把这些都留下来了，否则只能猜。

分层要点追问深挖时用

  • 结论：Trace 是调用树（因果），日志是事件流（细节）；span 必须带版本、Artifact 引用、幂等键。
  • 推导链：树有父子 → 能算"这一步占多少时间/失败是谁引起" → 采集字段 → 存不下就控粒度+采样+分级 → 三岔路归因。
  • 量化：50 span × 2 KB × 1 万 run ≈ 1 GB/天；采样策略是失败全采 + 成功抽样。
  • 边界与常见误解：Trace 与日志互补不是替代；采集必须非阻塞、先落地再入库（短命进程要 flush()，OTLP 下孤儿 span 会被静默丢弃），"有 Trace"要靠 Replay 反向验证。
