G4怎么让答案的每句话都能追溯到原文；找不到证据时该怎么办

骨架：先问"谁来承担校验成本" → 粗引用 vs 细引用的成本对比 → 关键动作是生成后验证（不是要求引用） → 验证的成本与取舍 → 拒答的定价（错误 vs 弃答）→ 好引用的五条标准 → 再次鉴权 → 收束到"绑定 + 撤稿"

一句话结论：可追溯不是"给个出处"，是让每句话都有据可查、没据的那句不出现。粗引用（文末列链接）把校验成本全推给读者——用户无法判断哪句可疑，只能全信或全不信；细引用（逐条绑片段 + 可定位到版本）把校验成本降到"可疑的那几条"。关键动作不是"要求模型给引用"，而是"生成之后回头验证引用"——把每条结论回原文找支撑，找不到的直接撤掉（Anthropic 管这叫"生成后自查撤稿"）。理由是："要求"改的是概率，"验证"才是机制——模型完全可以编一个看起来像引用的东西。代价：逐条验证会让 token 成本接近翻倍（10 条结论 ≈ 8,500 token vs 生成 4,500 token），所以只对高风险结论做（金额、权限、生效时间）。拒答是设计的一部分：把"自信的错误"（10 单位）换成"坦白的不知道"（1 单位），总代价降到 1/10——错误越贵，拒答越值钱。最后，引用和下载要再次鉴权——权限从召回到展示之间可能已经变了。

G5检索指标很好但答案还是差——怎么定位到底是哪一段坏了

骨架：先立"端到端定位不了" → 分层指标（检索层四个 + 答案层六个）→ 两层相乘的算式 → 归因决定修复上限（100 条的分段与 35% 的结论）→ 三段修复的成本差异 → 评测集 schema 与 holdout / 样本量 → 检索失败率 ≠ 幻觉率 → 收束到"评测要能定位"

主线：可追溯的前一半是"绑定"，后一半是"撤稿"。 绑定解决"每句话能查"；撤稿解决"没据的话不出现"——而后者才是让用户敢信的那个动作，因为它把校验从"事后逐条检查"变成了"事前自动过滤"。

1. 引用怎么做到"可追溯"而不是文末列链接？

逐条绑定 + 可定位到文档/章节/版本 + 找不到支撑就撤稿。计算类结论还要绑定 SQL / 工具运行 ID（这样用户能重跑）。

2. 什么情况下应该拒答？

五条：没有召回足够证据、多个权威来源冲突、用户身份不足、超出知识库边界、时间/主体/口径不明确。冲突时不强行合成唯一答案，而是显式返回证据（RuleArena 的做法）。

3. 怎么防止 RAG 越权？

身份进入检索层、ACL filter 先于召回；缓存按租户 / 权限分区；引用和下载再次鉴权；做跨租户与撤权测试；日志避免记录敏感原文。

4. 长文档怎么保证 grounding？

对超过 20k token 的文档，先要求逐字摘出相关原文（找不到就明说"没找到"），再基于摘录作答。这样引用在生成时就产生了，验证可以用代码做（核对摘录是否真在原文里）。

主线：评测的目的不是"给系统打分"，是"告诉你下一步该改哪里"。

1. 检索指标很好但答案仍差，怎么排查？

按三个岔路口走：① 正确证据进 TopK 了吗（没进 → 召回）；② 进最终 Context 了吗（没进 → 重排 / 预算 / 去重）；③ 都进了还是错（→ 生成 / Prompt / 引用）。前提是 Trace 把候选、分数、重排位置、上下文版本都留下来了——否则只能猜。

2. 为什么检索 Eval 和答案 Eval 要分开？

它们回答两个不同的问题（"证据有没有捞到" vs "答案对不对、有没有依据"），混在一起就两个都答不了。而且分开之后才能算"提升哪一层更划算"。

3. 评测集要多大？

取决于你要证明多大的差异。SE = √(p(1−p)/n)：150 条约 ±3.4%，200 条约 ±2.1%；想分辨 2 个百分点需要约 900 条。先想清楚"我要证明多大的差异"，再决定集合规模。

4. 怎么造评测集的数据？

五个来源：真实高频问题、专家构造的边界、线上 Bad Case、权限攻击样本、过期 / 冲突样本。后面三类是 RAG 特有的——它们测的是"该拒答时有没有拒答"。

5. 怎么防止评测集被过拟合？

保留 holdout，且只有验收时才看。真实案例：Anthropic 的 hillclimb 在训练集上最终配置与起点打平（都 98.9%），held-out 上才拉开 11.9 个点（[[母题-C3-Prompt版本管理与回归]]）。

13理解G3

这道题属于母题 G3 · 召回回来的东西怎么排得更准；为什么重排能涨分；涨了多少、代价是什么 · 下面挂它的完整回答（学的时候看）

实测 478 字 · 按 4 字/秒折算约 120 秒（秒数是估算，字数才是实测）

召回和精排的优化目标不同：召回面对全量，目标是"不漏"，所以只能用便宜的方法（双塔，文档向量可预计算）；精排面对已经缩小过的候选集，目标是"排得准"，所以可以用贵的方法（交叉编码器）。

本质差别是"有没有词级交互"：双塔把 query 和 doc 分别编码，编码时看不到对方，所以"除外""不适用"这类否定词被平均掉——这是结构性损失，换更大的双塔也补不回来；交叉编码器把两者拼在一起，能看到逐词交互。

代价是延迟随候选数线性增长（5 ms × N，重排 200 条就是 1 秒，比 ANN 召回慢两个数量级），所以常见折中是"召回几百 → 重排 50–100 → 进上下文 5–20"。

收益要说清口径：Contextual Retrieval 里重排把失败率从 2.9% 降到 1.88%——相对重排前降 35%、相对基线累计降 67%，这两个数不能混。而且不一定值得：精确编号、单跳事实这类查询召回本身已经排得很准，重排收益很小，应通过 Eval 判断是否只在难题启用。

多跳问题重排解决不了——重排只重排已有候选，需要的候选压根不在池子里；要靠 Query Decomposition 或第二轮由第一轮发现的实体驱动。

分层要点追问深挖时用

  • 结论：双塔管"不漏"、交叉编码器管"排得准"；重排是用延迟换质量，不一定值得。
  • 推导链：目标不同 → 是否词级交互 → 双塔的结构性损失 → 交叉编码器代价线性 → 折中链路 → 收益口径。
  • 量化：重排 5 ms × N（200 条 = 1 秒）；失败率 2.9% → 1.88%（相对降 35%、累计降 67%）；召回几百 → 重排 50–100 → 进上下文 5–20。
  • 边界与常见误解：RRF 融合不判断内容相关性深浅（那是交叉编码器的活），两级是串联不是二选一；K 取多大要用评测定（Anthropic 试 5/10/20，20 最好，但成本线性上升）。

15必背G4

这道题属于母题 G4 · 怎么让答案的每句话都能追溯到原文；找不到证据时该怎么办 · 下面挂它的完整回答（学的时候看）

实测 107 字 · 按 4 字/秒折算约 27 秒（秒数是估算，字数才是实测）

可追溯不是"给个出处"，是让每句话都有据可查、没据的那句不出现。粗引用（文末列链接）把校验成本全推给读者——用户无法判断哪句可疑，只能全信或全不信；细引用（逐条绑片段 + 可定位到版本）把校验成本降到"可疑的那几条"。

分层要点追问深挖时用

  • 结论：逐条绑定 + 生成后自查撤稿；拒答是设计的一部分。
  • 推导链：粗引用把成本推给读者 → 细引用 → "要求"改概率、"验证"才是机制 → 验证有成本所以只做高风险 → 拒答用便宜的"不知道"换掉贵的"错答案"。
  • 量化：10 条结论验证约 8,500 token vs 生成 4,500 token（接近翻倍）；自信的错误 10 单位 vs 坦白不知道 1 单位。
  • 边界与常见误解：引用本身也会被编（所以必须验证）；多轮对话里上一轮的引用会失效；长文档（>20k token）要先逐字摘录再作答，引用在生成时就产生。
