01主干：盒子 → 上线 → 排查（运维的日常顺序）正本 wiki/topics/Linux与部署/

先理解边界（X1）、再理解生命周期（X2）、最后才是排障（X3）；不知道「被管起来」这层，三个灵异现象都无法解释。
主干叙事（一段读完）：Linux与部署的一条线是运维的日常顺序：「它被关在什么盒子里 → 它怎么上线怎么退出 → 它坏了怎么查」，共享前提：现代服务都是被管起来的 —— 被容器、编排、信号和探针管理。 盒子：容器是被重新布置过视角的普通进程（namespace 改视野、cgroup 设额度，共享内核弱于 VM）；内存没有 namespace —— free 看到的是宿主机，上限在 memory.max，超了就是 cgroup OOM；CPU 配额是每周期预算（0.5 核 = 每 100ms 用 50ms），用完后核空闲也用不了 —— 「CPU 不高但延迟抖」先查 nr_throttled。 上线：起难在依赖就绪（探针别查 DB），停难在优雅退出 —— 四步顺序不能乱（摘流量最易漏）；SIGTERM 宽限期到就 SIGKILL，长任务必须可中断 + 可恢复；时间窗要能算（摘流 + 在途 P99.9 + 清理 < 宽限期）。 排查：用两个是非问题缩范围（全站 / 单机 × CPU / IO）；load 高 + CPU 低 = 在等 IO 的签名；内存看 available、磁盘 df / du 对不上是已删未释放句柄、容器内先查限流再谈加核——「限额配额优先于加机器」。
读法：三个大框就是运维日常顺序；橙字是判据与数字（0.5 核 / 时间窗都要能算），紫字是失效与误判（毒教材高发区）；绿字是三个项目的落点。底部横幅解释了三个「灵异现象」：莫名被杀、SIGTERM 没处理完、CPU 不高但抖。

      05要能现场算出来的数正本 母题卡「一、教材」推导

      每个数都要带推导，只报结果是会被追问倒的。
      0.5 核的真义
      100ms / 50ms
      每周期预算 50ms CPU 时间，不是半个物理核——突发周期超预算即限流，核空闲也用不了。
      限流证据
      nr_throttled
      cpu.stat 的限流次数与时长——「CPU 不高但延迟抖」的第一嫌疑，先查它再谈加核。
      JVM 容器错配
      4GB 堆 vs 512MB
      老 JVM 按宿主机 1/4 设堆：RSS 涨到 memory.max 即被 cgroup OOM——free 还有 15GB 救不了。
      退出时间窗
      2s < 10s
      摘流 1s + 在途 P99.9 800ms + 清理 200ms：能算才敢设；在途 30s 长任务 = 设计问题。
      错误率抬升
      千分之几 = bug
      发版后错误率小幅抬升通常就是没摘流量 / 没优雅退出——是 bug，不是发版成本。
      load 签名
      load 48 / 8 核 + CPU 45%
      load 高 + CPU 低 = 大量任务卡在不可中断等待（多为磁盘 IO）——不是 CPU 不够。
      内存看哪个
      available
      used 里很大部分是可回收页缓存——「用满」不是问题，「回收不动」才是。
      df vs du 对不上
      100% vs 60%
      已删除但句柄未释放的文件占着空间——lsof 找到进程，重启或截断才释放。
      探针反例
      DB 抖 3s
      /health 查库 + 存活探针 3s 超时 → 重启本来健康的容器 → 全体连锁重启——探针只测进程自身。

      06八句最容易说错的话正本 母题卡「二、自测」纠错题原话

      说对前半句没用，后半句才是判据。
      ✗「容器是轻量虚拟机」✓ 共享内核：namespace 改视野、cgroup 设额度——隔离的是视图与资源，强度弱于 VM。
      ✗「容器里 free 还有内存，所以不会 OOM」✓ 内存没有 namespace：上限在 memory.max，超了就是 cgroup OOM，与宿主机剩多少无关。
      ✗「CPU 利用率不高，说明还有余量」✓ 容器里配额是每周期预算，用完后核空闲也用不了——看 cpu.stat 的 nr_throttled。
      ✗「收到停止信号 exit(0) 就行」✓ 优雅退出四步：摘流量（最易漏）→ 等在途排空 → 关依赖 → 退出；顺序不能乱。
      ✗「进程活着就是服务可用」✓ 存活探针查 DB 时 DB 抖动会重启好容器——探针只测进程自身，依赖就绪用就绪探针。
      ✗「load 高就是 CPU 忙」✓ load 高 + CPU 低 = 大量任务卡在不可中断等待（多为磁盘 IO）——IO 等待的签名。
      ✗「free 显示用满就是要爆了」✓ 页缓存可随时回收，看 available / MemAvailable——「回收不动」才是问题。
      ✗「磁盘告警就是空间要满了」✓ 也可能是 inode 耗尽或已删未释放句柄（df 100% 但 du 60%）——lsof 找进程。
