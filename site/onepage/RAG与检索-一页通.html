01主干：存 → 取 → 用与证正本 wiki/topics/RAG与检索/

分层走一遍：离线摄取 → 在线检索 → 精排与组装 → 生成与证明 → 分层评测回灌。三段失败必须能分开归因。
主干叙事（一段读完）：RAG 的一条线是「存 → 取 → 用与证」。存的环节要承认一个矛盾：块要小才匹配得准、要大才语义自足 —— 所以要么解耦（小块召回、父块返回），要么让块自己知道自己在说什么（Contextual Retrieval 补 50–100 token 定位说明，索引只涨约 12.5%，失败率 5.7%→1.88%）。 取的环节要承认两路检索盲区不重叠：BM25 管专有名词与编号、向量管语义改写，两路量纲不可比所以用 RRF 按排名融合；而权限必须在召回前过滤——进了上下文就等于已经泄露，模型说不说只是概率问题；百万级用 HNSW 做 ANN（精确 KNN 要 1.5 秒/次，用不起）。 用与证的环节：双塔看不到词级交互，所以要用交叉编码器重排（延迟 5ms×N，所以折中是「召回几百 → 重排 50–100 → 进上下文 5–20」）；然后逐条引用绑定 + 生成后验证（找不到支撑就撤稿），该拒答时拒答。 最后分层评测：检索层与答案层分开评，两层的损失是相乘的；出问题按三个岔路口归因 —— 没进 TopK、进了没用上、都进了还错 —— 对应完全不同的修复动作和成本。评测结果回灌到切分、召回、重排，这条绿线才是闭环。
读法：蓝线是主线；橙线是每段的关键手段；紫线是分层评测与归因；绿线是闭环回灌；灰虚是拒答分支。三段的失败必须能分开归因——这是本模块与「调参式 RAG」的分水岭。

      05要能现场算出来的数正本 六张母题卡「一、教材」推导

      每个数都要带推导，只报结果是会被追问倒的。
      为什么必须 ANN
      15.36 亿次 ≈ 1.5 s
      100 万 × 1536 维，O(N×D)；即使每次 1ns 也要 1.5 秒/次。所以 ANN 不是「精度优化」，是算力逼出来的。
      上下文增强四级
      5.7% → 1.88%
      +Contextual Embeddings 3.7%（−35%）→ +Contextual BM25 2.9%（−49%）→ +Rerank 1.88%（−67%）。索引体积只涨约 12.5%；一次性成本约 $1.02/百万文档 token。
      块太大被稀释
      200 / 2000 = 10%
      2000 字块里只有 200 字相关 → 相关占比 10%，相似度信号被稀释，关键内容排不进 Top-K；块太小又语义不自足（单块意思可能是反的）。
      重排延迟
      5 ms × N
      重排 20→100ms、100→500ms、200→1000ms，对比 ANN 召回约 10ms —— 重排会主导整条链路延迟，所以候选数是一个必须算的成本决策。
      重排收益三个口径
      1.02 点 / 35% / 67%
      绝对降幅 1.02 个百分点、相对前一环 35%、相对基线累计 67% —— 「重排降了 67%」是错的，67% 是累计口径。
      验证引用的成本
      ≈1.9 倍
      10 条结论逐条验证：10×(800+50)=8,500 token vs 生成本身 4,500 → 成本接近翻倍。所以只对金额 / 权限 / 生效时间这类高风险结论做。
      拒答的收益
      1/10
      20% 查询没有足够证据：错误代价 10 单位、弃答 1 单位。把「自信的错误」换成「坦白的不知道」，总代价降到约 1/10 —— 错误越贵，拒答越值钱。
      两层相乘
      95% × 90% = 85.5%
      Recall@20 95% × faithfulness 90% = 端到端上限 85.5%。端到端既低于任何一层，又定位不了是哪一层拖的 —— 所以必须分层评。
      归因决定修复上限
      最多修 35%
      100 条失败里召回 40 / 排序 25 / 生成 35 —— 只换更强的模型最多修 35%。样本量：150 条标准误约 ±3.4%，分辨 2 个点需约 900 条。

      06八句最容易说错的话正本 母题卡「二、自测」Q4/Q5 纠错题原话

      说对前半句没用，后半句才是判据。
      ✗「统一切成 500 字一块，这是业界标准」✓ 切的是字符数不是语义边界；没有通用数字，要用代表性问题集测 Recall 与答案正确性来定。
      ✗「块切得越小，召回肯定越好」✓ 语义不自足 —— 单个块的意思甚至可能是反的；还有块数暴涨、重叠切分重复召回挤占预算。
      ✗「向量检索就够了，语义比关键词先进」✓ 盲区不重叠：trace ID 这类编码 Embedding 无能为力。按查询类型分桶评测，由数据决定配比。
      ✗「权限放在生成阶段，让模型别说就行」✓ 进上下文 = 已泄露；模型说不说只是概率问题；未授权内容还会挤占预算、进日志与缓存。
      ✗「升级更大的 Embedding，就不用重排了」✓ 双塔看不到词级交互是结构性损失，换更大的双塔补不回来；也不能靠「多召回几条」替代。
      ✗「召回率 95%，检索这块没问题了」✓ Recall@K 高 ≠ 答案好：正确证据排第 5、前 4 条挤占预算 → context rot；且两层损失相乘。
      ✗「文末列三条参考链接，可追溯就没问题」✓ 粗引用把校验成本推给读者（300 秒 vs 60 秒）；要逐条绑定 + 生成后验证 + 无据撤稿。
      ✗「检索失败率降 49%，所以幻觉降 49%」✓ 检索失败率只是「证据缺失型幻觉」的上界，不充分；总幻觉率与它无必然大小关系，方向上高估。
