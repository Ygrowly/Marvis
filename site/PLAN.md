# site · HTML 方案定稿（2026-09-10）

> 本文件是 `site/` 的**方案正本**。实现、改版、争议都以它为准，避免反复推翻。
> 更新规则：只在「确实发现了错误」时改，不因为「想到了新点子」改。新点子先进文末〈方案停车场〉。

## 一、第一性原理链

1. **目标**：知识长在人脑里，能在需要的那一刻被提取出来。不是建一个需要 AI 帮忙查的库。
2. **人脑怎么学**（本方案的理论地基）：
   - 提取练习：提升提取强度只能靠「提取」这个动作本身，不能靠再读一遍
   - 必要难度：越轻松的提取，学到的越少
   - 双重编码：文字走序列通道，图像走并行通道；**关系、过程、结构、分布**这四类信息用文字表达是降维，用图是直接编码
   - 组块化：先记组块轮廓，细节按需展开
   - 间隔重复：1-3-7-14-30
3. **推论**：md 与 html 不是替代关系，是**分工**。

## 二、md 与 html 的分工

| | md | html |
|---|---|---|
| 角色 | **工作台**：素材、讨论、推导、正本 | **学习界面**：表征、训练、诊断、交付 |
| 状态 | 允许乱、允许过程感 | 精炼，只留长进脑子的东西 |
| 谁写 | 人 + AI 讨论着写 | 自动派生，无人手写 |
| 可写性 | 唯一可写 | 只读，永不回写 md |

推论：判断一个 md 好不好，不是「读起来顺不顺」，是「它有没有把问题想清楚」。

## 三、判据（只用这一条）

> **一个视图值不值得做，看它是否增加了编码通道（图 / 动画 / 交互）或提取动作。只改排版 = 不做。**

据此：
- ❌ 把 md 排版成好看的网页 —— 零增益，不做
- ✅ 把关系 / 过程 / 结构 / 分布画出来 —— 直接编码，做
- ✅ 把知识做成要往外掏的卡 —— 提取，做
- ✅ 把复盘做成可视化分布 —— 诊断，做

## 四、三类页面

```text
md 工作台（唯一可写）
  ↓ build.py（按格式选 adapter）
  ├ 母题页 topics/     主卡 + 图 + 折叠子卡 + 复训
  ├ 诊断页 reviews/    评分 + 模块分组 + 缺口
  └ 交付页 deliver/    一页纸 / 简历，可打印
  ↑
训练台 index.html（唯一入口，调度三类页面 + 1-3-7-14-30 复训）
```

## 五、母题单元（重要：防卡片爆炸）

**一个母题 = 一个学习单元 = 一张主卡。**

```text
母题页 · LRU 缓存
├─ 主卡（1 张）   母题原句 → 一句话结论         ← 唯一进复训调度的单位
├─ 图（1 张）     哈希表与链表是同一状态的两个视图
├─ 折叠子卡       两层追问 / 同类变体 / 迁移场景 / 本次断点
└─ 复训状态       D1 · D3 · D7 · D14 · D30
```

- 复训计数单位是**母题**，不是卡
- 子卡默认收起，不进调度
- 反例（禁止）：把一个母题拆成 5 张平等卡片

## 六、图从哪来

原则：零依赖、离线可用、双击可开。

| 方案 | 决定 |
|---|---|
| mermaid.js / d3 / three.js | ❌ **页面里跑**：离线失效或体积过大 → ✅ 但 mermaid 只在**浏览器端**渲（`_data/mmd-boot.js` + 站点自带 mermaid.min.js，2026-09-25 定）：md 里照常写，build 不碰浏览器；想离线/加速再开 `MARVIS_MMD_PRERENDER=1` 预渲染成内联 SVG |
| **独立 `.svg` 文件 + md 里一行引用** | ✅ 采用 |
| **CSS @keyframes 动画（原生）** | ✅ 采用 |

md 里写 `::figure <文件名>`，build 时把 `site/figures/<文件名>` 内联进页面。
流程：**md 里描述需要什么图 → AI 生成 svg 文件 → 人审阅图对不对**。人不需要会写 SVG。

## 八、新内容处理流程

```text
新内容（分析 / 复盘 / 新题）
  ↓ ① 先查 MAP，落进 md 正本
  ↓ ② 判断产物类型
     ├ 要表征 + 训练 → 按母题卡模板写 → 母题页
     ├ 要诊断        → 按复盘格式写   → 诊断页
     ├ 要交付        → 按交付格式写   → 交付页
     └ 都不是        → 留在 md（素材 / 过程 / 讨论）
  ↓ ③ python site/build.py
  ↓ ④ 训练台按 1-3-7-14-30 调度
```

「都不是」的判据：它有没有需要你往外掏的东西（→训练），或需要你看出关系 / 分布的东西（→表征）。都没有，就是素材。

**只有 `status: integrated` 的正本才生成视图。** `candidate` / `reading` 停在 md。

## 九、两条防过度设计硬规则

1. 加任何页面 / 组件 / 图之前先问：**它增加的是编码通道还是提取动作？** 都不是 → 不加。
2. **一个母题 = 一个训练单元 = 一张主卡。** 子卡必须折叠。

## 十、死法预警

| 信号 | 含义 |
|---|---|
| 做页面的时间 > 练知识的时间 | 搬运取代训练（最阴险） |
| 页面数 > 每周打开次数 | 沦为第二个 `raw/` |
| 开始问「以哪个为准」 | 同步地狱 |
| 加第 11 个组件 | 结构设计错了 |
| md 里手写卡片数据 | 应当由 adapter 抽取 |
