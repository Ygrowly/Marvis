题目

面试官问——"你们的 RAG 怎么保证可追溯？用户凭什么相信这个答案是对的？"

一 · 教材 从前提推到结论，不需要先会

1. 前提：引用要解决的是"谁承担校验成本"

【推导】问一个更根本的问题：用户看到一段答案，他凭什么判断哪句可信？

① 粗引用（文末列链接）：
   正文 10 条结论没有任何标记，文末给 3 个链接
   → 用户无法判断哪一句有依据
   → 只能二选一：全信，或者全不信
   → 校验成本 = 【全部结论】
   → 而且错的那几条照样造成损失

② 细引用（逐条绑片段）：
   每条结论后面绑到具体片段 [doc_12#p3]
   找不到支撑引用的结论【直接撤掉】
   → 用户只需抽查可疑的那几条
   → 校验成本 = 【可疑的那几条】

【结论】引用的粒度决定"校验成本由谁承担"——粗引用是把成本全推给读者，细引用是把成本在生成时就付掉。

到这里你应该能回答：为什么"我们在文末列了参考链接"不算可追溯？

2. 关键动作是"生成后验证"，不是"要求引用"【推导】

【事实】Anthropic 文档里的三段式做法：

① 允许弃答：显式给模型"说不知道"的许可
② 先摘录、再作答：对长文档（>20k token），先逐字摘出相关原文，再基于摘录作答
③ 生成后验证：起草完，要求模型【回头为每条结论找支撑引用】；
              找不到支撑的那条，【直接撤掉】并标记

【推导】为什么"要求引用"不够：

"要求引用" 是 prompt 层的东西 —— 它改的是概率分布
"验证引用" 是机制层的东西 —— 它是一条独立的检查步骤

模型完全可以编一个看起来像引用的东西（比如引一个不存在的片段编号）
而 prompt 拦不住它，因为编引用和编结论是同一个机制

【推论】这跟 [[母题-C2-结构化输出与JSON可靠性]] 那条结论是同一条：

"要求"改的是概率，"验证"才是机制。

【事实】这一条在 [[母题-C4-幻觉的成因与可控性]] 里被点过一次名：Anthropic 把它叫"生成后自查撤稿"——每条结论回原文找支撑，找不到就撤。它是治"有据不依"那一类幻觉的正解。

到这里你应该能回答：为什么"我们在 prompt 里要求模型必须给引用"这句话经不起追问？

3. 验证的代价能算出来【推导】

一条回答有 10 条结论，逐条验证引用：
  每次验证输入约 800 token（问题 + 结论 + 候选原文）
  每次验证输出约 50 token（是否找到 + 引用位置）
  验证总量 = 10 × (800 + 50) = 8,500 token

生成本身（对照）：
  输入约 4,000 token（上下文）+ 输出约 500 token = 4,500 token

验证成本 / 生成成本 = 8,500 / 4,500 ≈ 1.9 倍

【结论】逐条验证会让 token 成本接近翻倍。

【取舍】所以生产上通常只对"高风险结论"做逐条验证：

值得验证的：金额、权限、生效时间、涉及外部副作用的结论
不必验证的：寒暄、过渡句、从证据直接摘录的原文

【推论】这也是"引用绑定"要和"证据重要性"一起设计的原因——不是所有结论都值得花同样的验证成本。

4. 拒答：把"自信的错误"换成"坦白的不知道"【推导】

【事实】应该拒答或澄清的条件（study/03 的清单）：

① 没有召回足够证据
② 多个权威来源相互冲突
③ 用户身份不足（权限）
④ 问题超出知识库边界
⑤ 时间、主体或指标口径不明确

4.1 拒答的收益能算出来【推导】

【推导】这跟 [[母题-C4-幻觉的成因与可控性]] 里"错误和弃答分开定价"是同一条原理：

设 20% 的查询没有足够证据。
错误（自信答错）的代价 = 10 单位（客诉 / 返工 / 信任损失）
弃答的代价            = 1 单位（转人工兜底）

不拒答：那 20% 全部变成错误 → 0.2 × 10 = 2.0 单位
拒答：  那 20% 转人工        → 0.2 × 1  = 0.2 单位

【结论】代价降到 1/10。

【推论】"拒答显得系统能力弱"是反的——用户对"自信的错误"的容忍度，远低于对"坦白的不知道"的容忍度。 这也是为什么汇报要用错误率而不是准确率。

4.2 引用绑定还必须在生成之后再做一次鉴权【事实】

【事实】study/03 的一条要求容易被漏掉："引用和下载再次鉴权"。

【推论】理由和 [[母题-G2-向量与关键词的混合检索]] 里"权限必须在召回前生效"是同一个：

召回时过滤了，但从"召回完成"到"用户看到答案"之间，
权限可能已经变了（撤权、角色变更、文档删除）
→ 所以展示引用时还要再验一次

到这里你应该能回答：为什么"拒答"不是能力不足，而是设计的一部分？

5. 好的引用长什么样【事实】

【事实】study/03 给的标准（这一条可以直接背）：

① 关键结论【逐项绑定】来源片段
② 引用可定位到【文档 / 章节 / 版本】
③ 计算结果绑定 SQL / 工具运行 ID
④ 用户能检查原始证据
⑤ 引用不存在、或不支持结论时【判失败】（不是警告，是失败）

【推论】第 ③ 条是企业问数场景特有的：SQL 的结果也要能追溯——引用绑定 Schema 版本、SQL AST、运行 ID 和结果摘要（数驭穹图的真实做法）。

【推论】第 ⑤ 条是关键：引用不支持结论 = 这条结论失败，而不是"打个标记继续展示"。判失败才能进评测（[[母题-G5-RAG评测与幻觉率]] 的 Citation completeness 就是测这个）。

6. 边界与常见误解

常见说法修正
"引用就是文末列参考链接"那不是引用，是把校验成本全推给读者。用户无法判断哪句有依据，只能全信或全不信。细引用把校验成本在生成时就付掉——而且找不到支撑的结论根本不出现
"在 prompt 里要求模型给引用就行了"不够。"要求引用"是 prompt（改概率），"验证引用"才是机制（独立检查步骤）。模型完全可以编一个看起来像引用的片段编号——因为它编引用和编结论是同一个机制
"拒答显得系统能力弱"反了。拒答是把"自信的错误"（代价 10 单位）换成"坦白的不知道"（代价 1 单位）——总代价降到 1/10。用户对自信错误的容忍度远低于对不知道的
"召回时过滤了权限就够了"不够。从"召回完成"到"用户看到答案"之间，权限可能已经变了（撤权、角色变更、文档删除）。所以展示引用和下载时要再次鉴权
"引用存在就说明结论对"引用存在 ≠ 引用支持结论。要区分"引了一个真实存在的片段"和"这个片段确实支撑这条结论"——后者才是 faithfulness（[[母题-G5-RAG评测与幻觉率]]）
"所有结论都做逐条验证"成本会接近翻倍（Q3）。只对高风险结论做：金额、权限、生效时间、涉及副作用的。其余靠"从证据直接摘录"来保证

【取舍】读成一句话：可追溯不是"给个出处"，是"让每句话都有据可查，没据的那句不出现"——前一半靠绑定，后一半靠拒答。

三 · 面试输出 闭卷口述 60 秒，再看结论

怎么让答案的每一句都能回到原文——以及当回不去的时候，系统该做什么？

翻面对照自测，评分会进训练台的复训调度。

为什么重要：这是 RAG 面试里最容易被答浅的一题——大多数人的答案是"我们在文末列了参考链接"。但真正的问题是：谁来承担校验成本。 引用的本质不是"给个出处"，是把验证的工作从"读者全量核对"降到"抽查可疑项"。而且这一题直接连着"拒答"——一个不拒答的 RAG 系统，等于把幻觉的责任推给了用户。

一句话结论 全卡唯一要背的锚点

可追溯不是"给个出处"，是让每句话都有据可查、没据的那句不出现。粗引用（文末列链接）把校验成本全推给读者——用户无法判断哪句可疑，只能全信或全不信；细引用（逐条绑片段 + 可定位到版本）把校验成本降到"可疑的那几条"。关键动作不是"要求模型给引用"，而是"生成之后回头验证引用"——把每条结论回原文找支撑，找不到的直接撤掉（Anthropic 管这叫"生成后自查撤稿"）。理由是："要求"改的是概率，"验证"才是机制——模型完全可以编一个看起来像引用的东西。代价：逐条验证会让 token 成本接近翻倍（10 条结论 ≈ 8,500 token vs 生成 4,500 token），所以只对高风险结论做（金额、权限、生效时间）。拒答是设计的一部分：把"自信的错误"（10 单位）换成"坦白的不知道"（1 单位），总代价降到 1/10——错误越贵，拒答越值钱。最后，引用和下载要再次鉴权——权限从召回到展示之间可能已经变了。
  • 引用粒度决定校验成本由谁承担
  • 粗引用 300 秒 vs 细引用 60 秒
  • "要求引用"是 prompt，"验证引用"才是机制
  • 生成后自查撤稿（找不到支撑就撤）
  • 逐条验证成本 ≈ 2 倍，只对高风险结论做
  • 先摘录再作答（引用在生成时产生）
  • 拒答把代价降到 1
  • 10，错误越贵越值钱
  • 引用要能定位到文档·章节·版本
  • SQL 结果绑运行 ID
  • 引用和下载再次鉴权
  • 引用不支持结论 = 判失败

展开（先自答，再看 · 默认收起，不进复训调度）

1. 引用怎么做到"可追溯"而不是文末列链接？

逐条绑定 + 可定位到文档/章节/版本 + 找不到支撑就撤稿。计算类结论还要绑定 SQL / 工具运行 ID（这样用户能重跑）。

2. 什么情况下应该拒答？

五条：没有召回足够证据、多个权威来源冲突、用户身份不足、超出知识库边界、时间/主体/口径不明确。冲突时不强行合成唯一答案，而是显式返回证据（RuleArena 的做法）。

3. 怎么防止 RAG 越权？

身份进入检索层、ACL filter 先于召回；缓存按租户 / 权限分区；引用和下载再次鉴权；做跨租户与撤权测试；日志避免记录敏感原文。

4. 长文档怎么保证 grounding？

对超过 20k token 的文档，先要求逐字摘出相关原文（找不到就明说"没找到"），再基于摘录作答。这样引用在生成时就产生了，验证可以用代码做（核对摘录是否真在原文里）。
  • 「引用能不能防幻觉？」——能防一部分，但引用本身也会被编。所以关键动作是生成后自查：每条结论回头去原文找支撑，找不到就撤稿。"要求引用"是 prompt，"验证引用"才是机制。
  • 「多轮对话里引用会不会失效？」——会。上一轮的结论进了下一轮上下文就变成"已确认事实"。所以摘要里要标注哪些是已验证事实、哪些是模型推断，关键状态回权威源重查（[[母题-C1-上下文组装与窗口预算]]）。

- 数驭穹图：引用绑定 Schema 版本、SQL AST、运行 ID 和结果摘要——这是"引用要能重跑"的最强形态（用户不仅能核对，还能自己重跑一遍 SQL）。 - RuleArena：冲突规则显式返回证据，不强行合成唯一答案——这是"拒答"的正例，也是本卡第 4 节五条拒答条件里"多个权威来源冲突"的真实版本。 - EnergyOps：故障建议要引用日志 / 指标 Artifact 和操作手册——"证据"有两种形态（实时数据和静态文档），引用格式要能区分。

先问"谁来承担校验成本" → 粗引用 vs 细引用的成本对比 → 关键动作是生成后验证（不是要求引用） → 验证的成本与取舍 → 拒答的定价（错误 vs 弃答）→ 好引用的五条标准 → 再次鉴权 → 收束到"绑定 + 撤稿"

可追溯的前一半是"绑定"，后一半是"撤稿"。 绑定解决"每句话能查"；撤稿解决"没据的话不出现"——而后者才是让用户敢信的那个动作，因为它把校验从"事后逐条检查"变成了"事前自动过滤"。

本次断点：【待填 —— 闭卷时具体卡在哪，写成事实不写评价】

通过证据：能说清"引用粒度决定校验成本由谁承担"；能算出逐条验证的成本倍数（≈1.9 倍）；能算出拒答的代价比（1/10，错误越贵越值钱）；能算出粗引用与细引用的校验成本（300 秒 vs 60 秒）；能说出"要求引用 vs 验证引用"的区别并解释为什么 prompt 拦不住编引用；能背出好引用的五条标准与拒答的五条条件；且自测 5 题全对。
