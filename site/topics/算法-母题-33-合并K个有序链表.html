题目

给定 k 条已经升序排列的链表，把它们合并成一条升序链表并返回。

三 · 面试输出 闭卷口述 60 秒，再看结论

如何从 k 个有序序列里，持续取出当前的最小值？

翻面对照自测，评分会进训练台的复训调度。

为什么重要：多路归并的母题，外部排序、多路日志合并、TopK 归并都用它。还考堆的工程细节（Python 元组比较陷阱）。

一句话结论 全卡唯一要背的锚点

最小堆维护 k 个候选头，弹出最小值接到结果后，把它的后继入堆。
  • k 路归并
  • 最小堆维护候选
  • 弹一个补一个
  • counter 防元组比较

卡住时靠这几个词重建整条链。

1. 堆和分治怎么选？

复杂度相同，堆代码短、适合流式；分治不需要额外堆、适合静态数据

2. Python 里 (val, node) 直接入堆为什么会报 TypeError？

val 相同时会比较 ListNode 对象，需加唯一 counter

讲解

输入示例：

lists = [
    1 → 4 → 5,
    1 → 3 → 4,
    2 → 6
]

结果：

1 → 1 → 2 → 3 → 4 → 4 → 5 → 6

设：

+ k 是链表数量。 + N 是所有链表的节点总数。

一种做法是使用最小堆。最小堆可以快速取出当前最小的头节点。

主线：

每条非空链表的头节点入堆
→ 弹出当前最小节点，接入结果
→ 将该节点的 next 放入堆
→ 重复直到堆为空

完整代码：

import heapq

def merge_k_lists(lists):
    dummy = ListNode(0)
    tail = dummy
    heap = []
    counter = 0                      # 唯一编号：val 相同时用它兜底，避免比较 ListNode

    for node in lists:               # 每条非空链表的头节点入堆
        if node:
            heapq.heappush(heap, (node.val, counter, node))
            counter += 1

    while heap:
        _, _, node = heapq.heappop(heap)
        tail.next = node             # 弹出最小节点，接到结果尾部
        tail = node

        if node.next:                # 弹一个补一个
            heapq.heappush(heap, (node.next.val, counter, node.next))
            counter += 1

    return dummy.next

不变量：每轮循环开始时，堆里恰好保存着「每条尚未耗尽的链表当前的第一个节点」，所以堆顶就是全局剩下的最小值。

1. 最小堆大小最多为 k，维持堆有序时，只需沿堆的高度调整：

堆高度 = log k

所以一次入堆或出堆都是：

O(log k)

2. 所有 N 个节点各入堆、出堆一次：

时间复杂度：O(N log k)
额外空间：O(k)

3. 两两分治合并的复杂度同样是：

O(N log k)

因为共有 log k 轮，每一轮所有节点总共被处理一次，即 O(N)。

最小堆：不断选出 k 个候选头中的最小值
两两分治：每轮把链表数量减半

最小堆恢复脚本：

每条链表先放一个头节点；弹出最小节点接到结果后，再把它的后继入堆。堆中始终保存每条未处理链表的最小候选。

更准确地说，Python 比较元组时会逐项比较：

(node.val, node)

如果两个节点的 val 相同，就会继续比较两个 ListNode 对象，而 ListNode 默认不能比较大小，会抛出：

TypeError: '<' not supported between instances of 'ListNode'

加入唯一的 counter：

(node.val, counter, node)

值相同时会比较整数编号，不会比较节点对象。
