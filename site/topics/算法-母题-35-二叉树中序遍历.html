题目

给定一棵二叉树，返回它的中序遍历结果（左 → 根 → 右）。

三 · 面试输出 闭卷口述 60 秒，再看结论

二叉树三种遍历顺序怎么写，迭代版又怎么写？

翻面对照自测，评分会进训练台的复训调度。

为什么重要：一切树题的地基。面试常追问迭代版和 Morris，用来看你对「显式栈替代递归」是否真的理解。

一句话结论 全卡唯一要背的锚点

左—根—右；迭代版把递归悄悄用的「调用栈 + 返回地址」拆成显式的 stack + cur——一路向左压到底，弹出才输出，再跳右子树。
  • 左根右
  • 显式栈
  • 一路向左压到底
  • 弹出即输出
  • 再跳右子树
  • BST 有序性

卡住时靠这几个词重建整条链。

展开（先自答，再看 · 默认收起，不进复训调度）

1. 迭代版为什么容易写错？

要显式维护两件状态：stack 记「欠账的祖先」、cur 记「走到哪」，并守住三条：循环条件 cur or stack 缺一不可、压栈必须写在 cur = cur.left 之前（覆盖前备份）、pop 之后必须接 cur = cur.right（弹出后改向）

2. BST 的中序遍历为什么是有序的？

左子树的全部节点 < 根 < 右子树的全部节点（注意是子树级性质，不是孩子级），而中序 = 左子树中序 + 根 + 右子树中序，拼接天然升序。反例锚点：左孩子的右孙子比它爹大、但仍然小于根。由此推出 LC 98 验证 BST 的经典错误：只查 left.val < node.val < right.val 是错的，必须维护上下界，或检查中序序列严格递增
  • LC 144 前序 / LC 145 后序（改访问顺序即可）
  • LC 102 层序遍历（换 BFS 队列）
  • LC 98 验证二叉搜索树（利用中序有序性）
  • 进阶：Morris 遍历 O(1) 空间

树形结构的展开顺序：组织架构、目录树、分类体系的递归渲染都用中序/前序骨架。凡是「要在遍历到某个节点时，它的左子树已经处理完毕」的题，都是这条骨架。

本次断点：迭代版已补（递归 → 显式栈的映射、不变量、统一骨架、栈里存什么的三条卡点）。仍缺：Morris 遍历 O(1) 空间、后序迭代版、用显式栈解 LC 173/230。

讲解

二、推导

2.1 顺序定义与递归版

中序遍历顺序：

左子树 → 当前节点 → 右子树

例如：

1
     \
      2
     /
    3

中序遍历结果：

[1, 3, 2]

完整代码：

def inorder_traversal(root):
    result = []

    def traverse(node):
        if not node:
            return

        traverse(node.left)
        result.append(node.val)
        traverse(node.right)

    traverse(root)
    return result

复杂度：

时间：O(n)，每个节点访问一次
空间：O(h)，取决于递归调用链的最大深度

其中：

平衡二叉树：O(log n)
退化成链表：O(n)

恢复脚本：

遇空返回，按照“左—根—右”递归，每个节点的值在左子树遍历完成后加入结果。

2.2 迭代版：显式栈

为什么中序的迭代版比前序难

前序是「看到就输出」，所以弹出即打印；中序必须是「先欠着，等左子树还完债再输出」。递归版靠调用栈同时保存了两件事——node（我在哪）和返回地址（我该干嘛）；写成迭代就得把这两件事拆开、显式摆在台面上：

递归里的东西迭代里的对应物含义
node 参数stack已经路过、但还没轮到输出的祖先（欠的账）
返回地址（PC）cur我正往哪棵子树里钻（走到哪了）

口诀：一路向左压到底，弹出即输出，然后跳右子树。

def inorder_traversal(root):
    result = []
    stack = []
    cur = root

    while cur or stack:          # 两件状态任一非空就要继续
        while cur:               # 阶段一：一路向左，沿途全部压栈
            stack.append(cur)
            cur = cur.left

        cur = stack.pop()        # 阶段二：左边到底了，还债
        result.append(cur.val)
        cur = cur.right          # 转向右子树，下一轮又会一路向左

    return result

不变量（面试要能口头说出来）

外层循环每一轮开始时：stack 自底向顶，恰好是从根一路向左下来的那条祖先链；链上每个节点的左子树都还没处理完（所以都欠着），而下一个该输出的就是栈顶。cur 指向下一步要深入的子树根，为 None 就表示「左边走不动了，该还债」。

为什么循环条件是 cur or stack（缺一不可）

  • 只写 while stack：初始时 stack 为空、cur = root，直接不进循环，整棵树丢掉。
  • 只写 while cur：弹出一个节点后 cur = cur.right 若为空，cur 变 None，但栈里还有欠账，会提前退出。

2.3 一套骨架，两种遍历

中序和前序共用同一套骨架，唯一区别是输出发生在哪一刻：

# 前序：压栈的同时就输出（根先出，路过即可还）
        while cur:
            result.append(cur.val)   # ← 唯一多出来的一行
            stack.append(cur)
            cur = cur.left
        cur = stack.pop()
        cur = cur.right

一句话记：前序在「下去」的路上输出，中序在「上来」的路上输出。后序要记录「上次访问的节点」或用双栈反转，属于另一套骨架，单独成卡。

2.4 高频卡点：栈里到底存什么

卡点一：「已经 res.append 过了，为什么还要压栈？」

因为访问 ≠ 处理完。一个节点在这套骨架里要活两辈子：

阶段什么时候干什么
第一次见面（下去的路上）内层 while cur 里res.append(cur.val) —— 访问，只干一次
第二次见面（上来的路上）cur = stack.pop() 之后cur = cur.right —— 去右子树，这件事还没做

栈里留下的不是「还没访问的节点」，而是「还没处理完的节点」——它的右子树那笔账还欠着。

卡点二：压栈必须写在 cur = cur.left 之前

cur 是个会被覆盖的局部变量。cur = cur.left 一执行，「我」就没了——栈是它唯一的备份。

        while cur:
            res.append(cur.val)   # ① 访问
            stack.append(cur)     # ② 备份「我」—— 必须在 ③ 之前
            cur = cur.left        # ③ 覆盖 cur，从此「我」只活在栈里

判断压栈该存谁的唯一判据：pop() 出来之后你要拿它取谁的 .right？要取 1.right，栈里就必须是 1。存成 cur.left 的话，pop 出来取的是 cur.left.right，原节点的右子树直接丢失。

卡点三：栈有两种职责，别混用

同一道前序有两种写法，栈的含义完全不同：

写法栈的含义关键动作
骨架版（见 2.2 / 2.3）回溯路径——记着怎么原路回去压栈不输出，回来取 .right；栈里允许有已输出的节点
经典版（见下）预约队列——待访问的节点先排队弹出即输出，之后彻底不需要它
# 经典版：弹出即输出（注意先压右、后压左）
def preorder(root):
    if not root:
        return []
    res, stack = [], [root]
    while stack:
        node = stack.pop()
        res.append(node.val)
        if node.right:
            stack.append(node.right)
        if node.left:
            stack.append(node.left)
    return res

「已经输出了就不用存了」这个直觉只对经典版成立。中序没有经典版——中序的输出发生在「回来」的路上，只能用骨架版。先把骨架版练成肌肉记忆，经典版知道有这条路即可。

2.5 复杂度

时间：O(n)，每个节点恰好压栈一次、弹栈一次
空间：O(h)，栈的最大深度就是树高
      平衡树 O(log n) ｜ 退化成链 O(n)

注意迭代版的 O(h) 与递归版量级相同，但迭代版不吃系统调用栈，且可以随时中断/恢复——LC 173 BST 迭代器、LC 230 第 K 小正是靠这一点做到 O(h) 空间提前退出。

三个最容易写错的地方（自查用）

1. while cur or stack 写成 while stack —— 初始时栈空，整棵树被跳过，返回 []。 2. 内层 while cur: 写成 if cur: —— 只压一层就转向左边，左链没压完，输出顺序退化成「根先出」。 3. cur = stack.pop() 之后漏掉 cur = cur.right —— 死循环：下一轮内层会把刚弹出的节点重新压回去。
