主卡

为什么重要：考的是摊还分析——嵌套循环不等于 O(n²)。也是「用集合换时间」和「用起点判据剪枝」的典型。

恢复关键词

  • 集合去重
  • 判起点( x-1 不在集合 )
  • 每段只扫一次

卡住时靠这几个词重建整条链。

展开（默认收起，不进复训调度）

1. 为什么总复杂度是 O(n) 而不是 O(n²)？

只有起点才触发内层延伸，每个数字在所有 while 中最多被访问一次，总次数 O(n)

2. 有重复数字时会怎样？

集合天然去重，不影响结果

  • LC 594 最长和谐子序列
  • 变体：要求返回序列本身而不只是长度

连续区间检测，例如订单号/流水号的连续性校验、批次号断号排查。

本次断点：一开始用「每个数字都往前找」的 O(n²) 思路，缺少起点判据

正文底稿

给定一个未排序的整数数组 nums，找出其中数字连续的最长序列长度。

要求算法时间复杂度为 O(n)。

输入：nums = [100, 4, 200, 1, 3, 2]
输出：4
解释：最长连续序列是 [1, 2, 3, 4]

注意：

+ “连续”指数字连续，不要求它们在原数组中的位置连续。 + 数组中可能有重复数字。

判断起点

有重复数字

每个数字都查找 n,n-1...1 o(n^2)

def longest_consecutive(nums):
    num_set=set(nums)
    longest=0
    for x in num_set:
        if x-1 not in num_set:
            current=x
            length=1
            while current+1 in num_set:
                current+=1
                length+=1
            longest=max(longest,length)
    return longest

内外两层：

可以从内外两层理解：

+ 外层不变量：处理当前数字前，longest 是此前所有已处理序列起点所对应的最长序列长度。 + 内层不变量：每次进入 while 时，x 到 current 是一段完整连续序列，并且 length = current - x + 1。

只从没有前驱的数字开始向后延申，使得每段连续序列只被完整扫描一次

虽然单次 while 可能很长，但所有 while 的执行次数加起来不超过 n：

+ 建立集合：O(n) + 外层遍历：O(n) + 所有内层延伸合计：O(n)

所以总复杂度是：

O(n)+O(n)+O(n)=O(n)

这种分析叫“总量分析”或“摊还分析”：不能只看到代码嵌套就直接相乘，要看内层操作在整个算法中总共执行多少次。

虽然存在 for 嵌套 while，但只有序列起点才开始延伸，每个数字在所有 while 中最多被访问一次，因此所有内层循环的执行次数合计为 O(n)，总时间复杂度为 O(n)。

恢复脚本：

集合去重 - 找到没有前驱的起点 - 只从起点向后延申 - 每段序列只扫描一次
