题目

一张表要同时支撑两种查询——按 status 等值过滤，和在 tags 数组里做「包含」判断。你只有一次建索引的机会，先建哪个？另一类查询怎么办？

主卡

在这里练也可以，评分会进训练台的复训调度。

为什么重要：这是 PG 与 MySQL 最显眼的一处差异。MySQL 基本上是「B+ 树 + 少量特例」，PG 是索引类型动物园——面试官问 PG 索引，考的从来不是记住几个缩写，而是你会不会按查询形状选型。答成「都建 B-tree」会立刻暴露没在 PG 上做过真实优化。

恢复关键词

  • 操作符类别（operator class）
  • B-tree 等值+范围+排序
  • GIN 多值包含
  • GiST 几何近邻
  • BRIN 块级摘要
  • Hash 只等值
  • 与部分索引组合

卡住时靠这几个词重建整条链。

展开（默认收起，不进复训调度）

数驭穹图的元数据检索（Schema / 目录字段常有 JSON 结构，GIN 主战场）；RuleArena 的规则与场景标签（多标签包含查询）。方言差异（面试安全底线）：MySQL 里没有 GIN / GiST / BRIN 这套东西，它对应的是「全文索引 / 空间索引」这类特例，而多值包含在 MySQL 里通常要靠生成列或拆表解决——不要把「JSONB 用 GIN」这套说法套到 MySQL 上，那是 PG 的机制。

默认为什么是 B-tree（覆盖面）→ 四种类型的组织方式与对应操作符 → 回到题目做选择 → 各自的代价与边界 → 一句判据收尾

索引是「按某种方式重新组织或摘要数据」的结构，它能回答哪类查询，由它的组织方式决定。 所以选型的第一句话永远是——这个查询用的是哪个操作符；第二句话才是——代价是什么。

本次断点：【待填 —— 闭卷时具体卡在哪，写成事实不写评价】

通过证据：能对一段「既有等值又有包含」的真实查询说出用哪个索引、为什么、代价在哪，并说清 GIN 与 B-tree 的组织方式差异。

正文底稿

原理分解

一、B-tree 为什么是默认

因为它同时支持这些，而绝大多数业务查询落在这里面：

能力例子
等值WHERE status = 'RUNNING'
范围WHERE created_at >= ? AND created_at < ?
排序ORDER BY updated_at DESC（可直接用索引序，省一次 sort）
前缀匹配WHERE name LIKE 'abc%'（前缀才行，%abc 不行）
唯一性UNIQUE、主键约束的底层

覆盖面最广 → 所以是默认。 这句话比任何类型清单都重要：默认不是「最好」，是「最不容易选错」。

二、四种类型：组织方式决定它能回答什么

类型怎么组织擅长回答典型场景
B-tree有序树，键 → 位置等值 / 范围 / 排序 / 前缀90% 的普通索引
GIN倒排：值 → 出现位置集合多值包含（@>、&&、@@）JSONB、数组、全文检索
GiST可扩展的平衡树，节点存包围盒 / 范围摘要几何相交、近邻（<->）、范围重叠地理位置、区间、模糊匹配
BRIN只存每个数据块的最小/最大值摘要大表按物理有序列做范围扫时序表按时间追加写
Hash哈希表，只存哈希 → 位置只有 =几乎用不上（B-tree 也能等值，还多给排序）

关键在 GIN 那一行：B-tree 的键是「整行的某个值」，所以 tags = '{a,b}' 这种整值比较能用，但 tags @> '{a}'（包含 a）用不了——因为 B-tree 不知道 {a,b} 里有没有 a。GIN 把每个元素单独建成一个键，所以「包含」变成了「按元素查」。这就是它适合 JSONB / 数组的根本原因，而不是「GIN 比较高级」。

三、回到题目

  • status 等值 → B-tree；如果 status 只有少量「活跃值」高频被查，直接用部分索引（见 P3）更省。
  • tags 包含判断 → GIN（GIN (tags)）。

给「只有一次机会」的答案：先建 B-tree 的 status（它服务的是最高频、最便宜的那类查询），再评估 tags 查询的频率——如果 tags 查询不是热点，就不该为它付 GIN 的写入代价。「先建哪个」这个问题本身在考你知不知道 GIN 更贵。

四、代价与边界（不说这段就等于没选型）

类型主要代价
B-tree写放大、空间；更新频繁时页分裂
GIN写入代价明显更高（一次写入要更新多个倒排项），常有 pending list / fastupdate 机制缓冲；体积也更大
GiST可能是有损的（需要回表复核），构建较慢
BRIN只对物理有序有效——数据一旦乱序（更新、VACUUM FULL 后顺序变化），摘要会退化到「每块范围都覆盖全表」，索引形同虚设
Hash不支持范围与排序，不能做唯一约束，崩溃安全性历史上也有问题

所以判据是两句话：① 查询用的操作符，只有这个类型的 operator class 支持；② 加上它以后，写入路径能不能承受。只说①不说②，是教科书答案；两句都说，才是做过线上的人。
