# 复盘与知识重构

## 目标

复盘不是汇报收藏数，而是找出：哪些认知真的变了、哪些能力产生证据、哪些问题仍在重复、下一周期把注意力放在哪里。

## 日常关闭（可选，3–5 分钟）

只在当天有新材料或行动时做：

- 今天哪条来源值得继续处理？
- 哪份待确认补丁需要决定？
- 明天唯一最小行动是什么？

不要求每天写日记。

## 周复盘（20–30 分钟）

### 1. 先回忆

在读取 Wiki 前，让用户回答：本周最重要的新判断是什么？在哪个场景用过？哪里仍说不清？

### 2. 检查闭环

读取本周来源、补丁、缺口和行动，关注：

- 新增来源中有多少被融合、仅归档或仍待处理；
- 已应用补丁是否改变了表达、决策或项目；
- 完成行动产生了什么证据；
- 哪个缺口仍高影响但没有最小路径；
- 哪个问题又重复发生。

### 3. 找主要矛盾

只选一个下周主要矛盾，例如“项目深度不足 vs 面试时间临近”。选择一条主线、一个保温项、一个明确暂缓项。

### 4. 形成下周输出

- 最多 3 个关键缺口；
- 一个可交付成果；
- 一个表达/迁移验证；
- 一个生活或精力护栏；
- 清理 1–3 条已经失去价值的待办或来源。

## 月度重构（45–60 分钟）

按信号重构，不按日历强行改目录：

| 信号 | 动作 |
|---|---|
| 多个近义节点重复 | 提议 merge，列明会失去的边界 |
| 一个节点包含多个问题 | 提议 split |
| 新证据长期冲突 | 标为争议或 correct |
| 结论过期且有替代 | deprecate 并重定向 |
| 节点长期无复用且无目标关系 | 降级归档，不必删除 |
| 某缺口有充分证据 | 标为已补齐并总结迁移条件 |

合并、拆分、修正、废弃必须生成补丁预览并由用户确认。

## 指标

指标只用于发现系统问题，不做自我惩罚。

优先：

- `闭环率`：已融合或仅归档来源 / 已处理来源；
- `补丁应用率`：已应用 / 已生成补丁；
- `证据转化率`：产生实际证据的完成行动 / 完成行动；
- `复用次数`：节点在项目、面试或决策中被调用；
- `陈旧缺口`：高影响但连续两周无行动的缺口；
- `重复模式`：同类生活问题再次发生且实验未调整。

不把总来源数、总字数、总节点数当成功指标。

## 求职期默认周模板

```text
本周市场信号：多份 JD/面经共同改变了什么判断？
项目证据：新增了哪项可展示结果？
能力缺口：最值得补的 1–3 项是什么？
表达验证：哪段回答说清了/没说清？
生活护栏：什么在消耗时间或精力？
下周主线：
保温项：
暂缓项及重启条件：
```

## 复习调度

只为高价值节点设置复查：

- 1 天：能否复述核心机制；
- 7 天：能否给出边界、反例和迁移；
- 30 天：是否在真实场景产生证据；
- 事件触发：面试、项目评审、购买决策前优先复习。

复查成功不等于“看完”；需要先检索后对照。
