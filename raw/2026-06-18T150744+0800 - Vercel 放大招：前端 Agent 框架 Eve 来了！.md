认真努力的小四子 *2026年6月18日 08:33*

**Vercel** 刚刚发布了一个新东西： `eve` 。

它不是一个普通的聊天机器人 **SDK** ，也不是一个简单的工具调用封装，而是一个开源 **AI Agent** 框架！

![图片](https://mmbiz.qpic.cn/mmbiz_png/7YalpHdlCY8NNDBunIewoJ3HFA6Eu2oxss1KkyiaecswMgWW6YbcxicicicGsv3RQ3E63WVlk2OYq8RP628X107PDwwO6mh0icfvqYUiaOwX3oUzo/640?wx_fmt=png&from=appmsg&tp=webp&wxfrom=5&wx_lazy=1#imgIndex=0)

如果只看一句话介绍， `Eve` 是一个用来构建、运行、扩展 AI Agent 的开源框架。

Vercel 官方在发布文章里直接把它放进了自己的 `Agent Stack` ，并且强调它内置了持久化执行、沙箱计算、人工审批、子 Agent、评测等生产级能力。

![图片](https://mmbiz.qpic.cn/sz_mmbiz_png/7YalpHdlCY8nWdeVoCBd5SGLOibmcjIsydAWGsMhn0nB1Z2xgDFxAra33H6UNB859ZpglCcxslInj1zGwSAQ9aqYVoJRMfto0e7CpzGeeVWI/640?wx_fmt=png&from=appmsg&tp=webp&wxfrom=5&wx_lazy=1#imgIndex=1)

过去大家做 **Agent** ，很多时候都是从 **Demo** 开始： `接一个模型，写几个工具函数，加一段 Prompt，再套一个聊天界面` 。

看起来能跑，但真要上线，问题马上就来了：

- 任务中断怎么办？
- **Agent** 调了什么工具怎么追踪？
- 危险操作怎么审批？
- 多入口怎么接？
- `Slack、GitHub、Linear、Teams` 怎么整合？
- 模型换了之后怎么回归测试？

这些东西以前都要自己拼。

`Eve` 想解决的就是这部分脏活。

## 一个 Agent，就是一个目录

`Eve` 最核心的设计非常前端化：

```
An agent is a directory
```

一个 **Agent** ，本质上就是一个目录。

官方给出的结构大概是这样：

```
agent/
  agent.ts
  instructions.md
  tools/
    run_sql.ts
    post_chart.ts
  skills/
    revenue-definitions.md
  subagents/
    investigator/
  channels/
    slack.ts
  schedules/
    monday-summary.ts
```

这个结构一眼就能看懂：

`agent.ts` 配模型， `instructions.md` 写角色和规则， `tools` 放工具能力， `skills` 放知识和流程， `subagents` 放子 Agent， `channels` 决定它跑在哪， `schedules` 决定它什么时候自动执行。

这套设计很像前端开发熟悉的约定式框架。

以前 `Next.js` 把路由、渲染、部署这些东西收进框架里，现在 `Eve` 想把 Agent 的工具、记忆、审批、评测、部署也收进一套目录结构里。

这就是 Vercel 最擅长的打法：把复杂工程问题变成文件约定。

## 快速上手 Eve

官方已经开放了 **public preview** ，初始化一个项目很简单：

```
npx eve@latest init my-agent
```

如果你想在已有项目里接入：

```
npm install eve@latest
```
![图片](data:image/svg+xml,%3C%3Fxml version='1.0' encoding='UTF-8'%3F%3E%3Csvg width='1px' height='1px' viewBox='0 0 1 1' version='1.1' xmlns='http://www.w3.org/2000/svg' xmlns:xlink='http://www.w3.org/1999/xlink'%3E%3Ctitle%3E%3C/title%3E%3Cg stroke='none' stroke-width='1' fill='none' fill-rule='evenodd' fill-opacity='0'%3E%3Cg transform='translate(-249.000000, -126.000000)' fill='%23FFFFFF'%3E%3Crect x='249' y='126' width='1' height='1'%3E%3C/rect%3E%3C/g%3E%3C/g%3E%3C/svg%3E)

初始化之后，核心文件一般从这两个开始：

```
agent/
  agent.ts
  instructions.md
```

`agent.ts` 用来定义模型：

```
import { defineAgent } from "eve";

export default defineAgent({
  model: "anthropic/claude-opus-4.8",
});
```

`instructions.md` 就是这个 **Agent** 的系统提示词：

```
你是一个高级数据分析助手。

回答问题时优先使用准确数据。
如果能通过工具计算，就不要凭感觉回答。
涉及金额、日期、筛选条件时，需要说明假设。
```

然后启动本地开发服务：

```
eve dev
```

这一步会进入一个终端交互界面，你可以直接和 **Agent** 对话，并且看到它加载了哪些 `skill` 、调用了哪些 `tool` 、执行到了哪一步。

官方文章里提到， `Eve` 的 TUI 会把每一步执行过程展示出来，同时这些步骤也是可 checkpoint 的持久化会话。

## 给 Agent 加一个工具

`Eve` 的工具就是一个 TypeScript 文件。

比如你想让 Agent 获取天气，可以新建：

```
agent/tools/get_weather.ts
```

示例代码可以这样写：

```
import { defineTool } from"eve/tools";
import { z } from"zod";

exportdefault defineTool({
  description: "获取指定城市的天气信息",
  inputSchema: z.object({
    city: z.string().describe("城市名称"),
  }),
async execute({ city }) {
    return {
      city,
      weather: "晴",
      temperature: "26°C",
    };
  },
});
```

文件放进去之后， `Eve` 会在构建时自动发现这个工具。你不用再写一堆注册逻辑，也不用手动把工具塞给模型。

这点很关键。

以前很多 Agent 项目写到最后，代码里全是胶水逻辑：注册工具、维护 schema、拼上下文、处理权限、接日志。 `Eve` 直接把这些统一成目录和文件。

## Skill：把业务知识文件化

除了工具， `Eve` 还有一个很实用的设计： `skills` 。

工具负责“能做什么”， `skill` 负责“知道什么”。

比如你要让 Agent 理解公司内部的收入定义，可以写：

```
agent/skills/revenue-definitions.md
```

内容类似：

```
---
description: 回答收入相关问题前需要加载这份规则
---

收入按退款后的净收入计算。
周维度统计以 UTC 时间为准。
所有试用账号和内部测试账号需要排除。
```

这样 Agent 在遇到收入问题时，就能按这份规则回答。

这比把所有业务知识都塞进一个巨大 Prompt 里更合理，也更适合长期维护。规则变了，改文件；加新知识，新增 markdown；需要 review，直接走 Git diff。

## 真正面向生产的部分

`Eve` 这次最值得关注的不是“又一个 Agent SDK”，而是它把生产环境里最麻烦的几个问题都放进来了。

首先是 **持久化执行** 。Agent 经常不是一问一答就结束，它可能要等人工审批、等接口返回、跑长任务，甚至执行好几小时。 `Eve` 把每次会话做成 durable workflow，每一步都会 checkpoint，所以任务可以暂停、恢复，甚至部署之后继续跑。

其次是 **沙箱执行** 。Agent 写出来的代码不能直接丢到应用运行时里跑，风险太大。 `Eve` 会给 Agent 一个独立 sandbox，用来执行 shell、脚本、文件读写等操作。本地可以跑在 Docker、microsandbox 或 just-bash 上，部署到 Vercel 时会切到 `Vercel Sandbox` 。

还有 **人工审批** 。比如 SQL 扫描超过 50GB、写生产数据、删除资源、触发外部系统，这些操作都可以加 `needsApproval` 。Agent 执行到这里会暂停，等人确认后再继续。

这就是 Agent 真正上生产必须面对的问题。

Demo 里最重要的是“能不能跑”，生产环境里最重要的是“能不能管”。

## 子 Agent、评测、部署也都有

`Eve` 还支持 `subagents` 。

子 Agent 本质上也是一个目录，可以有自己的 `agent.ts` 、 `instructions.md` 、 `tools` 和 sandbox。父 Agent 可以把任务交给子 Agent，子 Agent 做完之后再把结果返回。官方示例里，数据分析 Agent 可以把异常调查任务交给 investigator 子 Agent。

评测也被文件化了。

你可以写：

```
evals/revenue.eval.ts
```

然后用：

```
eve eval
```

跑回归测试。这样换模型、改 Prompt、加工具之前，都能先测一遍，避免上线之后才发现 Agent 行为变了。官方提到， `eve eval` 可以本地运行，也可以指向已经部署的应用。

部署则更 Vercel 风格：

```
vercel deploy
```

官方说， `Eve` Agent 就是一个普通 Vercel 项目，部署时不用额外配置基础设施；同一个目录在本地和线上保持一致，sandbox 会自动切换到 Vercel Sandbox。

## 接入 Slack 也很简单

Agent 不能只活在命令行里，真正有价值的 Agent 往往要进入团队工作流。

比如 Slack、Discord、Teams、Telegram、GitHub、Linear。

在 `Eve` 里，Channel 也是一个文件。

添加 Slack：

```
eve channels add slack
```

它会生成：

```
agent/channels/slack.ts
```

部署之后，这个 Agent 就可以在 Slack 里工作。官方还提到， `Eve` 默认开启 HTTP API，同时内置 Slack、Discord、Teams、Telegram、Twilio、GitHub、Linear 等 Channel。

这点很重要。

因为很多团队内部 Agent，最后都不是给网页用的，而是给 Slack、Linear、GitHub Issue、告警系统、客服系统用的。 `Eve` 把这些入口都做成 adapter，Agent 本身不用重复写一套。

## Vercel 自己已经在用了

官方说，他们内部已经有超过 100 个 Agent 在生产环境运行，而且这些 Agent 正在参与公司日常运营。

比如数据分析 Agent 每月处理超过 30000 个问题，销售 Agent 自动跟进线索，支持 Agent 处理工单，内容 Agent 做文章审核，还有一个路由 Agent 负责把请求分发给合适的 Agent。

更夸张的是部署数据。

一年前，由 Agent 触发的 Vercel 部署不到 3%；现在已经接近 29%。Vercel 预计，很快会有一半部署来自 Agent。

这基本说明了 Vercel 的判断：

未来的软件开发，不只是人点按钮、人写代码、人部署。Agent 会越来越多地参与开发、分析、测试、支持、运营和交付。

## 前端开发为什么要关注 Eve？

因为这东西很可能会把 Agent 开发带进前端熟悉的工程体系里。

![图片](data:image/svg+xml,%3C%3Fxml version='1.0' encoding='UTF-8'%3F%3E%3Csvg width='1px' height='1px' viewBox='0 0 1 1' version='1.1' xmlns='http://www.w3.org/2000/svg' xmlns:xlink='http://www.w3.org/1999/xlink'%3E%3Ctitle%3E%3C/title%3E%3Cg stroke='none' stroke-width='1' fill='none' fill-rule='evenodd' fill-opacity='0'%3E%3Cg transform='translate(-249.000000, -126.000000)' fill='%23FFFFFF'%3E%3Crect x='249' y='126' width='1' height='1'%3E%3C/rect%3E%3C/g%3E%3C/g%3E%3C/svg%3E)

以前做 Agent，很多后端、AI Infra、平台工程能力都要自己补。现在 Vercel 直接给出了一套前端开发看得懂的方式：

```
目录结构
TypeScript
Markdown
Git
Preview Deploy
CI
Vercel Deploy
Slack / GitHub / Linear Channel
```

这套路径对前端太熟了。

`Next.js` 当年把页面、路由、接口、渲染、部署串起来； `Eve` 现在想把模型、工具、知识、审批、沙箱、评测、部署串起来。

所以这次发布的重点不只是一个新框架，而是一个信号：

**Agent 开发开始进入框架化阶段了。**

以前拼的是谁的模型更强，谁的 Prompt 更花，谁的 Demo 更炫。

接下来真正拉开差距的，可能是工程化能力：能不能稳定运行，能不能安全执行，能不能追踪每一步，能不能接入团队系统，能不能像正常软件一样测试、部署和回滚。

`Eve` 就是 Vercel 对这个方向的一次下注。
