
白天的目标不要是“学很多”，而是：

> 保持工作主线 + 顺手积累材料。

比如 AI coding 跑的时候，只允许做三类事：

1. 记录当前项目问题：今天修了什么、踩了什么坑、可写进简历什么。
2. 看一张面试卡片：如 FastAPI 依赖注入、SQL 索引、事务隔离级别。
3. 整理一个问题清单：晚上再深学。

不要在白天打开小说、视频号、长篇 blog。它们会直接打断你的工作-学习状态。


关键不是你每天学到 12 点，而是**每天晚上 19:20 能启动**。

你现在 8 点多才开始，已经损失了最容易进入状态的时间段。建议把晚上主学习开始时间提前到 **19:20 - 19:40** 之间。

先学习再娱乐

### P0：实习产出 + 项目深挖

这是你简历和面试最直接的材料。

每天至少记录一个东西：

> 今天修了什么问题？  
> 涉及什么技术点？  
> 面试官问起来我怎么讲？

例如：

- MCP 工具如何设计？
- 能耗统计口径如何统一？
- 异常检测规则怎么做？
- FastAPI + SQLAlchemy 查询怎么优化？
- 部署时 Nginx / Docker / mcp-remote 起什么作用？

这些比泛泛看 blog 更有价值。

### P1：面试基础

每天只需要一个小块，不要贪多。

比如：

- Python 八股 1 个点
- SQL 题 2 道
- 后端场景题 1 个
- 项目问答 1 个

你现在的问题不是资源不够，而是输入太多、输出太少。

### P2：blog / 技术文章

blog 不是不能看，但要带任务看。

不要这样看：

> 看到一篇不错的文章，点进去看，看着看着累了。

改成：

> 我今天只看一篇，目标是提取 3 个可迁移到项目 / 面试的点。

格式可以固定为：

```
文章标题：核心观点：和我项目的关系：可以写进面试回答的一句话：是否值得深读：是 / 否
```

### P3：娱乐

娱乐可以保留，但不能放在关键学习前面。

建议规则：

> 王者只能放在当天主学习完成之后。  
> 中午不打。  
> 晚上最多 1-2 把。  
> 输了不补偿性再开。



**每个概念能用一句话定义 + 一个工程例子 + 一个坑点**。


### Agent 场景题骨架

> 需求是什么 → 是否需要 Agent → 用什么工具 → 状态/记忆怎么维护 → 任务怎么拆 → 工具怎么调用 → 如何防幻觉 → 如何评估 → 如何控制成本和延迟 → 如何保证安全。

示例题：

|题目|你要答出的关键词|
|---|---|
|设计一个指标异常分析 Agent|指标查询工具、异常检测、归因、报告生成、人审|
|设计一个智能客服 Agent|意图识别、知识库 RAG、订单工具、人工转接、权限|
|设计一个代码生成 Agent|仓库上下文、文件工具、测试工具、权限、回滚、trace|
|Agent 和 Workflow 区别|确定流程 vs 模型自主决策；稳定性、成本、可控性权衡|
|Multi-Agent 是否必要|多角色分工有用，但会增加通信成本、错误传播和调试难度|

### 后端场景题骨架

> 现象 → 根因 → 单机方案 → 分布式方案 → 高并发优化 → 数据一致性 → 失败补偿 → 监控告警。

示例题：

|题目|你要答出的关键词|
|---|---|
|超卖|原子扣减、Redis 预扣、MQ 异步、唯一索引、补偿|
|重复支付回调|幂等表、唯一流水号、状态机、乐观锁|
|缓存击穿|互斥锁、逻辑过期、热点 key 永不过期|
|缓存一致性|先更新 DB 再删缓存、延迟双删、binlog 订阅|
|MQ 重复消费|幂等 key、消费记录表、业务唯一索引|
|订单超时取消|延迟队列、定时扫描、状态机校验|
|大文件导入|分片、异步任务、批量写入、失败行记录|
|慢 SQL|explain、索引、覆盖索引、分页优化、归档|
