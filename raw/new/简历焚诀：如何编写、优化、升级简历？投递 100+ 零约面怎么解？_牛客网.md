## 如何编写简历

一份正规的简历一般包括基本信息、教育经历、实习/工作经历、项目经历、专业/职业/个人技能、(自我评价/介绍 /个人优势)、(荣誉奖项及其他经历/个人荣誉)、(开源项目)，下面我来分点讲解一下各个部分

> 有一定经验的 uu 可以直接针对性地看自己需要的部分，或者直接看“简历条目通用的核心要点”部分

## 【基本信息】

| 要素 | 重要程度 | 备注 |
| --- | --- | --- |
| 姓名 | 必选 |  |
| **电话** | 必选 |  |
| **邮箱** | 必选 | **企业中邮箱用的多，而且最好用高级点的邮箱** ，比如 gmail、outlook、163 等 |
| **求职意向 (意向岗位)** | 推荐 | 建议放上去 |
| **照片** | **自己权衡** |  |
| **Github 地址** | 可选 | 最低要求：Github 主页至少要有 **能看得过去的、README 完善** 的项目 |
| 年龄 | 可选 | 年龄特别小或者特别大的就不要写了 |
| 工作年限 | 可选 | 适用于社招 |
| 个人所在地/期望城市 | 可选 |  |
| 期望薪资 | 可选 | 技术面简历不推荐有这个要素，万一出现薪资倒挂，面试官心理可能不平衡；但同时也可以利用这点筛选掉薪资不符合你预期的公司 |
| 目前状况 | 可选 | 在职/离职 |

- 学历、专业、毕业学校推荐放到“教育经历”模块
- **关于照片**
	- 不要贴照片的说法
		- “除非长得特别帅，否则不要贴照片”
		- 贴照片的说法
		- “长得好看就贴照片，长相在某些时候可能加分”
				- 照片要拍得正式、得体、精神
- 期望薪资
	- 不推荐写，除非对薪资有明确硬性的高要求；加上之后可能一定程度减少面试机会
- **荣誉奖项、证书**
	> ps：也可以专门开一个模块，看个人排版和奖项数目了

## 【教育经历】

- **学历推荐单独放在这里，不要放到基本信息，方便 HR 阅读**
	> 有的同学可能觉得学历不太行，要不直接合并到基础信息 没有那么显眼？ 个人不推荐，学历信息基本是每个 HR 的必读项，遮遮掩掩没有意义 只能骗骗自己，不如大方展示出来
- 就读时间具体到月份

## 【实习/工作经历】

| 基本组成 | 重要程度 | 备注 |
| --- | --- | --- |
| **实习公司 (+部门)** | 必选 |  |
| **实习持续时间** | 必选 |  |
| 实习岗位 | 必选 |  |
| 背景 | 推荐 | 简要阐明项目背景/项目描述，简历上呈现1-2行 |
| **项目难点/个人职责** | 必选 | Star 法则编写 |
| 技术栈 | 可选 |  |
| 实习收获 | 可选 | 通常不用写，你在个人职责中写的东西就可以表明自己的主要收获；   实习收获主观性强，对面试官参考价值不大 |

- 排序方式：近期的实习放前面
- 社招注意点
	- 工作经历中的公司不要跨省，给人不稳定的感觉
		- 空窗期和跳槽频率：
		- 如果空窗期短，可以适当延迟上一份工作的离职时间
				- 如果空窗期长，要填补中间缺失的时间

## 【专业/职业/个人技能】

- 如何编写专业技能：
	- 可以使用 **精通/熟练/熟悉/了解** 之类的词汇来组织语言
		- \==把最核心、最自信的、理解原理的技术 **放在前面/加粗** ==
		- 两个极端
		- **太简单** ：不要简单罗列技术名词， **要体现对技术的理解和应用能力、技术栈的深度** （同时也能利用这点引导面试官提问自己擅长的技术点）
			> 比如写 Redis 的专业技能时，可以这么写：
			> 
			> “Redis：熟悉 Redis **五大数据类型** ， **缓存一致性，缓存雪崩 击穿 穿透** 及其解决方案，缓存淘汰策略，持久化方式等”
			> 
			> **让面试官知道你学习到了/掌握到了什么程度、什么深度**
				- **太详细** ：太过详细、过于复杂，会让关键技能信息被掩盖。
			> 反面示例： ![image_1782273833274](https://blog-hazenix-top.oss-cn-heyuan.aliyuncs.com/7991f566-6ffd-4499-a44d-3de0fca6df9b.png)
		- 控制篇幅：
		- 在这个模块中体现自己熟悉的技术栈，但不宜占用太多篇幅， **还是要靠项目经历展现自己的技术深度**
				- 一些非核心的专业技能直接在项目经历里面体现， 不需要单独浪费一个条目的空间写在专业技能里面
		- 诚信问题：写在简历上的专业技能必须能聊，不然就别写，否则就不只是技术问题了 面试官可能觉得你人品也差点意思
		- **做好分类** ，不要让面试官找（Java 基础、并发编程、JVM、MySQL……)
		- 不建议写 **精通** ，如果写了精通，面试官就会不断地针对这个点提问（当然如果很强当我没说👍👍）

> **可以不放这个模块吗？**
> 
> 如果你的项目经历里面足够很好体现技术栈/专业技能了，可以不加这个模块

## 【项目经验/经历】

| 基本组成 | 重要程度 | 备注 |
| --- | --- | --- |
| 项目名称 | 必选 | **项目名字高大上点** ，不要写 xx 管理系统；避免项目名大众化；（有些 uu 直接用的知识星球/b 站的项目 还直接用原名，我觉得名字至少要改掉吧😅） |
| **项目简介/描述/背景** | 可选 | 如果简历空间不是很紧张，建议放上去；   简单描述项目是做什么的，一定要压缩，简历上呈现为1-2行【项目内容，解决方案，最终结果】 |
| **项目难点/个人职责** | 必选 | **一个能放到简历上的项目一定要有难点和亮点** ；而不是只有功能和技术栈的堆砌、不是“技术自嗨”   一般 4-5 条 |
| 技术栈 | 可选 | 最好和应聘公司的技术栈匹配 |
| 项目持续时间 | **可选** |  |
| 个人收获 | 可选 | **通常是可以不用写个人收获的** ，因为你在个人职责中写的东西就可以表明自己的主要收获；   而且个人收货主观性强，对面试官参考价值不大 |
|  |  |  |

- 要点
	- 越 **熟悉的项目** 放到越前面（问的最多，第二个项目可能都不会问）
		- **不太建议放的项目** ：不熟悉的项目、和现有项目重复度太高的项目
		- **项目数量** ：个人项目 **在精不在多** 放两个能打的足矣，面试官一般主要问第一个/感兴趣的那个，放多了意义不大（有了实习之后可以适当减少个人项目）
		- 一条工作描述 **尽量不要超过两行** ，对于大的功能模块可以适当分多个子条
		- **个人职责最好三条以上** ，不然让人觉得你只做了边缘功能、没有参与到核心
		- **项目中要融合自己掌握的技术栈、展示自己掌握的技术栈**
		- **使用 Star 法则编写项目难点/个人职责**
		- **尽量避免全是性能优化或者问题排查相关的个人职责介绍，也要避免存业务性介绍过多** ，性能优化和问题排查方向上的亮点面试之前比较容易准备，但也不要都是性能优化相关的，这种也算是一个极端

在项目经历中体现自己解决问题的能力、体现业务深度和技术深度，在和面试官交流的过程中 展示自己的思考

## (自我评价/介绍 /个人优势)

> **不推荐写，因为简历空间宝贵，而且大部分人写的都是空话、并且“主观评价”对于面试官和 HR 没有参考价值** 但如果要写，那就要写好

1. **不要写废话、不要喊口号**
	> 比如个人能力强、编码能力强、沟通能力强、吃苦耐劳，没有事件和数据支撑
2. 如果要写，写确实有含金量的内容：
	- P 线：可以在这里提现自己的业务能力 经验、源码能力等，或者 做过和公司业务项目类似的项目； M 线：可以在这里体现自己的管理能力 经验
		- 不能写比较虚的， 没有数据或事件支撑的空话（比如勤奋、吃苦耐劳、热爱开发、学习能力强）
		- **要求有实例/数据支撑；不能太谦虚，不能太自大**
		- 用简洁的语言 **突出自己的特点和优势**
		- **参考角度**
		- 文档编写能力、学习能力、沟通能力、团队协作能力
				- 对待工作的态度以及个人的责任心
				- 能承受的工作压力以及对待困难的态度
				- 对技术的追求、对代码质量的追求
				- 分布式、高并发系统开发或维护经验
				- 架构、源码能力（为什么开源项目做出了贡献）
				- 业务领域的知识（有 xx 年的电商经验，主导过 QPS 到达 xxx 的营销系统）
				- 管理能力（ 有 xxx 年的管理经验，领导过 xx 人的团队）

## (荣誉奖项及其他经历/个人荣誉)

- 如果没有拿得出手的/奖项不多，没必要单独给一个模块，直接不写/放到 基本信息/教育经历里面
	- **含金量比较高的竞赛** ：ACM、某个企业的大赛 (面这个企业的时候可能加分)、蓝桥杯国奖、Kaggle 等；
		> 如果有这类含金量较高的比赛，可以将这个模块前置
- 奖项要有选择的呈现：选择含金量最高的1-3个呈现即可
- 作品集、证书、有价值的校园经历也可以放这里呈现
- \==如果有人工智能相关的比赛项目一定要写上去，面试官特别喜欢问==
	> 腾讯开悟人工智能挑战赛等

## (开源项目)

> 可选

如果有比较有价值的个人开源项目或者自己参与过开源项目，可以放在这里

## 简历条目通用的核心要点

- 两忌
	```java
	* ==忌内容堆砌，不聚焦==；**信息精简化，逻辑清晰、突出重点**，体现出个人竞争力；能打动面试官的只有关键的话
	 
	  > 如果写太多会显得自己总结提炼能力不行；严禁一大坨逻辑混乱、没有重点的文字描述
	```
	- \==忌描述空洞，不量化；== 很多简历的描述流于表面，套话太多，不落实处
- **简历条目要具体、但不能冗余** ： 简历条目要具体、避免模糊描述，但也要注意精简语言 （避免堆砌技术词，并省略不必要的描述）
- **建议使用star原则书写简历条目**
	> 腾讯 HR 在简历辅导直播中多次强调的点，可以让简历条目更规范、逻辑更清晰（详见下文“STAR 法则详解”）
- **简历要突出自身优势** ：
	- 各个模块该加粗的地方加粗，放大个人优势（自己编辑哦熟悉）
		- 扬长避短、尽量不要写短板
		- 放大价值感：你做的这件事情给公司带来了什么样的 **结果、价值**
		- 如果有学历/大厂实习经历，该加粗加粗、该增加篇幅增加篇幅
		- 突出符合该岗位招聘关键词的 核心经验和核心技能
- **关于简历排版的一些细节** ：
	- 中文和数字英文之间加上 **空格** 的话看起来会舒服一点
		- 不要使用 左右排布 的简历模板
		- **不能出现错别字** ，技术名词按照 **大小写规范** （和官网保持一致）
		- 简历当中整体字体大小保持一致、粗细保持一致(除了要加粗的)、段落间距保持一致
- **简历的命名细节** ：姓名+岗位+电话 (+工作年限) —— **简历导出之后不要直接发送，好的命名会给人更好的印象，减轻人事的压力**
- 简历在投递绝大部分公司时都是通用的，但也不要投递每一家公司都一成不变，可以== **适当根据不同的企业和岗位进行调整和优化，以更满足企业的要求** ==
- 补充：现在有些同学可能会使用 AI 辅助，但是 AI 味浓厚的话会降低真实性、降低筛选通过率，推荐使用 humanizer-zh 这个 SKILL 去一下 AI 味、同时自己做二次润色

#### STAR 法则详解

1. Situation：项目背景，当时具体是什么项目背景或遇到了什么问题
	> 项目背景部分编写条目的时候可以省略，可以选择在具体讲述的时候和面试官说清楚项目背景
2. Task：任务，你要完成的目标是什么
3. **Action(重点)** ：行动，你具体做了什么、怎么做的
4. **Result(重点)** ：结果，最终达成了什么样的效果，==要尽可能量化、用数字说话== （错误做法：使用“显著提升”“极大提高了 xxx”这种字眼描述结果）
- 示例
	- 在 xxx (场景)，用 xxx (技术) 解决了 xx (问题)，实现了什么结果 (或带来了什么价值)
		- 负责用户登录功能开发，使用 JWT 和 Redis 实现退出登录和黑名单功能 => 针对高并发场景下 Session 服务器压力大的问题（S），设计并实现无状态用户认证中心（T），采用 JWT + Redis 双 Token 机制，结合拦截器统一校验，支持安全登出与黑名单（A），单机 QPS 从 800 提升至 3000，接口响应时间降低至 30ms 以内（R）
		- 对菜品查询接口使用 Redis 做了缓存优化 => 负责接口性能优化（T），对菜品查询引入多级缓存，并使用 xxx 处理缓存雪崩与穿透（A），优化后响应时间降至 80ms，数据库查询量下降约 70%（R）
		- ……

## HR 是如何筛选简历的

我理解 HR 筛选简历有几个考量：

1. 是否和岗位 JD 匹配（ **合适程度** ）
2. 候选人是否稳定（ **稳定程度** ）
	> 就算候选人再合适，如果没有丝毫稳定性、有可能干不了几天就跑了，HR 也是不会招进来的
3. 候选人能力、竞争力

对于实习生来说：

- 会看学历、是否有实习经历、每段实习的实习时间
- 看技术是否匹配岗位，如果技术没问题、有可能会看看你做的项目的类型，如果正好和公司当前在做的项目匹配、就有可能优先招聘
- 看是否有量化的数据
- 是否有加分项：github 作品、博客……

对于社招：

- 还会看空窗期、跳槽频率、工作城市等影响社招生稳定性的因素

## 简历到底一页还是两页？

一般情况下，没有两段及以上实习的同学建议写一页，观感好、加分，符合“简历”二字中的“简”；

> 如果你没有实习，但是写了超过一页，可能需要反思一下自己是否放了一些 含金量不高/面试官通常不会问 的条目到简历上，或者使用的工具不太行、导致排版有问题， **简历上的空间非常宝贵** 以上两种情况都建议删掉冗余部分，整理成一页

当然，有的同学可能含金量高的东西很多、一页确实放不下，简历写两页也是合理的

最后， **简历其实没有标准答案** ，仁者见仁、智者见智，一切都是为了提高简历筛选通过率，朋友们如果有更多建议和技巧欢迎在评论区补充🫶， *希望能对大家有点帮助*
