# Wiki 入口页模板

## 使用规则

- 只初始化空白页；已有正文先读取并做合并预览，不覆盖。
- 动态区块从 Base 的真实记录生成；没有数据就写“尚未产生”，不编造节点。
- 首页保持一屏到两屏，详细内容放子节点或 Base 视图。
- 模板正文使用飞书文档支持的简洁标题、段落、列表和链接。

## 00｜知识生长首页

```markdown
# 个人知识生长系统

这不是收藏夹。每条重要信息都要回答：它改变了什么认知、连接了什么旧知识、将通过什么行动验证。

## 当前主线
- 阶段目标：2027 秋招与项目能力证明
- 本周主要矛盾：尚未填写
- 本周唯一交付：尚未填写

## 最关键缺口
从“成长缺口”读取影响度和紧迫度最高、状态未完成的最多 3 条。

## 待确认补丁
从“知识补丁”读取状态为“待确认”的最多 5 条。

## 本周行动
从“行动与验证”读取本周截止、状态未完成的最多 5 条。

## 最近生长
列出最近已应用的 3–5 份补丁及目标节点。

## 使用入口
- 先存：只进来源收件箱
- 融合：连接旧知识并生成补丁
- 确认：批准后更新 Wiki
- 复盘：检查闭环、缺口和下一主线
```

## 四个模型入口页

四页共用结构，只替换问题和准入标准。

```markdown
# <模型名>

## 本模型回答
<世界：外部事物为何运作；能力：要做到什么并如何证明；自我：我在什么情境下反复如何反应；实践：怎样把理解变成结果。>

## 当前稳定节点
仅列状态为“稳定”或“生长中”且近期会复用的节点。

## 争议与待验证
列出冲突节点、低置信结论和计划中的验证。

## 新节点准入
只有回答稳定问题、具有复用价值并已产生真实知识增量时才创建子节点。
```

自我模型入口额外写明：单个事件不形成稳定人格判断；情境模式需重复证据、反例和实验。

## 90｜系统说明

```markdown
# 系统说明

## 核心闭环
来源 → 找连接 → AI 压缩 → 用户关键判断 → 知识补丁 → 确认应用 → 行动验证 → 复盘重构

## 数据职责
- Wiki：当前最佳解释
- Base：来源、关系、历史、目标、缺口和行动
- Skill：分析与写入协议

## 不变量
- 来源不覆盖
- 补丁只追加
- Wiki 通过已确认补丁更新
- 自我模型从暂定假设开始
- 重复且无新增量时允许 NoOp

## 成功标准
不是保存多少，而是有多少重要知识被复用、验证并改变了决策或能力。
```
