# 飞书信息架构

## 存储职责

- Wiki：人日常阅读的“当前最佳解释”，允许经批准的 Patch 局部更新。
- Base：来源、节点索引、补丁历史、目标、缺口、行动及其关系。
- Skill：分析和写入协议。不能把仅存在于对话上下文的结论当作已入库。

## Wiki 树

```text
个人知识生长系统
├─ 00｜知识生长首页
├─ 10｜当前阶段
│  └─ 2027秋招与当前行动主线
├─ 20｜世界模型
├─ 30｜能力模型
├─ 40｜自我模型
├─ 50｜实践模型
└─ 90｜系统说明
```

四个模型节点是入口，不要求所有知识直接写在入口页。只有当一个稳定问题已经累计足够内容或会被反复调用时，才创建子节点。

首页只展示：当前主线、最关键 3 个缺口、本周行动、待确认补丁、最近生长节点。不要做全库导航大全。

## 最小关系图

```text
来源 -> 补丁 -> 知识节点
                 |
目标 -> 缺口 -> 行动 -> 验证结果
          \_______关联知识_______/
```

不要增加“标签表”“人物表”“平台表”等辅助表，除非真实使用中出现至少三次重复管理问题。

## 数据不变量

- 来源内容不覆盖，只追加更完整转写或勘误说明。
- 补丁不修改旧记录；状态字段除外。
- 知识节点稳定 ID 不随标题修改。
- Wiki 当前结论与“知识节点.当前结论”保持简短同步。
- 一个缺口可关联多个岗位和来源；不要按岗位复制。
- 任何 Wiki 结论都能追溯到一个或多个已应用补丁。
