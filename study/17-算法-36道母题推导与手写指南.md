## 二、固定恢复脚本的实际写法

每道题都按下面七步推进：

1. **澄清：** 输入输出是什么？连续还是任意选择？返回下标还是数值？能否修改输入？
2. **模拟：** 用一个三到五个元素的小样例手动计算答案。
3. **暴力：** 先说最直接的枚举方法和复杂度。
4. **找瓶颈：** 哪一步被重复执行？是重复查找、重复计算，还是枚举了无效状态？
5. **匹配模型：** 根据哈希、连续区间、单调性、树图结构、重复子问题等信号选工具。
6. **说不变量：** 每轮循环结束后，哪些事实始终成立？递归函数到底返回什么？
7. **写骨架并检查：** 先写初始化、遍历、更新、返回，再展开代码，最后测空输入、重复值和边界位置。

面试时可以直接这样说：

> 我先给一个直接方案。它需要……，复杂度是……。瓶颈在于反复……。题目具有……结构，所以我用……维护……。每轮结束后始终保证……。我先写初始化和状态更新，再用边界样例检查。

不要背完整字符，而要记代码中不可缺少的结构：

## M01｜1. 两数之和

### 先自己回答

- 暴力解要枚举什么？
- 扫描到当前数字时，真正需要查询的是什么？
- 为什么要先查哈希表，再把当前元素放进去？

### 用恢复脚本推导

直接方案是枚举所有下标对 `(i, j)`，判断两数和，时间 `O(n²)`。瓶颈是：对每个数 `x`，都在剩余数组里重复寻找 `target-x`。

哈希表能把“这个补数以前是否出现过”降为平均 `O(1)`。扫描到 `x` 时，表中只保存左侧已经处理过的数，因此命中补数后天然对应两个不同下标。

不变量是：处理下标 `i` 前，`seen` 包含且只包含 `0..i-1` 的值和下标。

### 代码脊柱

```text
seen = {}
遍历 i, x：
    complement = target - x
    如果 complement 在 seen：返回两个下标
    记录 x 的下标
```

### Python 实现

```python
def two_sum(nums: list[int], target: int) -> list[int]:
    seen: dict[int, int] = {}

    for i, x in enumerate(nums):
        complement = target - x
        if complement in seen:
            return [seen[complement], i]
        seen[x] = i

    return []
```

### 走样例与检查

`nums=[2, 7, 11, 15], target=9`。先记录 `2:0`；扫描到 7 时补数为 2，命中并返回 `[0,1]`。

重点检查 `[3,3], target=6`。先查后存可确保使用两个不同位置。复杂度是时间 `O(n)`、空间 `O(n)`。

### 面试一句话

> 暴力解重复查找补数，我用哈希表保存左侧元素；扫描当前值时先查补数再登记当前下标，从而在线性时间内得到答案。

## M02｜560. 和为 K 的子数组

### 先自己回答

- 为什么有负数时不能直接使用普通滑动窗口？
- 若当前前缀和为 `s`，需要寻找什么历史前缀和？
- 为什么计数表初始化为 `{0: 1}`？

### 用恢复脚本推导

暴力解枚举子数组起点和终点，并计算区间和，至少 `O(n²)`。连续区间和提示前缀和：下标 `j` 处前缀和为 `s`，若此前某处前缀和为 `s-k`，两者之间的区间和就是 k。

同一个前缀和可能出现多次，每一次都对应一个不同子数组，所以哈希表保存的不是单个下标，而是出现次数。负数会使窗口和增减没有单调性，因此不能靠“和大了左移、和小了右移”解决。

不变量是：处理当前前缀和之前，`count` 记录所有历史前缀和的出现次数。

### 代码脊柱

```text
count = {0: 1}
prefix = answer = 0
遍历每个数：
    更新 prefix
    answer += count[prefix - k]
    count[prefix] += 1
```

### Python 实现

```python
from collections import defaultdict


def subarray_sum(nums: list[int], k: int) -> int:
    count = defaultdict(int)
    count[0] = 1
    prefix = 0
    answer = 0

    for x in nums:
        prefix += x
        answer += count[prefix - k]
        count[prefix] += 1

    return answer
```

### 走样例与检查

`nums=[1,1,1], k=2`。前缀和依次为 1、2、3；到 2 时寻找 0，到 3 时寻找 1，共得到 2 个答案。

初始化 `count[0]=1` 代表数组开始前的空前缀，使从下标 0 开始的区间也能被统计。复杂度为时间 `O(n)`、空间 `O(n)`。

### 面试一句话

> 连续区间和可以写成两个前缀和之差，我统计历史前缀和 `prefix-k` 的出现次数，并在登记当前前缀和之前累加答案。

## M03｜15. 三数之和

### 先自己回答

- 排序带来了什么可利用的单调性？
- 固定第一个数后，剩下是什么经典问题？
- 哪三个位置需要去重？

### 用恢复脚本推导

三重循环是 `O(n³)`。如果先排序并固定第一个数 `nums[i]`，剩余目标变为 `-nums[i]`，问题退化为有序数组两数之和。左右指针之和过小时左移，过大时右移，能排除整批不可能的组合。

结果要求按数值去重，所以固定数重复时跳过；找到答案后，左右指针也要跨过相同值。

不变量是：对固定的 `i`，`left..right` 是尚未被单调性排除的候选区间。

### 代码脊柱

```text
排序
枚举 i，并跳过重复固定值
left = i + 1, right = n - 1
根据三数和移动左右指针
命中后记录，并跳过两侧重复值
```

### Python 实现

```python
def three_sum(nums: list[int]) -> list[list[int]]:
    nums.sort()
    answer: list[list[int]] = []
    n = len(nums)

    for i in range(n - 2):
        if i > 0 and nums[i] == nums[i - 1]:
            continue
        if nums[i] > 0:
            break

        left, right = i + 1, n - 1
        while left < right:
            total = nums[i] + nums[left] + nums[right]
            if total < 0:
                left += 1
            elif total > 0:
                right -= 1
            else:
                answer.append([nums[i], nums[left], nums[right]])
                left += 1
                right -= 1
                while left < right and nums[left] == nums[left - 1]:
                    left += 1
                while left < right and nums[right] == nums[right + 1]:
                    right -= 1

    return answer
```

### 走样例与检查

`[-1,0,1,2,-1,-4]` 排序为 `[-4,-1,-1,0,1,2]`。固定 -1 后，双指针分别找到 `[-1,-1,2]` 和 `[-1,0,1]`；第二个 -1 作为固定值时跳过。

主要错误是只去重 `i`，却遗漏命中后的左右去重。时间 `O(n²)`，额外空间取决于排序实现。

### 面试一句话

> 排序后固定一个数，把三数问题转成有序两数之和；双指针按和的大小单调移动，并分别处理固定值和两侧的重复。

## M04｜3. 无重复字符的最长子串

### 先自己回答

- 为什么答案一定可以用一个连续窗口维护？
- 遇到重复字符时，左端应该移动到哪里？
- 为什么更新左端要取 `max`？

### 用恢复脚本推导

暴力解枚举所有子串再检查重复，至少 `O(n²)`。题目要求连续区间，右端逐步扩张时，只有新字符与窗口内已有字符冲突才需要调整左端。

记录每个字符最近出现的位置。若当前字符上次出现在窗口内，左端直接跳到该位置后一位。旧记录可能位于窗口左侧，因此左端只能右移，不能被拉回。

不变量是：处理完 `right` 后，窗口 `[left,right]` 内没有重复字符。

### 代码脊柱

```text
last = {}
left = answer = 0
遍历 right, char：
    left = max(left, last[char] + 1)
    更新 last[char]
    更新窗口长度
```

### Python 实现

```python
def length_of_longest_substring(s: str) -> int:
    last: dict[str, int] = {}
    left = 0
    answer = 0

    for right, char in enumerate(s):
        if char in last:
            left = max(left, last[char] + 1)
        last[char] = right
        answer = max(answer, right - left + 1)

    return answer
```

### 走样例与检查

`abba`：第二个 b 使 `left` 跳到 2；最后一个 a 的历史位置 0 已在窗口外，`max(left,1)` 保持 left 为 2，不能退回 1。

空串自然返回 0。时间 `O(n)`，空间 `O(字符集大小)`。

### 面试一句话

> 我用滑动窗口维护无重复区间，并记录字符最近位置；重复时把左端跳到上次位置后一位，同时用 `max` 保证左端不回退。

## M05｜76. 最小覆盖子串

### 先自己回答

- “覆盖”为什么必须记录字符次数，而不仅是集合？
- 右指针和左指针分别承担什么职责？
- 什么时候窗口从可行变为不可行？

### 用恢复脚本推导

枚举所有子串并检查覆盖是 `O(n²)` 甚至更高。题目要求最短连续区间：右端用于补齐缺失字符，一旦窗口可行，左端就应尽量收缩。

使用 `need` 保存窗口还欠每个字符多少个，`missing` 保存总共还欠多少个字符。加入一个仍然缺少的字符时，`missing` 减一；移出字符后若 `need` 变为正数，说明窗口重新缺少它。

不变量是：`missing==0` 当且仅当当前窗口覆盖 t 的全部字符及次数。

### 代码脊柱

```text
need = Counter(t), missing = len(t)
右端逐个加入字符
missing == 0 时：
    更新最短答案
    左端移出字符并判断是否重新缺失
```

### Python 实现

```python
from collections import Counter


def min_window(s: str, t: str) -> str:
    if not t:
        return ""

    need = Counter(t)
    missing = len(t)
    left = 0
    best_start = 0
    best_length = float("inf")

    for right, char in enumerate(s):
        if need[char] > 0:
            missing -= 1
        need[char] -= 1

        while missing == 0:
            length = right - left + 1
            if length < best_length:
                best_start = left
                best_length = length

            left_char = s[left]
            need[left_char] += 1
            if need[left_char] > 0:
                missing += 1
            left += 1

    if best_length == float("inf"):
        return ""
    return s[best_start:best_start + best_length]
```

### 走样例与检查

`s="ADOBECODEBANC", t="ABC"`。右端第一次覆盖 ABC 时得到 `ADOBEC`，随后左缩到即将丢失 A；后面再次可行并收缩，最终得到 `BANC`。

检查 `t` 含重复字符，例如 `AABC`，仅使用集合会误判。时间 `O(|s|+|t|)`。

### 面试一句话

> 右端负责把窗口扩到可行，左端负责在可行时收缩；我用欠缺计数和 `missing` 精确表示窗口是否覆盖目标的全部字符次数。

## M06｜53. 最大子数组和

### 先自己回答

- 若最优子数组必须以当前位置结尾，它只有哪两种来源？
- 为什么全负数组不能把初值设为 0？

### 用恢复脚本推导

枚举所有连续区间是 `O(n²)`。考虑“必须以当前位置结尾”的最优答案：要么只取当前数重新开始，要么把当前数接到以前一位置结尾的最优子数组后面。

这给出状态转移 `end_here=max(x,end_here+x)`。它只依赖前一个状态，可以压缩到常数空间；全局答案另外维护。

不变量是：处理完 `x` 后，`end_here` 是以 x 结尾的最大和，`best` 是所有已处理结尾中的最大和。

### 代码脊柱

```text
用首元素初始化 end_here 和 best
从第二个数开始：
    end_here = max(x, end_here + x)
    best = max(best, end_here)
```

### Python 实现

```python
def max_sub_array(nums: list[int]) -> int:
    end_here = nums[0]
    best = nums[0]

    for x in nums[1:]:
        end_here = max(x, end_here + x)
        best = max(best, end_here)

    return best
```

### 走样例与检查

`[-2,1,-3,4,-1,2,1,-5,4]`：到 4 时抛弃此前负贡献重新开始，随后累加到 `4,-1,2,1`，最大和为 6。

检查 `[-3,-2,-5]`，答案应为 -2 而不是 0。时间 `O(n)`、空间 `O(1)`。

### 面试一句话

> 我定义“必须以当前位置结尾”的最大和，它要么从当前数重新开始，要么延续前一状态，再额外维护全局最大值。

## M07｜56. 合并区间

### 先自己回答

- 为什么必须先按起点排序？
- 排序后，新区间为什么只需和结果中的最后一个区间比较？

### 用恢复脚本推导

未排序时，每个区间可能与任意其他区间重叠，关系混乱。按起点升序后，如果当前区间与已合并结果发生重叠，它只能接在最后一个区间上；若它的起点已经大于最后区间的终点，就不可能再与更早区间重叠。

不变量是：`merged` 始终按起点有序、内部互不重叠，并完整覆盖已经扫描过的区间。

### 代码脊柱

```text
按起点排序
遍历区间：
    结果为空或不重叠：追加
    否则：扩大最后区间的右端点
```

### Python 实现

```python
def merge_intervals(intervals: list[list[int]]) -> list[list[int]]:
    intervals.sort(key=lambda interval: interval[0])
    merged: list[list[int]] = []

    for start, end in intervals:
        if not merged or start > merged[-1][1]:
            merged.append([start, end])
        else:
            merged[-1][1] = max(merged[-1][1], end)

    return merged
```

### 走样例与检查

`[[1,3],[2,6],[8,10],[15,18]]`：前两个区间合并为 `[1,6]`，后两个分别追加。

闭区间 `[1,4]` 和 `[4,5]` 也重叠，因此判断不重叠使用 `start > last_end`。时间由排序主导，为 `O(n log n)`。

### 面试一句话

> 按起点排序后，当前区间只可能与结果最后一段重叠；我维护一个已经有序且互不重叠的结果列表，逐个合并或追加。

## M08｜206. 反转链表

### 先自己回答

- 修改 `cur.next` 前为什么必须保存什么？
- `prev` 和 `cur` 分别代表哪一段？

### 用恢复脚本推导

链表只能沿 `next` 向后访问。若直接执行 `cur.next=prev`，原来的后继节点会丢失，所以必须先保存 `nxt=cur.next`。

每轮把当前节点从未处理部分摘下，接到已反转部分前面。更新顺序固定为“保存后继—反转指针—推进 prev—推进 cur”。

不变量是：`prev` 是已经反转完成的前半段头节点，`cur` 是尚未处理部分的首节点。

### 代码脊柱

```text
prev = None, cur = head
while cur：
    保存 nxt
    cur.next 指向 prev
    prev、cur 各向前推进
返回 prev
```

### Python 实现

```python
# ListNode 由题目环境提供
def reverse_list(head):
    prev = None
    cur = head

    while cur:
        nxt = cur.next
        cur.next = prev
        prev = cur
        cur = nxt

    return prev
```

### 走样例与检查

`1 -> 2 -> 3`。第一轮得到 `1 -> None`，cur 指向 2；第二轮得到 `2 -> 1`；最终 prev 指向 3。

空链表自然返回 None，单节点链表原样返回。时间 `O(n)`、空间 `O(1)`。

### 面试一句话

> 我维护已反转部分的头节点 prev 和未处理部分的首节点 cur，每次先保存后继，再改变当前节点的指向。

## M09｜21. 合并两个有序链表

### 先自己回答

- 为什么虚拟头节点能减少分支？
- 循环结束后为什么可以一次性连接剩余链表？

### 用恢复脚本推导

两条链表都已经有序，因此剩余部分的最小节点必然是两个当前头节点中较小者。每次选择它接到结果尾部并推进对应链表。

虚拟头节点让第一次连接和后续连接完全一致，不需要单独决定结果头。某条链表耗尽后，另一条剩余部分已经有序且全部不小于当前结果尾部，可直接连接。

不变量是：`tail` 之前是已合并的有序部分，`list1` 和 `list2` 指向各自未处理部分。

### 代码脊柱

```text
dummy, tail
两条链表都非空时：
    连接较小节点
    推进对应链表和 tail
连接剩余链表
返回 dummy.next
```

### Python 实现

```python
def merge_two_lists(list1, list2):
    dummy = ListNode(0)
    tail = dummy

    while list1 and list2:
        if list1.val <= list2.val:
            tail.next = list1
            list1 = list1.next
        else:
            tail.next = list2
            list2 = list2.next
        tail = tail.next

    tail.next = list1 if list1 else list2
    return dummy.next
```

### 走样例与检查

`1->2->4` 与 `1->3->4`：依次选择 1、1、2、3，第一条剩下 4、第二条剩下 4，继续选择后再连接剩余部分。

检查一条链表为空的情况，虚拟头模板无需新增分支。时间 `O(m+n)`、空间 `O(1)`。

### 面试一句话

> 两条链表有序，所以每次只需连接当前较小头节点；虚拟头节点统一第一次连接，最后直接接上未耗尽的有序尾部。

## M10｜19. 删除链表的倒数第 N 个节点

### 先自己回答

- 如何把“倒数第 N 个”转换为两个指针之间的距离？
- 为什么需要虚拟头节点？

### 用恢复脚本推导

直接方案是先遍历得到链表长度，再第二次遍历到正数第 `length-n` 个前驱节点，能做但需要两遍。

一遍做法是让 `fast` 先走 n 步，再让 `fast` 和 `slow` 同时前进。两者始终相差 n 个节点，当 `fast` 到达末尾节点时，`slow` 正好位于待删除节点的前驱。两指针从 dummy 出发，可以统一删除头节点的场景。

不变量是：同步移动阶段，`fast` 始终领先 `slow` n 个节点。

### 代码脊柱

```text
dummy.next = head
fast = slow = dummy
fast 先走 n 步
while fast.next：两者同走一步
slow.next = slow.next.next
返回 dummy.next
```

### Python 实现

```python
def remove_nth_from_end(head, n: int):
    dummy = ListNode(0, head)
    fast = dummy
    slow = dummy

    for _ in range(n):
        fast = fast.next

    while fast.next:
        fast = fast.next
        slow = slow.next

    slow.next = slow.next.next
    return dummy.next
```

### 走样例与检查

`1->2->3->4->5, n=2`。fast 先走到 2；同步移动至 fast 为 5 时，slow 为 3，删除 slow.next 即节点 4。

检查单节点链表且 `n=1`，slow 保持在 dummy，能正确删除头节点。时间 `O(n)`、空间 `O(1)`。

### 面试一句话

> 我让快指针先走 n 步，再与慢指针同步移动，始终保持 n 个节点的间距；快指针到尾部时，慢指针正位于待删除节点前驱。

## M11｜142. 环形链表 II

### 先自己回答

- 快慢指针为什么有环时一定会相遇？
- 相遇后为什么一个指针回到头节点，再同速前进就会在入口相遇？

### 用恢复脚本推导

使用集合记录访问节点能在线性时间找入口，但需要 `O(n)` 空间。Floyd 算法用慢指针一步、快指针两步：若无环，快指针到空；若有环，快指针进入环后会不断缩短与慢指针的环上距离，最终相遇。

设头到入口距离为 a，入口到第一次相遇点距离为 b，环剩余距离为 c。相遇时快指针比慢指针多走若干整环，可推出 a 与从相遇点继续走到入口的距离同余。因此一个指针回到头，另一个留在相遇点，同速前进会在入口相遇。

### 代码脊柱

```text
slow = fast = head
寻找第一次相遇；若 fast 到空则无环
finder = head
finder 与 slow 每次走一步
再次相遇即入口
```

### Python 实现

```python
def detect_cycle(head):
    slow = head
    fast = head

    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow is fast:
            break
    else:
        return None

    finder = head
    while finder is not slow:
        finder = finder.next
        slow = slow.next

    return finder
```

### 走样例与检查

`3->2->0->-4`，尾节点指回节点 2。第一阶段快慢指针在环中相遇；第二阶段 finder 从 3 出发，slow 从相遇点出发，最终同在节点 2。

比较节点身份使用 `is`，而不是比较值。无环、空链表和单节点自环都要检查。时间 `O(n)`、空间 `O(1)`。

### 面试一句话

> Floyd 第一阶段用速度差判断并找到环内相遇点，第二阶段让头指针与相遇点指针同速前进，根据路程关系，它们会在环入口相遇。

## M12｜23. 合并 K 个升序链表

### 先自己回答

- 顺序两两合并的最坏复杂度为什么会变高？
- 堆中需要保存每条链表的多少个节点？

### 用恢复脚本推导

每次扫描 K 条链表的头节点找最小值会产生 `O(NK)`。小根堆可以在 `O(log K)` 内取得当前最小值。

因为每条链表有序，只需把每条链表当前最小的未处理节点放入堆。弹出一个节点后，它所在链表的下一个节点才有资格成为候选。

不变量是：堆中最多有 K 个节点，分别代表各未耗尽链表的最小未处理节点。

### 代码脊柱

```text
各链表非空头节点入堆
反复弹出最小节点接到结果
该节点有 next 时，把 next 入堆
```

### Python 实现

```python
import heapq
from itertools import count


def merge_k_lists(lists):
    heap = []
    sequence = count()

    for node in lists:
        if node:
            heapq.heappush(heap, (node.val, next(sequence), node))

    dummy = ListNode(0)
    tail = dummy

    while heap:
        _, _, node = heapq.heappop(heap)
        tail.next = node
        tail = node
        if node.next:
            heapq.heappush(heap, (node.next.val, next(sequence), node.next))

    return dummy.next
```

### 走样例与检查

三条链表头为 1、1、2，堆先弹出其中一个 1，再把它的后继放入；全过程堆只保存每条链表的前沿节点。

Python 元组值相同时会继续比较下一项，因此加入唯一序号，避免比较 `ListNode`。总节点数 N、链表数 K，时间 `O(N log K)`、堆空间 `O(K)`。

### 面试一句话

> 每条链表有序，所以堆中只保留 K 个当前头节点；每次弹出全局最小节点，并把它的后继补入堆，总复杂度是 `O(N log K)`。

## M13｜25. K 个一组翻转链表

### 先自己回答

- 翻转一组前必须先确定哪两个边界？
- 为什么局部反转时可以把 `prev` 初始化为下一组首节点？

### 用恢复脚本推导

难点不在普通反转，而在分组边界与重连。对每组先从 `group_prev` 向后寻找第 K 个节点 `kth`；找不到说明不足一组，直接结束。保存 `group_next=kth.next` 后，反转半开区间 `[group_start, group_next)`。

把 `prev` 初始化为 `group_next`，本组原首节点在第一次改变指针时就会连接到下一组。反转完成后，再让上一组尾部指向新组头，并把旧组头设为新的 `group_prev`。

不变量是：`group_prev` 之前的所有组已经正确翻转并连接。

### 代码脊柱

```text
dummy, group_prev
寻找本组 kth；不足 k 个则结束
保存 group_next 和旧组头
以 prev=group_next 反转本组
连接新组头，group_prev 移到旧组头
```

### Python 实现

```python
def reverse_k_group(head, k: int):
    dummy = ListNode(0, head)
    group_prev = dummy

    while True:
        kth = group_prev
        for _ in range(k):
            kth = kth.next
            if not kth:
                return dummy.next

        group_next = kth.next
        group_start = group_prev.next

        prev = group_next
        cur = group_start
        while cur is not group_next:
            nxt = cur.next
            cur.next = prev
            prev = cur
            cur = nxt

        group_prev.next = kth
        group_prev = group_start
```

### 走样例与检查

`1->2->3->4->5, k=2`。第一组边界是 1、2，next 为 3，翻转后得到 `2->1->3`；group_prev 移到旧组头 1。第二组处理 3、4，节点 5 不足一组保持不变。

重点检查 k=1、链表长度恰好是 k、最后不足 k。时间 `O(n)`、空间 `O(1)`。

### 面试一句话

> 我先确定每组第 K 个节点和下一组首节点，再反转这个半开区间；用下一组首节点初始化 prev 可以在反转时直接接好后半段。

## M14｜146. LRU 缓存

### 先自己回答

- 为什么单独使用字典或普通链表都不能满足两个操作 `O(1)`？
- 双向链表两端分别表示什么？

### 用恢复脚本推导

字典能 `O(1)` 找节点，却不知道谁最久未使用；链表能维护新旧顺序，但单链表无法在已知节点时 `O(1)` 删除其前驱。组合“字典 + 双向链表”即可同时满足定位、删除、移动和淘汰。

使用两个哨兵节点：左侧之后是最旧项，右侧之前是最新项。任何 `get` 命中或 `put` 更新，都把节点移到右端；超容量时删除左端真实节点。

不变量是：链表从左到右按使用时间由旧到新排列，字典与链表节点一一对应。

### 代码脊柱

```text
Node(key, value, prev, next)
remove(node)
add_recent(node)
get：定位，移动到最近端
put：更新或新增；超容量淘汰最旧端
```

### Python 实现

```python
class Node:
    def __init__(self, key=0, value=0):
        self.key = key
        self.value = value
        self.prev = None
        self.next = None


class LRUCache:
    def __init__(self, capacity: int):
        self.capacity = capacity
        self.nodes: dict[int, Node] = {}
        self.left = Node()   # 最旧端哨兵
        self.right = Node()  # 最新端哨兵
        self.left.next = self.right
        self.right.prev = self.left

    def _remove(self, node: Node) -> None:
        node.prev.next = node.next
        node.next.prev = node.prev

    def _add_recent(self, node: Node) -> None:
        previous = self.right.prev
        previous.next = node
        node.prev = previous
        node.next = self.right
        self.right.prev = node

    def get(self, key: int) -> int:
        if key not in self.nodes:
            return -1
        node = self.nodes[key]
        self._remove(node)
        self._add_recent(node)
        return node.value

    def put(self, key: int, value: int) -> None:
        if key in self.nodes:
            node = self.nodes[key]
            node.value = value
            self._remove(node)
            self._add_recent(node)
            return

        node = Node(key, value)
        self.nodes[key] = node
        self._add_recent(node)

        if len(self.nodes) > self.capacity:
            least_recent = self.left.next
            self._remove(least_recent)
            del self.nodes[least_recent.key]
```

### 走样例与检查

容量 2：`put(1,1), put(2,2), get(1), put(3,3)`。`get(1)` 后顺序从旧到新为 2、1，所以插入 3 时淘汰键 2。

常见错误是链表删除后忘记同步删除字典，或更新已有键时未移动为最近使用。所有操作平均 `O(1)`，空间 `O(capacity)`。

### 面试一句话

> 字典负责常数时间定位，双向链表负责常数时间删除和移动；链表左端最旧、右端最新，访问后移到右端，超容量淘汰左端。

## M15｜94. 二叉树的中序遍历

### 先自己回答

- 中序遍历的访问顺序是什么？
- 用显式栈模拟递归时，节点为什么要沿左链入栈？

### 用恢复脚本推导

递归写法直接体现“左—根—右”，但迭代写法更能暴露栈的作用。某节点不能立即访问，因为必须先完成其左子树，所以沿左链把节点依次压栈；无法再向左时，弹出最近节点访问，再转向它的右子树。

不变量是：栈中节点尚未访问，但其左侧路径已经被展开；栈顶是下一个应访问节点。

### 代码脊柱

```text
cur = root, stack = []
while cur 或 stack：
    沿左链入栈
    弹出并访问
    转到右子树
```

### Python 实现

```python
def inorder_traversal(root) -> list[int]:
    answer = []
    stack = []
    cur = root

    while cur or stack:
        while cur:
            stack.append(cur)
            cur = cur.left

        cur = stack.pop()
        answer.append(cur.val)
        cur = cur.right

    return answer
```

### 走样例与检查

树 `2` 的左子为 1、右子为 3：先压入 2、1，弹出访问 1，再访问 2，最后转向并访问 3。

外层条件必须是 `cur or stack`，否则 cur 为空但栈还有节点时会提前结束。时间 `O(n)`、空间 `O(h)`。

### 面试一句话

> 中序要求先左后根，我用栈保存回溯路径：不断压入左链，弹出节点访问，再进入右子树。

## M16｜102. 二叉树的层序遍历

### 先自己回答

- 为什么使用队列而不是栈？
- 如何区分当前层与下一层？

### 用恢复脚本推导

按距离根节点由近到远访问是 BFS，因此使用先进先出的队列。每轮开始时，队列中现有节点全部属于当前层；先记录 `level_size=len(queue)`，只弹出这些节点，新加入的孩子留给下一轮。

不变量是：一轮开始时，队列前 `level_size` 个节点恰好构成同一层。

### 代码脊柱

```text
根节点入队
while queue：
    记录当前长度
    弹出这么多个节点组成一层
    将其孩子入队
```

### Python 实现

```python
from collections import deque


def level_order(root) -> list[list[int]]:
    if not root:
        return []

    queue = deque([root])
    answer = []

    while queue:
        level = []
        for _ in range(len(queue)):
            node = queue.popleft()
            level.append(node.val)
            if node.left:
                queue.append(node.left)
            if node.right:
                queue.append(node.right)
        answer.append(level)

    return answer
```

### 走样例与检查

根 3，孩子 9、20，20 的孩子 15、7。第一轮长度 1，第二轮长度 2，第三轮长度 2，输出 `[[3],[9,20],[15,7]]`。

注意 Python 的 `range(len(queue))` 在进入 for 前固定次数，新入队节点不会在本层被处理。时间 `O(n)`，空间最坏 `O(n)`。

### 面试一句话

> 我用 BFS 队列逐层访问，每轮先固定当前队列长度，只处理这一批节点，新加入的孩子自然属于下一层。

## M17｜98. 验证二叉搜索树

### 先自己回答

- 为什么只检查父节点与左右孩子会出错？
- 一个节点的合法范围来自哪里？

### 用恢复脚本推导

仅检查 `left.val < root.val < right.val` 不够，因为右子树深处的节点也必须大于根，左子树深处也必须小于根。祖先约束需要沿递归路径继续传递。

定义 `dfs(node, low, high)`：判断整棵子树的所有值是否严格位于开区间 `(low, high)`。进入左子树时把当前值设为新上界，进入右子树时设为新下界。

不变量是：递归到某节点时，low 和 high 汇总了所有祖先对它的约束。

### 代码脊柱

```text
空节点合法
当前值不在 (low, high) 则失败
左子树使用 (low, val)
右子树使用 (val, high)
```

### Python 实现

```python
def is_valid_bst(root) -> bool:
    def validate(node, low, high) -> bool:
        if not node:
            return True
        if not low < node.val < high:
            return False
        return (
            validate(node.left, low, node.val)
            and validate(node.right, node.val, high)
        )

    return validate(root, float("-inf"), float("inf"))
```

### 走样例与检查

根 5，右子 6，6 的左子 3。3 虽小于父节点 6，但它位于根 5 的右子树，递归下界仍为 5，因此判错。

BST 要求严格不等，重复值非法。时间 `O(n)`、递归空间 `O(h)`。

### 面试一句话

> 节点是否合法取决于整条祖先路径，而不只是父节点；我递归传递开区间上下界，进入左右子树时分别收紧边界。

## M18｜105. 从前序与中序遍历序列构造二叉树

### 先自己回答

- 前序遍历提供什么信息，中序遍历提供什么信息？
- 为什么递归时必须先构造左子树？

### 用恢复脚本推导

前序顺序是“根—左—右”，所以尚未消费的第一个前序值就是当前根。根在中序数组中的位置，把当前中序区间分成左子树与右子树。

若每次线性查找根在中序中的位置，总复杂度会退化到 `O(n²)`；预先建立值到下标的映射可降为 `O(1)`。因为前序接下来先出现左子树节点，所以必须先递归左区间，再递归右区间。

递归契约是：`build(left,right)` 构造中序闭区间对应的子树，并按需消费前序节点。

### 代码脊柱

```text
建立 inorder 值到下标映射
preorder_index = 0
build(left, right)：
    空区间返回 None
    取下一个前序值为根
    根据中序位置先建左，再建右
```

### Python 实现

```python
def build_tree(preorder: list[int], inorder: list[int]):
    inorder_index = {value: i for i, value in enumerate(inorder)}
    preorder_index = 0

    def build(left: int, right: int):
        nonlocal preorder_index
        if left > right:
            return None

        root_value = preorder[preorder_index]
        preorder_index += 1
        root = TreeNode(root_value)

        middle = inorder_index[root_value]
        root.left = build(left, middle - 1)
        root.right = build(middle + 1, right)
        return root

    return build(0, len(inorder) - 1)
```

### 走样例与检查

`preorder=[3,9,20,15,7]`，`inorder=[9,3,15,20,7]`。先取 3 为根，中序将左区间分为 `[9]`、右区间分为 `[15,20,7]`；随后按前序顺序先构造 9。

节点值必须唯一才能直接建立映射。时间 `O(n)`、映射与递归空间 `O(n)`。

### 面试一句话

> 前序的下一个值确定当前根，中序位置划分左右子树；我用哈希表定位中序下标，并按前序顺序先递归构造左子树。

## M19｜543. 二叉树的直径

### 先自己回答

- 最长路径为什么不一定经过根节点？
- 递归向父节点返回什么，局部又用什么更新全局答案？

### 用恢复脚本推导

若对每个节点分别计算左右深度，会重复遍历子树。后序递归可以在一次遍历中同时完成：先得到左右子树深度，经过当前节点的路径边数就是 `left_depth+right_depth`。

但是向父节点延伸时不能同时选择左右两边，只能返回其中较深的一侧再加当前节点。因此这类树题有两个量：递归返回值与全局答案更新值。

递归契约是：`depth(node)` 返回从当前节点向下的最大节点深度；全局直径用 `left+right` 更新。

### 代码脊柱

```text
diameter = 0
depth(node)：
    空节点返回 0
    后序得到 left、right
    diameter = max(diameter, left + right)
    返回 1 + max(left, right)
```

### Python 实现

```python
def diameter_of_binary_tree(root) -> int:
    diameter = 0

    def depth(node) -> int:
        nonlocal diameter
        if not node:
            return 0

        left = depth(node.left)
        right = depth(node.right)
        diameter = max(diameter, left + right)
        return 1 + max(left, right)

    depth(root)
    return diameter
```

### 走样例与检查

根 1，左子 2、右子 3，节点 2 又有孩子 4、5。节点 2 处局部路径为 4—2—5，长度 2；根处可得到 4—2—1—3，长度 3。

题目按边数计数，所以空节点深度为 0 时，`left+right` 直接是边数。时间 `O(n)`、空间 `O(h)`。

### 面试一句话

> 后序递归返回单侧最大深度供父节点使用，同时用左右深度之和更新经过当前节点的全局最长路径。

## M20｜236. 二叉树的最近公共祖先

### 先自己回答

- 递归函数应该返回布尔值、目标节点，还是最终答案？
- 左右子树都返回非空时说明什么？

### 用恢复脚本推导

从根向下直接判断目标在哪一侧，会反复搜索。后序递归可以让每棵子树把“我找到了 p、q 或它们的祖先”向上传递。

当前节点为空或就是 p/q 时返回自身。若左右递归都非空，说明两个目标分居两侧，当前节点是第一次汇合处；若只有一侧非空，就继续把那一侧结果向上传。

递归契约是：`dfs(node)` 返回当前子树中找到的目标节点或最近公共祖先；什么都没找到返回空。

### 代码脊柱

```text
空节点或命中 p/q：返回当前节点
left = dfs(left), right = dfs(right)
两侧非空：返回当前节点
否则返回非空一侧
```

### Python 实现

```python
def lowest_common_ancestor(root, p, q):
    if not root or root is p or root is q:
        return root

    left = lowest_common_ancestor(root.left, p, q)
    right = lowest_common_ancestor(root.right, p, q)

    if left and right:
        return root
    return left if left else right
```

### 走样例与检查

若 p 在当前节点左子树、q 在右子树，左右递归均非空，当前节点就是答案。若 p 本身是 q 的祖先，递归到 p 时直接返回 p，并一路上传。

题目保证 p、q 存在。若不保证，需要额外统计命中数，不能看到单侧非空就断定答案有效。时间 `O(n)`、空间 `O(h)`。

### 面试一句话

> 我让每棵子树返回找到的目标或已有祖先；左右都非空说明目标在两侧，当前节点就是最低汇合点，否则继续向上传递非空结果。

## M21｜200. 岛屿数量

### 先自己回答

- 什么时候可以确定发现了一座新岛？
- DFS/BFS 的作用是计数，还是消除同一连通块的重复计数？

### 用恢复脚本推导

逐格扫描时，每遇到一块尚未访问的陆地，就发现了一个新的连通块，答案加一。随后从这里 DFS/BFS，把上下左右相连的整座岛都标记为已访问，避免后续扫描再次计数。

可以额外使用 `visited`，也可以原地把访问过的 `"1"` 改成 `"0"`，后者更简洁但会修改输入。

不变量是：扫描位置之前的所有陆地都已经归入某个被计数的岛屿。

### 代码脊柱

```text
双重遍历网格
遇到陆地：答案加一
从该位置 DFS 四方向，把整块陆地标记掉
```

### Python 实现

```python
def num_islands(grid: list[list[str]]) -> int:
    if not grid:
        return 0

    rows, cols = len(grid), len(grid[0])

    def flood(row: int, col: int) -> None:
        if not (0 <= row < rows and 0 <= col < cols):
            return
        if grid[row][col] != "1":
            return

        grid[row][col] = "0"
        flood(row + 1, col)
        flood(row - 1, col)
        flood(row, col + 1)
        flood(row, col - 1)

    answer = 0
    for row in range(rows):
        for col in range(cols):
            if grid[row][col] == "1":
                answer += 1
                flood(row, col)

    return answer
```

### 走样例与检查

扫描到一片 2×2 相连陆地的第一个格子时答案加一，flood 会把另外三个全部改成水，之后扫描不会再次计数。

先判越界，再访问网格。大网格可能触发 Python 递归深度限制，面试追问时可改用显式栈。时间 `O(mn)`、空间最坏 `O(mn)`。

### 面试一句话

> 每遇到一块未访问陆地就发现一个新连通块，我立即用 DFS 淹没整座岛，从而保证每个格子只处理一次。

## M22｜994. 腐烂的橘子

### 先自己回答

- 为什么所有初始腐烂橘子必须同时入队？
- BFS 的一层为什么等于一分钟？

### 用恢复脚本推导

如果从每个腐烂橘子分别 BFS，会重复访问且无法表达“同时扩散”。把所有初始腐烂橘子作为第 0 层一起入队，就是多源 BFS；它们同时向外扩一层，恰好对应一分钟。

同时统计新鲜橘子数。新鲜橘子首次变腐烂时立即改状态并减一，防止被多个来源重复入队。

不变量是：每轮队列中现有节点都在同一分钟腐烂，下一轮节点将在下一分钟腐烂。

### 代码脊柱

```text
所有腐烂橘子入队，统计 fresh
while queue 且 fresh > 0：
    处理当前层
    腐烂相邻新鲜橘子并入队
    minutes += 1
最后检查 fresh
```

### Python 实现

```python
from collections import deque


def oranges_rotting(grid: list[list[int]]) -> int:
    rows, cols = len(grid), len(grid[0])
    queue = deque()
    fresh = 0

    for row in range(rows):
        for col in range(cols):
            if grid[row][col] == 2:
                queue.append((row, col))
            elif grid[row][col] == 1:
                fresh += 1

    minutes = 0
    directions = ((1, 0), (-1, 0), (0, 1), (0, -1))

    while queue and fresh > 0:
        for _ in range(len(queue)):
            row, col = queue.popleft()
            for dr, dc in directions:
                nr, nc = row + dr, col + dc
                if 0 <= nr < rows and 0 <= nc < cols and grid[nr][nc] == 1:
                    grid[nr][nc] = 2
                    fresh -= 1
                    queue.append((nr, nc))
        minutes += 1

    return minutes if fresh == 0 else -1
```

### 走样例与检查

网格中若有两个腐烂源，它们都在第 0 层；第一轮共同腐烂相邻格子，避免人为给某个源更早的时间。

若初始没有新鲜橘子，循环不执行并返回 0；若 fresh 仍大于 0 但队列为空，说明存在隔离区域，返回 -1。时间 `O(mn)`。

### 面试一句话

> 这是多个起点同时扩散的最短时间问题，我把所有初始腐烂橘子作为第 0 层做多源 BFS，每处理一层就过去一分钟。

## M23｜207. 课程表

### 先自己回答

- 先修关系 `[a,b]` 应该建立哪条方向的边？
- 为什么最终处理节点数不足说明图中有环？

### 用恢复脚本推导

课程依赖构成有向图。`[a,b]` 表示 b 完成后才能学 a，所以建边 `b -> a`，并增加 a 的入度。

所有入度为 0 的课程目前没有未完成前置，可以安全学习。学完后删除其出边，使后继入度减一。若最后仍有课程未处理，它们互相依赖形成环，没有任何节点能先开始。

不变量是：队列中的节点当前入度为 0，`processed` 统计已经从依赖图中移除的课程。

### 代码脊柱

```text
建邻接表 prerequisite -> course，统计入度
所有入度 0 课程入队
弹出课程，后继入度减一；变 0 时入队
比较 processed 与课程总数
```

### Python 实现

```python
from collections import deque


def can_finish(num_courses: int, prerequisites: list[list[int]]) -> bool:
    graph = [[] for _ in range(num_courses)]
    indegree = [0] * num_courses

    for course, prerequisite in prerequisites:
        graph[prerequisite].append(course)
        indegree[course] += 1

    queue = deque(i for i, degree in enumerate(indegree) if degree == 0)
    processed = 0

    while queue:
        course = queue.popleft()
        processed += 1
        for next_course in graph[course]:
            indegree[next_course] -= 1
            if indegree[next_course] == 0:
                queue.append(next_course)

    return processed == num_courses
```

### 走样例与检查

`numCourses=2, prerequisites=[[1,0]]`：0 入度为 0，先处理 0，再使 1 入度降为 0，最终处理两门。若再加入 `[0,1]`，两门入度都为 1，初始队列为空。

孤立课程也要计入 processed。时间 `O(V+E)`、空间 `O(V+E)`。

### 面试一句话

> 我把先修课指向后续课程，用 Kahn 拓扑排序不断处理入度为 0 的节点；若最终无法处理全部节点，剩余依赖中就存在环。

## M24｜46. 全排列

### 先自己回答

- 回溯树每一层做的决定是什么？
- 为什么需要 `used`，保存答案时为什么要复制 path？

### 用恢复脚本推导

每个排列有 n 个位置。回溯树的第 k 层决定第 k 个位置放哪个尚未使用的元素。选择一个元素后标记使用并递归，返回时撤销，尝试同层的其他选择。

`path` 是同一个可变列表，如果直接把它加入答案，后续撤销会改变已经保存的结果，所以必须保存副本。

不变量是：进入某层时，path 是一个合法排列前缀，used 与 path 中元素完全对应。

### 代码脊柱

```text
path, used
长度等于 n：保存副本
遍历所有未使用元素：
    选择并标记
    递归
    撤销选择和标记
```

### Python 实现

```python
def permute(nums: list[int]) -> list[list[int]]:
    answer = []
    path = []
    used = [False] * len(nums)

    def backtrack() -> None:
        if len(path) == len(nums):
            answer.append(path.copy())
            return

        for i, x in enumerate(nums):
            if used[i]:
                continue
            used[i] = True
            path.append(x)
            backtrack()
            path.pop()
            used[i] = False

    backtrack()
    return answer
```

### 走样例与检查

`[1,2,3]`：第一层选 1，第二层可选 2 或 3；完成 `[1,2,3]` 后撤销 3，再撤销 2，转而生成 `[1,3,2]`。

本题元素互不相同；若有重复元素且要求去重，需要排序并增加同层去重。时间 `O(n·n!)`。

### 面试一句话

> 回溯树每层确定排列的一个位置，我用 used 保证元素不重复选择，并在递归返回后撤销状态以探索其他分支。

## M25｜39. 组合总和

### 先自己回答

- 组合与排列的核心差别是什么？
- 为什么递归下一层传 `i` 而不是 `i+1`？

### 用恢复脚本推导

若像全排列一样每层从头选，会同时产生 `[2,3]` 与 `[3,2]`。组合不关心顺序，因此用 `start` 限制后续只能选择当前及右侧候选，统一生成一种顺序。

每个候选可重复使用，所以选择 `candidates[i]` 后，下一层仍从 i 开始；若每个数只能用一次才传 `i+1`。排序后，当前候选大于剩余目标时，后面更大的数都无需尝试。

不变量是：path 按候选下标非递减，remain 是尚未凑出的金额。

### 代码脊柱

```text
排序候选
backtrack(start, remain)
remain == 0：保存
从 start 枚举；大于 remain 时停止
选择后递归 i，再撤销
```

### Python 实现

```python
def combination_sum(candidates: list[int], target: int) -> list[list[int]]:
    candidates.sort()
    answer = []
    path = []

    def backtrack(start: int, remain: int) -> None:
        if remain == 0:
            answer.append(path.copy())
            return

        for i in range(start, len(candidates)):
            value = candidates[i]
            if value > remain:
                break
            path.append(value)
            backtrack(i, remain - value)
            path.pop()

    backtrack(0, target)
    return answer
```

### 走样例与检查

`candidates=[2,3,6,7], target=7`：选择 2 后仍可从 2 开始，得到 `[2,2,3]`；选择 7 直接得到 `[7]`。不会生成 `[3,2,2]`。

候选是正数，remain 才会不断下降并允许剪枝。复杂度为指数级。

### 面试一句话

> 组合不区分顺序，所以我用 start 限制后续选择范围；当前数允许复用，因此递归仍传当前下标 i，并用排序做提前剪枝。

## M26｜79. 单词搜索

### 先自己回答

- 递归状态至少要包含哪些信息？
- 为什么当前格必须在递归返回后恢复？

### 用恢复脚本推导

需要从每个可能的首字符出发尝试路径。状态由当前位置 `(row,col)` 和正在匹配的字符下标 `index` 决定。若越界、字符不匹配或当前格已在路径中，分支失败。

选择当前格后临时标记为已访问，再探索四个方向；该标记只对当前路径有效，所以无论分支成功还是失败，函数返回前都恢复原字符。

递归契约是：`search(row,col,index)` 判断能否从当前格开始匹配 `word[index:]`。

### 代码脊柱

```text
依次尝试每个起点
search(row, col, index)：
    index 到末尾则成功
    越界或字符不符则失败
    标记当前格
    搜索四方向的下一个字符
    恢复当前格并返回结果
```

### Python 实现

```python
def exist(board: list[list[str]], word: str) -> bool:
    rows, cols = len(board), len(board[0])

    def search(row: int, col: int, index: int) -> bool:
        if index == len(word):
            return True
        if not (0 <= row < rows and 0 <= col < cols):
            return False
        if board[row][col] != word[index]:
            return False

        original = board[row][col]
        board[row][col] = "#"
        found = (
            search(row + 1, col, index + 1)
            or search(row - 1, col, index + 1)
            or search(row, col + 1, index + 1)
            or search(row, col - 1, index + 1)
        )
        board[row][col] = original
        return found

    for row in range(rows):
        for col in range(cols):
            if search(row, col, 0):
                return True
    return False
```

### 走样例与检查

寻找 `ABCCED` 时，从 A 出发依次选择相邻 B、C、C；若某一步走入死路，恢复沿途格子，使其他路径仍可使用它们。

同一格不能在同一路径中复用，但不同起点可以使用，因此恢复不可遗漏。最坏时间约 `O(mn·3^L)`。

### 面试一句话

> 我从每个首字符起点做网格回溯，状态是位置和单词下标；当前格临时标记防止路径内复用，分支结束后恢复。

## M27｜34. 查找第一个和最后一个位置

### 先自己回答

- “找等于 target”为什么不足以直接得到边界？
- 左边界与右侧插入点分别是什么定义？

### 用恢复脚本推导

普通二分命中任意一个 target 后无法保证是边界。将问题改写为两个单调边界：第一个 `>= target` 的位置，以及第一个 `> target` 的位置。若前者确实等于 target，答案右边界就是后者减一。

统一采用左闭右开区间 `[left,right)`：答案始终在这个区间内。条件成立时收缩右端，否则移动左端到 `mid+1`。

### 代码脊柱

```text
first_ge(target)
first_gt(target)
left 越界或值不等于 target：[-1,-1]
否则返回 [left, upper - 1]
```

### Python 实现

```python
def search_range(nums: list[int], target: int) -> list[int]:
    def first_ge() -> int:
        left, right = 0, len(nums)
        while left < right:
            middle = (left + right) // 2
            if nums[middle] >= target:
                right = middle
            else:
                left = middle + 1
        return left

    def first_gt() -> int:
        left, right = 0, len(nums)
        while left < right:
            middle = (left + right) // 2
            if nums[middle] > target:
                right = middle
            else:
                left = middle + 1
        return left

    first = first_ge()
    if first == len(nums) or nums[first] != target:
        return [-1, -1]
    return [first, first_gt() - 1]
```

### 走样例与检查

`nums=[5,7,7,8,8,10], target=8`。第一个 `>=8` 的位置是 3，第一个 `>8` 的位置是 5，所以答案为 `[3,4]`。

不要用 `target+1` 代替上界查找，它依赖整数且可能溢出。空数组、目标在两端、目标不存在都要检查。时间 `O(log n)`。

### 面试一句话

> 我不直接寻找任意 target，而是分别二分第一个大于等于 target 和第一个大于 target 的位置，再组合出左右边界。

## M28｜33. 搜索旋转排序数组

### 先自己回答

- 旋转数组每次二分后，为什么至少有一半仍然有序？
- 判断某一半有序后，如何确认 target 是否在其中？

### 用恢复脚本推导

线性扫描是 `O(n)`，但题目要求 `O(log n)`，说明仍需二分。数组只发生一次旋转，因此中点把当前区间分开后，至少一侧保持升序。

先用 `nums[left] <= nums[middle]` 判断左半是否有序。若有序，再判断 target 是否位于 `[nums[left], nums[middle])`，在就保留左半，否则保留右半；右半有序时对称处理。

不变量是：若目标存在，它始终位于当前闭区间 `[left,right]` 中。

### 代码脊柱

```text
闭区间二分
判断左半是否有序
若左半有序：判断 target 是否落在左半
否则右半有序：做对称判断
```

### Python 实现

```python
def search_rotated(nums: list[int], target: int) -> int:
    left, right = 0, len(nums) - 1

    while left <= right:
        middle = (left + right) // 2
        if nums[middle] == target:
            return middle

        if nums[left] <= nums[middle]:
            if nums[left] <= target < nums[middle]:
                right = middle - 1
            else:
                left = middle + 1
        else:
            if nums[middle] < target <= nums[right]:
                left = middle + 1
            else:
                right = middle - 1

    return -1
```

### 走样例与检查

`[4,5,6,7,0,1,2], target=0`。第一次中点为 7，左半 `[4,5,6,7]` 有序但不含 0，因此舍弃左半；随后在右侧找到 0。

本题元素互不重复。若存在大量重复值，可能无法根据端点判断有序半区，需要缩边并可能退化为 `O(n)`。

### 面试一句话

> 旋转数组二分后至少一侧仍有序，我先识别有序半区，再判断目标是否在其值域中，从而每次排除一半。

## M29｜20. 有效的括号

### 先自己回答

- 为什么这是后进先出的匹配关系？
- 右括号到来时要检查哪两件事？

### 用恢复脚本推导

最近出现但尚未闭合的左括号必须最先被匹配，正是栈的后进先出。遍历时左括号入栈；遇到右括号，栈必须非空且栈顶类型匹配，否则立即失败。

不变量是：栈中按出现顺序保存所有尚未匹配的左括号，栈顶是下一个右括号唯一可能匹配的对象。

### 代码脊柱

```text
右括号到左括号的映射
左括号入栈
右括号检查栈非空且栈顶匹配
最后栈必须为空
```

### Python 实现

```python
def is_valid_parentheses(s: str) -> bool:
    matching = {")": "(", "]": "[", "}": "{"}
    stack = []

    for char in s:
        if char not in matching:
            stack.append(char)
        else:
            if not stack or stack.pop() != matching[char]:
                return False

    return not stack
```

### 走样例与检查

`([{}])` 中左括号依次入栈，遇到 `}`、`]`、`)` 时依次匹配栈顶。`([)]` 遇到 `)` 时栈顶是 `[`，立即失败。

检查字符串以右括号开头，以及遍历结束仍有左括号。时间 `O(n)`、空间 `O(n)`。

### 面试一句话

> 未闭合的最近左括号必须先匹配，所以我用栈保存它们；右括号到来时校验栈顶，最终栈为空才合法。

## M30｜739. 每日温度

### 先自己回答

- 栈中应该保存温度还是下标？
- 当前温度能够解决栈中哪些历史位置？

### 用恢复脚本推导

对每天下标向右线性寻找更高温度是 `O(n²)`。扫描到当前温度时，它可以一次性解决所有“温度比它低且仍未找到答案”的最近历史位置。

用单调不增栈保存这些下标。只要当前温度严格高于栈顶温度，弹出历史下标并计算距离；之后当前下标入栈，等待未来更高温度。

不变量是：栈中下标对应温度从底到顶单调不增，且它们都还没有找到右侧第一个更高温度。

### 代码脊柱

```text
answer 全 0，stack 存下标
遍历 i：
    当前温度更高时持续弹栈并写距离
    i 入栈
```

### Python 实现

```python
def daily_temperatures(temperatures: list[int]) -> list[int]:
    answer = [0] * len(temperatures)
    stack: list[int] = []

    for i, temperature in enumerate(temperatures):
        while stack and temperature > temperatures[stack[-1]]:
            previous = stack.pop()
            answer[previous] = i - previous
        stack.append(i)

    return answer
```

### 走样例与检查

`[73,74,75,71,69,72,76,73]`。72 会依次解决 69 和 71，但不能解决 75；76 到来时再解决 72、75 等尚未完成的位置。

相等温度不能弹出，因为要求严格更高。每个下标最多入栈、出栈一次，时间 `O(n)`、空间 `O(n)`。

### 面试一句话

> 我用单调不增栈保存尚未找到更高温度的下标，当前温度更高时连续弹栈，弹出时当前下标就是第一个有效答案。

## M31｜84. 柱状图中最大的矩形

### 先自己回答

- 如果固定某根柱子作为矩形最低高度，需要知道哪两个边界？
- 柱子何时从栈中弹出，弹出后宽度如何计算？

### 用恢复脚本推导

暴力枚举区间并取最小高度是 `O(n²)`。换个角度：让每根柱子都尝试成为矩形的最低高度，它能向左右扩展到第一个严格更矮柱子之前。

维护高度单调不降的下标栈。当前柱子更矮时，栈顶柱子的右边界首次确定为当前下标 i；弹出后新的栈顶是它左侧第一个更矮位置。因此宽度是 `i-stack[-1]-1`。

不变量是：栈中柱子高度单调不降，且它们的右侧第一个更矮位置尚未出现。

### 代码脊柱

```text
末尾追加高度 0，栈先放哨兵 -1
当前高度更小时持续弹栈：
    height = 被弹柱高
    width = i - 新栈顶 - 1
    更新面积
当前下标入栈
```

### Python 实现

```python
def largest_rectangle_area(heights: list[int]) -> int:
    extended = heights + [0]
    stack = [-1]
    best = 0

    for i, height in enumerate(extended):
        while stack[-1] != -1 and extended[stack[-1]] > height:
            rectangle_height = extended[stack.pop()]
            width = i - stack[-1] - 1
            best = max(best, rectangle_height * width)
        stack.append(i)

    return best
```

### 走样例与检查

`[2,1,5,6,2,3]`。扫描到高度 2 时，6 和 5 依次弹出：6 的宽度为 1，5 弹出后新栈顶是高度 1 的位置，宽度为 2，面积 10。

末尾 0 用于统一清空栈；哨兵 -1 让最左边界的宽度公式保持一致。时间 `O(n)`、空间 `O(n)`。

### 面试一句话

> 我让每根柱子作为最低高度，单调栈在遇到更矮柱子时确定其右边界，弹栈后的新栈顶给出左边界，从而在线性时间计算面积。

## M32｜215. 数组中的第 K 个最大元素

### 先自己回答

- 为什么完整排序做了多余工作？
- 第 K 大在升序下标中对应哪个位置？
- 分区后为什么只需继续搜索一侧？

### 用恢复脚本推导

排序是 `O(n log n)`，但只需要一个位置。快速选择沿用快速排序的 partition：把一个枢轴放到最终排序位置，使左侧不大于它、右侧不小于它。

第 K 大对应升序目标下标 `n-k`。若枢轴位置正好等于目标，直接返回；目标较小则只搜索左侧，否则只搜索右侧。随机枢轴降低持续选到极端值的概率。

不变量是：目标下标始终位于当前闭区间 `[left,right]`。

### 代码脊柱

```text
target = n - k
随机枢轴做 Lomuto 分区
比较 pivot_index 与 target
只保留目标所在一侧
```

### Python 实现

```python
import random


def find_kth_largest(nums: list[int], k: int) -> int:
    target = len(nums) - k

    def partition(left: int, right: int) -> int:
        pivot_index = random.randint(left, right)
        nums[pivot_index], nums[right] = nums[right], nums[pivot_index]
        pivot = nums[right]

        store = left
        for i in range(left, right):
            if nums[i] <= pivot:
                nums[store], nums[i] = nums[i], nums[store]
                store += 1

        nums[store], nums[right] = nums[right], nums[store]
        return store

    left, right = 0, len(nums) - 1
    while left <= right:
        pivot_index = partition(left, right)
        if pivot_index == target:
            return nums[pivot_index]
        if pivot_index < target:
            left = pivot_index + 1
        else:
            right = pivot_index - 1

    raise ValueError("k 超出有效范围")
```

### 走样例与检查

`nums=[3,2,1,5,6,4], k=2`，目标升序下标为 4，对应值 5。每次 partition 后只进入包含下标 4 的一侧。

数组可有重复值，求的是排序后的第 K 个位置。平均时间 `O(n)`、最坏 `O(n²)`；实现会修改原数组。

### 面试一句话

> 完整排序处理了不需要的相对顺序，我用快速选择把第 K 大转换为升序下标 `n-k`，每次分区后只搜索目标所在一侧。

## M33｜55. 跳跃游戏

### 先自己回答

- 为什么不需要真的枚举或记录具体跳跃路径？
- 遍历到位置 i 时，什么条件说明它根本不可达？

### 用恢复脚本推导

DFS 枚举跳法会产生大量重复状态，DP 也可以做，但只判断可达性时信息过多。扫描过程中，只需维护所有已知可达位置共同能够覆盖的最远下标 `farthest`。

若当前下标 `i > farthest`，说明此前所有可达位置都跨不过这个断点，必然失败；否则当前位置可达，可以用 `i+nums[i]` 扩展最远范围。

不变量是：处理下标 i 前，`farthest` 是利用所有已处理且可达位置能到达的最远下标。

### 代码脊柱

```text
farthest = 0
遍历 i, jump：
    i > farthest：失败
    更新 farthest
    覆盖终点：成功
```

### Python 实现

```python
def can_jump(nums: list[int]) -> bool:
    farthest = 0

    for i, jump in enumerate(nums):
        if i > farthest:
            return False
        farthest = max(farthest, i + jump)
        if farthest >= len(nums) - 1:
            return True

    return True
```

### 走样例与检查

`[2,3,1,1,4]`：下标 0 最远到 2，下标 1 可达并把最远范围扩到 4，因此成功。`[3,2,1,0,4]` 的 farthest 最多为 3，扫描到 i=4 时发现断点。

单元素数组起点就是终点，应返回 true。时间 `O(n)`、空间 `O(1)`。

### 面试一句话

> 只判断能否到达，不需要记录路径；我贪心维护所有可达位置能覆盖的最远下标，遇到超出覆盖范围的位置就失败。

## M34｜198. 打家劫舍

### 先自己回答

- 处理当前房屋时只有哪两种选择？
- `dp[i]` 应表示“必须偷第 i 间”还是“前 i 间的最优答案”？

### 用恢复脚本推导

暴力递归对每间房做“偷或不偷”会产生 `2^n` 分支，并重复求相同后缀。定义 `dp[i]` 为考虑到第 i 间房时的最大金额。

若不偷当前房，答案继承 `dp[i-1]`；若偷当前房，则不能偷上一间，答案为 `dp[i-2]+nums[i]`。取二者较大值。状态只依赖前两个位置，可压缩为两个变量。

不变量是：`prev1` 是处理到上一间的最优答案，`prev2` 是处理到上上间的最优答案。

### 代码脊柱

```text
prev2 = prev1 = 0
遍历金额：
    current = max(prev1, prev2 + money)
    prev2, prev1 = prev1, current
返回 prev1
```

### Python 实现

```python
def rob(nums: list[int]) -> int:
    prev2 = 0
    prev1 = 0

    for money in nums:
        current = max(prev1, prev2 + money)
        prev2, prev1 = prev1, current

    return prev1
```

### 走样例与检查

`[2,7,9,3,1]`：处理 9 时比较“不偷 9 得 7”和“偷 9 加上 2 得 11”；最终答案 12。

空数组自然返回 0。关键是同时更新变量，避免新 prev1 污染 prev2。时间 `O(n)`、空间 `O(1)`。

### 面试一句话

> 当前房只有偷和不偷两种选择，我定义前缀最优状态，转移为 `max(上一状态, 上上状态+当前金额)`，再压缩到两个变量。

## M35｜322. 零钱兑换

### 先自己回答

- 为什么这是“可重复选择”的完全背包？
- `dp[x]` 的准确含义和不可达初值是什么？

### 用恢复脚本推导

暴力枚举硬币组合存在大量重复子问题。若凑出金额 x 的最后一枚硬币是 coin，那么之前必须先凑出 `x-coin`，所需数量再加一。

定义 `dp[x]` 为凑出金额 x 的最少硬币数。`dp[0]=0`；其他金额初始化为无穷大表示不可达。每个金额枚举所有可使用硬币，取最小转移。

不变量是：计算 dp[x] 时，所有更小金额的最优答案已经确定。

### 代码脊柱

```text
dp = [inf] * (amount + 1), dp[0] = 0
金额从 1 到 amount：
    枚举 coin <= current
    dp[current] = min(dp[current], dp[current-coin] + 1)
```

### Python 实现

```python
def coin_change(coins: list[int], amount: int) -> int:
    dp = [float("inf")] * (amount + 1)
    dp[0] = 0

    for current in range(1, amount + 1):
        for coin in coins:
            if coin <= current:
                dp[current] = min(dp[current], dp[current - coin] + 1)

    return -1 if dp[amount] == float("inf") else dp[amount]
```

### 走样例与检查

`coins=[1,2,5], amount=11`。`dp[5]=1`，`dp[10]=2`，最后用硬币 1 从 dp[10] 转移到 3，得到 `5+5+1`。

金额 0 返回 0；若 `coins=[2], amount=3`，dp[3] 保持无穷大并返回 -1。时间 `O(amount·n)`、空间 `O(amount)`。

### 面试一句话

> 我定义 dp[x] 为凑出 x 的最少硬币数，枚举最后使用的硬币，从 `dp[x-coin]+1` 转移；不可达状态初始化为无穷大。

## M36｜1143. 最长公共子序列

### 先自己回答

- 子序列与子串的区别是什么？
- 两个当前字符相等和不相等时，状态分别从哪里转移？

### 用恢复脚本推导

两个字符串同时存在维度，且问题反复比较前缀，因此定义二维 DP。`dp[i][j]` 表示 `text1[:i]` 与 `text2[:j]` 的最长公共子序列长度。

若两个前缀的最后字符相同，可以把该字符接到更短前缀答案后：`dp[i-1][j-1]+1`。若不同，公共子序列不可能同时使用这两个末尾字符，至少舍弃其中一个，取 `dp[i-1][j]` 与 `dp[i][j-1]` 的最大值。

不变量是：按行列递增计算时，当前状态依赖的左、上、左上状态都已经确定。

### 代码脊柱

```text
建立 (m+1) × (n+1) 的全 0 表
遍历 i=1..m, j=1..n：
    字符相等：左上 + 1
    否则：max(上, 左)
返回 dp[m][n]
```

### Python 实现

```python
def longest_common_subsequence(text1: str, text2: str) -> int:
    rows = len(text1) + 1
    cols = len(text2) + 1
    dp = [[0] * cols for _ in range(rows)]

    for i in range(1, rows):
        for j in range(1, cols):
            if text1[i - 1] == text2[j - 1]:
                dp[i][j] = dp[i - 1][j - 1] + 1
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])

    return dp[-1][-1]
```

### 走样例与检查

`text1="abcde", text2="ace"`。a、c、e 依次匹配，每次由左上状态加一，最终得到 3。它们在原字符串中不连续，但相对顺序一致。

多出的第 0 行和第 0 列表示空前缀，使边界自然为 0。时间 `O(mn)`、空间 `O(mn)`。

### 面试一句话

> 我用二维 DP 表示两个字符串前缀的 LCS；末尾字符相等时从左上加一，不等时舍弃其中一个末尾字符并取上、左最大值。
