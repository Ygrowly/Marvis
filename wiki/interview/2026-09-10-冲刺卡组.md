## 算法

::card id=lru-01 tag=算法
Q: LRU 为什么必须是「哈希表 + 双向链表」两个结构？单链表为什么不行？
A: 哈希表负责 O(1) 按 key 定位节点，双向链表负责 O(1) 调整使用顺序。
删除任意节点需要同时拿到前驱和后继：node.prev.next = node.next; node.next.prev = node.prev。
单链表拿不到前驱，删除要 O(n) 遍历，所以不行。
::end

::card id=lru-02 tag=算法
Q: 为什么要在链表两端设虚拟 head / tail 哨兵节点？
A: 真实节点都夹在两个哨兵之间，任何位置的插入删除都不用判空，也不用特判头尾。
约定：head 后面 = 最近使用；tail 前面 = 最久未使用。淘汰时直接删 tail.prev。
::end

## 数字口径（Q-2026-010）

::card id=num-01 tag=数字口径
Q: 简历写「压缩 80%」，面试官追问「怎么知道是对的」，怎样答才不露怯？
A: 四要素一次说清：判定基准（谁算对）、是否控制变量、数据来自自建评测集还是生产 P99、样本量多少。
没有 ground truth 的成功率只能叫「跑通率」，不能叫准确率。
::end

::card id=num-02 tag=数字口径
Q: Execution Accuracy 和 Exact Set Match 有什么区别？各在什么场合用？
A: Execution Accuracy：执行出来的结果集是否一致，容忍 SQL 写法不同。
Exact Set Match：要求 SQL 的子句集合精确匹配，更严格。
对外报数用 Execution Accuracy；要卡住「写法是否走对索引与权限路径」时才用 Exact Set Match。
::end

## 网络与成本（9.9 被问住的点）

::card id=net-01 tag=网络
Q: SSE 是长连接吗？和 WebSocket 的本质区别是什么？
A: 是长连接。SSE 基于 HTTP，服务端保持响应不关闭，持续单向推送，自带断线重连与事件 ID。
WebSocket 需要协议升级，双向通信。SSE 只解决服务端推客户端这一个方向。
::end

::card id=net-02 tag=网络
Q: 502 和 504 有什么区别？各说明哪里出了问题？
A: 502 Bad Gateway：网关收到了上游的无效响应（上游活着，但答了不能解析的东西）。
504 Gateway Timeout：上游在超时时间内一个字都没回。
一句话：502 是答非所问，504 是根本没答。
::end

::card id=cache-01 tag=成本
Q: 什么改动会击穿 prompt 前缀缓存？怎么设计才不被击穿？
A: 前缀里任何一个 token 变动，该位置之后的缓存全部失效——包括 tool schema 的增删改与顺序变化、system prompt 微调、模型版本切换。
做法：稳定内容（system、工具定义）放最前，动态内容（用户输入、检索结果、当前时间）放最后。
::end

## 数据库（Q-2026-012）

::card id=db-01 tag=数据库
Q: MySQL 和 PostgreSQL 的默认事务隔离级别分别是什么？面试怎么答不串台？
A: MySQL InnoDB 默认 REPEATABLE READ；PostgreSQL 默认 READ COMMITTED。
我的项目全用 PostgreSQL。答题前先声明「你说的是哪个栈」，避免岗位栈和项目栈串台——SSE、502/504 那次就是串台付的代价。
::end

::card id=db-02 tag=数据库
Q: 乐观锁在 MySQL 和 PostgreSQL 里怎么落？差异在哪？
A: 应用层写法一样：版本号或 CAS 条件更新（UPDATE ... WHERE id=? AND version=?），看影响行数是否为 1。
差异在底层：两者都是 MVCC，但 MySQL InnoDB 用回滚段 undo log，PostgreSQL 把元组多版本留在堆里、需要 VACUUM 回收；加上默认隔离级别不同，会影响「同一事务内能否看到他人已提交的更新」。
::end

## 项目表达

::card id=proj-01 tag=项目表达
Q: 简历上一个 bullet 好不好的判断标准是什么？
A: 能不能引出追问。写成「具体问题 → 技术取舍 → 验证结果」，不写功能清单。
并且必须能回答「为什么不用现成方案」。
::end

::card id=proj-02 tag=项目表达
Q: 「生产四问」是哪四问？为什么它能区分搭过 Demo 和跑过生产？
A: 投递失败怎么记 / 超时写操作能否重试 / 以谁的身份行动 / 版本升级如何证明不退化。
前两问考幂等与恢复，第三问考权限边界，第四问考评测基线——这四处 Demo 通常不碰。
::end

::card id=ra-01 tag=项目表达
Q: RuleArena 60 秒介绍主讲哪个技术点？
A: 只讲一个：「动态计划下如何可靠执行与验收」。
先说问题（计划会变，执行不能乱），再说取舍（幂等 + 可恢复 + oracle 校验），最后给验证口径（没测量就不写数字）。
::end
