# 20｜场景设计题库（AI 应用 / Agent / 后端 十道母题）

> 用途：study/16 D9 系统设计日 + 每周模拟面试 #2 的题库，同步学习积累用。
> 通用答题顺序（study/11 §5）：澄清需求边界 → 估算量级 → 核心链路设计 → 关键失败处理 → 指标验证 → 权衡与替代。
> 规矩：每题的 E（证据）必须落到自己三项目；口述时先给 60 秒骨架，被追问再下钻 L3。来源：study/00 总验收原题、study/13 系统设计母题、raw 案例簇、learn-claude-code。

## 题 1｜企业规则审查与发布门禁 Agent（study/00 总验收原题）

- 澄清：规则从哪来（自然语言）、审什么（规则变更的业务风险）、谁说了算（Agent 提议 vs 确定性裁决）。
- P：规则间组合出错，单测覆盖不到"人没想到的路径"；LLM 自证不可信。
- D：NL→RuleSpec 编译（歧义清单人工确认、不可变版本）→受控 Agent 搜动作序列→Reference Simulator 剪枝→独立 Sandbox 真实 HTTP 重放→Oracle 按资金守恒/幂等不变量裁决→Delta Debugging 压 1-minimal 反例→一键导出 pytest 回归。
- F：Agent 全程无法触达 Ground Truth（防自证）；门禁承诺"预算内未发现"而非"规则安全"；FSM+Checkpoint 恢复、ACTION_UNKNOWN 先查权威状态。
- M：双评测集（dev 16 + hidden 8 物理隔离）、正常场景误报 0、同版本重放一致、GT 泄漏 0；P0 反例 100% 回归。
- E：RuleArena 全套（作战地图 §4）。
- 追问：为什么不让 LLM 直接审规则？消融怎么设计？24 Case 会过拟合吗？

## 题 2｜企业问数平台（NL2SQL Data Agent）

- P：SQL 能执行≠业务答案正确；"销售额"跨行业口径完全不同。
- D：意图路由→语义层检索（Domain Pack：指标/别名/表关联）→NL2SemQL→SQL 生成→安全校验→受控执行→证据绑定解释；执行反馈限次自愈。
- F：口径歧义必须澄清（选项由 Domain Pack 枚举，不让模型自行决定）；只读 AST 审查+tenant 服务端注入；大结果 Artifact 外置；权限撤销即时生效、副本按当前权限裁剪。
- M：成功率 78→91%（150 条评测）、拦截 100%/误拦 2.7%（300 条对抗）、Token 18.4K→3.6K。
- E：数驭（作战地图 §3）；旁证：高德 6 步工作流（准确率>95%）、NL2BI 五层边界（fail-closed→白名单 Tool→不可信输入→唯一当前态→最小披露）。
- 追问：语义层怎么沉淀？SQL 跑对了语义错了怎么发现？权限过滤在哪层做？

## 题 3｜园区能耗监控告警 Agent

- P：原始读数质量参差；真告警被淹没；结算要对得上账。
- D：raw→interval→hourly→daily 四层+7 类质量状态与可信白名单→「异常候选≠业务告警」三层分离（自适应基线→dry-run 准入→指纹去重）→月度结算三道质量门→受控 Agent 入口（R0/R1/R2）。
- F：幂等窗口+任务状态持久化+启动 7 天自动回补；R2 未确认直接阻断；结算任一门失败阻断账单。
- M：完整率 96.8→99.7%、告警 -43%、研判 18→6min、P95 20.4→2.8s、聚合成功率 99.6%。
- E：EnergyOps（作战地图 §2）。
- 追问：乱序补数怎么保证不重不漏？为什么结算用人工底稿（口径唯一，自动只核对）？

## 题 4｜通用 Coding Agent（产品设计视角）

- P：LLM 只会输出指令不会执行；长任务漂移；上下文爆炸；写操作有风险。
- D：最小 Loop（while + "无 tool_use 即退出"）+TOOLS/TOOL_HANDLERS 分发→权限三闸门（硬拒/规则/人工）→Hooks 四事件→TodoWrite 计划外化→Subagent 上下文隔离→Compact 四步（预算→snip→micro→摘要）→Memory 写入门控→Task 依赖图→Checkpoint/journal 续跑→Goal Loop 判停自动续轮。
- F：拒绝也是合法 tool_result（让模型自纠）；compact 丢约束→CLAUDE.md 每次重注入；先确定性文本操作最后才模型摘要；恢复后必须重读环境。
- M：任务完成率、每任务上下文 token、恢复成功率、无效重试率（Anthropic：连续失败 3000 次→熔断"连续 3 次"）。
- E：learn-claude-code 17 机制（study/15 §1.3）+Anthropic CC best practices；我的 Hook 链+R0/R1/R2 与 Permission/Hooks 同构。
- 追问：权限判定为什么在执行前？为什么 grep 不建向量索引（0.67→0.83）？多 Agent 什么时候值得用？

## 题 5｜模型路由与成本网关

- P：强模型贵弱模型差；Agent 成本失控（token 是新电费）。
- D：任务分桶 Eval→Router（输入：难度/风险/延迟预算/供应商健康度）→分级路由；前缀按稳定度分区（缓存命中×10 计费）；工具 defer_loading 按需加载；MCP→CLI 化；Early-Exit 早停；thinking_budget 上限。
- F：路由错→下游指标标 error 跳过（防错误雪崩）；529 切 fallback model；降级阶梯：减步骤→换小模型→只读 Workflow→异步/转人工。
- M：单任务成本、P95、任务成功率、缓存命中率、路由准确率。
- E：study/15 §二/§八；旁证数字：MCP→CLI 省 61%、按需提取再省 88%、Early-Exit 再省 50-70%，合计 -95%；账单 -88% 四因子拆解。
- 追问：怎么证明路由策略有效（分桶消融）？路由错了怎么办（error 跳过+人工复核）？

## 题 6｜Agent 评测平台

- P：改一处坏十处；LLM 打分不稳；上线没有门禁就靠赌。
- D：数据集四分区（dev/golden/holdout/adversarial）→grader 三类组合（代码判硬条件/校准 LLM Judge 判语义/人工终判）→题目级 Rubric 版本化→Run 存版本化 Trace 支持 Replay→CI 门禁→shadow/灰度→badcase 回流成新 Case。
- F：环境噪声与运行方差（用 pass^k 连续成功率）；测试泄漏（hidden 集物理隔离）；Rubric 漂移（版本号+一致性监控）。
- M：Judge-人工一致率 ≥85% 才自动化（二元化使 62%→92%）；回归通过率；消融显著性 SE≈√(p(1-p)/n)。
- E：RuleArena 双集+消融+门禁；AgentLoop 回测与离线实验平台；评测指标 20→200 个是被 Bad Case 喂出来的。
- 追问：冷启动 20 个 case 怎么选（真实失败任务）？为什么不看总分？

## 题 7｜高并发 LLM API 网关

- P：下游又慢又贵；突发流量；SSE 长连接占资源。
- D：FastAPI 异步接入（流式转发）→租户维度限流（令牌桶）→并发控制（Semaphore+连接池）→背压（bounded queue，慢消费者不拖垮全局）→KV Cache 前缀复用→降级阶梯。
- F：上游 429/529 指数退避+jitter、529 切 fallback；取消传播（客户端断开→终止生成，不白烧 token）；端到端 deadline 分配给各跳；CPU 密集出进程池。
- M：TTFT/P95、吞吐、错误率、单任务成本。
- E：study/15 §八+推理服务卡；EnergyOps SSE 与背压实践。
- 追问：为什么 SSE 不等完整 JSON（TTFT）？流量翻十倍先挂哪（排队→OOM→连接耗尽，按容量估算答）？

## 题 8｜幂等支付与权益系统

- P：回调重复/乱序、双写不一致、权益多发。
- D：验签→幂等键（tenant+entity+operation，唯一约束）→订单/权益状态机（非法跃迁拒绝）→本地消息表/Outbox 同事务写事件→对账兜底。
- F：unknown outcome 先查权威状态，证明未执行才重试；迟到消息带 version 被拒；永久失败进可治理 DLQ+人工补偿。
- M：账权一致率、重放重复次数、事件重复率。
- E：Ovanta（账权 99.95%、2000 次构造回放重复 0）；learn-claude-code s12 at-least-once+last_fired 去重。
- 追问：Exactly-once 可能吗（端到端做不到，效果幂等才可能）？双 Worker 怎么不重复发放（lease+唯一约束）？

## 题 9｜长任务执行引擎（暂停/恢复/重试/取消）

- P：任务几十分钟，崩溃、发版、人工审批都会打断。
- D：任务拆可序列化幂等 Step→关键节点 checkpoint（状态存库、大结果 Artifact）→Worker lease 抢占→事件带 sequence→取消向下游传播→HITL 等待持久化不占进程。
- F：Resume 前先对账已完成副作用（查权威状态）；区分 Retry/Resume/Replay/Fork；迟到结果按 version 拒绝；journal 按 key 稳定哈希命中缓存跳过已完成步。
- M：恢复成功率、重复副作用 0、断线恢复时间、取消延迟。
- E：EnergyOps 任务状态持久化+7 天回补；RuleArena FSM/Checkpoint；learn-claude-code s16 Workflow Runtime。
- 追问：checkpoint 存什么不存什么（结构化事实，不存聊天记录）？为什么恢复后要重读环境？

## 题 10｜企业知识库 RAG 系统

- P：跨文档语义割裂、权限泄漏、知识过期。
- D：Chunk（256-1024 token+10-20% 重叠）→contextual retrieval 逐块语境补全（失败率 -49%，+rerank -67%）→BM25+向量+元数据过滤三路→RRF→rerank→按 token 预算组装→逐项引用生成→证据不足拒答。
- F：权限过滤下推检索层（不能生成后再删）；增量索引+版本（过期语义不冒充当前口径）；知识 <20 万 token 可免 RAG。
- M：recall@k / success@k（口径讲清）、faithfulness、端到端成功率。
- E：数驭 Domain Pack+混合检索（81→95%）；study/15 §四。
- 追问：为什么不直接上 GraphRAG（多跳消歧才需要）？权限怎么保证不泄漏？

## 使用方法
