## 第 0 节面试元能力（先背这个）

- **P-D-F-M-E 骨架**（study/11）：Problem 什么矛盾 → Design 主链路 → Failure 边界降级 → Measure 质量延迟成本风险 → Evidence 项目测试复盘。标准话术："这个问题的本质是【P】，我会把系统拆成【D】，主要风险是【F】所以加入【控制】；若【边界】成立改用【替代】，效果用【M】验证，在【E】里验证过。"
- **三层追问**（study/12）：基础必问层（背景/职责/链路/数字，脱口而出）→ 进阶深挖层（选型对比/优化/Bad Case）→ 死亡追问层（重构/极端/迁移/失败复盘）。面试官六问：真做过吗、Agent≠一次调用、多 Agent 必要性、能否沿 Trace 归因、能否落进可靠后端、微调真实性。
- **临场规则**（study/13）：30 秒先结论后细节；不会的题"承认+给 AI 视角的判断"；被质疑选型时主动挑战自己（"这数据量 pgvector 就够"是高分答法）。

## 一 Agent 本质与架构

**1.1 Agent vs Workflow**
- L1：Workflow 控制流由代码预定义；Agent 是 LLM 在循环中根据环境反馈动态决定下一步，本质是"model using tools in a loop"。〔Anthropic building-effective-agents〕
- L2：判据——流程固定可枚举→Workflow；开放式跨工具、路径不可预知→Agent。生产 Agent 还要加状态、预算、checkpoint、验证、取消、审计。七种可组合模式：Prompt chaining（含 gate）/Routing/Parallelization（Sectioning/Voting）/Orchestrator-workers/Evaluator-optimizer/Agent/Augmented LLM 基块。
- L3：框架掩盖底层，宜 API 直连起步；"simple, composable patterns"胜过复杂框架。我的三个项目分别站在哪：数驭=六阶段 Workflow 带局部 Agent、EnergyOps=受治理 Agent、RuleArena=显式 FSM（流程确定性要求最高）。

**1.2 Agent Layer 与 Harness 五要素**
- L1：Agent 系统四层——模型决策层 / Context-State 层 / Runtime 层（observe-decide-act-verify+预算终止checkpoint）/ Assurance 层（权限/Eval/Trace）。〔study/13①〕
- L2：Harness 五要素：Context（看到什么）/Tools（能做什么）/Constrain（边界）/Verify（验证）/Correct（纠正）。模型不缺智商缺纪律——竞争力在 Harness 工程。〔ai-agent-book ch1〕
- L3 弹药：LangChain 仅改 Harness，Terminal Bench 2.0 从 52.8%→66.5%（30 名开外→前 5）；缺工具定义时模型照样笃定作答——"给出回答"≠"完成任务"。

**1.3 17 个 Harness 机制总分类**〔learn-claude-code，每一课都是一个可讲的机制〕
- 循环基础：Agent Loop（while True + "无 tool_use 即退出"）、Tool Use（TOOLS schema + TOOL_HANDLERS dispatch map）、Subagent（嵌套同构循环做上下文隔离，隔离消息不隔离资源）。
- 治理安全：Permission（执行前三闸门：硬拒/规则/人工——R0/R1/R2 的老祖宗）、Hooks（四事件 UserPromptSubmit/PreToolUse/PostToolUse/Stop；PreToolUse 返回非 None 即拦截短路，注册顺序即优先级）、MCP Plugin（宿主不信任远端 readOnlyHint，权限按 (server,tool) 配置）。
- 上下文管理：TodoWrite（计划外化+3 轮未更新注入 reminder，对抗注意力稀释）、Skill Loading（YAML frontmatter 目录常驻+按需加载正文）、Context Compact（四步管线：tool_result 预算→snip→micro→模型摘要；先确定性操作最后才摘要）、Memory（一记忆一文件+索引，写入门控 scope+去重，满 10 条 consolidate）。
- 生命周期：Task System（依赖图 blockedBy+磁盘持久化）、Background Tasks（占位 tool_result+完成通知注入）、Cron（durable+at-least-once+last_fired 去重）、Workflow Runtime（模型只提交 name/args，`agent()` 按稳定哈希命中 journal 缓存，只有改动处重跑）、Goal Loop（"想停"与"该停"分离：独立只读模型调用判 `{ok,reason}`，不通过自动续轮，保留 max_turns 双出口）。
- 协作：Agent Teams（原子认领=进程锁+文件锁、task 绑 worktree、审批协议 ProtocolState——认领/释放改变 work version 使旧审批失效）。
- 一句话收束："多种机制，一个循环"——一切治理都是在循环固定切点注入。

## 二 上下文工程

**2.1 上下文=稀缺资源**
- L1：上下文是有限注意力预算，token 越多召回越差（context rot），工程是"找到最小的高信号 token 集"。〔Anthropic context-engineering〕
- L2：策略族——系统提示 Goldilocks 最小充分；few-shot 用 canonical 例子；检索 just-in-time 优于预取；长任务三技：Compaction（保连贯）/ Structured note-taking（里程碑式迭代）/ Sub-agent architectures（并行隔离）。
- L3 弹药：打乱上下文信息组织成功率降 30%+；删工具描述调用错误+45%；时间戳每轮注入 system prompt 使首 token 延迟 0.5s→3-5s（KV Cache 全失效）。

**2.2 前缀缓存与成本**〔面经+AgentLoop 成本篇+study/13〕
- L1：API 无状态，每轮重建 c_t；缓存命中的 token 计费约 1/10，前缀不变性是铁律——改第 k 个 token 则 k 起全失效。
- L2：工程做法——稳定内容前置、易变内容后置或异步；tool schema 是缓存前缀的一部分永不改动（Claude Code 的 EnterPlanMode 做成工具+system-reminder 软约束就是为保字节级不变）；defer_loading 按需加载不破坏缓存；memory 注入放 prompt 最前。
- L3：成本五招（账单降 88% 的拆解）：少发（Skill 只注入一次+短回执、前缀按稳定度分区）×发得便宜（缓存命中×10%、thinking_budget 上限）×少想×subagent 只回传 ≤600 字摘要×hook 断空转（复读 3 次、同参数 8 turn、连续 5 次空结果即停）。另一组：MCP→CLI 省 61%、按需提取再省 88%、Early-Exit 再省 50-70%，合计降 95%+。〔AgentLoop 终章/网关审计〕

**2.3 压缩与隔离**〔learn-claude-code s08 + Anthropic + 得物〕
- L1：compact 四步按成本递增：tool_result 预算（落盘留路径）→ snip（保头尾、不拆 tool_use/tool_result 配对）→ micro（保最近未读）→ 模型摘要（必丢细节，最后才用）。
- L2：隔离优于压缩——subagent 用脏上下文换父上下文整洁；compact 丢约束是真实故障，对策是把约束写进 CLAUDE.md 每次重注入。得物数字：subagent 隔离使 compact 频率降 50-70%，规范遵守率 70-80%→95%+。
- 项目锚：数驭 Artifact 外置 Hot/Warm/Cold（模型只收口径摘要）=同一思想，Token 18.4K→3.6K。

## 三 工具、MCP 与安全

**3.1 工具=契约**〔Anthropic writing-tools〕
- L1：工具是确定性系统与非确定性 agent 间的契约，面向 agent 而非开发者设计，评估驱动迭代。
- L2：设计清单——命名空间（asana_search）、描述带示例（准确率 72%→90%）、参数自描述（user_id）、返回高信号（弃 uuid、ResponseFormat enum）、token 效率三招（pagination/filtering/truncation 25K 上限）。参数保真是底线：禁止静默转换/注入（弯引号静默转换能让模型死循环）。〔ai-agent-book ch4〕
- L3：工具过多三方案：defer_loading 按需加载（省 ~95% 上下文，检索预筛准确率 49%→74%）、Programmatic Tool Calling（代码编排，中间结果不进上下文，token -37%）、input_examples。超 100 个工具时先进模型也选错；code_interpreter 可替代数十个专用工具。

**3.2 MCP 与宿主侧安全**
- L1：MCP 三原语 tools/resources/prompts，标准化能力发现与调用；但**不自动提供**最小权限、沙盒、业务幂等。〔study/11第 2.5 节〕
- L2：三大风险：工具描述投毒、供应链、tool shadowing；宿主侧对策——权限按 (server,tool) 白名单、不信任远端自述 hint、错误留在工具边界让模型自纠。〔learn-claude-code s14〕
- L3：Credential Vault 叙事："不是让沙箱更方便存密钥，而是让沙箱不再需要保存真实密钥"——假密钥进沙箱，egress sidecar 按 scheme/host/path 注入真凭据，默认拒绝出站。〔OpenSandbox〕

**3.3 风险分级与 Hook（我的主场）**
- L2：三闸门（硬拒/上下文规则/人工确认）对应 R0/R1/R2；PreToolUse 拦截=执行前判定；"拒绝也是合法 tool_result，要让模型能自纠"；hook 顺序即风险优先级。〔learn-claude-code s03/s04〕
- L3：对照词——prompt 是说服、hook 是强制（"模型无法幻觉绕过的确定性"）；腾讯 DECO 三类护栏：偷懒（Hook→重试）、越权（HITL beforeTool 守卫）、失忆（Hook→state→Attachment 闭环）；读侧降级、写侧阻断是差异化失败语义。〔raw Harness 簇〕

**3.4 幂等与写安全**〔study/11第 2.6 节 + learn-claude-code s10/s12〕
- L2：ToolCallID 只是协议调用不是业务意图；幂等键=tenant+entity+operation；副作用前记录 intent，服务端唯一约束/条件更新；超时进 unknown outcome→先按业务键查权威状态，证明未执行才重试，无法确认转人工/补偿。
- L3：cron 的 at-least-once+last_fired 去重、task 系统的 owner 校验+成环检测，都是同一模式；Anthropic 数据：同一恢复路径连续失败 3000+ 次，无效重试每天浪费 25 万次调用——熔断阈值"连续 3 次"由此而来。

## 四 RAG 与企业知识

**4.1 全链路**（study/11第 2.4 节为底）
- L1：离线（解析→结构化 Chunk 256-1024 token+10-20% 重叠→补元数据/ACL/版本→向量+关键词双索引）；在线（query 理解→权限过滤→混合召回→RRF→rerank→按 token 预算组装→逐项引用生成）；证据不足拒答。
- L2：BM25 管精确匹配（错误码/ID），向量管语义变体，RRF(k=60) 融合，cross-encoder 重排；**Contextual Retrieval**：为每 chunk 生成 50-100 token 语境说明，检索失败率 -49%，加 rerank -67%。〔Anthropic contextual-retrieval〕
- L3：RAPTOR 擅长概念下钻、GraphRAG 擅长多跳消歧；知识 <20 万 token 可免 RAG；多租户权限过滤必须下推检索层；指标用 Recall@K/MRR/nDCG（口径实为 success@k 时要讲清）。〔ai-agent-book ch3〕

**4.2 NL2SQL 是知识工程问题**〔raw NL2SQL 簇〕
- L1：准确率=语义理解深度×规范覆盖度；确定性路由优于 RAG——"收入"在不同域 embedding 几乎一样但口径完全不同。
- L2：高德四层（域路由→知识加载→6 步工作流→公共服务）：352 表 3 万行文档按需加载 200-400 行，6 节知识卡片+两级路由+澄清只给 2-3 选项，准确率>95%，取数从 8 小时缩短 30 倍。
- 项目锚：数驭 Domain Pack 65 指标+120 别名=同一思想；六阶段可归因对照高德 6 步（前置检查→路由→加载→口径确认→选表自检→执行解读）。

## 六 记忆与多 Agent

**6.1 记忆分层与写入门控**
- L1：Context 是一次调用看到的 token；Agent State 是 Run 的结构化事实；Business State 是数据库权威状态；Memory 是跨会话复用。恢复从 checkpoint+业务状态重建 Context，不把聊天记录当真相。〔study/11第 2.3 节〕
- L2：得物四层 Working/Session/User/Agent+MemOS：短期 Redis+MySQL 双写、Token Budget 4000（user_profile ≤60%）、LLM 判断写入+Jaccard 0.7 去重、先写后删；写入冲突分五类（替代/事件/并存/推测/纠正），冲突询问用户。陈述性记忆进 Memory，**程序性记忆必须是可版本化可回滚的 Skill**（防局部经验升格为通用策略）。
- L3：写入门控类比幂等窗口——不是所有状态都值得落盘；"让正确的过去，在正确的时候，以正确的作用域，正确的方式重现"。

**6.2 多 Agent 判据**〔Anthropic multi-agent + ai-agent-book ch10 + 面经〕
- L1：唯一判据——是否引入单 Agent 生成时无法获得的**新信息**（执行反馈/视觉反馈/工具验证）；无新信息的同上下文辩论无效甚至有害。
- L2：收益与代价：Opus 主导+Sonnet 子代理比单 Agent 高 90.2%，但总 token 约 15 倍，token 用量解释 80% 的方差——"多 Agent 系统有效主要是因为花了足够的 token"。适用研究类开放任务，**不适用 coding/共享上下文**。业界正回归"单强 Agent+好工具+上下文工程"。
- L3：通信三机制（工具参数/共享文件系统/消息总线）；A2A 管 Agent↔Agent、MCP 管 Agent↔工具；六大失败模式（并发冲突/错误级联/同质趋同/扯皮/循环失控/理解债）；30 个 Agent 中 18 个自发创建同名分支=同质化证据；结算点是"第一个已验证成功"而非"第一个声称成功"。
- 面试高危题："你的多 Agent 各用不同模型吗"→按职责分级（意图小模型/汇总强模型/摘要便宜模型）；"固定 router 算多 Agent 吗"→诚实承认那是 Workflow+自我修正。

**6.3 长任务与恢复**〔study/11第 2.10 节 + learn-claude-code s16/s17 + Anthropic harnesses〕
- L2：任务拆可序列化幂等的离散 Step，关键节点 checkpoint，大结果写 Artifact；Worker 用 lease，崩溃后读 checkpoint→先查业务权威状态与已完成副作用→从安全节点 resume。区分 Retry/Resume/Replay/Fork。
- L3：Anthropic 长任务两大失败模式：one-shot 中途上下文耗尽留半成品、见进展提前宣布完工——对策：JSON feature list 全标 failing+progress 文件+每 session 只做一个 feature+严禁未测标 passing；Workflow Runtime 的 journal 稳定哈希续跑是 checkpoint 的高级形态；Goal Loop="想停"与"该停"分离。

## 七 评测、Trace 与门禁（RuleArena 主场）

**7.1 评测体系四层**
- L1：测"模型+Harness 组合体"；四层指标——结果（任务成功）/过程（路由检索工具步骤）/工程（P95 成本恢复）/安全（越权副作用）。〔study/11第 2.7 节〕
- L2：数据集四分区 dev/golden/holdout/adversarial；精确约束用代码 grader，语义用校准过的 LLM Judge；每次 Run 存版本与轨迹支持 Replay；变更进 CI 门禁再 shadow/灰度。新模型公开基准变好≠你的任务变好，必须自建评估集。
- L3 弹药：**pass@k vs pass^k**（p=0.6、k=5 时 pass@5≈99.0% 而 pass^5≈7.8%——业务可靠性要看连续成功率）；think tool 使 τ-bench airline pass^1 相对+54%；Veto 一票否决项；轨迹前缀回归（冻结首错前状态）=CI 级回归测试；SWE-bench Verified 2294 题人工质控留 500（评估成本降 80%）。〔Anthropic evals/think-tool + book ch7〕

**7.2 LLM Judge 校准**〔raw 评测簇〕
- L2：规则主判+LLM Judge 管语义+人工终判三层；Judge 与人工一致率 85% 才允许自动化；二元化 Rubric 使人机一致率 62%→92%（"一个独裁者好过十个民主者"）；分数异常先查 Rubric 再查版本——"别把尺子不准当成东西变差"。
- L3：题目级 Rubric（每题绑自己的标准）；评测体系不是设计出来的是被 Good/Bad Case 喂养的（指标 20→近 200 个）；badcase 五步 RCA：证据→收敛→分模块→定责→落盘。

**7.3 数据飞轮**〔raw AgentLoop 五篇〕
- L1：上线才是调优起点；飞轮=接入→观测→审计→数据集→评估→实验→经验库反哺。
- L2：两种模式互补——专家驱动建 Rubric 标准+经验库自动增益（召回阈值 0.6 只取 top1，注入位置"问题→规则→经验"+仅历史参考护栏；消融验证耗时 -30~40%、成本 -20~47%）；训练/验证集分离防 reward hacking；经验进化分级 lesson→pattern→instinct（置信度 <0.55 废弃）。
- 项目锚：EnergyOps 六层评测+工单信号自动回流、RuleArena 双集隔离——飞轮论文的实践版。

## 八 Python 后端与数据系统（后端官主战场）

> 12 标准答案原文必背：study/11 第 2.8 节 asyncio / 第 2.9 节 MQ / 第 2.10 节长任务 / 第 2.11 节降级。题库细节：raw 四份面试题。此处只放深挖弹药。

- **asyncio**：模型/检索/工具全是慢 I/O，await 让出 loop 承载在途请求；路由内禁止同步阻塞；TaskGroup 管生命周期、timeout/取消向下传播、Semaphore+bounded Queue 背压；CPU 密集进进程池。追问：coroutine vs Task、TaskGroup vs gather、SSE 断线恢复。
- **MySQL**：MVCC=undo log 版本链+ReadView 快照；RR 防幻读=快照读靠 MVCC、当前读靠临键锁；联合索引最左匹配+覆盖索引+索引下推；失效四式（函数/隐式转换/最左破坏/like 前缀）；redo/undo/binlog 两阶段提交；深分页用延迟关联。项目锚：P95 重构=重复 JOIN 定位+组合索引+预聚合。
- **Redis**：单线程=内存+无锁+epoll；6.0 网络 IO 多线程但命令仍单线程；RDB fork 快照 vs AOF everysec；缓存三问（穿透=空值/布隆、击穿=互斥锁、雪崩=随机过期）；分布式锁 SET NX PX+唯一 value+Lua 原子解锁；Redis ~10 万 QPS vs MySQL ~5 千。
- **MQ/分布式**：at-least-once→消费端幂等（唯一业务 ID/版本号/唯一约束）；丢消息三环节各设防；顺序=同 key 同分区单线程；Outbox 同事务写事件；CAP 中 P 必选、CP=ZK/AP=Eureka；分布式 ID 雪花结构与时钟回拨；限流四算法（令牌桶最优可应对突发）；TCC/Saga/本地消息表取舍。项目锚：幂等窗口+7 天自动回补+启动时补数（96.9→99.6%）。
- **推理服务 2 分钟版**（年包 50w 岗 JD 明确要求）：KV Cache=注意力中间态按 token 预计算缓存，自回归每步只算新 token——前缀缓存省钱的技术基础；Orca（OSDI'22）提出 iteration-level scheduling（以模型迭代而非请求为调度单位），是 continuous batching 的思想源头；vLLM=PagedAttention 显存分页+continuous batching 随到随插，吞吐数倍；流式 SSE 优化的是首字延迟 TTFT 不是总耗时；量化 INT8/FP8/AWQ 降显存换少量精度；投机解码=小模型草稿+大模型验证。被问"为什么 SSE 不等完整 JSON"答 TTFT。分布式共识被问 Raft 时答三件事：任期选举（随机超时+多数派）、日志复制（Append+日志匹配性质）、安全性（提交规则），对比一句 ZAB/Paxos，不展开论文。
- **推理服务常识**：KV Cache、vLLM、流式、Token 成本（年包 50w 岗清单）；SQLite 单机→多实例迁 PG/pgvector（可替代 Milvus）。

## 九 模型与算法基础

- **自注意力（可背）**：Q（我在找什么）K（我能提供什么）V（实际内容），softmax(QK^T/√dk)V；√dk 防点积过大使 softmax 进饱和区；多头=多子空间学不同关系。比 RNN 优：任意两 token 路径 O(1)（RNN 串行衰减）+大矩阵乘法天然 GPU 并行。复杂度 O(n²)，优化有 FlashAttention/稀疏/线性注意力。
- **位置编码（可背）**：自注意力是集合操作无位置信息；正弦余弦（可外推）→可学习（BERT 限 512 的根源）→**RoPE**（对 Q/K 做正比旋转，点积只依赖相对位置差，配 YaRN 到百万级上下文，LLaMA/Qwen/GLM 主流）→ALiBi（分数加线性负偏置，外推天然）。
- **微调判断**：才微调的三条件（开源基座弱/格式遵从性要求高/成本延迟硬约束）；微调的是四层能力（格式→工具选择→多步规划→异常纠错）；数据集=完整 Trajectory+Loss Mask+刻意混 10-20% 异常样本+维护 100-200 条评估集；LoRA 提升分布内行为不证明本质推理。
- **选型**：max Quality s.t. P95/Cost/Risk；按任务分桶 Eval，Router 输入难度/风险/延迟/预算/健康度；小模型靠 Harness 而非长 Prompt。

## 十 AI Coding 工程实践

- L1：Evidence-driven——需求→设计→测试先行→Proof（CI/截图/diff）→风险门禁→Postmortem 沉淀 Skill。〔study/13⑯〕
- L2：agentic coding 里 context window 是最需管理的资源；**必须给可运行检查，否则你成为验证环节**；Explore→Plan→Code→Commit；CLAUDE.md 只留代码推不出的规则（过长会被忽略）；subagent 隔离调查防实现者自评；"干净的会话+更好的 prompt 几乎总是胜过累积修正的长会话"。〔Anthropic CC best-practices〕
