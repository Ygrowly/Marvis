## 1. EnergyOps（锚点：执行可控）

**核心三句**（先于一切 bullet，§0.7 立意正本）：

1. **立意（A≠B）**：读数齐全 ≠ 能耗账可信；能调工具 ≠ 操作受控——做的是 **AI 接入核心业务系统的信任工程**（第三方数据进财务账、Agent 开写权限）。
2. **真差异**：执行前拦截 + 高风险人工确认是 2026 共识（Tool Call Guard / Edictum），不声称首创；差异在**业务能力级风险分级**（R 级配在业务能力上，不是通用安全策略）+ **与数据质量/责任门联动** + 可插拔配置；数据侧同理——7 类质量状态是「参差第三方数据 → 业务账」的领域格。
3. **证据**：完整率 96.8→99.7%、80 条越权拦截 100%、研判 18→6min（全 E2）。

**before 一句话**：行政按月手工对账、告警直发一天几十条淹没真问题、第三方累计读数直接相减出错账单、系统写操作无分级误操作直通账单——现在分层建模+质量治理自动出可信账、三层过滤 18→6min、坏数据进异常账、R 分级 Hook 前置拦截。

### EO1 四层数据模型 + 7 类质量状态 + 可信白名单（完整率 96.8→99.7%）
- **30 秒速答**：raw 不可信 → interval 定质 → hourly/daily 聚合，三账分流（用能账/异常账/结算账）；只有可信区间进聚合，坏数据进异常账不进用能账。
- **追问会怎么打**：① 四层各解决什么，能否合并？② 7 类质量状态怎么判定，举「倍率变更」例子？③ 白名单误杀好数据怎么办？④ 96.8→99.7 怎么算的？
- **深挖弹药**：完整率 = 有效区间 ÷ 应产生区间（604×24×4 ≈ 5.8 万/日）；口径唯一，自动聚合只做交叉核对，结算以抄表底稿为准（不抢）；病根格 =「把物理事实当业务事实用」——**坏数据的去处是异常账，不是消失**。
- **证据**：项目说明 §3/§6；§0.7.2 行 1。

### EO2 30 个 MCP 工具 + 6 类 Capability Bundle + R0/R1/R2 + Hook 校验链（完成率 83.3→95.8%、越权拦截 100%）
- **30 秒速答**：六类业务能力收敛为 30 个 MCP 工具 + 6 类 Bundle；R0/R1/R2 风险分级配在能力上，Before/After Tool + Before Model 三个 Hook 插桩点分别管越权、上下文膨胀、过程失忆；R2 未确认直接阻断。
- **追问会怎么打**：① Hook 链几个插桩点，各防什么？② R 分级怎么定，R2 未确认会怎样？③ 为什么 Hook 不是 Prompt 约束？换个业务怎么复用？④ 拦截 100% 的 80 条用例怎么构造？
- **深挖弹药**：R 级是 Hook 上的策略配置，不是独立机制；失败语义分级返回（NEEDS_CONFIRMATION / PARTIAL / TOOL_TIMEOUT）；**「核心 Loop 不随业务增改」**——业务只声明「哪个能力什么风险级要不要确认」（新简历取舍句，必讲）；80 条越权 = 跨租户/越权限/越范围三类构造；完成率口径 = 72 条固定任务集（同模型同权限）。
- **证据**：项目说明 §6/§14.3；§0.7.2 行 2；金山话术文件。

### EO3 查询重构（重复 JOIN/全表扫描 → 组合索引+预聚合）P95 20.4→2.8s；幂等窗口 + 状态持久化 + 7 天回补（96.9→99.6%）
- **30 秒速答**：设备归属关联导致每窗口重复 JOIN + 全表扫描；EXPLAIN 定位后按查询模式建组合索引，聚合结果预计算落表；重启缺口由任务状态持久化发现，启动时按窗口幂等键回补 7 天，重跑不重不漏。
- **追问会怎么打**：① 重复 JOIN 怎么产生、怎么定位？② 组合索引怎么设计，为什么预聚合能到 2.8s？③ 重启缺口怎么发现、回补怎么不重不漏？④ 幂等窗口的键是什么？
- **深挖弹药**：立意上这是**工程基本功，支撑机制，不单列创新**（§0.7.2 末行）——被问「算创新吗」就答支撑层；聚合成功率 = 成功窗口 ÷ 应执行窗口；补数对比取两个等长窗口；P95 ↓86.3% 是**派生值**：(20.4−2.8)/20.4 = 86.3%，追问直接给算式，不是另一组测量。
- **证据**：项目说明 §6/§7；§0.7.2 末行。

### EO4 「异常候选 ≠ 业务告警」三层分离（告警 -43%、研判 18→6min）
- **30 秒速答**：自适应基线从多日历史学正常形态输出候选 → 历史 dry-run 准入验证规则质量 → 告警指纹去重守住通知门槛；拆开的原因：识别准确率和打扰成本是两个目标，耦合在一起两者都做不好。
- **追问会怎么打**：① 三层各是什么，为什么拆？② 自适应基线怎么学正常形态？③ 误报和漏报怎么权衡，指纹去重会漏掉真问题吗？
- **深挖弹药**：病根格 =「告警 = 规则直发」；研判时间 = Incident 到首次分类的**中位时长**。
- **证据**：项目说明 §5/§8；§0.7.2 行 4。

### EO5 结算三道质量门（分摊守恒率 100%）+ 92 单元 + 30 回归（核心链路 98.4%）
- **30 秒速答**：事实源门（数据齐且可信）→ 预演门（分摊守恒校验）→ 责任门（行政确认 + 财务核验）；任一失败阻断正式账单生成——结算错误是不可逆外部影响，宁可延迟不可出错。
- **追问会怎么打**：① 三道门各挡什么，为什么任一失败是阻断不是告警？② 分摊守恒怎么校验？③ 测试怎么分层，回归集怎么维护？
- **深挖弹药**：病根格 =「AI 生成结果没人负责」——**AI 不能替代责任人的业务口径裁决**；结算财务口径与财务团队对齐（不抢）；92+30 覆盖统计口径、数据质量、工具参数、权限边界、失败恢复。
- **证据**：项目说明 §4.5/§7.4/§14.3；§0.7.2 行 5；金山话术。

## 2. 数驭穹图（锚点：数据可信）

**核心三句**（§0.7 立意正本）：

1. **立意（A≠B）**：SQL 能执行 ≠ 业务答案正确——语义层解决「理解对」，但语义层在 2025–2026 已是共识（SuperSonic / Wren AI / Kyligence）；**真正的最后一公里是治理与闭环**：口径错了能不能停（fail-closed）、结果能不能被证明（证据绑定）、答案能不能沉淀成资产（回写复用）。
2. **真差异（按防御力排序）**：① 口径治理一票否决（无对位物）→ ② 三重证据绑定 → ③ 协作沉淀回写 → ④ 不绑定数仓的轻量湖仓；「有语义层」「六阶段」只是入场券，不单当差异讲。
3. **证据**：150 条评测集「可执行且口径正确」78→91%（含人工复核）、100 条抽检复现一致率 100%、Token 18.4K→3.6K——全部 E2 固定评测集。

**before 一句话**：业务人员提工单等排期（周报取数 40→12min）→ 自助问数，拿到能交出去、能被追问的答案；数据团队从取数工单里出来做指标治理。

### SZ1 「SQL 能执行 ≠ 业务答案正确」六阶段可归因链路 + 限次自愈（30→8min、78→91%）
- **30 秒速答**：意图路由 → Domain Schema 检索 → NL2SemQL → SQL 生成 → 安全校验 → 执行；拆开使业务理解错误、SQL 生成错误、执行错误可独立归因；自愈区分语法错误/字段缺失/方言差异/权限拒绝，回灌执行反馈 + 有效 Schema + 错误标签，限次防震荡。
- **追问会怎么打**：① 六阶段各自产出什么，为什么拆？② 错误怎么归因到阶段？③ 自愈回灌什么信息，为什么限次？④ 为什么不让模型从 NL 直接生成 SQL？
- **深挖弹药**：直接 NL→SQL 无法独立验证「理解对」和「写对」；六阶段是入场券不是差异（真差异排序里没有它）；150 条评测集判定 =「可执行且口径正确」，含人工复核。
- **证据**：项目说明 §4/§13.3；§0.7 真差异排序。

### SZ2 五层查询安全边界（拦截 100%、误拦 2.7%）
- **30 秒速答**：租户权限 → 受治理 Tool 注册 → Tool Call Schema/Validator 校验（**tenant_id 服务端注入，模型报的不算**）→ 只读 SQL AST 审查（租户注入/超时/行数限制）→ 输出字段脱敏；核心姿态 = 把模型输出当不可信输入。
- **追问会怎么打**：① 五层各挡什么威胁？② 为什么把模型输出当不可信输入？③ AST 审查查什么？④ 300 条对抗请求怎么构造？⑤ 拦截 100% 会不会牺牲可用性？
- **深挖弹药**：对抗请求三类 = 提示注入诱导越权 / 跨租户 / 写操作；误拦 2.7% = 150 条正常查询里 4 条；**执行侧五层 vs 结果侧五层不是一回事**，被混问先分清。
- **证据**：项目说明 §4/§13.3 末行。

### SZ3 轻量湖仓物理隔离 + Artifact 外置（Token 18.4K→3.6K，↓80.4%）
- **30 秒速答**：文件/协同表格/同步数据以 Parquet 副本交 DuckDB 本地计算；强实时走只读受限连接（EXPLAIN 成本预估、慢查询熔断降级、独立配额）；分析负载与客户生产库物理隔离；大结果外置为 Artifact（Hot/Warm/Cold），模型只收口径摘要 + 聚合统计。
- **追问会怎么打**：① 哪些走 DuckDB、哪些走只读连接，路由依据？② 客户生产库被慢查询拖垮怎么办？③ 大结果外置后模型看到什么？
- **深挖弹药**：Token 降 80% 的本质是**「给模型结论，不给明细」**；↓80.4% 是**派生值**：(18.4−3.6)/18.4 = 80.4%，追问直接给算式；真差异第 4 位（不绑定数仓的轻量湖仓）——被问「凭什么不用数仓」答：目标客户没有数仓团队，也要用得起、部署得动。
- **证据**：项目说明 §4.11（慢 SQL 四招 + 权限撤销收敛）；§0.7.2。

### SZ4 3 套 Domain Pack + 领域路由 + 混合检索（Top-K Schema 召回 81→95%）
- **30 秒速答**：65 核心指标 + 120 术语别名 + 指标口径 + 表关联约束，来自行业调研 + 客户共建；关键词（精确术语）+ 向量（语义变体）+ 元数据过滤（域内收窄）三路混合检索。
- **追问会怎么打**：① Domain Pack 里具体有什么，怎么沉淀出来的？② 三路各解决什么？③ 新行业接入要多久？④ 召回率怎么算？
- **深挖弹药**：Top-K 正确表/字段命中即召回；与 EnergyOps 迁移「三件套」同构（字段/点位映射 + 领域规则 + 分级表）——**两项目复用性互证**，跨项目迁移题的弹药。
- **证据**：项目说明 §4/§13；§0.7.3。

### SZ5 语义资产健康度 + 口径一票否决 + 三重证据绑定（100 条抽检复现一致率 100%）
- **30 秒速答**：核心指标缺业务定义即暂停该域自动问数（fail-closed）；Schema/DDL 变更自动降级资产可信度；结果绑定 call_id / query_fingerprint / result_hash 三重证据，图表渲染校验失败降级占位块——**宁可显示异常，不出示假数据**。

- **深挖弹药**：**本条是真差异第 1、2 位的承载**（口径一票否决无对位物、三重证据绑定），数驭穹图「最后一公里是治理与闭环」立意的主战场；过期语义不能冒充当前口径；抽检复现 100% 是**抽检口径（100 条抽样），不是全量一致**——账本专门标过，别说错。
- **证据**：项目说明 §4/§13；§0.7 真差异排序。

## 3. RuleArena（锚点：结果可证）

**核心三句**（§0.7 立意正本）：

1. **立意（A≠B）**：ACK ≠ 业务成功；单次成绩 ≠ 可复现能力——把「上线前的评测分数」变成「**发布时的门禁行为**」：门禁的价值在不放行时兑现（57% < 75% 如实拒绝）。
2. **真差异**：pass@k / pass^k 沿用 τ-bench（Sierra，2024）是依据不是首创；**产品化组合无对位物**——运行时门禁 + 独立 Oracle 不变量裁决 + 反例回归资产 + 如实拒绝放行。
3. **证据**：裸跑 ¥1920 → 门禁 0 笔（15 工单 × 2 模式 × 3 重复，E2 可复现）；pass@3 = 8/14 vs pass^3 = 1/14；机制层误报 0 / 泄漏 0 / 稳定重放 42/42。

**before 一句话**：上线后靠对账差异和客户投诉发现问题 → 上线前预算内搜索 + 独立裁决 + 如实放行或拒绝；运营/风控从「不敢让 Agent 碰写操作」变成「有门禁数据才放行」。

### 附 A1 · NL→RuleSpec 编译链路（**非简历 bullet**——7→5 压缩时降级为口述弹药，被问 RuleArena 工作原理时的底稿）
- **30 秒速答**：自然语言 → 候选 RuleSpec → 确定性校验 → 歧义清单 → 人工确认 → 不可变 RuleVersion；歧义必须人工澄清冻结，模型不自行决定语义；限定优惠/退款/积分/会员四域固定原语才能确定性证明；未确认规则不得进入攻击运行。
- **追问会怎么打**：① 为什么编译成契约而不是直接让 Agent 理解规则？② 歧义清单怎么产生？③ 为什么禁止动态表达式求值？
- **深挖弹药**：确定性证明的前提是**原语封闭**——原语不封闭就不存在可判定的不变量；「Issue 描述了目标 ≠ Issue 定义了完成」，完成由证据证明。
- **证据**：项目说明 §2/§5；§0.7.2。

### RA1 「候选风险 ≠ 确认漏洞」防自证三角（Simulator → Sandbox → Oracle）
- **30 秒速答**：Agent 提议只算候选 → Reference Simulator 快速剪枝 → 干净 Commerce Sandbox（幂等键 / ActionReceipt / 只追加事件）真实 HTTP 重放 → 独立 Oracle 按资金守恒、状态生命周期、幂等不变量裁决；裁决以冻结 RuleSpec 为基准、**每步重读权威状态而非信任 Receipt**；Agent 全程无法触达 Ground Truth。
- **追问会怎么打**：① Oracle 依据什么不变量？② Agent 能不能污染 Ground Truth？③ Simulator 会不会滤掉真 bug，晋升靠什么？
- **深挖弹药**：防自证的关键 = 裁决者与被裁决者隔离（Oracle 不读 Agent 的任何中间结论）；Simulator 只做剪枝不做裁决，晋升必须过 Sandbox 实测 + Oracle 判定。
- **证据**：项目说明 §2/§3/§14。

### RA2 门禁实测（裸跑 60% / 多退 ¥1920 → 门禁 100% / 0 笔，而且更省）
- **30 秒速答**：同一份 Agent 跑两次，15 张工单 × 2 模式 × 3 次重复：裸跑组 6 张工单重复退款、多退 ¥1920、终态正确率 60%；加门禁后重复退款 0 笔、终态正确率 100%、误拦 0——**而且更省**：少发 30 次工具调用、平均耗时低 0.3s。
- **追问会怎么打**：① 加了门禁为什么反而更快更省？② 误拦 0 是怎么保证的？③ 这个实验证明的是「规则安全」吗？
- **深挖弹药**：「更省」的原因 = 坏路径在门禁处被拦掉，省掉无效工具调用与重试；门禁承诺「预算内未发现」，**不承诺「规则安全」**——分层不混淆；**两项指标必须并列报（终态正确率 ≠ 无资损），不许合并成一句「正确率 100%」**——账本红线；这是全库唯一一组「裸跑 vs 门禁」对照实验，E2 可复现。
- **证据**：项目说明 §0.6；账本 §5.2。

### RA3 双评测集 + 归一化预算消融 + pass@3 vs pass^3（8/14 vs 1/14、57% < 75% 如实拒绝）
- **30 秒速答**：development 21 + hidden 17 物理隔离（Runtime 连读都读不到，防针对考纲训练）；Random / BFS 基线在同一归一化预算下比较，证明策略增益不是预算堆出来的；hidden 重复 3 次暴露 **pass@3 = 8/14 而 pass^3 = 1/14**——单次成绩掩盖搜索不可复现；Release Gate 据此如实拒绝放行（57% < 75% 门槛）；机制层误报 0 / 泄漏 0 / 稳定重放 42/42。
- **追问会怎么打**：① hidden 怎么隔离、防什么？② 为什么做预算归一化消融？③ 门禁承诺的是什么、不是什么？④ 21+17 的规模会过拟合吗？⑤ pass@3 和 pass^3 为什么要分开报？
- **深挖弹药**：dev 集 Multi-strategy 5/14 > BFS 2/14 说明**策略有增益**；hidden pass^3 = 1/14 说明**增益不可复现**——两件事必须并列讲，这正是「必须有运行时门禁」的实测依据；pass^3 定义（同一任务 3 次全部通过的比例）要能脱口而出。
- **证据**：项目说明 §6/§9；§0.7 核心三句。

### RA4 四个真实缺陷 + Delta Debugging 最小反例 + FSM/Checkpoint/ACTION_UNKNOWN
- **30 秒速答**：四个缺陷全是真实运行打出来的——工具层把沙箱「业务拒绝」（HTTP 200 + status: REJECTED）读成成功、504 未走恢复路径、同幂等键重放被当成新写入、门禁理由码泄给 Agent；修完补回归测试后重跑出 RA3 的数字。确认违规经删除式 Delta Debugging 压到 1-minimal 并绑定证据链（请求序列 + 回执 + 事件 + 状态 Diff + 违反的不变量）；修复版本自动重放历史反例；显式 FSM 支持 Checkpoint 恢复与 ACTION_UNKNOWN 超时语义。
- **追问会怎么打**：① 四个缺陷分别暴露什么机制缺口？② 反例为什么压到 1-minimal？③ 旧反例怎么防复发？④ ACTION_UNKNOWN 是什么问题，怎么解？
- **深挖弹药**：四个缺陷 = 四条机制层教训——成功判定要看**业务语义**不是 HTTP 码 / 超时必须有恢复路径 / 幂等键重放语义要明确（同键 = 查询不是新写入）/ 面向 Agent 的信息要脱敏（理由码泄给 Agent 等于把考卷给考生）；ACTION_UNKNOWN 的解法 = 超时后**查询权威状态**防重复副作用，不靠猜测；「执行中打出并修正」是本简历最值钱的叙事——缺陷不是设计出来的，是跑出来的。
- **证据**：项目说明 §6/§9/§10。

## 6. 三遍法（自练协议，不需要对话陪练）

1. **第 0 遍 · 通读（30 分钟/项目）**：通读本图该项目的核心三句 + 5 条 bullet，只求知道骨架长什么样，**不背**。
2. **第 1 遍 · 提取轮（约 90 分钟/项目，建议次日）**：对着简历 PDF 逐条——先合上材料自己讲 60–90 秒（手机录音、掐表），再对照标缺口；**只在缺口处停留**，缺口写成事实句（"能说 X，说不清为什么 Y"）进 `questions.md`；最后过一遍 §4 数字总表（遮罩自测）。
3. **第 2 遍起 · 回抽轮（第 1/3/7/14 天，每次 15–20 分钟）**：只回听录音 + 只看「30 秒速答」行重讲；三项目 90 秒全貌（总主线收尾）每天开场一遍。
4. **过关线**：闭卷 3 分钟 + 两层追问 + 数字带口径；§5 写型 5 项闭卷写出来。
