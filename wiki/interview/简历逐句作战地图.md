## 2. 金山 EnergyOps 逐句（锚点：执行可控）

### 2.1 四层数据模型 + 7 类质量状态 + 可信白名单（完整率 96.8→99.7%）
- **考什么**：数据建模功底；为什么不把原始读数直接聚合。
- **追问链**：① 四层各解决什么，能否合并？② 7 类质量状态怎么判定，举个"倍率变更"例子？③ 白名单误杀好数据怎么办；96.8→99.7 怎么算的？
- **骨架**：raw 不可信 → interval 定质 → hourly/daily 聚合；只有可信区间进聚合，坏数据进异常账不进用能账；完整率 = 有效区间 ÷ 应产生区间（604×24×4≈5.8 万/日）；口径唯一，自动聚合只做交叉核对，结算以抄表底稿为准。
- **证据**：EnergyOps 项目说明第 3 节/第 6 节；量化口径文件。**状态：✅ 口径已同步**

### 2.2 30 个 MCP 工具 + 6 类 Capability Bundle + R0/R1/R2 分级 + Hook 校验链（完成率 83.3→95.8%、越权拦截 100%）
- **考什么**：Agent 治理范式（本简历最硬的一条，A 类公司必深挖）。
- **追问链**：① Hook 链有哪几个插桩点，各防什么？② R 分级怎么定，R2 未确认会怎样？③ 为什么用 Hook 而不是 Prompt 约束？换一个业务怎么复用？④ 拦截 100% 的 80 条用例怎么构造？
- **骨架**：Before/After Tool + Before Model 三个插桩点，分别管越权、上下文膨胀、过程失忆；R0/R1/R2 是 Hook 上的策略配置不是独立机制；R2 未确认直接阻断，失败语义分级返回（NEEDS_CONFIRMATION/PARTIAL/TOOL_TIMEOUT）；治理策略可插拔，业务只声明"哪个能力什么风险级要不要确认"，核心 Loop 不随业务改；80 条越权用例=跨租户/越权限/越范围三类构造。
- **证据**：项目说明第 6 节/第 14.3 节；金山话术文件。**状态：✅ 口径已同步 ｜ ⚠️ 补课：能写出 Hook 拦截 R2 的伪代码、任务状态外置字段**

### 2.3 查询重构（重复 JOIN/全表扫描 → 组合索引+预聚合）P95 20.4→2.8s；幂等窗口+状态持久化+7天自动回补（96.9→99.6%、补数 -72%）
- **考什么**：SQL/后端性能功底 + 可靠性设计（后端面试官的主战场）。
- **追问链**：① 重复 JOIN 是怎么产生的，怎么定位的？② 组合索引怎么设计的，为什么预聚合能到 2.8s？③ 服务重启后聚合缺口怎么发现的、回补怎么保证不重不漏？④ 幂等窗口的键是什么？
- **骨架**：设备归属关联导致每窗口重复 JOIN + 全表扫描；EXPLAIN 定位后按查询模式建组合索引，聚合结果预计算落表；重启缺口由任务状态持久化发现，启动时按窗口幂等键回补 7 天，重跑不产生重复记录；聚合成功率=成功窗口÷应执行窗口，补数对比取两个等长窗口。
- **证据**：项目说明第 6 节/第 7 节；量化口径。**状态：⚠️ 补课：写出幂等键设计+回补流程**

### 2.4 「异常候选 ≠ 业务告警」三层分离（告警 -43%、研判 18→6min）
- **考什么**：产品设计判断力（为什么不是一条告警规则直发）。
- **追问链**：① 三层分别是什么，为什么拆开？② 自适应基线怎么学正常形态？③ 误报和漏报的权衡，指纹去重会不会漏掉真问题？
- **骨架**：自适应基线从多日历史学正常形态输出候选 → 历史 dry-run 准入验证规则质量 → 告警指纹去重守住通知门槛；拆开的原因：识别准确率和打扰成本是两个目标，耦合在一起两者都做不好；研判时间=Incident 到首次分类的中位时长。
- **证据**：项目说明第 5 节/第 8 节；量化口径。**状态：✅**

### 2.5 结算三道质量门（分摊守恒率）+ 92 单元 + 30 回归（核心链路 98.4%）
- **考什么**：对"钱的正确性"的工程态度；测试体系。
- **追问链**：① 三道门各挡什么，为什么任一失败要阻断而不是告警？② 分摊守恒怎么校验？③ 测试怎么分层，回归集怎么维护？

## 3. 数驭穹图逐句（锚点：数据可信）

### 3.1 「SQL 能执行 ≠ 业务答案正确」六阶段链路 + 限次自愈（Bad Case 30→8min、78→91%）
- **考什么**：NL2SQL 架构设计（B 类公司核心题）；为什么要拆六阶段。
- **追问链**：① 六阶段各自产出什么，为什么要拆？② 错误怎么归因到阶段？③ 自愈回灌什么信息，为什么限次？④ 为什么不让模型从 NL 直接生成 SQL？
- **骨架**：意图路由→Domain Schema 检索→NL2SemQL 语义解析→SQL 生成→安全校验→查询执行；拆开使业务理解错误、SQL 生成错误、执行错误可独立归因；自愈区分语法错误/字段缺失/方言差异/权限拒绝，回灌执行反馈+有效 Schema+错误标签，限次防震荡；直接 NL→SQL 无法独立验证"理解对"和"写对"。
- **证据**：数驭穹图项目说明第 4 节/第 13.3 节（150 条评测集口径）。**状态：⚠️ 补课：AnalysisIntent→SemQL 关键字段与校验**

### 3.2 五层查询安全边界（拦截 100%、误拦 2.7%）
- **考什么**：Agent 安全设计（大厂必问，数据岗一票否决区）。
- **追问链**：① 五层各自挡什么威胁？② 为什么把模型输出当不可信输入？③ AST 审查查什么？300 条对抗请求怎么构造？④ 拦截 100% 会不会牺牲可用性？

### 3.3 湖仓物理隔离 + Artifact 外置（Token 18.4K→3.6K）
- **考什么**：架构权衡（为什么不是所有查询都走生产库）。
- **追问链**：① 哪些走 DuckDB 本地、哪些走只读连接，路由依据？② 客户生产库被慢查询拖垮怎么办？③ 大结果外置后模型看到什么？
- **骨架**：文件/协同表格/同步数据 → Parquet 副本交 DuckDB 本地计算；强实时 → 只读受限连接（EXPLAIN 成本预估、慢查询熔断降级、独立配额）；分析负载与生产库物理隔离；大结果外置为 Artifact（Hot/Warm/Cold），模型只接收口径摘要+聚合统计——Token 降 80% 的本质是"给模型结论不给明细"。
- **证据**：项目说明第 4.11 节（慢 SQL 四招+权限撤销收敛）。**状态：✅**

### 3.4 3 套 Domain Pack + 领域路由 + 混合检索（Top-K Schema 召回 81→95%）
- **考什么**：语义层/领域知识工程（NL2SQL 区分度所在）。
- **追问链**：① Domain Pack 里具体有什么，怎么沉淀出来的？② 混合检索三路各解决什么？③ 新行业接入了要多久？召回率怎么算？

## 4. RuleArena 逐句（锚点：结果可证）

> **门禁组已实测**（裸跑 60% / 6 笔 ¥1920 → 加门禁 100% / 0 笔，见项目说明 §0.6）；搜索层见 4.3 的 golden-v4 数字。两组必须并列讲。

### 4.1 NL→RuleSpec 编译链路（固定原语、禁动态求值、未确认不进攻击）
- **追问链**：① 为什么编译成契约而不是直接让 Agent 理解规则？② 歧义清单怎么产生？③ 为什么禁止动态表达式求值？
- **骨架**：自然语言→候选 RuleSpec→确定性校验→歧义清单→人工确认→不可变 RuleVersion；歧义必须人工澄清冻结，模型不自行决定语义；限定优惠/退款/积分/会员四域固定原语才能确定性证明；未确认规则不得进入攻击运行。
- **证据**：RuleArena 项目说明第 2 节/第 5 节。**状态：✅ 设计可讲 ｜ ⚠️ 补课：写出一条不变量判定逻辑（退款后积分守恒）**

### 4.2 「候选风险 ≠ 确认漏洞」防自证三角
- **追问链**：① Oracle 怎么裁决，依据什么不变量？② Agent 能不能污染 Ground Truth？③ Simulator 会不会滤掉真 bug，晋升靠什么？
- **骨架**：Agent 提议只是候选 → Reference Simulator 快速剪枝 → 独立 Commerce Sandbox（幂等键/ActionReceipt/只追加事件）真实 HTTP 重放 → 独立 Oracle 按资金守恒/状态生命周期/幂等不变量裁决；裁决以冻结 RuleSpec 为基准、每步重读权威状态而非信任 Receipt；Agent 全程无法触达 Ground Truth。
- **证据**：项目说明第 2 节/第 3 节/第 14 节。**状态：✅**

### 4.3 双评测集 + 发布门禁 + 三隔离策略 + 归一化预算消融（误报 0、重放 42/42、泄漏 0）
- **追问链**：① hidden 17 怎么隔离，防什么？② 为什么做预算归一化消融？③ 门禁承诺的是什么、不是什么？④ 21 + 17 的规模会过拟合吗？⑤ **为什么 `pass@3` 和 `pass^3` 要分开报？**
- **骨架**：development 21 + hidden 17 物理隔离，hidden 连运行时都读不到，防针对考纲训练；Random/BFS 基线在同一归一化预算下比较，证明策略增益不是预算堆出来的；门禁承诺"预算内未发现"，不承诺"规则安全"——分层不混淆。**最新实测（golden-v4）：dev 集 Multi 5/14 已高于 BFS 2/14，但 hidden 重复三次 `pass@3 = 8/14`、`pass^3 = 1/14`——单次成绩掩盖了搜索不可复现，这正是"必须有运行时门禁"的实测依据。**
- **证据**：项目说明第 6 节/第 9 节。**状态：✅ 已实测**（golden-v4 / deepseek-v4.1-flash）

### 4.4 Delta Debugging 最小反例 + 回归资产 + FSM/Checkpoint/ACTION_UNKNOWN
- **追问链**：① 反例为什么要压到 1-minimal？② 修复后怎么保证旧反例不复发？③ ACTION_UNKNOWN 是什么问题，怎么解？
- **骨架**：删除式 Delta Debugging 压缩到最小可复现步骤，绑定完整证据链一键导出 pytest；修复版本自动重放全部历史反例+正常 Case，回归资产随使用增厚；写动作带幂等键+Receipt，超时进入 ACTION_UNKNOWN 后查询权威状态防重复副作用；Checkpoint 恢复 Run 状态，COMPLETED≠漏洞确认。
- **证据**：项目说明第 6 节/第 9 节/第 10 节。**状态：⚠️ 补课：幂等键+Receipt+ACTION_UNKNOWN 状态流；公开 repo README（说服力折半项）**
