## ground ground-net · 网络基础地基包

**定位**：八股高频层 + Agent 后端真正要用的部分：HTTP/TCP/TLS 的链路观、SSE/WebSocket 选型（Agent 流式输出天天用）、高并发连接模型。不含抓包技巧与协议字段背诵。

**心智模型**：网络 = **一层层委托，每层只解决一段不可靠**：TCP 管「包会丢会乱」，TLS 管「会偷会改」，HTTP 管「语义与缓存」。所以排查铁律是先定位**断在哪一层**。而服务端到客户端的演进（轮询 → SSE → WebSocket）是一条线：从「反复问」到「挂着听」——Agent 流式输出选 SSE 的全部理由都在这条线上：单向、文本、够用，就不该为它上双向协议。

**必会清单**：
- URL → 响应全链路：DNS → TCP 握手 → TLS 握手 → HTTP → 渲染；每层背一个典型失败点（解析失败/超时/证书/状态码）[@网络基础-1]
- TCP 三次握手的理由：双方都要确认「收与发」两个方向的能力，两次不够 [@网络基础-1]
- SSE vs WebSocket vs 轮询：单向文本流够用就不上双向协议；断线重连 SSE 内建 [@网络基础-2]
- 心跳与重连是谁的责任：连接断了应用层要能恢复现场（续传/幂等）[@网络基础-2]
- C10K：每连接一线程为什么崩（切换与内存），事件循环 + epoll 怎么救 [@网络基础-3]

**学习路径**：
1. 先学全链路：所有网络题的定位框架 [@网络基础-1]
2. 再学推送三件套：结合 Agent 流式输出的真实场景记选型 [@网络基础-2]
3. 最后扛连接：与操作系统地基的 IO 主线并学，epoll 一课两处用 [@网络基础-3]

**验收门**：
- 白板画出一次 HTTPS 请求的分层与每层失败点 [@网络基础-1]
- 一句话答「Agent 输出为什么常用 SSE 而不是 WebSocket」 [@网络基础-2]
