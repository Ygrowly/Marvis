## ground ground-llm · LLM 与上下文 地基包

**定位**：AI 四簇的第一块地基，只回答四个问题：模型为什么这样、上下文该放什么、输出怎么被约束住、钱花在哪。不含训练侧。

**心智模型**：**不可靠是前提不是缺陷**——概率性只能收敛不能消除，工程都围绕这一点展开。注意力是 n² 关系 = 有限预算：token 越多预算被摊薄（context rot），所以**窗口是容量不是质量**。上下文工程就是找最小的高信号 token 组合，四个手段：选择 / 压缩 / 隔离 / 缓存。

**必会清单**：
- 成本平方增长：每轮重发全部历史，40 轮 × 15K 累计输入 12.3M token，是最后一轮的 20.5 倍 [@LLM与上下文-2]
- Context 是视图、State 是运行权威、Memory 是派生物需治理；恢复执行先查权威状态 [@LLM与上下文-2]
- 摘要必留六项：副作用记录丢了会导致写操作被重复执行 [@LLM与上下文-2]
- 同一 token 四种价：输入 1× / 缓存写 1.25×（1h TTL 2×）/ 缓存读 0.1× / 输出 5× [@LLM与上下文-2]
- 降本顺序：缓存命中 → 删拐杖 → 压缩 → 调 effort；压缩是最后手段 [@LLM与上下文-2]
- 结构化输出三层：提示约束 / 解码约束（strict 把非法 token 概率压成 0，有 20 工具 / 24 参数硬上限）/ 事后校验 [@LLM与上下文-3]
- 幻觉是四成因叠加，RAG 必要不充分：治其中一个成因可能加剧另一个 [@LLM与上下文-1]
- 拐杖 = 曾有效现在只加成本的指令：清六类拐杖后成本降 14.6%、准确率升 5.3%（Anthropic） [@LLM与上下文-3]

**学习路径**：
1. 先学「模型为什么不可靠」：不理解它，就会把工程问题当成换模型问题 [@LLM与上下文-1]
2. 再学「上下文怎么装配与维持」：预算有限是装配与成本两个问题的共同前提 [@LLM与上下文-2]
3. 最后「输出怎么被约束与验收」：从「请求它做对」升级成「结构上做不错」 [@LLM与上下文-3]

**验收门**：
- 能对一个 40 轮对话当场算出累计成本量级，并给出至少两条降本动作的先后顺序 [@LLM与上下文-2]
- 能讲出「同一个输出约束需求」在三层里各怎么落地、各自的失效方式 [@LLM与上下文-3]
