## ground ground-redis · Redis 地基包

**定位**：缓存与内存数据结构服务——面试必问，也是最容易出「事故题」的模块。范围：单机数据结构与持久化、缓存一致性、生产大 key/热 key；集群与哨兵只在主线四带过，不含运维深水区。

**心智模型**：快是两条的乘积——**内存比磁盘快 4–5 个数量级 + 单线程事件循环免去锁与上下文切换**。五个结构全是「为特定访问模式定制的内存索引」。而它的三类风险共用一个根源：**内存是易失且昂贵的**——易失，所以持久化在赌（快照还是日志）；昂贵，所以只放热数据、缓存在骗（与 DB 两份真相）；单线程，所以一个慢命令或大 key 就能堵住所有人。

**必会清单**：
- 五结构选型：String 计数、Hash 对象、List 队列/流、Set 交并差、ZSet 排行榜（跳表）[@Redis-1]
- 单线程为什么反而快：内存操作 + IO 多路复用；瓶颈在网络带宽与慢命令，不在 CPU [@Redis-1]
- RDB 是某刻快照（恢复快、丢窗口），AOF 是追加日志（丢得少、重放慢）；生产用混合 [@Redis-2]
- 缓存三事故的根因与解法：穿透（查不存在 → 布隆/空值缓存）、击穿（热点过期 → 互斥/逻辑过期）、雪崩（同时过期 → 错峰 TTL）[@Redis-3]
- 一致性默认答案：Cache Aside，先更 DB 再删缓存；「删」而非「更」是因为并发写会把旧值写回 [@Redis-3]
- 大 key/热 key：先发现（统计/采样），再拆（hash 分片）或挡（本地缓存）[@Redis-4]

**学习路径**：
1. 先学结构与快：选型能力是一切面试题的载体 [@Redis-1]
2. 再学持久化：先懂「易失」才懂后面全部权衡 [@Redis-2]
3. 然后缓存三事故：与 MySQL 业务并发主线联动着学 [@Redis-3]
4. 最后生产不出大事：大 key/热 key 是上面三条在真实体量下的样子 [@Redis-4]

**验收门**：
- 给一个场景选结构并说出「访问模式 → 为什么是它」 [@Redis-1]
- 三类事故各自一句话讲清根因与解法 [@Redis-3]
- 能答「为什么先更 DB 再删缓存，而不是更新缓存」 [@Redis-3]
