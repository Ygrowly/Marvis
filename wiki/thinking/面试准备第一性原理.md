# 面试准备第一性原理

> 来源：[[2026-09-08-面试准备第一性原理-乐元素冲刺与通用打法|raw 素材正本]]（综合 `raw/面试官对历史实习都会问哪些东西？.md`、`raw/面试官描述需求能力.md`、`raw/年包50w的字节 Agent 岗，到底要会啥_牛客网-2026-08-28T235113+0800.md`）。
> 2026-09-08 经本人确认采纳为**所有面试准备的总操作系统**，优先级高于零散技巧。同日补充 [[如何深挖自己的项目-飞书云文档-2026-09-08T104638+0800|深挖三问]]（见 §3.5，"挖"环节的审讯脚本）。

## 一、原理本身

> **面试官只有一个问题要回答："把我的需求交给这个人，他能不能扛住？"**
> 而他唯一的信息来源，是你讲述经历时暴露出来的**判断痕迹**。

三个不受公司、岗位影响的推论：

1. **面试不是知识考试，是证据采集。** 背八股、跑 Demo 都只是入场券，不是证据。
2. **"真做过"的验证方式 = 三种痕迹：**
   - **迭代痕迹**：想做 A → 不行 → 换成 B。只有一个版本的故事 = 背教程。
   - **对比痕迹**：选 A 弃 B，能说出两者优缺点 + 自己场景的约束。"因为主流" = 零分。
   - **复盘痕迹**：重做会改什么？最蠢的决策是什么？答不出 = 没想过上线后的事。
3. **准备 ≠ 学更多。准备 = 把做过的事"开矿"成决策链 + 大量口述输出。**

个人诊断（2026-09-08）：短板排序 **口述输出 > 决策链整理 > 知识面**。系统设计是强项，但只在"讲出来"那一刻才变成分数。

## 二、三层框架（别混用，别错位）

| 文档 | 回答的问题 | 层面 |
|---|---|---|
| 面试官对实习问什么 | **怎么讲**：STAR 骨架 + 三问结构 | 表达结构 |
| 面试官描述需求能力 | **讲多深**：功能层(入场券)→设计层(及格线)→工程层(加分项) | 内容深度 |
| 字节 Agent 岗要会啥 | **面什么**：后端基本功 × AI 工程落地 × 业务理解 | 岗位地图 |

**常见错位**：用"岗位地图"层的努力（再学一个框架）掩盖"内容深度/表达结构"层的欠账（没有决策链、没口述过）。感觉"方向偏了"就是这个根源。**判断规则：下次想"再学点什么"时，先问——这段经历挖成决策链了吗？口述过关了吗？没有就先挖。**

## 三、每场面试的最小动作：45 分钟循环

```
挖（15min，番茄钟 1）：挑一段经历，逼问三个问题——
  为什么当时这么做？还考虑过什么、为什么放弃？
  出过什么问题、怎么定位怎么修的？

写（15min，番茄钟 2）：写成书面稿。
  自检：有没有数字？有没有对比？有没有"后来发现不行"？

说（15min，番茄钟 3）：口述录音 3 分钟讲完，回听。
  听感标准：面试官不打断，3 分钟内能否得出"这人真做过"？
```

口头禅自检：出现"我们用了""因为主流/常用"而没有"当时还想过 A，因为场景约束 X 选了 B，后来发现 C"——就是没挖透，回炉。

### 3.5 "挖"环节的审讯脚本：深挖三方向（2026-09-08 补充）

> 来源：[[如何深挖自己的项目-飞书云文档-2026-09-08T104638+0800|raw 素材]]。核心逻辑一句话：**把项目当成真正要上线的产品来思考**——每个技术选择有理由、每个实现考虑边界、每个功能想"1000 个用户同时用会怎样"。项目不需要真有上万 QPS，但要证明你思考过。

**方向一：技术选型——"为什么用它而不是另一个"**（每个选型必答三问）

1. 这个场景的核心需求是什么？
2. 有哪些备选方案？各自的取舍是什么？
3. 最终选了什么？在我的场景下为什么它最合适？

| 选型场景 | 面试官想听的 | 踩雷回答 |
|---|---|---|
| LangChain vs 自研（Agent 岗必考） | 上手快但黑箱多、调试成本高 vs 控制力强但造轮子成本高——讲清自己链路复杂度与可观测性要求 | "star 多" / "自研显得厉害" |
| 消息队列 Kafka vs RabbitMQ | 日志/事件流吞吐优先→Kafka 分区模型；任务分发需细粒度确认→RabbitMQ ack | "Kafka 流行" |
| Redis vs 本地缓存 | 多实例一致性难保证→Redis；单机小数据量→本地缓存省网络 RT | "Redis 快" |
| MySQL vs MongoDB | 强事务联表→MySQL；schema 迭代快、嵌套文档→MongoDB；讲清自己的数据模型 | "NoSQL 高级" |

**方向二：技术细节——"你到底写了什么"**：不是报 API 名，而是讲清数据怎么流转、模块怎么交互、异常怎么兜底——设计是怎么解决问题的。

**方向三：边界与规模——上线视角**（原文截断，按导语推断）：每个功能想"真有 1000 个用户同时用会怎样"——限流、降级、失败兜底。与生产四问（Q-2026-006）互为印证。

**用法**：45 分钟循环的"挖"环节，按 选型三问 → 数据流/兜底 → 上线边界 的顺序过一遍那段经历，三条痕迹（迭代/对比/复盘）自然就出来了。

## 五、面试后的强制动作（唯一新增纪律）

1. **24h 内**：被问住的每个问题 → `questions.md` 新增条目（写清被谁问、卡在哪一层：表达/深度/知识）。
2. **表达层卡壳** → 回 45 分钟循环的"说"；**深度层卡壳** → 回"挖"；**知识层缺口** → 才允许进入学习（面试间隙做，不占冲刺时间）。
3. 面试间隙（非前夜）补硬通货：RAG 全链路选型、Agent 核心机制（ReAct/Plan-and-Execute/Memory/Tool Calling/MCP）、推理侧（KV Cache/vLLM/流式/Token 成本）。

## 六、一句话

> 面试不考你知道多少，考你想过多深、讲得多清。
> 方向从"再学点什么"切换到"把做过的东西挖成决策链，再大声讲出来"。
