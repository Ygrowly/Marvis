## 6. 方言桥（MySQL 问法 ←→ PG 项目证据）

> **这张表是本卡的安全网**：你项目全是 PostgreSQL，岗位栈是 MySQL。混着说就是下一个「SSE 是短连接」。

| 面试官问的（MySQL / InnoDB） | 你项目里的（PostgreSQL） | 关键差异 | 你该怎么说 |
|---|---|---|---|
| 聚簇索引、回表 | 堆表（heap），索引存 ctid 指向行 | InnoDB 是**索引组织表**，主键即数据顺序；PG 所有索引都是二级索引 | 「项目里 PG 是堆表，MySQL 是索引组织表，所以 MySQL 主键选择对性能影响更大」 |
| MVCC：undo log 版本链 + ReadView | 元组多版本留在堆里，靠 xmin/xmax + vacuum | MySQL 旧版本进 undo log 需 purge；PG 死元组需 vacuum | 「两者读都不加锁，但版本存放位置和回收方式不同」 |
| binlog（server 层逻辑日志） | WAL + 逻辑复制 | 复制机制与日志层级不同 | 「MySQL 用 binlog 做 CDC，PG 用逻辑复制 / WAL——我在数驭穹图两种都适配过」 |
| 间隙锁 / next-key lock（RR 默认） | 无间隙锁，靠 SSI 做可串行化 | 幻读的处理机制不同 | 「MySQL RR 靠 next-key lock 防幻读，PG 靠快照隔离，需要真串行时上 SSI」 |
| Online DDL / pt-osc / gh-ost | `CREATE INDEX CONCURRENTLY` | 都有在线方案，工具不同 | 类比讲即可，不要说「MySQL 也用 CONCURRENTLY」 |
| 默认隔离级别 RR | 默认 RC | 默认值不同 | 「我项目默认 RC，MySQL 默认 RR，所以你们库里的 RR 行为我要先确认」 |

**铁律**：面试时说项目，一律说「PostgreSQL」；被问 MySQL 时，先答 MySQL 的机制，再补「我项目里 PG 对应的是……，差异在……」。**绝不把 PG 的说法当成 MySQL 的答案。**
