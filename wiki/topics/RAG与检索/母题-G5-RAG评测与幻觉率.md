**题目**：面试官问——"你们怎么证明这个 RAG 系统是好的？检索指标很好但答案还是差，你怎么排查？"

**母题**：**"检索指标好但答案差"这句话本身说明了什么——为什么一个端到端的分数永远定位不了问题？**

**为什么重要**：这是 RAG 面试的**分水岭题**。答"我们用准确率评测"的人，会在被追问"那准确率低的时候你改哪里"时卡住。**这道题真正考的是"你的评测能不能定位"**——不能定位的评测，只是一张成绩单。

## 一、教材

### 1. 前提：一个端到端的分数，定位不了问题

【推导】**RAG 的失败发生在三个不同的地方，而端到端指标把它们全混成一个数**：

```text
① 证据没被捞到        → 摄取 / 切分 / 查询改写 / 召回的问题
② 捞到了但没进上下文   → 重排 / 去重 / token 预算的问题
③ 进了上下文还是答错   → 生成 / Prompt / 引用 / 模型的问题
```

【推论】**一个"准确率 78%"告诉不了你该动哪一段**——而这三段的修复动作完全不同、成本也差一个数量级（改切分要重建索引，改 Prompt 只是改几行字）。

【事实】archive/study-courses/03 给的归因链就是按这个顺序设计的：

::figure rag-failure-attribution.svg | 答案失败的归因链：三个岔路口决定该动哪一段 | ① 没进 TopK → 动摄取与召回；② 进了但没用上 → 动精排与组装；③ 都进了还是错 → 动生成与验收

**到这里你应该能回答**：为什么"我们 RAG 的准确率是 78%"这句话，面试官会接着问什么？

### 2. 分层评测：两层的损失是相乘的【推导】

【事实】**检索层指标**（回答"证据有没有被捞到"）：

| 指标 | 回答什么 |
|---|---|
| **Recall@K** | 正确证据**是否出现在前 K 个候选里** |
| **Precision@K** | 前 K 个里有多少是相关证据 |
| **MRR** | **第一个**正确证据出现得有多早 |
| **nDCG@K** | 多级相关性 + 排序质量 |

【事实】**答案层指标**（回答"答案对不对、有没有依据"）：

| 维度 | 判定方式 |
|---|---|
| **Correctness** | 与参考事实 / 业务规则一致 |
| **Faithfulness** | 每项主张**由上下文支持** |
| **Citation completeness** | 需要证据的结论是否都有引用 |
| **Answerability** | 无答案时能否**正确拒答** |
| **Safety / ACL** | 是否泄露未授权信息 |
| **Task success** | 用户最终任务是否完成 |

#### 2.1 为什么不能只看一层【推导】

```text
检索层：Recall@20 = 95%   → 5% 的查询，证据压根没进来
答案层：在证据进来的 95% 里，faithfulness = 90%
        → 其中 10% 的情况「给了证据但没用上」

端到端正确率上限 = 95% × 90% = 85.5%
```

【结论】**两层的损失是相乘的**——**端到端指标既低于任何一层的指标，又定位不了是哪一层拖的**。

【推论】**所以"检索指标好但答案差"这句话本身就是一个有效的诊断信息**：它说明瓶颈在①之后（排序 / 预算 / 生成），而**不是**在召回。**这正是分层评测的价值——它把"一句话的抱怨"变成了"该看哪一段"。**

【事实】**判据**：archive/study-courses/03 的原文是"**检索 Eval 和答案 Eval 不能混为一个分数**"——**它们回答的是两个不同的问题，混在一起就两个都答不了。**

**到这里你应该能回答**：为什么端到端指标一定低于同层的单项指标？

### 3. 归因决定修复的上限【推导】

【推导】**不做归因就动手，是在赌**。把 100 条失败样本归因一遍：

```text
假设归因结果是：
  ① 证据没进 TopK        40 条  → 召回问题
  ② 进了但没用上         25 条  → 排序 / 预算问题
  ③ 都进了但还是错       35 条  → 生成问题

如果直接去换一个更强的模型（只治 ③）：
  最多修好 35 条 → 还有 65 条照样错
```

【结论】**不做归因就动手，最多只能修三分之一。**

【推论】**而且这三段的修复成本差得很远**：

```text
③ 生成问题 → 改 Prompt / 加重排后的引用绑定 → 便宜、可快速迭代
② 排序问题 → 加/调重排、调 token 预算      → 中等
① 召回问题 → 改切分、改 Embedding、重建索引 → 最贵（因为要重跑离线链路）
```

【取舍】**所以顺序应该是"先归因、再动手"**，而不是"先挑一个最贵的手段上"（那通常是把问题往后推）。

**到这里你应该能回答**：为什么"先换个更强的模型试试"通常不是最好的第一步？

### 4. 评测集怎么建【事实】

【事实】每条样本至少包含（archive/study-courses/03 的 schema）：

```json
{
  "question": "...",
  "user_scope": "tenant_a/analyst",        ← 权限维度
  "gold_evidence_ids": ["doc_12#p3"],      ← 正确证据（检索层的答案）
  "reference_answer": "...",               ← 参考答案（答案层的答案）
  "must_include": ["生效日期"],
  "must_not_include": ["未授权字段"],
  "answerability": true,                    ← 是否可答（测拒答）
  "tags": ["multi_hop", "permission"]       ← 分桶标签
}
```

【事实】**数据来源**：**真实高频问题、专家构造边界、线上 Bad Case、权限攻击、过期 / 冲突样本**。

【取舍】**两个必须注意的点**：

```text
① 保留 holdout —— 避免对测试集过拟合
   （[[母题-C3-Prompt版本管理与回归]] 里那个真实案例：训练集打平、held-out 差 11.9 个点）

② 样本量决定分辨率
   200 条 → 标准误 ≈ √(0.9×0.1/200) ≈ 2.1%，只够抓大幅回退
   要分辨 2 个百分点 → 需要约 900 条
```

【推论】**"评测集有 150 条"和"评测集能分辨 2 个点"是两件事**——**小评测集只能告诉你"没有崩"，不能告诉你"变好了 2 个点"。**

### 5. 一个必须分清的口径：检索失败率 ≠ 幻觉率【推导】

【事实】这条在 [[母题-C4-幻觉的成因与可控性]] 里讲过，这里是它的落地版：

```text
检索失败（证据没取回来）
   ↓ 是「证据缺失型幻觉」的必要条件，但不充分
   ↓ 模型仍可能靠参数化知识答对
证据缺失型幻觉  ≤  检索失败率        ← 它是上界，不是下界

总幻觉率 = 证据缺失型 ＋ 有证据不依 ＋ 无模式事实 ＋ 评测激励
        → 与检索失败率之间没有必然的大小关系
```

【结论】**Contextual Retrieval 报的"失败率降 49%"是检索层数字**，**不能说成"幻觉降低了 49%"**——**方向上还是高估**（真实改善一定小于这个数）。

【推论】**反过来也成立**：**检索成功率提高 ≠ 幻觉率下降**。C4 的 Q2 算过——有证据但模型不用（faithfulness 问题）照样是幻觉。**所以两层指标必须分开看、分开报。**

**到这里你应该能回答**：为什么"我们把检索失败率降了 49%"不能当作"幻觉治理的成果"来汇报？

### 6. 边界与常见误解

| 常见说法 | 修正 |
|---|---|
| "我们看端到端准确率就够了" | **不够，因为它定位不了**。RAG 的失败发生在三个不同地方（没捞到 / 没进上下文 / 生成错），**端到端指标把它们混成一个数**，而三段的修复动作和成本完全不同 |
| "检索指标好就说明检索没问题" | **只能说"候选池没问题"**。正确证据排在第 20 位被预算挤掉时，Recall 照样 100%。**要看 nDCG@K** 才知道排得对不对 |
| "RAG 的幻觉率就是检索失败率" | **不是**。检索失败只是**证据缺失型幻觉的上界**（且不充分——模型可能靠参数知识答对）；反过来，**检索成功了模型也可能不用**（faithfulness 问题）。**两者不能互换** |
| "评测集 150 条够用了" | **取决于你要证明多大的差异**。150 条的标准误约 2.4%，**只能抓大幅回退**；想论证"改进了 2 个点"，需要约 900 条（[[母题-C3-Prompt版本管理与回归]] 的样本量算式） |
| "有评测集就不用留 holdout 了" | **必须留**。调优时反复看同一套集合，它就成了训练集。**真实案例：训练集上 98.9% 打平，held-out 上 90.5% vs 78.6%** |
| "换更强的模型是通用解" | **只在"都进了上下文还是错"时才有效**。如果是召回问题（40%）或排序问题（25%），换模型**最多修三分之一**（第 3 节） |
| "拒答率高说明系统差" | **反了**。拒答把"自信的错误"（代价 10 单位）换成"坦白的不知道"（1 单位）→ **总代价降到 1/10**（[[母题-G4-引用绑定与证据可追溯]]）。**要看的是错误率，不是拒答率** |

【取舍】读成一句话：**评测的目的不是"给系统打分"，是"告诉你下一步该改哪里"——不能定位的评测，价值接近于零。**

## 二、自测

**Q1（计算）**：某 RAG 系统的 **Recall@20 = 95%**（5% 的查询证据没进来），在证据进来的那些查询里 **faithfulness = 90%**（10% 给了证据但没用上）。

问：**端到端正确率的上限是多少？**这个数说明什么？

**A1**：

```text
端到端正确率上限 = 95% × 90% = 85.5%
```

【结论】**两层的损失是相乘的**——**端到端指标既低于任何一层的单项指标，又定位不了是哪一层拖的**。

【推论】**所以"检索指标好但答案差"这句话本身就是有效诊断**：它说明问题在"排序 / 预算 / 生成"这三段里，**而不在召回**。这就是分层评测的价值——**它把一句抱怨变成了"该看哪一段"**。

【补充】注意 90% 这个 faithfulness 是**条件概率**（在证据进来的前提下）。**把两层的坑分开算，才能知道"提升哪一层更划算"**：把 95% 提到 98% 只多 2.7 个点；把 90% 提到 95% 能多 4.75 个点。

**Q2（计算）**：对 **100 条失败样本**做归因，结果是：

```text
① 证据没进 TopK      40 条
② 进了但没用上       25 条
③ 都进了但还是错     35 条
```

问：**如果只换一个更强的生成模型（只治 ③），最多能修好多少条？**这个结果对排查顺序意味着什么？

**A2**：

```text
只治 ③：最多修好 35 条
剩下的 40 + 25 = 65 条照样错

修复率 = 35 / 100 = 35%
```

【结论】**不做归因就动手，最多只能修三分之一。**

【推论】**而且这三段的修复成本差得很远**：

| 段 | 修复动作 | 成本 |
|---|---|---|
| ③ 生成 | 改 Prompt、加引用绑定、换模型 | 便宜、可快速迭代 |
| ② 排序 | 调重排、调 token 预算 | 中等 |
| ① 召回 | 改切分、换 Embedding、**重建索引** | **最贵** |

【取舍】**所以正确顺序是"先归因、再动手"**——**先花半天做归因，再决定改哪一段**；而不是先挑一个最贵的手段上（那通常是把问题往后推，下次又冒出来）。

**Q3（判读）**：两个 RAG 系统的评测数据如下：

```text
系统 A：Recall@20 = 98%，faithfulness = 70%
系统 B：Recall@20 = 85%，faithfulness = 95%
```

问：**哪个系统更好？该优先改哪个？**

**A3**：

```text
端到端上限：
  系统 A = 98% × 70% = 68.6%
  系统 B = 85% × 95% = 80.75%

→ 系统 B 的端到端上限更高
```

【结论】**B 更好**，尽管它的召回率低了 13 个百分点——**因为 A 的瓶颈在"给了证据不用"，那一层拖得更狠。**

【该改哪里】两个系统的短板不同：

```text
系统 A：瓶颈在 faithfulness（70%）
  → 动生成与验收：加强引用绑定、生成后验证撤稿、允许弃答
  → 这是"便宜、可快速迭代"的那一段

系统 B：瓶颈在召回（85%）
  → 动摄取与召回：切分、混合检索、查询改写
  → 这是"最贵"的那一段
```

【推论】**"哪个系统更好"和"该优先改哪个"是两个不同的问题**——**前者看端到端上限，后者看哪一层的提升空间更大**。而这两件事只有在**分层评测**下才都答得出来。

**Q4（纠错）**：下面这段话哪里不准确？

> "我们用了 Contextual Retrieval，检索失败率降了 49%，所以幻觉问题基本解决了。"

**A4**：三处问题。

1. **口径错了**：49% 是**检索层**的数字（top-20 检索失败率），**不是幻觉率**。幻觉率还包含"证据给了没用上""无模式的事实""评测激励"这几类（[[母题-C4-幻觉的成因与可控性]]）。
2. **关系是"上界"不是"等式"**：**证据缺失型幻觉 ≤ 检索失败率**——而且**不充分**，模型可能靠参数化知识答对；**反过来，检索成功了模型也可能不用**。
3. **方向上是高估**：把检索层的改善说成幻觉的改善，**真实改善一定小于这个数**。

【准确说法】"**检索层和答案层要分开报**：'检索失败率从 5.7% 降到 2.9%'说的是**证据更容易被捞到**；要证明幻觉下降，还得看 **faithfulness** 和**端到端错误率**。"

**Q5（纠错）**：下面这段话哪里不准确？

> "我们建了一个 150 条的评测集，跑出来准确率 78%，说明系统还有提升空间。"

**A5**：三处问题。

1. **150 条的分辨率不够**：`SE = √(p(1−p)/n) = √(0.78×0.22/150) ≈ 3.4%`——**它只能告诉你"大致在这个水平"，分辨不出 2–3 个百分点的改进**。想论证"改进了 2 个点"，需要**千条量级**。
2. **"准确率"这个词太粗**：它**定位不了问题**（Q2：只优化生成最多修 35%）。至少要拆成 **Recall@K / nDCG@K（检索）** 和 **Correctness / Faithfulness / Citation completeness / Answerability（答案）**。
3. **没说有没有 holdout**：如果这 150 条被反复用来调优，**它已经变成训练集了**——真实案例里，训练集上打平、held-out 上差 11.9 个点。

【准确说法】"评测集要能回答三个问题：**规模够不够分辨我想证明的差异、指标能不能定位到具体哪一段、以及有没有留出没参与调优的 holdout**。**只报一个准确率的评测集，价值接近于零。**"

## 三、面试输出（学完再看）

**一句话结论**：**RAG 的失败发生在三个不同地方**——① 证据没被捞到（召回）、② 捞到了没进上下文（重排 / 预算）、③ 进了还是答错（生成）——**而端到端指标把它们混成一个数，所以定位不了问题**。所以必须**分层评测**：检索层看 **Recall@K / nDCG@K**，答案层看 **Correctness / Faithfulness / Citation completeness / Answerability**。**两层的损失是相乘的**（Recall@20 95% × faithfulness 90% = 端到端上限 85.5%），端到端指标一定低于任何单层。**归因决定修复上限**：100 条失败里如果召回占 40、排序占 25、生成占 35，**只换更强的模型最多修 35%**。评测集要**保留 holdout**（真实案例：训练集打平、held-out 差 11.9 个点），而且要够大——**150 条的标准误约 3.4%，只能抓大幅回退**。最后一条最容易混：**检索失败率 ≠ 幻觉率**——前者只是"证据缺失型幻觉"的上界，反过来检索成功了模型也可能不用。

**完整回答（口述稿）**：
RAG 的失败发生在**三个不同地方**：① 证据没被捞到（召回）、② 捞到了没进上下文（重排 / 预算）、③ 进了还是答错（生成）。**端到端指标把它们混成一个数，所以定位不了问题**——这就是必须分层评测的原因。

检索层看 **Recall@K / nDCG@K**，答案层看 **Correctness / Faithfulness / Citation completeness / Answerability**。**两层的损失是相乘的**（Recall@20 95% × faithfulness 90% = 端到端上限 85.5%），所以端到端指标一定低于任何单层。

**归因决定修复上限**：100 条失败里如果召回占 40、排序占 25、生成占 35，**只换更强的模型最多修 35%**。评测集要**保留 holdout**（真实案例：训练集打平、held-out 差 11.9 个点），规模按 `SE = √(p(1−p)/n)` 定：150 条约 ±3.4%，想分辨 2 个百分点需要约 900 条。数据来源五类：真实高频问题、专家构造的边界、**线上 Bad Case**、**权限攻击样本**、**过期/冲突样本**——后三类是 RAG 特有的，测的是"该拒答时有没有拒答"。

排查顺序（检索好但答案差）：① 正确证据进 TopK 了吗 → 召回；② 进最终 Context 了吗 → 重排/预算/去重；③ 都进了还是错 → 生成/Prompt/引用。前提是 **Trace 把候选、分数、重排位置、上下文版本都留下来了**。

**分层要点**：
- **结论**：三段归因，检索层与答案层分开评；端到端指标一定低于任何单层。
- **推导链**：失败三段 → 分层指标 → 损失相乘 → 归因决定修复上限 → 三岔路排查。
- **量化**：Recall@20 95% × faithfulness 90% = 端到端上限 85.5%；150 条约 ±3.4%、分辨 2 个点需约 900 条；召回 40 / 排序 25 / 生成 35 时换模型最多修 35%。
- **边界与常见误解**：幻觉率不能用检索失败率代替（后者只覆盖漏召）；检索指标好而答案差，问题常出在"进没进上下文"这一层。

**追问**（先说后看）

1. **检索指标很好但答案仍差，怎么排查？** —— **按三个岔路口走**：① 正确证据进 TopK 了吗（没进 → 召回）；② 进最终 Context 了吗（没进 → 重排 / 预算 / 去重）；③ 都进了还是错（→ 生成 / Prompt / 引用）。**前提是 Trace 把候选、分数、重排位置、上下文版本都留下来了**——否则只能猜。
2. **为什么检索 Eval 和答案 Eval 要分开？** —— **它们回答两个不同的问题**（"证据有没有捞到" vs "答案对不对、有没有依据"），**混在一起就两个都答不了**。而且分开之后才能算"提升哪一层更划算"。
3. **评测集要多大？** —— **取决于你要证明多大的差异**。`SE = √(p(1−p)/n)`：150 条约 ±3.4%，200 条约 ±2.1%；**想分辨 2 个百分点需要约 900 条**。**先想清楚"我要证明多大的差异"，再决定集合规模。**
4. **怎么造评测集的数据？** —— **五个来源**：真实高频问题、专家构造的边界、**线上 Bad Case**、**权限攻击样本**、**过期 / 冲突样本**。**后面三类是 RAG 特有的**——它们测的是"该拒答时有没有拒答"。
5. **怎么防止评测集被过拟合？** —— **保留 holdout**，且**只有验收时才看**。真实案例：Anthropic 的 hillclimb 在训练集上最终配置与起点打平（都 98.9%），**held-out 上才拉开 11.9 个点**（[[母题-C3-Prompt版本管理与回归]]）。

**同类变体**

- 「拒答率算不算一个评测指标？」——**算，但它不是"越低越好"**。拒答测的是 **Answerability**：**无答案时能否正确拒答**。拒答率高可能说明系统诚实，也可能说明召回太差——**要和无证据样本的占比一起看**。
- 「LLM-as-Judge 靠谱吗？」——**它是分层评测里最便宜的一层**，但要明确边界：**规则 / 代码优先判精确约束**（格式、数值、权限字段），**模型 Judge 判语义质量**（faithfulness、正确性），**高风险和校准样本由人工复核**。这是 archive/study-courses/03 给的三层 grader 组合。
