**题目**：面试官问——"你们怎么评测这个系统？用一个什么分数衡量？"

**母题**：**"这个系统好不好"该怎么变成一个可比较、可复现、可定位的判断——为什么"一个综合分"是错的？**

**为什么重要**：这一题**决定了整个 AI 工程的能力上限**。**没有分层的评测，前面所有的优化都是凭感觉**——而且更糟的是，**一个综合分会让严重错误被平均掉**。这道题也是**面试里区分"做过工程"和"做过 demo"最直接的一题**：demo 会说"我们准确率 85%"，工程会说"我们分六层看，安全违规单独门禁"。

## 一、教材

### 1. 前提：一个综合分会掩盖严重错误

::figure eval-three-layers.svg | 评测的三件事：指标分层、数据集分层、判分优先级 | 六层指标、五层数据集、四级判分；底部用具体数字说明综合分怎么掩盖安全违规

【推导】**算一下"压成一个分"的后果**：

```text
业务结果 80 · 任务结果 85 · 过程 70 · 工程 90 · 资源 75 · 安全 10（有越权）

平均 = (80 + 85 + 70 + 90 + 75 + 10) / 6 = 68.3 分
```

【结论】**看起来"刚及格"，但那个 10 分的安全违规不是"拉低平均"——它是不可接受的。**

【推论】**这就是原始素材那句话的含义**：

> **"不要用一个综合分掩盖严重错误。高风险安全违规通常是单独门禁，不与文案质量平均。"**

【推论】**根本原因是"这些指标不可通约"**：**"文案读起来更顺"和"泄露了跨租户数据"不是同一量纲的东西，不能相加**——**和 [[母题-C4-幻觉的成因与可控性]] 里"错误和弃答必须分开定价"是同一个道理**（一旦同价平均，算出来的结论就是错的）。

**到这里你应该能回答**：为什么"我们的综合分是 68 分"这句话，既不能说明系统好，也不能说明系统坏？

---

### 2. 指标分六层【事实】

| 层 | 典型指标 | 诊断价值 |
|---|---|---|
| **业务结果** | 解决率、转化、人工节省、风险损失 | 是否产生价值 |
| **任务结果** | 任务成功率、答案正确、最终状态 | 端到端是否完成 |
| **过程** | 路由、检索、工具选择 / 参数、步骤效率 | **为什么成败** |
| **工程** | P50/P95/P99、超时、恢复率、可用性 | 能否稳定服务 |
| **资源** | Token、模型 / 工具成本、缓存命中、重试 | 是否经济 |
| **安全** | 越权、注入成功、敏感泄露、未确认副作用 | **风险是否可控（单独门禁）** |

【推导】**这六层是"从外到内"排列的**：

```text
业务结果 → 是最外层，决定这件事值不值得做
任务结果 → 是"有没有完成"
过程     → 是"为什么成 / 为什么败"（诊断层）
工程     → 是"能不能稳定地做到"
资源     → 是"做到的代价"
安全     → 是"底线"（不参与权衡）
```

【推论】**面试里最容易漏的是"过程"层**——**只报业务和任务结果，就无法回答"为什么"**。**而过程指标正是 [[母题-G5-RAG评测与幻觉率]] 里那条三岔路归因的数据来源**（没捞到 / 没进上下文 / 生成错）。

【推论】**"安全"放在最后不是因为它最不重要，恰恰相反**——**它是唯一一条"一票否决"的线**，所以不参与平均。

**到这里你应该能回答**：为什么"过程指标"是六层里诊断价值最高的？

### 3. 数据集分五层【事实】

| 集合 | 作用 | 能不能拿来调优 |
|---|---|---|
| **Dev** | 快速迭代 | ✓ **可以频繁看** |
| **Golden regression** | **核心不能退化的样本** | ✗ |
| **Holdout** | **防对固定测试过拟合** | ✗ |
| **Adversarial** | 安全与边界 | ✗ |
| **Online sample** | **监测真实分布漂移** | ✗ |

【推导】**"哪一层能拿来调优"是这张表的核心**：

```text
只有 Dev 可以反复看 —— 因为它就是为此设计的
其余四层【看多了就变成 Dev 了】

真实案例（[[母题-C3-Prompt版本管理与回归]]）：
  Anthropic 的 hillclimb 在训练集上最终配置与起点打平（都 98.9%）
  但在 held-out 上 90.5% vs 78.6% —— 【11.9 个点的差距只在未见数据上才现形】
```

【推论】**"不留 holdout"这件事的代价不是"分数不准"，是"你不知道自己有没有变好"。**

【事实】**数据集来源**（六类）：**真实高频任务、专家定义的关键能力、历史失败与用户纠正、权限 / 注入 / 过期 / 冲突等对抗样本、无答案 / 需澄清样本、长尾和极端输入。**

【推论】**后三类是 AI 系统特有的**——**传统软件的测试用例不会包含"用户问了一个知识库里没有的问题"**，但对 AI 系统来说，**"该拒答时有没有拒答"才是核心指标**（[[母题-C4-幻觉的成因与可控性]] 的 Answerability）。

【事实】**质量规则**（容易被忽略但很重要）：**样本任务可解且环境完整；参考答案不是唯一可接受措辞时用 rubric；多人复核高风险样本；版本化 fixture 与数据源；去重并检查泄漏；定期审计"坏题"，不要把错误 benchmark 当目标。**

【推论】**最后一条最值钱**：**"不要把错误的 benchmark 当目标"**——**如果评测集本身有错题，优化它就是在优化错误**。**所以评测集需要像代码一样被审计**。

**到这里你应该能回答**：为什么"我们有 500 条评测集"这句话，必须先回答"其中多少条能拿来调优"？

### 4. pass^k：测的是稳定性，不是能力上限【推导】

【推导】**pass^k 的含义**：**同一个任务跑 k 次，全对的概率**。

```text
设单次成功率 p = 0.9

pass@1 = 0.9            = 90%
pass^3 = 0.9³           = 72.9%
pass^5 = 0.9⁵           = 59.0%
pass^10 = 0.9¹⁰         = 34.9%
```

【结论】**pass^k 衰减得非常快**——**单次 90% 看起来不错，但连做 5 次全对的概率只有 59%。**

【推论】**它和 pass@k 是**相反**的两个指标**：

```text
pass@k：k 次里至少有 1 次对（测"能力上限" —— 只要有解就行）
pass^k：k 次里全都对    （测"稳定性"   —— 每一步都不能掉链子）
```

【取舍】**该看哪个取决于场景**：

```text
看 pass@k：探索型任务（"帮我找几个方案"）—— 有一个能用的就够
看 pass^k：生产型任务（"每天给 1000 个用户处理订单"）—— 
          因为用户遇到的是【单次】，而系统要连着对很多次
```

【推论】**这解释了为什么"单次 90% 准确率"在生产上可能完全不够**：**1000 个用户里就有 100 个遇到错误**——**而系统自己的长期成功率（pass^k）会低得多。**

**到这里你应该能回答**：为什么"我们的单次准确率有 90%"这句话，在长任务场景下说服力有限？

### 5. Grader 选择：能确定性的，不用模型【推导】

【事实】**四级 grader 的对比**：

| Grader | 最适合 | 优点 | 风险 |
|---|---|---|---|
| **Code / Rule** | JSON、数值、SQL、安全约束、最终状态 | 快、稳定、可解释 | **语义覆盖有限** |
| **Reference comparison** | 有标准结果 | 简单 | 多个正确答案难处理 |
| **Model Judge** | 语义正确、完整、风格、证据关系 | 覆盖开放输出 | **偏差、漂移、自洽幻觉** |
| **Human** | 高风险、模糊价值判断、校准 | 责任与深度 | 慢、贵、不一致 |

【事实】**推荐顺序**：

> **"能确定性判断的不用模型 Judge；模型 Judge 用人工样本校准，且记录 grader 版本。"**

【推导】**为什么这个顺序的收益是指数级的**（[[母题-A8-动态计划下的可靠执行]] 算过）：

```text
10 项检查，模型 Judge 假设 85% 准：
  全部用模型 Judge   = 0.85¹⁰ ≈ 19.7%
  60% 确定化后的混合 = 1⁶ × 0.85⁴ ≈ 52.2%
```

【推论】**每把一项检查确定化，端到端可靠性就往 100% 推一步。** 所以**"这段能不能写成断言"是一个每天都要问自己的问题**。

【事实】**好 rubric 的六条**（study/07）：**明确评分维度和等级锚点；要求引用输入证据；将高风险错误单列；不把长度、语气误当正确；随机化顺序；必要时多 Judge / 抽样人工复核。**

【推理】**"不把长度、语气误当正确"这一条特别实际**——**模型 Judge 有强烈的"偏爱长回答"倾向**，**这会让"把答案写长"变成一条捷径**（[[母题-C3-Prompt版本管理与回归]] 里"准确率 +5.3%"那一类汇报，如果 grader 偏长，就会被这个偏差污染）。

**到这里你应该能回答**：为什么"模型 Judge 便宜又能覆盖开放输出"这句话只对了一半？

### 6. 边界与常见误解

| 常见说法 | 修正 |
|---|---|
| "用一个综合分衡量整体质量" | **会掩盖严重错误**：业务 80 / 任务 85 / 过程 70 / 工程 90 / 资源 75 / **安全 10** → 平均 68 分「刚及格」，**但安全违规是不可接受的，不是"拉低平均"**。**高风险项单独门禁，不参与平均** |
| "评测集越大越好" | **规模只决定分辨率，不决定有效性**。而且关键是**分层**：**只有 Dev 能反复看，Holdout / Adversarial / Online 看多了就变成 Dev 了**。**500 条不分层，不如 200 条分好层** |
| "我们准确率 90%，挺好" | **要看是 pass@k 还是 pass^k**：**pass^k（k 次全对）衰减极快**——p=0.9 时 pass^5 只有 **59%**、pass^10 只有 **34.9%**。**生产型任务要连对很多次，看的是后者** |
| "LLM-as-Judge 又便宜又能覆盖开放输出" | **它有偏差、会漂移、会自洽幻觉**。**尤其偏爱长回答**——这会把"把答案写长"变成一条捷径。**所以①能确定性判断的绝不用它 ②它要用人工样本校准 ③要记录 grader 版本** |
| "有标准答案就能自动判分" | **只在"答案唯一"时成立**。**多个正确答案难处理**——这也是为什么"参考答案不是唯一可接受措辞时要用 rubric" |
| "评测集是配好的，不用动" | **它需要被审计**：**样本任务可解且环境完整、去重并检查泄漏、定期清理"坏题"**。**"不要把错误的 benchmark 当目标"——如果评测集本身有错题，优化它就是在优化错误** |
| "安全指标也放进总分一起看" | **不可以**。**安全是唯一一条"一票否决"的线**——它不参与权衡。**把它放进平均分，等于允许"用高质量文案换一次越权"** |

【取舍】读成一句话：**评测的第一性原理不是"算出一个数"，是"把模糊目标变成可比较、可复现、可定位的判断"——所以它必须是分层的，且每层回答不同的问题。**

## 二、自测

**Q1（计算）**：某 Agent 的单次任务成功率是 **p = 0.9**。

问：**pass@1、pass^3、pass^5、pass^10 分别是多少？**这两个指标（pass@k 与 pass^k）分别测什么？

**A1**：

```text
pass@1  = 0.9      = 90%
pass^3  = 0.9³     = 72.9%
pass^5  = 0.9⁵     = 59.0%
pass^10 = 0.9¹⁰    = 34.9%
```

【两个指标的区别】：

```text
pass@k：k 次里【至少有 1 次】对  → 测"能力上限"（有解就行）
pass^k：k 次里【全都】对          → 测"稳定性"（每一步都不能掉链子）
```

【结论】**pass^k 衰减极快**：单次 90% 看起来不错，**但连做 5 次全对只有 59%、10 次只有 34.9%**。

【取舍】**看哪个取决于场景**：

- **探索型任务**（"帮我找几个方案"）→ 看 **pass@k**（有一个能用的就够）
- **生产型任务**（"每天给 1000 个用户处理订单"）→ 看 **pass^k**——**因为用户遇到的是单次，而系统要连着对很多次**

【补充】**如果要求 pass^5 = 0.9，那么单次成功率必须达到**：

```text
p⁵ = 0.9  →  p = 0.9^(1/5) ≈ 0.979 = 97.9%
```

**这就是"长任务对单步成功率的要求高得离谱"的数学原因**（[[母题-A8-动态计划下的可靠执行]] 的"错误会累积"是同一件事）。

**Q2（计算）**：某评测集有 **200 条**样本，基线通过率约 **90%**。

问：**它的分辨率是多少？**想分辨 **2 个百分点**的改进，需要多少条？

**A2**：

```text
标准误 SE = √(p(1−p)/n) = √(0.9 × 0.1 / 200) = √0.00045 ≈ 0.0212 = 2.1%

要让 SE = 1%（此时 2 个点约等于 2 个标准误）：
  n = p(1−p) / SE² = 0.09 / 0.0001 = 900 条
```

【结论】**200 条的分辨率约 ±2.1%，只够抓大幅回退；想论证"改进了 2 个点"，需要约 900 条。**

【推论】**所以"我们有 150 条评测集"这句话要补一句口径**：**它的分辨率约 ±2.4%，只能告诉你"没有崩"，不能告诉你"变好了 2 个点"**——**主动说出这个限制，比只报数字更像做过评测**（数驭穹图的 150 条就是这种情况）。

**Q3（计算）**：某系统的六层指标如下：

```text
业务结果 80 · 任务结果 85 · 过程 70 · 工程 90 · 资源 75 · 安全 10（存在跨租户越权）
```

问：**如果压成一个综合分是多少？**这个分数会掩盖什么问题？

**A3**：

```text
平均 = (80 + 85 + 70 + 90 + 75 + 10) / 6 = 410 / 6 ≈ 68.3 分
```

【结论】**看起来"刚及格"，但那个 10 分的安全违规是不可接受的。**

【掩盖的问题】**它把"一票否决"变成了"拉低平均"**：

```text
压成一个分之后，读出来的意思是：
  "有些地方好，有些地方差，整体中等"

而真实情况是：
  "这个系统有跨租户数据泄露，无论其他指标多好都不能上线"
```

【推论】**根本原因是这些指标不可通约**：**"文案读起来更顺"和"泄露了跨租户数据"不是同一量纲的东西**——**和 [[母题-C4-幻觉的成因与可控性]] 里"错误和弃答必须分开定价"完全同源**。**一旦同价平均，算出来的结论就是错的。**

【正确做法】**安全单独门禁**：**跨租户泄露必须为 0、R2 未确认执行必须为 0**（study/07 给的门禁示例）——**它们是"通过与不通过"，不是"多少分"。**

**Q4（纠错）**：下面这段话哪里不准确？

> "我们建了一个 500 条的评测集，每次改动都跑一遍看总分变化。"

**A4**：三处问题。

1. **"总分"会掩盖严重错误**（Q3）：安全违规会被平均掉。**高风险项必须单独门禁，不参与平均。**
2. **500 条没分层的话，会被调优吃透**。**只有 Dev 集能反复看；Golden / Holdout / Adversarial / Online 看多了就变成 Dev 了**——真实案例是训练集打平、held-out 差 **11.9 个点**。
3. **"每次改动都跑一遍"要看是哪一层**：**全量跑 500 条**在某些改动上没必要（改文案不必跑安全集）；而**关键改动跑太少又不够**。**所以要先定"这次改动属于哪一类，该跑哪些集合"。**

【准确说法】"评测集要**分层**：**Dev 用来迭代、Golden 防退化、Holdout 防过拟合、Adversarial 测安全、Online 测漂移**；**指标也要分层**：**安全单独门禁、过程指标用于归因、业务指标判断价值**。**"一个总分"两头都做不到。**"

**Q5（纠错）**：下面这段话哪里不准确？

> "我们用 LLM-as-Judge 来评测，因为它又便宜又能覆盖开放式的输出。"

**A5**：三处问题。

1. **它有系统性偏差**：**尤其偏爱长回答**——**这会让"把答案写长"变成一条捷径**，而那条捷径和"答案更对"无关。还有**自洽幻觉**（模型给自己打高分）和**漂移**（同一份输入不同时间分数不同）。
2. **它应该排在确定性判分之后**：**"能确定性判断的不用模型 Judge"**——因为**10 项检查全用模型（85% 准）只有 19.7% 全对，60% 确定化后是 52.2%**（[[母题-A8-动态计划下的可靠执行]]）。
3. **它必须被校准**：**用人工样本校准**，而且**记录 grader 版本**——否则**"这周分数涨了"可能是 grader 变了，不是系统变了**。

【准确说法】"**能确定性判断的绝不用模型**；模型 Judge 用来覆盖语义与开放输出，**但要用人工样本校准、要记录版本、要防长度偏好**。**而且它对高风险错误应该单列，不参与平均。**"

## 三、面试输出（学完再看）

**一句话结论**：**评测的第一性原理是"把模糊目标变成可比较、可复现、可定位的判断"**，所以它必须**分层**。**指标分六层**：业务结果 / 任务结果 / **过程**（诊断价值最高）/ 工程 / 资源 / **安全**——**安全单独门禁，不参与平均**，因为把它放进平均等于允许"用高质量文案换一次越权"（业务 80、任务 85、过程 70、工程 90、资源 75、**安全 10** 的平均分是 68.3，看起来"刚及格"）。**数据集分五层**：**Dev 可以反复看，Golden / Holdout / Adversarial / Online 不能拿来调优**——**看多了就变成 Dev 了**（真实案例：训练集打平、held-out 差 11.9 个点）。**判分四级且顺序不能反**：**能确定性判断的不用模型 Judge**（10 项检查全用模型只有 19.7% 全对，60% 确定化后 52.2%）。**稳定性和能力要分开测**：**pass@k 测能力上限（有一个能用的就行），pass^k 测稳定性（每次都要对）**——p=0.9 时 **pass^5 只有 59%、pass^10 只有 34.9%**；反过来，**要求 pass^5 = 90% 意味着单次要做到 97.9%**。最后，**样本量决定分辨率**：200 条约 ±2.1%，**想论证"改进了 2 个点"需要约 900 条**。

**恢复关键词**：**指标六层**（业务 / 任务 / **过程** / 工程 / 资源 / **安全单独门禁**）/ 综合分会掩盖严重错误（68.3 分的例子）/ **数据集五层**（Dev 可反复看，其余四层不行）/ holdout 的必要性（训练集打平、held-out 差 11.9 点）/ **grader 顺序：Code/Rule > Reference > Model Judge > Human** / rubric 六条（**别把长度语气误当正确**）/ **pass@k 测上限、pass^k 测稳定**（0.9⁵ = 59%）/ 200 条约 ±2.1%，900 条分辨 2 点 / 评测集要审计（**别把错题 benchmark 当目标**）

**核心不变量 / 主线**：
**评测不是"算出一个数"，是"把模糊目标变成可比较、可复现、可定位的判断"。**
所以它必须分层——**因为不同的层回答不同的问题，把它们压在一起，就一个都答不了。**

**完整回答骨架**：先破"一个综合分"（给 68.3 的例子）→ **指标六层**（点明过程层是诊断价值最高的）→ **数据集五层与"哪层能调优"** → **pass@k vs pass^k**（给衰减算式）→ **grader 四级与顺序**（给 19.7% vs 52.2%）→ 样本量与分辨率 → 评测集的审计 → 收束到"分层才能定位"

**追问**（先说后看）

1. **如何评测一个 Agent？** —— **从真实任务构造可重置环境；分结果、过程、工程、安全和业务指标；规则 / 代码 grader 优先，语义用校准过的模型 Judge；保存完整轨迹；离线回归后再 shadow / A-B；线上 Bad Case 回流。**（这是 study/07 的 Q1 标准答案，**注意它把"可重置环境"放在第一位**——[[母题-E2-Trace与可观测性]] 会展开。）
2. **LLM-as-a-Judge 有什么问题？** —— **偏差（偏爱长回答）、漂移（同输入不同时间不同结果）、自洽幻觉（给自己打高分）**。**所以要用人工样本校准、记录 grader 版本、并且只用在确定性判分覆盖不到的地方。**
3. **Golden Set 怎么维护？** —— **版本化；去重；检查泄漏；定期审计"坏题"**；**来源要包含真实失败与用户纠正**（不只是专家构造）。**关键是"它不能参与调优"**——否则它就退化成 Dev 集。
4. **模型输出非确定，CI 怎么做？** —— **看 pass^k 而不是单次**；**固定随机种子与环境 fixture**；**门禁用"通过率不低于阈值 + 置信区间"**，而不是"这一次过了就行"（[[母题-E3-回归门禁与发布卡口]] 展开）。
5. **怎么评估新模型是否值得切换？** —— **同一套 holdout 上对比，看 pass^k、P95 延迟、单任务成本三件事**；**而且要重跑消融**——因为 prompt 是针对旧模型写的（[[母题-C3-Prompt版本管理与回归]]、[[母题-C5-模型选型与降级三角]]）。

**同类变体**

- 「业务指标和离线评测冲突了怎么办？」——**业务指标是最终裁判，离线评测是先行指标**。**冲突时的排查顺序**：**① 评测集是否偏离了真实分布（Online sample 就是干这个的）② 离线指标是否漏测了某个维度 ③ 业务侧的度量口径是否变了**。**不能直接说"离线涨了所以业务会涨"**。
- 「怎么测一个"没有标准答案"的任务（比如文案生成）？」——**用 rubric 而不是参考答案**（grader 表里"多个正确答案难处理"就是这种情况）。**而且 rubric 要把高风险错误单列**——**文案可以风格不同，但不能编造事实**（[[母题-C4-幻觉的成因与可控性]] 的 faithfulness）。
