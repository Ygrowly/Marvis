**题目**：面试官问——"你们的发布门禁卡什么？阈值怎么定的？模型输出是非确定的，CI 怎么做？"

**母题**：**改了东西怎么保证不退化——门禁该卡在哪一道、卡多严，而"没测出问题"又意味着什么？**

**为什么重要**：这道题是**"有评测"和"评测真的在起作用"的分界线**。有评测集的团队很多，**但门禁要么太松（形同虚设）要么太紧（天天误报，最后所有人都学会绕过它）**。**能说清"阈值要和分辨率匹配"和"红线不接受阈值"这两件事，基本就证明门禁是你真的维护过的东西。** 这也是 RuleArena"门禁拒绝是设计目标"的机制底稿。

## 一、教材

### 1. 前提：门禁有两类，性质完全不同

::figure release-gate.svg | 回归门禁：分层漏斗，以及两类性质不同的卡口 | 分层漏斗：冒烟 → 金标+安全 → 影子/灰度；两类卡口：统计阈值型必须与分辨率匹配，绝对红线型不接受平均与阈值

【推导】**为什么必须分两类**：

```text
A · 统计阈值型："核心成功率下降不超过 2%"
   → 它是一个【连续量】的比较，天然有噪声
   → 阈值必须与评测集的分辨率匹配（否则误报或漏报）

B · 绝对红线型："跨租户泄露必须为 0"
   → 它不是"不超过多少"，是【存在性】判断
   → 一次就是事故，所以不接受平均、也不接受阈值
```

【事实】**study/07 给的门禁示例正好两类都有**：

```text
统计阈值型：
  · 核心任务成功率不得下降超过阈值
  · P95 和单任务成本不能超预算
  · 新增能力样本达到最低成功率

绝对红线型：
  · R2 未确认执行必须为 0
  · 跨租户泄露必须为 0
```

【推论】**把它们混在一起处理，两类都会坏**：

```text
把红线放进平均分 → 允许"用高质量文案换一次越权"（[[母题-E1-评测集设计与pass^k]] 的 68.3 分）
把阈值当成红线 → 一次正常的统计波动就会阻塞发布，然后所有人学会绕过门禁
```

【事实】**Anthropic 那篇 evals 文章给了同一件事的另一种切法**：

```text
Capability evals（能力评测）：测"这个 Agent 擅长做什么"（原文 *What can this agent do well?*）——目标是挑它【当前做不好】的任务，从一个低通过率往上爬
Regression evals（回归评测）：测"它原来能做的任务现在还都能做吗"（原文 *Does the agent still handle all the tasks it used to?*）——期望通过率【接近 100%】，它防的是滑坡
```

【推论】**这两类的阈值策略完全不同**：

```text
Capability：看"有没有达到最低线"（新增能力样本达最低成功率）
Regression：看"有没有退化"（相对基线的变化在阈值内）
```

**而且它们的基线不同**：**Capability 的基线是「零」（新能力本来没有）——注意：这一句是本卡的推论，原文只说 capability 应当从一个低通过率起步，没有说基线一定是零**；**Regression 的基线是「上一个版本」**——**这也是为什么 Regression 更依赖稳定的历史数据**。

**到这里你应该能回答**：为什么"用一个统一的门禁阈值"会把门禁做成摆设？

### 2. 阈值必须与评测集分辨率匹配【推导】

【推导】**算一下"阈值设得太紧"会发生什么**：

```text
评测集 200 条，基线成功率约 90%
标准误 SE = √(p(1−p)/n) = √(0.9 × 0.1 / 200) ≈ 2.1%

若门禁设"不得下降超过 2%"：
  在【真实没有变化】的情况下，
  观测值也会有约 ±2.1%（1 个标准误）的随机波动
  阈值 2% ÷ 2.1% ≈ 0.95 个标准误
  → 单侧 P(Z ≥ 0.95) ≈ 【17%】的概率会观测到 ≥ 2% 的下降
  → 【门禁会频繁误报】
```

【结论】**阈值设得比评测集分辨率还紧，门禁就会在"什么都没变"的时候报警。**

【取舍】**两条出路**：

```text
① 放宽阈值到 2 个标准误（约 4.2%）
   → 单侧误报降到约 2.3%，但代价是漏报也变大（真掉 3% 可能测不出来）

② 把评测集做大
   → 900 条时 SE ≈ 1%，阈值可以收到 2%
   → 但这要花钱维护
```

【推论】**这就是"门禁阈值不能拍脑袋"的原因**——**它是一个统计决策，要把"误报"和"漏报"的代价一起考虑**：

```text
误报的代价：阻塞发布 → 团队开始绕过门禁（最坏的结果）
漏报的代价：退化上线 → 线上事故
```

【事实】**原始素材的提醒**：

> **"统计上要报告样本量和置信区间；小样本的 1–2 个波动不要过度解释。"**

【推论】**"不要过度解释"是双向的**：**不要因为掉了 2 个点就紧急回滚，也不要因为涨了 2 个点就庆祝**——**小集合上这两个都没意义。**

【假设】**上面这个 17% 属于单样本口径**——它把基线当成**已知固定的 90%**。如果门禁实际比的是「**新版本 vs 上一版**」（两样本），差值的标准误变成 √(0.09 × 2 ÷ 200) ≈ **3.0%**，同样 2% 的阈值只有 0.67 个标准误，**单侧误报会升到约 25%**。**所以「阈值该定多少」的第一问不是数字，是「比的是谁」。**

**到这里你应该能回答**：为什么"我们的门禁是准确率不能低于 88%"这句话，必须先回答"评测集多少条"？

### 3. 红线要报"上界"，不是"通过"【推导】

【事实】**红线型门禁的例子**："跨租户泄露必须为 0"。

【推导】**但"测了 1000 个对抗样本，0 次泄露"到底说明了什么**：

```text
观测到 0 次，不代表真实概率是 0
它只说明：真实泄露率【低于某个上界】

用"三倍法则"（rule of three）粗估 95% 置信上界：
  上界 ≈ 3 / n = 3 / 1000 = 0.3%

→ 你能说的是"泄露率低于约 0.3%"
→ 而【不能说"不会泄露"】
```

【结论】**红线门禁的正确输出是"上界"，不是"通过"**。

【推论】**这直接影响你该怎么定测试规模**：

```text
想声称"泄露率低于 0.1%" → 需要 n ≈ 3 / 0.001 = 3000 个对抗样本
想声称"低于 0.3%"       → n ≈ 1000
```

【取舍】**这就是安全测试的规模从哪来**——**不是"跑 100 个意思一下"，是从"你能承诺的上界"倒推。**

【推论】**同样的逻辑适用于所有"必须为 0"的指标**：**未确认的副作用、越权执行、数据泄露**——**"跑了一轮没出事"是一个弱得多的声明，要说清楚 n 是多少。**

**到这里你应该能回答**：为什么"我们测过，没有越权"这句话，必须补一个数字？

### 4. Replay 的四种模式【事实】

【事实】study/07 给的对照（**这张表是这一题的高分点**）：

| 模式 | 工具结果 | 用途 |
|---|---|---|
| **Exact trace view** | **读取历史记录** | **人工复盘** |
| **Mock replay** | **固定历史 Tool Result** | **比较模型 / Prompt 变化** |
| **Sandbox replay** | **在可重置环境重新执行** | **端到端行为验证** |
| **Shadow replay** | **新版本处理脱敏真实流量但不影响用户** | **上线前分布验证** |

【事实】**一条硬规矩**：

> **"写工具默认不能在生产 Replay。"**

【推导】**为什么**——**这正是 [[母题-A3-失败恢复与幂等]] 里"Replay 默认不重做真实副作用"的落地**：

```text
Replay 的目标是"复现 / 评估轨迹"
若它在生产环境重做写工具 → 【调试变成重复执行副作用】
→ 你会在分析一次重复扣款事故的过程中，再制造一次重复扣款
```

【推导】**四种模式的选择判据是"要验什么"**：

```text
要"看当时发生了什么"          → Exact trace view（只读）
要"换个 Prompt / 模型会怎样"    → Mock replay（固定工具结果，隔离变量）
要"端到端行为是否还对"          → Sandbox replay（可重置环境里真跑）
要"真实分布上会不会出问题"      → Shadow replay（脱敏真实流量 + 不影响用户）
```

【推论】**Mock replay 的价值在于"隔离变量"**：**固定了工具结果，就只剩下模型 / Prompt 这一个变量**——**这是"某个改动到底有没有用"最干净的实验设计**（[[母题-C3-Prompt版本管理与回归]] 的消融需要同一个思路）。

**到这里你应该能回答**：为什么"在生产环境重放一遍"这个看似最真实的验证方式，是最危险的？

### 5. 分层过滤：门禁的效率【推导】

【事实】**CI 的流程**（study/07）：

```text
Prompt / Model / Tool / RAG 变更
  → 小型 Smoke Eval
  → Golden + Safety Eval
  → 门禁通过？
     → 否：失败归因
     → 是：Shadow / 灰度
```

【推导】**算一下分层能省多少**：

```text
全量 500 条 × $0.03/条 = $15/次
一天改 10 次 → $150/天

分层：先跑 30 条冒烟（30 × $0.03 = $0.9）
  假设 70% 的改动在冒烟阶段就被否掉
  → 实际跑全量的次数 = 10 × 30% = 3 次/天
  → 成本 = 3 × $15 + 10 × $0.9 = $45 + $9 = $54/天

降到 36%
```

【结论】**分层过滤把门禁成本降到约 1/3，而"全量回归"仍然每次都发生过。**

【推论】**这解决的是一个真实矛盾**：**"每次都跑全量"太贵太慢 → 团队开始跳过 → 门禁名存实亡**。**分层让"快"和"全"共存**：

```text
冒烟集负责"快"（抓明显坏改动）
全量集负责"全"（兜住细微退化）
```

【事实】**还有一条更省的**：**如果改动类型明确**（比如只改了文案），**可以只跑相关的那一层**——**不是每次都必须跑全部集合**。**但前提是"改动类型的判定"本身可靠。**

**到这里你应该能回答**：为什么"门禁太慢"这件事，最终会变成"门禁失效"？

### 6. 边界与常见误解

| 常见说法 | 修正 |
|---|---|
| "我们的门禁是准确率不得低于 88%" | **必须先回答"评测集多少条"**：**200 条的标准误约 2.1%**，阈值设 2% 会让门禁在"什么都没变"时频繁误报（单侧约 17%）；**要么放宽到 2 个标准误，要么把集合做大** |
| "所有的门禁都设一个阈值" | **门禁有两类，性质完全不同**：**统计阈值型**（成功率降幅、P95、成本）与**绝对红线型**（跨租户泄露 = 0、未确认执行 = 0）。**红线不接受平均也不接受阈值**——**一次就是事故** |
| "我们测了 1000 次没有越权，说明安全" | **"0 次观测"只给出上界，不给结论**：按三倍法则，1000 次 0 泄露的 95% 上界约 **0.3%**——**你能说"低于 0.3%"，不能说"不会泄露"**。**要声称更低的上界，就得把 n 做大** |
| "Replay 就是把生产流量重放一遍" | **写工具默认不能在生产 Replay**——**那会把调试变成事故重放**。四种模式各有用途：**Exact view 复盘、Mock 比 Prompt/模型、Sandbox 验端到端、Shadow 验真实分布** |
| "门禁太慢就先跳过，紧急发布" | **跳过一次就会变成每次都跳**（[[母题-C3-Prompt版本管理与回归]] 的"草稿只读不练"是同一个道理：规则的例外一旦常态化，规则就没了）。**正解是分层过滤——让冒烟集承担"快"，全量集承担"全"** |
| "改动后指标涨了就是好事" | **小样本的 1–2 个点波动不要过度解释**（study/07 原话）。**200 条上掉 3 个点在统计上不能判定**——**门禁要报告样本量和置信区间**，否则团队会陷入"追噪声" |
| "新能力达标就行，不用管旧的" | **那会漏掉回归**。Anthropic 把评测明确分成 **capability（新能力）与 regression（不退化）两类**——**它们的基线不同（一个从零起、一个对上一版），必须分开卡** |

【取舍】读成一句话：**门禁的目标不是"卡得严"，是"每次变更都有一次可信的判断"——太严会让它被绕过，太松会让它没意义。**

## 二、自测

**Q1（计算）**：某团队的门禁是"核心成功率不得下降超过 **2%**"，评测集 **200 条**，基线 **90%**。

问：**这个阈值合理吗？**在真实没有变化的情况下，门禁大约多久误报一次？

**A1**：

```text
标准误 SE = √(p(1−p)/n) = √(0.9 × 0.1 / 200) ≈ 2.1%

阈值 2% ≈ 0.95 个标准误
在【真实无变化】时，观测值波动约 ±2.1%
→ 单侧 P(Z ≥ 0.95) ≈ 【17%】的概率观察到 ≥ 2% 的下降
```

【结论】**阈值设得比评测集分辨率还紧，门禁会在"什么都没变"时频繁报警**——**约六分之一的运行会触发**。

【两条出路】：

```text
① 放宽到 2 个标准误（约 4.2%）→ 单侧误报降到约 2.3%，但漏报变大
② 把评测集做大到约 900 条（SE ≈ 1%）→ 阈值可以收到 2%
```

【推论】**门禁阈值是一个统计决策，要同时考虑两类错误的代价**：

- **误报的代价**：阻塞发布 → **团队开始绕过门禁**（最坏结果）
- **漏报的代价**：退化上线 → 线上事故

**Q2（计算）**：某安全门禁用 **1000 个**对抗样本测"跨租户泄露"，结果是 **0 次泄露**。

问：**这能说明"不会泄露"吗？**你能得出的结论是什么？如果想声称"低于 0.1%"，需要多少样本？

**A2**：

```text
不能说明"不会泄露"。
观测到 0 次只说明真实概率【低于某个上界】。

用三倍法则粗估 95% 置信上界：
  上界 ≈ 3 / n = 3 / 1000 = 0.3%

→ 你只能说"泄露率低于约 0.3%"

想声称"低于 0.1%"：
  n ≈ 3 / 0.001 = 3000 个对抗样本
```

【结论】**红线门禁的正确输出是"上界"，不是"通过"。**

【推论】**这直接决定了安全测试的规模从哪来**：**不是"跑 100 个意思一下"，是从"你能承诺的上界"倒推。**

【补充】**同样的逻辑适用于所有"必须为 0"的指标**：**未确认的副作用、越权执行、数据泄露**——**"跑了一轮没出事"是一个弱得多的声明，必须说清 n 是多少。**

**Q3（计算）**：全量回归 500 条 × **$0.03/条** = **$15/次**，一天改 **10 次**。

问：**不做分层过滤的成本？**如果先跑 30 条冒烟（$0.03/条），且 **70%** 的改动在冒烟阶段被否掉，成本降到多少？

**A3**：

```text
不做分层：
  10 次 × $15 = $150 / 天

分层过滤（30 条冒烟先跑）：
  冒烟成本 = 10 × 30 × $0.03 = $9
  全量次数 = 10 × 30% = 3 次 → 3 × $15 = $45
  合计 = $45 + $9 = $54 / 天

降到 36%
```

【结论】**分层把门禁成本降到约 1/3，而"全量回归"仍然每次都发生过。**

【推论】**这解决的是一个真实矛盾**：

```text
"每次都跑全量" → 太贵太慢 → 团队开始跳过 → 门禁名存实亡
分层过滤     → 冒烟集管"快"、全量集管"全" → 两者共存
```

【取舍】**还有一条更省的**：**如果改动类型明确**（比如只改了文案），**可以只跑相关的那套集合**。**但前提是"改动类型判定"本身可靠**——**判错了就会漏测**。

**Q4（纠错）**：下面这段话哪里不准确？

> "我们要复现昨天那次线上事故，直接把生产流量重放一遍最真实。"

**A4**：三处问题。

1. **写工具默认不能在生产 Replay**。**Replay 的目标是"复现 / 评估轨迹"，不是"把事做完"**——**重做写操作会让调试变成事故重放**（[[母题-A3-失败恢复与幂等]] 的硬规矩）。
2. **"最真实"要看你验什么**：

```text
要"看当时发生了什么"       → Exact trace view（只读，最安全）
要"换 Prompt / 模型会怎样"  → Mock replay（固定工具结果，隔离变量）
要"端到端行为是否还对"      → Sandbox replay（可重置环境里真跑）
要"真实分布上会不会出问题"  → Shadow replay（脱敏真实流量 + 不影响用户）
```

3. **Shadow replay 才是"真实流量"的正确用法**——**用新版本处理脱敏流量，但结果是旁路的、不影响用户**。

【准确说法】"**要真跑，去 Sandbox；要真实分布，用 Shadow；要隔离变量，用 Mock；要复盘，用 Exact view。** **只有"要真执行"的那两种，才涉及副作用——而它们都不碰生产。**"

**Q5（纠错）**：下面这段话哪里不准确？

> "这次改动评测分数涨了 3 个点，看来效果不错，可以发。"

**A5**：三处问题。

1. **要看评测集多大**。**200 条的标准误约 2.1%**——**涨 3 个点在统计上不足以判定**（[[母题-C3-Prompt版本管理与回归]]：200 条上"改进了 2 个点"多半是噪声）。
2. **要看涨的是哪一套集合**。**如果是 Dev 集**，那它本来就可以被反复看——**它的提升不保证在 holdout 上成立**（真实案例：训练集打平、held-out 差 11.9 个点）。
3. **还要看有没有踩红线**。**分数涨了不等于门禁全过**——**跨租户泄露、未确认执行这些红线是独立的，不会体现在总分里**（[[母题-E1-评测集设计与pass^k]]）。

【准确说法】"**报样本量和置信区间**；**验收用没参与调优的集合**；**红线单独卡**。**三个条件都满足，才叫"这次改动可信"。**"

## 三、面试输出（学完再看）

**一句话结论**：**门禁有两类，性质完全不同**——**统计阈值型**（成功率降幅、P95、成本）与**绝对红线型**（跨租户泄露 = 0、未确认执行 = 0）；**红线不接受平均、也不接受阈值**。**阈值必须与评测集分辨率匹配**：200 条的标准误约 **2.1%**，阈值设 2% 会在"什么都没变"时**约 17% 的单侧误报概率**——**要么放宽到 2 个标准误，要么把集合做大到约 900 条**。**红线还要报"上界"而不是"通过"**：1000 个对抗样本 0 次泄露，按三倍法则 95% 上界约 **0.3%**——**你能说"低于 0.3%"，不能说"不会泄露"**；要声称 0.1% 就得有 3000 个样本。**Replay 有四种模式**（Exact view 复盘 / Mock 比 Prompt 与模型 / Sandbox 验端到端 / Shadow 验真实分布），**写工具默认不能在生产 Replay**——否则调试变成事故重放。最后，**门禁要分层过滤**：冒烟 30 条先筛（70% 的坏改动在这里被否），全量 500 条只跑剩下的 **3 次/天**，成本从 $150 降到 **$54（36%）**——**这解决的是"太慢 → 被跳过 → 名存实亡"这个真实矛盾**。而 Anthropic 把评测分成 **capability（新能力）与 regression（不退化）**，**它们的基线不同，必须分开卡**。

**恢复关键词**：两类卡口（**统计阈值 vs 绝对红线**）/ 红线不接受平均与阈值 / **阈值必须匹配分辨率**（200 条 SE 2.1%，阈值 2% → 单侧 17% 误报）/ 放宽到 2 SE 或把集合做到 900 条 / **三倍法则**（0/1000 → 上界 0.3%）/ 要 0.1% 就需 3000 样本 / Replay 四模式（Exact · Mock · Sandbox · Shadow）/ **写工具默认不能生产 Replay** / 分层过滤（$150 → $54）/ **capability vs regression（基线不同）** / 报样本量与置信区间，小波动别过度解释

**核心不变量 / 主线**：
**门禁的目标不是"卡得严"，是"每次变更都有一次可信的判断"。**
太严 → 频繁误报 → **团队学会绕过 → 门禁失效**；太松 → 退化上线。**所以阈值是一个统计决策，"红线"则根本不是在讨论阈值——它在讨论"这件事能不能发生"。**

**完整回答骨架**：两类卡口（阈值型 vs 红线型）→ **阈值与分辨率匹配的算式** → **红线上界的算式（三倍法则）** → Replay 四模式与"写工具不进生产" → **分层过滤的成本算式** → capability vs regression → 收束到"可信的判断"

**完整回答（口述稿）**：
**门禁有两类，性质完全不同**：**统计阈值型**（成功率降幅、P95、成本）与**绝对红线型**（跨租户泄露 = 0、未确认执行 = 0）；**红线不接受平均、也不接受阈值**，两类要分开报。

**阈值必须与评测集分辨率匹配**：200 条的标准误约 **2.1%**，阈值设 2% 会在"什么都没变"时有**约 17% 的单侧误报概率**——要么放宽到 2 个标准误，要么把集合做大到约 900 条。

**红线要报"上界"而不是"通过"**：1000 个对抗样本 0 次泄露，按三倍法则 95% 上界约 **0.3%**——你能说"低于 0.3%"，不能说"不会泄露"；要声称 0.1% 就得有 3000 个样本。

模型输出非确定，CI 怎么做四条：**① 看 pass^k 而不是单次**；② **固定环境 fixture 与随机种子**；③ 门禁报"**通过率 + 置信区间**"；④ **Mock replay 隔离变量**，让比较只受一个因素影响。

**Replay 有四种模式**：Exact view（复盘）、Mock（比 Prompt 与模型）、Sandbox（验端到端）、Shadow（验真实分布）；**写工具默认不能在生产 Replay**——否则调试变成事故重放。

单步好但端到端差的三个原因：错误累积、优化子指标伤了总目标、评测口径不一致（单步 Mock / 端到端 Sandbox 环境不同）。

**分层要点**：
- **结论**：红线为 0 且报上界，统计阈值按分辨率定；非确定性靠 pass^k + 置信区间 + Mock replay。
- **推导链**：两类门禁性质不同 → 阈值 vs 集合分辨率 → 红线只能报上界 → CI 四条 → Replay 四模式各自验什么。
- **量化**：200 条标准误约 2.1%，阈值 2% → 约 17% 误报；1000 样本 0 泄露 → 95% 上界约 0.3%（声称 0.1% 需 3000 样本）。
- **边界与常见误解**：红线"看到就停，不等统计显著"；Replay 不要在生产重放写工具。

**追问**（先说后看）

1. **模型输出非确定，CI 怎么做？** —— **① 看 pass^k 而不是单次**（[[母题-E1-评测集设计与pass^k]]：0.9 的单次、pass^5 只有 59%）② **固定环境 fixture 与随机种子**（[[母题-A8-动态计划下的可靠执行]] 的"可重置环境"）③ **门禁报"通过率 + 置信区间"**，不是"这一次过没过"④ **Mock replay 隔离变量**，让比较只受一个因素影响。
2. **门禁该卡哪些指标，阈值怎么定？** —— **红线**（越权、未确认副作用、跨租户泄露）**必须为 0**；**统计阈值**（成功率、P95、成本、新能力最低线）**按评测集分辨率定**。**而且这两类要分开报**。
3. **单步指标好但端到端差，为什么？** —— **可能的原因有三类**：① **错误会累积**（每步 95%，10 步就是 60%）② **优化某个子指标伤害了总目标**（典型：召回更多文档提高 Recall，但上下文噪声增加让最终正确率下降——[[母题-G5-RAG评测与幻觉率]]）③ **评测口径不一致**（单步用 Mock、端到端用 Sandbox，两者的环境不同）。**"错误会累积"这条原文明确点过。**
4. **新模型要不要切？** —— **同一套 holdout 上比三件事**：**pass^k、P95 延迟、单任务成本**；**而且要重跑消融**（prompt 是针对旧模型写的，[[母题-C3-Prompt版本管理与回归]]、[[母题-C5-模型选型与降级三角]]）。
5. **怎么保证 Replay 是确定的？** —— **Mock replay 固定了工具结果**，所以剩下的变量只有模型和 Prompt；**Sandbox replay 要保证环境 fixture 可重置**（否则两次运行的初始状态不同，结果没法比）。

**同类变体**

- 「为什么 RuleArena 把"门禁拒绝"当成设计目标？」——**因为门禁的价值就在于"它真的拦住了东西"**——**一个从来没拦过任何改动的门禁，无法区分"没有坏改动"和"门禁没生效"**。**"拒绝"是它有效的证据。**
- 「回归集和验收集能不能是同一套？」——**不能**。**回归集会被反复跑、反复看，久了就退化成 Dev 集**（[[母题-E1-评测集设计与pass^k]]）。**所以至少要有"调优用"和"验收用"两套**——RuleArena 的双评测集就是这个结构。
