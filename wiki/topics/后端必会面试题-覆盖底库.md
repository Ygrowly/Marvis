# 后端必会面试题 · 跨模块覆盖底库

> **这是什么**：一张**横着看**的表——把散在各模块卡里的"必会题"按模块归口，标出**每题挂在哪张母题卡上**，并把**还没母题卡的缺口**单独列出来。
> **怎么用**：① **查漏**——面试前扫一遍，看到挂不出母题 ID 的题就是缺口；② **反查**——被问到某题，从这张表跳到对应母题卡；③ **体检**——第 4 节的缺口清单就是"下一个模块该建什么"的依据。
> **⚠️ 它不是题库正文**：各模块的**完整**题单在模块卡第 4 节（`wiki/topics/{模块}/{模块}模块卡.md`），本表**只收「必会」级**并**只做归口**，不复制题单全文（全库闸门：**一个主题一个正本，卫星只引用不复制**）。
> **它是「只查不练」的**：不进复训牌组，不产生派单。**要练的是母题卡。**

---

## 一、为什么需要这张表

全库现在的题库分布在 **11 个模块卡** 里（MySQL / PostgreSQL / Redis / 网络 / 消息队列 / 操作系统 / LLM与上下文 / RAG与检索 / Agent运行时与工具 / 评测观测与治理 / 算法）。这套结构的问题是**只能竖着看**：

```
竖着看（模块卡内部）：这个模块的题全不全  ✅ 已经做过覆盖度校验
横着看（跨模块）：    整个"后端底盘"哪块最薄  ❌ 没有地方看
```

**而面试官是按"人"问的，不是按"模块"问的**——他会从 HTTP 问到 TCP、从 TCP 问到进程线程、从进程线程问到内存、再从内存问回"你的服务为什么这么配"。**这张表补的就是这条横向的地图。**

【结论】**三个用途**：查漏（题挂不上母题 ID 就是缺口）、反查（从题跳卡）、体检（缺口清单 = 下一步建什么）。
