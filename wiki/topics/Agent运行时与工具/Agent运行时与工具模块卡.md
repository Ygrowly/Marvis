# Agent 运行时与工具模块卡

> 本卡是 [[模块深挖卡模板]] 的实战卡。**主线优先**：先看三条线，再落母题，题单只用来查漏。
> 定位：**AI 主战场里最"工程"的一块**。上位是 [[母题-C1-上下文组装与窗口预算]]（Agent 循环每转一圈都在生成新上下文），同层是 [[母题-G5-RAG评测与幻觉率]]（Agent 的评测同样要分层归因）。

## 0. 模块边界（先写这个，防无限扩张）

**包含**：Agent 循环的形状与停止条件、工具契约与 MCP 边界、失败恢复与幂等、长任务的状态模型与 checkpoint、上下文压缩与记忆、沙箱与权限分级、多 Agent 拆分的判据、动态计划下的可靠执行。

**明确不包含**：

- **具体框架的 API**（LangGraph / Agent SDK 的写法）——只讲**选型判据**（状态是否可导出、checkpoint 粒度、幂等支持），不讲怎么调 API
- **模型训练侧的 Agent 能力**（RL 训 tool use）——只到"工具的 schema 设计会影响选择准确率"
- **多 Agent 的具体通信协议实现**（消息队列选型、gRPC 细节）——属于后端底盘
- **前端交互细节**（怎么渲染流式）——只在"事件流要结构化"这一层提
- **自建 MCP server 的完整开发**——只到"边界在哪、什么该做成工具"

**边界判据**：**本模块只回答"Agent 怎么不失控、失败之后怎么接着干、风险怎么管住"**。凡是"某个框架怎么用"的，不进本卡。

## 2. 主线拆解（骨架：这个域在回答哪几个问题）

| # | 主线（它在回答什么问题） | 这条线的关键取舍 | 落几个母题 |
|---|---|---|---|
| 一 | **循环怎么转、什么时候停**：模型怎么在循环里做决定，什么算"做完" | 自主性 vs 可控性；工具能力的表达力 vs 选择准确率 | 2 |
| 二 | **中断与失败之后怎么继续**：进程重启、工具超时、用户确认之后怎么不出错 | 恢复的完整性 vs 重做的成本；记忆的收益 vs 污染 | 3 |
| 三 | **风险与复杂度怎么管**：权限、多 Agent、计划会变 | 安全 vs 效率；能力上限 vs 协调成本 | 3 |

**三条线的关系**：一是"正常路径"，二是"异常路径"，三是"边界"。**面试里区分度最高的是第二条**——因为正常路径人人能画，异常路径才见真章（Raw 里的原话：**"只保存消息历史，进程重启后不知道哪些写操作已完成"**）。

## 5. 项目映射（四个项目逐个过）

### 5.1 RuleArena（规则竞技场）· 主承载项目

- **锚点**：`projects/RuleArena/`
- 用在哪：**显式 FSM 编排**（准备 → 取证 → 各角色审查 → 合并 → 确定性验证 → 人工确认 → 完成）；**Thread/Run/Step/Checkpoint/Artifact/Event 数据模型**；**每个步骤记录 Prompt/Model/Tool/Rule 版本**
- 解决什么问题：**高风险修复发布前 interrupt**；**从任一步 fork 比较不同策略**；**Replay 默认使用记录的工具结果**
- 踩过的坑：【待填 —— 提示：为什么不用 LangGraph 的自由编排？】
- 决策与取舍：【待填 —— 提示：连续无进展、预算耗尽、证据冲突为什么要各有独立终止原因？】
- 对应母题：【A4】【A8】

### 5.2 EnergyOps（金山园区能耗）· 最硬的证据区
