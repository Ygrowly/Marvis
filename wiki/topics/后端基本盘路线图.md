# 后端基本盘路线图

> **定位**：我的主战场是 **AI 应用 / Agent 开发**，后端是**底盘**——它不是加分项，是**准入门槛**。不会就直接挂，会了也不加分。
> 所以策略是：**只铺够用的底盘，把省下的时间投到 Agent 能力上。**
> 铁律：**一次只推进一个模块，未闭环不开下一个。**

## 一、依据

1. **9.9 乐元素实测**：扣分全部落在后端基础（计算机基础 12.4、八股+手撕 10.0），项目题反而 18–21。**短板在底盘，不在项目。**
2. **JD 频率**：六家公司融合核对表里，数据库 / 缓存 / HTTP / 并发是通用要求，且是「为什么选 X 不选 Y」追问的主战场。
3. **来源材料**：`raw/后端技术进阶之路-2026-09-10T171536+0800.md`（小林coding 目录）是**素材库**，不是学习计划——按下面的筛选取用，不按它的顺序走。

## 三、P2：明确不包含（写下它们，然后放下）

> 不是"以后学"，是**现在决定不学**。写在纸上是为了不再惦记。

- **分布式 / 微服务 / 云原生**：服务注册、服务网格、K8s 深入、Serverless —— 校招很少深问
- **非关系型存储的深入机制**：Elasticsearch、MongoDB、HDFS 的内部实现 —— 除非某家 JD 明确要求
  > **2026-09-24 修订**：它们的**选型边界**已由 [[数据存储选型模块卡|数据存储选型]] 的 S3 覆盖（"什么时候不该用关系数据库"）。区别在于：**那份卡只回答"该不该引入、引入要付什么账"，不回答"它内部怎么实现"**——所以这条 P2 依然成立，只是范围收窄了。
- **JVM 调优 / GC 参数**：除非投 Java 岗且被问到
- **设计模式大全**：按需在项目里用，不背 23 种
- **MySQL 源码 / DBA 参数调优大全**：只到「能讲清机制 + 能定位于问题」
- **小林目录里的「高并发优化」独立板块**：其中与业务相关的部分已并进 MySQL 主线六、七

## 四、与 Agent 轨的关系（双轨，不同时推）

| 轨 | 内容 | 定位 | 时间安排 |
|---|---|---|---|
| **A · 后端底盘** | 上面六个模块 | 防守：决定**能不能过** | 主投入 |
| **B · Agent 能力** | 用（重度用 Claude Code/Codex）→ 懂（Agent Loop / 上下文工程 / 工具调用）→ 造（一个做透的端到端项目） | 进攻：决定**上限** | 用每天「1+1+1」里的那一项维持，不单独占大块时间 |

**为什么不并行大投入**：一次只推一个模块是既有铁律。A 是显性短板，先补；B 靠日课维持手感，等 A 的 P0 闭环后再切换重心。

## 五、每个模块的统一动作

```text
① 拆主线（这个域在回答哪几个问题）—— 3–7 条，从问题出发不是从名词出发
② 每条主线落 1–3 个母题（wiki/topics/{模块}/母题-NN-名称.md，按 [[母题卡模板]]）
③ 串完一条主线，立刻口述 3 分钟 + 答两层追问（不是读完再统一练）
④ 走 site/build.py → 母题页 + 复训牌组 → 1-3-7-14-30 调度
⑤ 全模块过 验收门（含判断力测试）才算闭环，未闭环不开下一个
```

**手撕代码是独立日课**，不占模块时间——它练肌肉记忆，模块练理解，混着做两样都做不好。
