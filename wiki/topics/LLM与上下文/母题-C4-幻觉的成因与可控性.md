## 一、教材

### 1. 前提：先把"幻觉"拆成四件事

#### 1.1 定义【事实】

**幻觉（hallucination）**：模型**自信地**生成了一个不成立的陈述。

两个关键词：**自信**（不是"不确定地猜"，是语气笃定）和**不成立**（与事实或与给定证据不符）。

【推导】先破一个直觉：**这不是模型"坏掉了"，而是三套机制叠加的必然产物**——预训练的统计结构、评测的激励结构、以及上下文里有没有那条信息。所以正确的问法不是"怎么消灭幻觉"，是"**我手里这个错误属于哪一类，这一类能压到多低**"。

#### 1.2 来源一：训练数据的统计结构【推导】

预训练做的事是**预测下一个词**，而且——

> **它看到的全是"流畅语言"的正例，没有任何一句被标注为"这是假的"。**

【推导】这直接推出一件事：**错误的可消除性，取决于那类知识有没有规律**。

```text
拼写、括号配对   → 有稳定的模式  → 随模型规模变大而消失
宠物的生日       → 没有模式可学  → 无论算法多先进都必然出错
```

【事实】OpenAI 用一个类比讲得很清楚：如果给几百万张猫狗照片打"猫/狗"标签，算法能学得很准；但如果给每张照片打上"这只宠物的生日"，**这个任务本身就会永远出错**——因为生日跟照片内容没有关系。

【推论】**所以有一类幻觉从根上就学不出来**，只能靠"给外部证据"或者"承认不知道"来处理。这也解释了为什么**拼写错误消失了，事实错误没有**。

#### 1.3 来源二：评测口径的激励【推导】

这是最反直觉、也最值钱的一条。

```text
假设一道题模型不会，它有两个选择：
  猜一个 → 有概率蒙对（比如生日，1/365）
  说"我不知道" → 稳定得 0 分

如果排行榜只看准确率：
  猜 的期望收益 > 0  >  弃答的期望收益 = 0
→ 几千道题累积下来，"爱猜的模型"在榜上比"谨慎的模型"更好看
```

【事实】OpenAI 在 SimpleQA 上的实测，把这个效应量化得很干净：

| 指标 | gpt-5-thinking-mini | OpenAI o4-mini |
|---|---|---|
| 弃答率（不给具体答案） | **52%** | **1%** |
| 准确率（答对，越高越好） | 22% | **24%** |
| 错误率（答错，越低越好） | **26%** | **75%** |

**看这两行**：按准确率排名，o4-mini **更高**（24% > 22%）；按错误率排名，gpt-5-thinking-mini **好得多**（26% < 75%）。

【推论】**排行榜的指标选择，决定了你会选出哪个模型。** 只看准确率，你会挑到一个幻觉率接近 3 倍的模型，还以为自己选对了。这一条直接连到 [[母题-C5-模型选型与降级三角]]。

#### 1.4 来源三、四：上下文工程能管的部分【事实】

- **来源三：上下文里根本没有这条信息。** 模型看不见你的数据库、权限表、上个月刚改的政策。它要么说不知道，要么用训练分布里"相近的知识"补上——**后者看起来完全合理**。
- **来源四：信息给了，但没用上。** 证据确实在上下文里，可是：被长历史稀释（context rot，见 [[母题-C1-上下文组装与窗口预算]]）；两份材料互相冲突、模型自己挑了一个；或者结论对但**引用对不上原文**。

::figure hallucination-sources.svg | 幻觉的四个来源与各自的对策 | 四个来源分别对应不同的对策；前两类的"置信度"部分属于模型属性只能管理，后两类是工程问题能压到接近零——这就是"接了 RAG 就解决了"这句话错在哪

**到这里你应该能回答**：为什么"拼写错误会随规模消失，事实错误不会"？

### 2. 候选对策（先各自介绍，不比较）

#### 2.1 给证据【事实】

- **检索**：把相关材料放进上下文（[[母题-C1-上下文组装与窗口预算]] 的装配问题）
- **先摘录、再作答**：对长文档（超过 20k token），要求模型**先逐字摘出相关原文**，再基于摘录作答；找不到摘录就说"没找到"
- **引用绑定**：要求每条结论都挂到具体来源；**生成之后再自查一遍**——找不到支撑引用的结论，直接撤掉
- **限制外部知识**：明确要求"只用给定资料，不要用你自己的知识"

#### 2.2 允许弃答 + 改评测口径【事实】

- 显式给模型"说不知道"的许可（这一条被 Anthropic 列为**最基本的**手段）
- 更根本的是**改评分**：**把"自信的错误"罚得比"承认不确定"更重**，并给恰当的弃答**部分分**
- 这不是新想法——标准化考试里早就有"答错倒扣分 / 留空给部分分"的做法

#### 2.3 拆解与自校验【事实】

- **链式推理校验**：先让模型把推理过程写出来，再给结论（暴露错误的前提）
- **Best-of-N**：同一 prompt 跑多次，比较输出——不一致的地方就是可疑处
- **迭代精炼**：把上一轮输出当输入，要求它复核或补充

#### 2.4 上下文管理【事实】

压缩、隔离、把证据放到模型真正看得见的位置（[[母题-C1-上下文组装与窗口预算]]）。

### 3. 逐个淘汰（统一指标：**被消除的错误数 ÷ 增加的成本**，且错误与弃答分开定价）

先立口径——**这是本节最重要的一步**：

> **错误（答错）和弃答（说不知道）不是同一种失败，不能同价。**
> 弃答的成本是"转人工兜底"；错误的成本是"客诉 / 返工 / 回滚 / 信任损失"。后者通常贵一个数量级。

#### 3.1 只靠"给证据"能治到哪【推导】

- **治来源三**（没有信息）：非常有效
- **治来源四**（给了没用上）：部分有效——但**如果上下文变长了，反而可能加剧**（context rot）
- **治来源一、二**：**无效**。模型可能拿到了证据，仍然在证据没覆盖的细节上"补全"

【取舍】所以"接了 RAG 幻觉就解决了"的问题在于：**它只治四类里的一类，还可能加重另一类。**

#### 3.2 为什么"允许弃答"是性价比最高的一招【推导】

因为它的成本结构完全不同：

```text
给证据   → 每次请求都要付检索 + 更长的输入（持续成本）
改评测/给许可 → 一次性的口径调整（几乎零边际成本）
```

【事实】而且论文给了它一个更硬的理由：**校准比准确"便宜"得多**——

> 一个完全不懂毛利语的小模型，可以直接说"我不会"；而一个懂**一点**毛利语的模型，反而必须先判断自己的置信度。
> **Being "calibrated" requires much less computation than being accurate.**

【推论】**"让模型知道自己不知道"这件事，比"让模型什么都知道"容易得多。** 所以这是一个性价比极高的方向，也是它最容易被忽略的原因——它不像"上更强的模型"那样有故事性。

#### 3.3 自校验的代价【推导】

- **Best-of-N**：成本直接 ×N，而且**N 次不一致时你还需要一个仲裁策略**
- **链式校验**：增加输出 token（输出比输入贵得多，见 [[母题-C6-成本与长上下文截断]]）
- **迭代精炼**：轮次不可控，容易收敛到"自我确认"而不是"纠错"

【取舍】自校验适合**高价值、低频次**的判定（比如最终发布前的复核），不适合每一次调用。

#### 3.4 胜出方案：按来源分层，各治各的【取舍】

```text
来源一（无模式的事实）→ 给证据；证据也没有 → 允许弃答
来源二（评测激励）    → 改评分：罚自信错误 > 罚弃答，给弃答部分分
来源三（上下文缺失）  → 检索 + 装配 + 先摘录再作答
来源四（给了没用上）  → 上下文管理 + 引用绑定 + 生成后自查撤稿
```

【推论】**这是一个"下限可以推、上限推不动"的问题**：来源三、四是纯工程问题，可以压到接近零；来源一、二里的"置信度"部分是模型属性，**只能管理，不能消除**。任何声称"彻底解决幻觉"的方案，都是在拿来源三、四的成绩去覆盖来源一、二。

**到这里你应该能回答**：为什么"我们用了 RAG"和"我们没有幻觉"之间隔着一整个来源二？

### 4. 量化验证：两笔账

**第一笔：只看准确率，你会选错模型**

沿用 1.3 的 SimpleQA 数据。设某业务每天 10,000 次查询：

```text
弃答 → 转人工，成本 $0.5/次
错误 → 客诉 / 返工，成本 $10/次   （按 20 倍估）
```

| | gpt-5-thinking-mini | OpenAI o4-mini |
|---|---|---|
| 弃答 5,200 × $0.5 | $2,600 | — |
| 弃答 100 × $0.5 | — | $50 |
| 错误 2,600 × $10 | $26,000 | — |
| 错误 7,500 × $10 | — | $75,000 |
| **每日总成本** | **$28,600** | **$75,050** |
| **准确率** | 22%（更低） | **24%（更高）** |

【结论】**准确率更低的那一个，总成本只有对方的 38%。** 排行榜上的名次和业务成本的方向是**相反的**——因为准确率口径把"弃答"和"错误"都算成了"没答对"。

**第二笔：为什么"猜"在准确率口径下几乎不吃亏**

```text
1000 道题，模型明确会 600 道，剩下 400 道完全不知道

弃答模型：600 对 + 400 弃答      → 准确率 600/1000 = 60.00%
猜测模型：600 对 + 400 题按 1/365 蒙
         期望蒙对 ≈ 400 × 0.0027 ≈ 1.1 题
         → 准确率 601.1/1000 = 60.11%

准确率差距：0.11 个百分点   （几乎看不出来）
错误数量差距：0 条  vs  约 399 条   （差 399 倍）
```

【结论】**这就是"考核什么，就得到什么"。** 在两套口径下，"猜测模型"的准确率只差 0.11 个点，但它多产出了近 **400 条自信的错误**。排行榜看不见这 400 条——**而业务方付的正是这 400 条的钱**。

**到这里你应该能回答**：为什么"改评测口径"是减少幻觉的一部分，而不是"刷分技巧"？

### 5. 边界与常见误解

【事实】OpenAI 论文直接列了五条常见误解并逐条反驳，这几条在面试里非常好用：

| 常见说法 | 实际情况 |
|---|---|
| "准确率做到 100% 就没有幻觉了" | **准确率永远到不了 100%**——不管模型多大、搜索和推理多强，有些真实问题本质上无法回答 |
| "幻觉是不可避免的" | **不是**——模型可以在不确定时**弃答**。可避免指的是"自信的错误"，不是"不知道" |
| "避免幻觉需要更大的模型" | **校准比准确便宜**。小模型**可能更容易**知道自己不知道（完全不懂毛利语 → 直接说不会） |
| "幻觉是神秘的故障" | 不是。**成因是清楚的**：预训练的统计结构 + 评测的激励结构 |
| "做一个好的幻觉评测就够了" | **不够**。一个好的幻觉评测，对抗不了几百个"惩罚谦逊、奖励猜测"的准确率评测——**要改的是主口径** |
| "接了 RAG，幻觉就解决了" | **只治来源三**（没给信息）。来源四（给了没用上）可能**加重**；来源一、二它完全不治 |
| "检索失败率降了 49%，所以幻觉降了 49%" | **偷换指标**。检索失败率是**检索层**数字，它只是"证据缺失型幻觉"的**上界**；幻觉里还有"证据给了没用上"和"证据没覆盖但模型硬答"两类，**两者不是包含关系，不能互相换算**。见自测 Q3 |
| "让模型说'我不知道'显得系统很弱" | **反了**。用户对"自信的错误"的容忍度远低于"坦白的不知道"。**用错误率而不是准确率向业务汇报** |

【取舍】读成一句话：**幻觉不是要"消灭"的东西，是要"分门别类地管理"的东西——先把错误和弃答分开定价，你才知道该先治哪一类。**

## 二、自测

**Q1（计算）**：某评测 1000 道题，模型明确掌握其中 600 道。剩下 400 道它完全不知道。

问：**"弃答"策略和"每个都猜"策略（假设蒙对概率 1/365），在准确率上差多少？在错误数量上差多少？**这说明什么？

**A1**：

```text
弃答：600 对 + 400 弃答
     准确率 = 600 / 1000 = 60.00%

猜：  600 对 + 400 题按 1/365 蒙
     期望蒙对 ≈ 400 × (1/365) ≈ 1.1 题
     准确率 = 601.1 / 1000 = 60.11%

准确率差距 = 0.11 个百分点
错误数量：0 条  vs  约 399 条（400 − 1.1）
```

【结论】**准确率口径下两者几乎无法区分（0.11 个点），但多出来的是近 400 条自信的错误。** 这就是"评测口径决定了模型学什么"的具体数量——**榜上看不见那 400 条，业务方赔的正是那 400 条。**

【补充】注意这里的关键结构：**"猜"的期望收益永远为正（1/365 > 0），而"弃答"稳定为 0。** 只要评分不给弃答部分分、不给错误额外惩罚，**理性模型就该猜**。

**Q2（计算）**：沿用 SimpleQA 的实测数据（弃答/准确/错误：gpt-5-thinking-mini = 52%/22%/26%，o4-mini = 1%/24%/75%）。某业务每天 10,000 次查询，**弃答转人工 $0.5/次，错误按客诉计 $10/次**。

问：**两个模型的每日总成本各是多少？如果只看准确率会得出什么错误结论？**

**A2**：

| | gpt-5-thinking-mini | OpenAI o4-mini |
|---|---|---|
| 弃答成本 | 5,200 × $0.5 = $2,600 | 100 × $0.5 = $50 |
| 错误成本 | 2,600 × $10 = $26,000 | 7,500 × $10 = $75,000 |
| **合计** | **$28,600/天** | **$75,050/天** |
| 准确率 | 22% | **24%** |

```text
成本比 = 28,600 / 75,050 ≈ 0.38      → gpt-5-thinking-mini 只要 38% 的成本
```

【结论】**准确率更低（22% < 24%）的模型，总成本只有对方的 38%。** 只看准确率排行榜，你会选到一个成本高 2.6 倍的模型，并且完全不知道问题出在哪。

【补充】这个结论对**倍率极度敏感**：

```text
若错误成本 = 弃答成本（都是 $0.5）：
  gpt-5-thinking-mini = 5,200×0.5 + 2,600×0.5 = $3,900
  o4-mini = 100×0.5 + 7,500×0.5 = $3,800     → 几乎一样，甚至反过来
若错误成本 = 弃答成本 × 100（都是 $50）：
  gpt-5-thinking-mini = $2,600 + $130,000 = $132,600
  o4-mini = $50 + $375,000 = $375,050        → 差距拉大到 2.8 倍
```

**所以做这个判断前，必须先回答一个问题：在你的业务里，一次"自信的错误"值多少次"转人工"？** 这个问题答不出来，选型就是在赌。

**Q3（计算）**：某团队报告："我们用了 Contextual Retrieval，**检索失败率从 5.7% 降到 2.9%（降 49%）**，加上重排后降 67%。"

问：**能说"幻觉降低了 49%～67%"吗？**这两个数字分别是什么口径？

**A3**：**不能。**

```text
5.7% → 2.9%   是「top-20 检索失败率」：相关文档没被召回进前 20 的比例
5.7% → 1.88%  是加上重排后的同一指标（5.7% × (1 − 67%) ≈ 1.88%）
```

两个都是**检索层**指标，衡量的是"**证据有没有被取回来**"。它只对应幻觉四类来源里的**来源三**，而且关系比看上去弱：

```text
检索失败（证据没取回来）
   ↓ 是"证据缺失型幻觉"的必要条件，但不充分
   ↓ 模型仍可能靠参数化知识答对 —— 所以检索失败不等于一定出错
证据缺失型幻觉  ≤  检索失败率          ← 它是上界，不是下界

总幻觉率 = 证据缺失型 ＋ 有证据不依（来源四）＋ 无模式事实（来源一）＋ 评测激励（来源二）
        →  与检索失败率之间没有必然的大小关系
```

【结论】**检索失败率是"证据缺失型幻觉"的上界，不是幻觉率**。把 -49% 说成"幻觉降低 49%"是**指标偷换**——方向上还是**高估**（真实改善一定小于这个数）。

【正确说法】"我们把检索失败率从 5.7% 降到 2.9%，这**消除了'无据可依'这一类幻觉的约一半**；但检索层解决不了'给了证据没看进去'和'不确定时仍然作答'这两类，需要上下文管理和评测口径配合。"

**Q4（纠错）**：下面这段话哪里不准确？

> "等模型再大一点、再强一点，幻觉就自然解决了。"

**A4**：三处不准确。

1. **准确率永远到不了 100%**。论文明确指出：不管模型多大、搜索和推理能力多强，**有些真实世界的问题本质上无法回答**（信息不存在、需要澄清的歧义、需要现实世界动作才能确定的事）。所以"等一个 100% 准确的模型"这条路不存在。
2. **方向反了**：幻觉里"自信的错误"这部分，是可以靠**弃答**避免的——**问题不是模型不够强，是评测奖励它猜**。
3. **"更大 = 更会承认不知道"也不成立**。论文给了一个反直觉的例子：一个**完全不懂**毛利语的小模型可以直接说"我不会"；而**懂一点**毛利语的模型反而必须去判断自己的置信度。**"Being calibrated requires much less computation than being accurate."**

【准确说法】"幻觉里有一部分（任意低频事实）从统计上就学不出来，这部分要靠**外部证据 + 允许弃答**处理；而'爱猜'这个行为是**评测激励**塑造的，换更大的模型不会自动改掉——**要改的是评分口径。**"

**Q5（纠错）**：下面这段话哪里不准确？

> "我们给系统接了 RAG，检索到的资料都会进上下文，所以幻觉问题基本解决了。"

**A5**：三处。

1. **RAG 只治四类来源里的第三类**（上下文里没有这条信息）。它对**来源一**（任意低频事实）无效——如果检索没覆盖到，模型照样会补;对**来源二**（评测激励）**完全不治**——即使证据齐备，模型仍会在证据没覆盖的细节上自信作答。
2. **它可能加重来源四**。资料进上下文会让上下文变长，而长上下文里关键证据会被稀释（context rot）。**"检索到了"不等于"用上了"。**
3. **"检索到的都会进上下文"这句本身就不严谨**：检索有 top-k 截断、有重排、有权限过滤，进不去的部分是静默的。

【准确说法】"RAG 把'无据可依'这一类幻觉压下去了，但它同时引入了'证据被稀释'的新风险；剩下两类（低频事实、评测激励）需要靠**引用绑定 + 生成后自查撤稿 + 允许弃答 + 改评分口径**来处理。"

## 三、面试输出（学完再看）

**一句话结论**：幻觉不是一个 bug，是**四件不同的事叠加**：① 预训练只有流畅语言的正例、没有真假标签，所以**任意低频事实（比如生日）从统计上就学不出来**，而拼写这类有规律的错误会随规模消失；② 评测只按准确率排名时，"猜"的期望收益为正、"弃答"稳定为零，**模型被训成应试高手**；③ 上下文里根本没有那条信息；④ 信息给了却被稀释、冲突或忽略。**对策必须按来源分开**：给证据 + 先摘录再作答 + 引用绑定（治③④）、允许弃答 + 改评分（治②）、上下文管理（治④）。最关键的一个换算：**错误和弃答不能同价**——实测数据里，准确率更低（22% vs 24%）的模型，错误率只要 26% vs 75%，按业务成本算总成本只有对方的 **38%**。

**恢复关键词**：四类来源 / 预训练没有真假标签 → 有规律的错消失、随机的错留下 / 生日类比 / 准确率口径奖励猜测（1/365 > 0）/ SimpleQA 22-26 vs 24-75 / 错误与弃答分开定价 / 校准比准确便宜 / 先摘录再作答（>20k 文档）/ 引用绑定 + 生成后撤稿 / RAG 只治第三类，可能加重第四类 / 检索失败率 ≠ 幻觉率 / 改主口径而不是加一个小评测

**核心不变量 / 主线**：
**幻觉的可治程度取决于它的来源，而"来源"和"模型强弱"几乎无关。**
属于**工程**的（没给信息、给了没用上）可以压到接近零；属于**统计与激励**的（无模式的事实、评测奖励猜测）只能管理——**而管理它的代价，远低于消除它的代价**。

**完整回答骨架**：先拆词（四类来源，各自的成因）→ 用"拼写会消失、生日不会"说明统计结构这一层 → 用 SimpleQA 数据说明评测激励这一层 → 上下文两类的工程对策 → 逐个对策的代价与边界 → 错误/弃答分开定价的算式 → RAG 只治一类的辨析 → 收束到"分层管理，不是消灭"

**完整回答（口述稿）**：
幻觉不是一个 bug，是**四件不同的事叠加**：① 预训练只有流畅语言的正例、没有真假标签，所以任意低频事实从统计上就学不出来（而拼写这类有规律的错误会随规模消失）；② 评测只按准确率排名时，"猜"的期望收益为正、"弃答"稳定为零，模型被训成应试高手；③ 上下文里根本没有那条信息；④ 信息给了却被稀释、冲突或忽略。

对策必须**按来源分开**：给证据 + 先摘录再作答 + 引用绑定（治③④）；允许弃答 + 改评分（治②）；上下文管理（治④）。长文档（超过 20k token）的做法是先逐字摘出原文、找不到就明说"没找到"，再基于摘录作答。

最关键的一个换算：**错误和弃答不能同价**——准确率更低（22% vs 24%）的模型，只要错误率是 26% vs 75%，按业务成本算总成本只有对方的 **38%**。

最后一条边界：RAG 是**必要不充分**——它治的是"无据可依"，接完还要做引用绑定和答案级评测。

**分层要点**：
- **结论**：四类成因（统计结构 / 评测激励 / 上下文缺失 / 有据不依），对策必须按来源分开；错误与弃答不能同价。
- **推导链**：预训练只有正例 → 评测奖励猜测 → 上下文缺信息 → 信息被稀释或冲突 → 各自对应不同对策。
- **量化**：错误率 26% vs 75% 时总成本只有对方 38%；准确率 22% vs 24% 但总成本更低。
- **边界与常见误解**：准确率做不到 100%；幻觉不是"神秘的故障"；校准比准确率便宜（小模型可能更容易承认不知道）；只做幻觉评测对抗不了几百个奖励猜测的准确率评测——**要改的是主口径**；RAG 接了不代表没幻觉。

**追问**（先说后看）

1. **怎么让模型愿意说"我不知道"？** —— 两层：**prompt 层**显式给许可（"不确定就说不确定"）；**评分层**把"自信的错误"罚得比"承认不确定"更重，给恰当的弃答部分分。**第二层更根本**——因为第一层只是措辞，第二层才改激励。
2. **长文档怎么做 grounding？** —— 对超过 20k token 的文档，**先要求逐字摘出相关原文（找不到就明说"没找到"），再基于摘录作答**。生成完成后再自查一遍：每条结论找支撑引用，找不到的**直接撤掉**。
3. **Best-of-N 值不值得？** —— 对**高价值、低频次**的判定值得（发布前复核、高风险决策）；对每次调用不值得——成本 ×N，而且还需要一个仲裁策略处理不一致。**别把它当常规防线。**
4. **怎么向业务方汇报幻觉治理的效果？** —— **用错误率，不用准确率**。原因见 Q1：准确率对"弃答"和"错误"一视同仁，看不出差别；而业务的成本是错误数的函数。**"准确率 +5.3%"听起来平淡，"错误率减半"是同一件事的另一种说法**（[[母题-C3-Prompt版本管理与回归]]）。
5. **RAG 和幻觉是什么关系？** —— RAG 降低的是"**无据可依**"这一类，代价是上下文变长可能加剧"**有据不依**"。**所以 RAG 是必要不充分**——接完 RAG 以后，还要做引用绑定和答案级的评测。
6. **怎么设计评测集才能反映幻觉？** —— 三个要点：**指标里区分错误与弃答**；**答案级评测要和检索级评测分开**（别拿召回率冒充正确率）；**held-out 集合**（[[母题-C3-Prompt版本管理与回归]]）。

**同类变体**

- 「RAG 的引用能不能防幻觉？」——**能防一部分，但引用本身也会被编**。所以关键的工程动作是**生成后自查**：把每条结论回头去原文里找支撑，找不到就撤稿。**"要求引用"是 prompt，"验证引用"才是机制。**
- 「多轮对话里幻觉会不会累积？」——会。上一轮的错误结论进了下一轮上下文，就变成了"已确认事实"。**所以摘要必须标注哪些是已验证事实、哪些是模型推断**，并且关键状态要回权威源重查（[[母题-C1-上下文组装与窗口预算]]）。
- 「模型拒答率太高怎么办？」——先分清是**安全拒答**（`stop_reason: refusal`，会绕过 schema）还是**不确定性弃答**。两者处理方式完全不同：前者是策略问题，后者可能是"证据没给够"或"任务本身无解"。

**可迁移场景**：

- **数驭穹图**：NL2SQL 的幻觉有专门形态——**表名、字段名、口径被编出来**。这类属于**来源三**，靠"Schema 装配 + 干跑校验"压；但"口径理解错"属于**来源四**，需要把口径定义和样例一起放进上下文并做引用绑定。
- **RuleArena**：审查结论的幻觉表现为**引用了不存在的规则条款**。这正好对应 Anthropic 的"生成后自查撤稿"：**每条结论回原文找支撑，找不到就撤**。规则条款的存在性校验是纯工程，能压到零。
- **EnergyOps**：告警诊断会编造不存在的"历史相似事件"。**对策不是换模型，是给证据**——把历史工单检索进上下文，并且**要求引用具体的工单号**。

**方言差异（与 RAG 簇的分工）**：本卡管的是"**幻觉作为一类错误的成因与对策**"；检索怎么做到位（切分、混合检索、重排、增量索引）属于 RAG 簇（G 系列）。**两边的接口是"检索失败率 ≠ 幻觉率"这一条**——RAG 负责把失败率压下去，本卡负责告诉你压下去之后还剩什么。
