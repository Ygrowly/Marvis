# 网站设计参考与图表/界面 Agent Skills 盘点

> **缘起**：主人想给第二大脑站点加 3D，但自己先立了判断——**「3D 确实很酷炫，但应该为网站目标服务」**。本文档据此归纳：先记本站目标是什么，再按「能用在哪」整理参考源，而不是收藏炫技链接。
> **来源性质**：所有条目均于 2026-09-26 逐一抓取一手页面 / GitHub README 核实；star 数是**第三方目录自述的易变测量值**，只记「日期 + 来源」，不当规格用（照「最贵的教训」）。

## 一、本站目标（先立靶子）

`site/` 是**面试复训系统**：母题页、进度页、项目口述页——核心动作是「看题自答 → 展开核对 → 派单复训」。它不是作品集落地页。

推论：
- 3D / 着色器类效果只配当**特定页面的点缀**（如项目口述页的 hero），不是全站方向；任何效果不得拖慢复训主路径。
- 本站已有红线继续有效：离线优先、mermaid 双轨（2026-09-25 定）、`site/figures/*.svg` 走 build.py 流水线、**图由 AI 生成、人审图**。

## 二、设计参考站点（看样与抄结构）

### ThreeUI — threeui.com/browse

Three.js 组件 / 模板 / 交互着色器库。九个分类：Landing Pages · Hero · Three.js · Backgrounds · Buttons · Text Animation · UI Elements · CSS · Motion Design。条目标 FREE / PRO，多数给 full html（单文件可拆）。

**用法**：想要 3D 点缀时来这里挑 FREE 的 full-html 样例拆着学；PRO 只看不买。注意它的样例是营销落地页气质，与复训站气质不同，拆结构不抄气质。

### Beautiful UI — beautifului.dev

**「AI 原生界面」的原语集**，这是四个参考里气质最贴本站的。收录的组件类型：loading state（像素网格 + 已耗时）、thinking（可展开的 traces：steps/reasoning/search/coding）、tool chips（工具调用压缩成小片）、prompt bar（@ 来源、/ 命令、模型选择器、听写）、diff table（AI 对表格数据的逐行修改提案）、sidebar nav、command search、code block + diff、fine-tune card（agent 调设计属性的 inspector）。

**用法**：本站若加「AI 问答 / 复训对话卡」「追问展开」这类界面，直接对照它的结构抄；它是纯结构参考，不绑定某套框架。

## 三、界面质量类 Agent Skills

### hallmark — github.com/Nutlope/hallmark

Together AI 出品，定位 **「Anti-AI-slop design skill」**：拒绝一切一眼 AI 生成的设计。机制：按 brief 选 macrostructure（21 种）+ 穿 21 个 theme 之一，过 **58 道 slop-test 门**（编号 1–57 加 38a，v1.1 后口径）+ 产出前自评（pre-emit self-critique）。核心理念：两份不同 brief 的产出要像两个不同的站，不是同一模板换色。安装 `npx skills add nutlope/hallmark`，规则在 `SKILL.md + references/`，worked examples 在 `docs/`。

**用法**：做任何对外单页（简历交付案例页、破局方案页这类 HTML 成品）时值得对照它的 slop-test 清单自检——那份清单本身就是免费的「AI 味体检表」。

### jakubkrehel/skills — 11 个界面质量 skill 合集

作者 jakub.kr / 设计工程杂志 Interfaces 的方法论 skill 化。清单：

| skill | 干什么 |
|---|---|
| better-interface | 把下面所有 better-* 合成一次总审查 |
| better-ui | 同心圆角、光学对齐、语境图标、点击热区、动画等 |
| better-typography | 字阶、间距、可变字体、OpenType 特性、截断换行 |
| better-colors | 生成调色板、语义 token、格式转换、对比度检查（OKLCH） |
| better-accessibility | 无障碍合规 |
| better-layout | 分组、对齐、阅读顺序 |
| better-writing | 产品文案一致性 |
| interface-review | 多维度详细评审（用户手动触发） |
| explain-interface | 拆解网上某个动效 / UI 是怎么实现的 |
| break | 把组件渲成全状态页做压力测试 |
| variant | 给正在做的组件生成多个变体迭代 |

安装 `npx skills add jakubkrehel/skills`。

**用法**：这些是「改质量」不是「换方向」，与本站现有 CSS 体系兼容；进度页重构后（2026-09-25）若再动布局，可拿 better-ui / better-layout 逐条对照体检。explain-interface 正好对上「看到好页面想知道怎么做的」这类需求。

### 横评结论（选型速查）

- 要**放进展里的交互架构图** → Archify（可验证、可探索、有校验回执）。
- 要**中文名、出高清 PNG、AI/Agent 领域图** → fireworks-tech-graph（本机需先解决 rsvg-convert）。
- 要**最全图类型 + 官方图标 + 可回编辑器改** → drawio-skill（依赖 desktop CLI，与站内自动构建不合，适合独立产物）。
- Cocoon-AI 单图类型，价值在其**暗色语义配色规则**，可抄规则不必装工具。

## 五、对本站（site/）的落点建议

1. **3D**：降级为项目口述页 hero 级点缀；真要做，拆 ThreeUI 的 FREE full-html 样例，且不进复训主路径（不挡渲染、可整段删除）。当前秋招窗口期，**不建议动**。
2. **界面质量**：hallmark 的 slop-test 清单 + jakubkrehel 的 better-* 合集，作为下次动 progress.html / 口述页样式时的**体检清单**用，不引入新框架。
3. **图表**：本站已有 mermaid 双轨 + `site/figures/*.svg` 两条正轨。fireworks-tech-graph 的 SVG 产出**理论可入 `site/figures/`**（人审后），但需先验证 Windows 下 rsvg-convert；Archify 产自包含 HTML 而非内联 SVG，**进 build.py 流水线需先评估**，短期更适合当独立查证工具（如数驭穹图架构图的交互版）。
4. **红线不变**：所有工具产出都是 AI 生成——「图由 AI 生成、人审图」继续适用；图表里的数字 / 结构必须对着项目正本核对（口述页 90 秒稿的教训：数字只能从 md 正本原样抽取）。
