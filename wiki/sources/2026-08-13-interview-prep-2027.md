## 共同结论

1. **面试考三层**：会不会用 → 理不理解设计 → 能否工程取舍；无标准答案，考「经历过什么」。
2. **2026 高频深挖区**：RAG 全流程、Agent Evaluation、前缀缓存、上下文管理、记忆系统、成本控制——全部指向「工程取舍」而非概念背诵。
3. **简历每句话都要扛住三层深挖**，每个技术选型都要能答「为什么选 X 不选 Y」；答不上的删掉或补课。
4. **表达先结论后细节**，不会就承认；复盘是最大杠杆。
5. **投递执行层决定约面率**：STAR + 量化、项目必须上线、作品集/GitHub 链接、命名与招呼语细节。

## 真正的分歧

- **「AI 生成 90% 代码」的表达**：鱼皮认为是加分项（人在把控方案）；面试官复盘则专门拷打「堆技术」简历——同一事实的表达方式决定观感，需要把「用 AI」转译为「工程判断」。
- **反问策略**：46 分钟篇主张攻击性问题（问竞品优势、带教是谁，筛掉不靠谱公司）；修炼手册主张请面试官给自己复盘——场景不同：前者反向筛选，后者学习复盘。
- **记忆位置的说法矛盾**：1h19m 篇说 memory 放 prompt 最前是为前缀缓存；46 分钟篇抓包「memory 位于 prompt 中部」与实际「检索后注入」不符——两个来源对记忆注入位置的表述不一致，需自行理清正确实现。

## 新增或修正的知识

- **前缀缓存细节**：tool schema 是缓存前缀的一部分，改动即击穿；Claude Code Plan 模式用软约束保缓存。
- **成本控制五法**：前缀缓存友好设计、模型分级、减少 step、上下文剪枝、重试限流。
- **记忆系统灵魂**：事实/推导/偏好三型 + 写入触发 + 矛盾检测。
- **生产四问**：投递失败怎么记（Run Outcome ≠ Delivery Outcome）、超时写操作能否重试（幂等键/checkpoint/unknown）、以谁的身份行动（用户 vs 应用身份）、版本升级如何证明不退化。
- **实习表达三问框架**：真做过、为什么做、有无可迁移判断力——别陷入代码细节。
- **项目合理性公式**：真实问题 × 现有方案不足 × 技术增益；「豆包就能解决」的场景要换掉。
