# 主题：Agent 评测与可观测体系

## 一句话结论

评测体系是 Agent 上生产的质量基线：先分对象再定指标，观测（Trace）是评测的基座，评分器优先级共识为「确定性规则 > LLM Judge（须与人工校准）> 人工兜底」，badcase 回流成回归用例并嵌入 CI 门禁是评测飞轮的核心。

## 共同结论

1. **观测/Trace 是评测基石**：没有全链路轨迹，评测无从谈起；LoongSuite 主张从设计期就把可观测作为 Agent 的标准能力。
2. **只评结果会漏掉「结果对、过程错」的假阳性**：过程 + 结果双评是共识（美团四层、TPerf 五大维度、推查查轨迹回放都指向同一结论）。
3. **评分器优先级共识**：确定性规则 > LLM Judge > 人工兜底；LLM Judge 必须与人工校准（参考值：美团 99% 数字站长、得物 92%+、方法论文建议 85% 起步）。
4. **badcase 是最核心资产**：必须回流成回归用例（TPerf 主张能力测评毕业后 100% 转回归测评）并嵌入 CI 门禁。
5. **评测体系靠 Good/Bad Case 迭代演化**，而不是一次设计完美。

## 真正的分歧

- **离线 vs 在线**：方法论文与 TPerf 以离线评测集 + 门禁为主（方法论文主张离线门禁与线上灰度联动）；得物推荐平台是纯线上大盘审计（小时级反馈）；监控篇是「在线基线 + 离线回放验证」。
- **指标选择不可通用**：任务成功率/pass^k、主观 1-5 分体验、时序偏离三者互不通用，印证「先分对象再定指标」。
- **稳定性容忍度**：腾讯按 Agent 类型定 0%~40%（对辅助分析类主动选 0 容忍）；方法论文要求统计显著性检验；pass@k（至少一次成功）与 pass^k（连续成功）并存。
- **模型能否当评委**：多数文章把 LLM Judge 作为主路径校准后使用；监控篇和推查查更信任确定性规则与回放。

## 新增或修正的知识

- **长程 Agent 的 Task 三元组评测**：prompt + expected behavior + trace，比单轮问答评分更接近真实任务。
- **Skill 全生命周期测评**：触发/过程/产物/容错四个环节分别评，而非只评最终输出。
- **回放准入制**：诊断 Agent 的自主推理轨迹只有通过沙箱回放、与专家一致率 >90% 才能泛化成 Highway 的 Story/Skill——「反思-抽象-验证」的进化闭环。
- **Skill/Token 级观测语义**：gen_ai.skill.* 与 invoke_skill Span 做功能域归因，每 Token 耗时/Top-K 概率可观测。
- **「候选≠通知」边界**：异常发现只生成带证据的候选，是否通知由策略层决定，避免误报消耗信任。
