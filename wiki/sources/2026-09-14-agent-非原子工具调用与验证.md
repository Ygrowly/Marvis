# Agent 非原子工具调用与「验证先于重试」（2026 双论文综述）

> **来源范围**：两篇 2026 年 arXiv 论文 + 工程侧同类做法的横向对照。为 RuleArena 的定位校验而做（2026-09-14），非日常收藏流。
>
> - **论文 A**：*Verified Tool Calls Improve LLM Agent Reliability Under Non-Atomic Failures*（arXiv:2608.02645，2026-07-31，Old Dominion University / Christopher Newport University）
> - **论文 B**：*RAILS: Verification-Native Clearing for Agentic Commerce*（arXiv:2606.08790，2026-06-07，Evolutionairy AI）

## 一句话结论

**「工具调用不是原子的」已经被形式化，且「重试前先验证外部状态」被实测证明有效——收益来自验证而不是重试。**

## 核心内容

### 论文 A：把问题说清楚了，并用实验证明了怎么解

**根因表述（本项目直接借用）**：

> **Agent 看到的是「响应通道」，事情实际发生在「效果通道」——两个通道是分开的。**

**四种非原子失败模式**：超时但已生效、延迟可见、部分状态更新、陈旧读。

**实测结论**（两个任务 × 三档故障强度）：

| 方法 | 重复副作用发生率 |
| --- | --- |
| 只重试（Retry Only） | **20% → 76%** |
| 重试前验证（Verify-Before-Retry） | **0% → 20%** |

**最关键的一条消融**：**收益来自「验证」而不是「重试」**——重试本身会不断制造新的重复机会。

**另一条容易被忽略的贡献**：只看「任务最终是否成功」会**掩盖不安全的执行路径**（Agent 可能靠别的方式把事做对，但路上已经产生了重复写入）。

### 论文 B：把问题抬到结算层，做了形式化

提出 **agentic clearing**（智能体清算）：结算发生之前必须先裁决 Agent 是否履行了义务。核心不变量是——

> **任何有资金后果的结算，都不得由低于义务门槛的证据支撑。**

配套七个原语（义务对象、证据信封、验证网格、清算决策、结算指令、清算护照、终局规则）与「可采纳性分级验证」的形式模型。**注意：论文不移动也不持有资金**，它是协议规格而非实现。

## 观点差异（两篇真正分歧的地方）

| | 论文 A | 论文 B |
| --- | --- | --- |
| **层** | 工程层：工具调用封装 | 结算层：清算协议 |
| **产物** | 减少重复副作用 | 清算决策 + 结算指令 |
| **方法** | 实验测量 | 形式化建模 + 不变量声明 |
| **验证依据** | 后置条件（布尔） | 可采纳性门槛（分级） |

**共同点**：都认为**正确性依据必须来自外部状态，不能来自执行信号**。这是两篇能拼在一起的原因。

**张力的地方**：论文 B 声称「我们不知道有先前的 agent-commerce 验证机制声明过这类性质」——**这是该文自己的新颖性主张，不是已验证事实**；论文 A 做的是 wrapper 层，不做裁决也不做结算。两者合起来说明：**这个方向在快速细分，但尚无人把它落成「上线前的发布门禁」**。

## 相对现有知识的新增

1. **一套可直接用的术语**：「响应通道 vs 效果通道」「非原子工具调用」「verify-before-retry」——比「ACK 不等于成功」更精确，面试可用。
2. **一个可引用的数字**：只重试的基线重复副作用高达 **76%**，验证后压到 20% 以内。
3. **一条评测设计依据**：不能只看最终成功率，否则会漏掉「路径不安全但结果正确」的失败。
4. **一个定位校正**：**这不是无人区**。声称首创会被击穿；正确姿势是承认共识已成形、说清自己占哪一格。

## 可信度与待验证点

**可信**
- 论文 A 的核心结论（验证优于重试）有对照实验支撑，且与本项目在真实沙箱里的设计取向一致（不信 ACK、重读权威状态、幂等键 + Receipt）。
- 两篇的**问题描述**互相印证：不同团队、不同层，都指向同一个根因。

**待验证**
- **两篇都是 arXiv 预印本，未经同行评审**——引用时说「有论文指出」，不要说「已被证实」。
- 论文 A 的绝对值（20–76%、0–20%）来自**受控模拟环境**，不能直接外推到生产；引用时带上「在他们的模拟环境里」。
- 论文 B 是**协议规格**，含形式模型与健全性声明，但**不是跑出来的系统**；把它当作「学术议程」而非「可用产品」。
- 「尚无人做发布门禁」是**基于当前检索的判断**，不是已证明的空白——检索范围有限（本次为定向搜索，非系统综述）。

## 带着哪些问题读

1. 论文 A 的四种失败模式里，**哪几种在本项目的沙箱里能确定性复现**？——这直接决定 Refund Agent 的故障轴怎么设计。
2. 论文 A 的「后置条件验证」与我们的「业务不变量裁决」差在哪？**布尔通过 vs 算得出金额**，这个差异在面试里怎么一句话说清？
3. 论文 B 的「可采纳性门槛」如果借用，能否给「门禁阈值」一个更严谨的说法？
4. 还有没有第三类做法（既不是 wrapper，也不是清算协议）在做这件事？——**这个问题的答案会决定 §1.6 要不要再改一次**。
