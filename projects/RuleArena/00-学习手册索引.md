# RuleArena 快速学习与面试手册 v0.1

适用目标：AI 应用开发、Python 后端、Agent 工程岗位  
学习方式：半开卷速学 + 案例决策链 + 尽早模拟 + 只补严重断点  
依据：RuleArena PRD、领域模型、技术 Spec、阶段 Spec 与已确认项目说明  

> 这套资料用于掌握项目设计和面试表达，不替代代码事实审计。凡涉及“已实现、已部署、达到指标”的说法，必须在真实仓库、测试、BenchmarkRun 或线上环境中再次核对。

---

## 1. 最终学习目标

### 功能层

能够讲清：

- RuleArena 解决谁的什么问题；
- 为什么是电商退款、优惠、积分和会员规则；
- 用户输入、系统处理、输出和边界；
- 黄金案例怎样从规则变更走到发布回归；
- 为什么不是一段 Prompt 或普通测试生成器。

### 设计层

能够讲清：

- 为什么先编译 RuleSpec 并人工确认；
- 为什么 Workflow 控制主流程、Agent 只搜索未知路径；
- 为什么必须分离 Simulator、Sandbox、Oracle 和 Ground Truth；
- 为什么用 BFS + 策略 Agent，而不是纯 Agent；
- 为什么多策略隔离而不让 Agent 自由讨论；
- 关键替代方案、代价和升级条件。

### 工程层

能够讲清：

- 写动作如何处理幂等、超时和结果未知；
- Worker 崩溃、SSE 断线、Redis 故障如何恢复；
- Trace、Checkpoint 和权威状态怎样分工；
- Golden Set、Baseline、pass@k/pass^k 和 Release Gate；
- Ground Truth 如何隔离，怎样防止泄题和指标作弊；
- 如何做容量规划、成本限制、监控和发布回滚。

最终能力不是背诵术语，而是：

> **把一个真实业务问题从需求、建模、设计、实现、验证、上线风险到演进条件完整讲明白。**

## 2. 一条项目主线

```text
电商规则变更
→ 自然语言编译为 RuleSpec
→ 人工确认歧义并冻结版本
→ BFS 与策略 Agent 搜索异常动作序列
→ Reference Simulator 快速探索
→ Commerce Sandbox 真实 API 重放
→ 确定性 Oracle 检查业务不变量
→ 生成 1-minimal Counterexample
→ Fixed 版本回归
→ Benchmark 与发布门禁
```

一句话记忆：

> **Agent 找路径，Sandbox 执行动作，Oracle 判结果，Counterexample 做回归。**

---

## 3. 三个核心难题

### 主战难题：如何证明 Agent 找到的风险是真的

重点：Simulator/Sandbox/Oracle 分离、黑盒 Replay、Evidence、1-minimal。

### 增强难题一：有副作用动作超时后怎样不重复执行

重点：业务幂等键、ActionReceipt、权威状态查询、Checkpoint、`ACTION_UNKNOWN`。

### 增强难题二：怎样证明 Multi-Agent 真的有价值

重点：Golden Set、hidden 隔离、Random/BFS/Single/Multi、公平预算、pass@k/pass^k、成本和误报。

这三个难题分别证明：

| 难题 | 面试信号 |
| --- | --- |
| 独立裁决 | 懂 Agent 可靠性和业务验证 |
| 副作用恢复 | 懂后端一致性和生产故障 |
| 评测门禁 | 懂模型不确定性和持续迭代 |

## 5. 推荐学习方式

每篇只进行四步：

1. **看主线**：先理解问题与方案关系；
2. **看标答**：不要求先独立想出答案；
3. **看关键词复述**：用自己的话讲 30～90 秒；
4. **只记断点**：事实或原理错误才专项补充。

半开卷复述：

```text
阅读完整答案
→ 只看“关键词”
→ 用自己的话复述
→ 卡住立即查看
→ 第二次讲顺就进入下一项
```

不要做：

- 一开始逐题闭卷；
- 因为一个细节卡住半小时；
- 把所有实现细节背成源码；
- 为了显得深入学习不属于项目规模的复杂架构；
- 在没有事实证据时背诵漂亮指标。

## 6. 三个交互检查点

### 检查点一：项目总览

学完 `01` 后，闭卷讲一次 90 秒主线。只检查：

- 用户与问题是否具体；
- 链路是否完整；
- Agent 与确定性程序分工是否正确；
- 是否讲出最小反例和修复回归。

### 检查点二：核心难题

学完 `03`～`05` 后，用 3～5 分钟讲“如何证明 Agent 找到的漏洞是真的”。只追问三个问题：

1. 为什么 Simulator 不能直接作为漏洞证据？
2. Oracle 怎样避免与 Sandbox 自己验证自己？
3. Multi-Agent 的提升如何排除预算更多造成的假象？

### 检查点三：完整项目模拟

全部完成后进行一次 30～40 分钟模拟：项目介绍、核心难题、架构选型、故障处理、指标口径和迁移题。每轮只记录并修复三个最严重断点。

## 7. 事实标签

学习和面试统一使用：

| 标签 | 含义 | 面试表达 |
| --- | --- | --- |
| `DESIGN` | 已确认设计 | “项目设计为……” |
| `IMPLEMENTED` | 代码与测试可证明 | “当前已经实现……” |
| `MEASURED` | 来自实际运行 | “在某版本评测中测得……” |
| `TARGET` | 验收目标 | “MVP 的门禁目标是……” |
| `ESTIMATE` | 容量/成本估算 | “按照当前配置估算……” |
| `NOT VERIFIED` | 尚未独立核验 | “目前没有足够证据确认……” |

当前学习资料中的容量、成本和部分性能数据默认是 `ESTIMATE`；24 Case、hidden ≥75% 等首先是 `TARGET`，只有完成实际 Benchmark 后才能变成 `MEASURED`。

## 8. 第 1、3、7 天复习

### 第 1 天：恢复主线

- 只看各篇“关键词”；
- 讲 90 秒项目介绍；
- 讲主战难题；
- 回答 10 道最高频题；
- 修复最多 3 个断点。

预计 35～45 分钟。

### 第 3 天：串联设计

- 随机抽 4 张架构选型卡；
- 随机抽 3 个线上故障；
- 解释一个指标口径；
- 做一次 15 分钟短模拟。

预计 45～60 分钟。

### 第 7 天：真实面试模式

- 闭卷 20 秒、90 秒和 5 分钟介绍；
- 完整模拟一次；
- 检查所有简历 Claim 是否有证据；
- 只更新三个最严重断点。

预计 60～90 分钟。

## 9. 完成标准

不要求一次全部记住。快速学习完成的标准是：

- 90 秒主线没有事实错误；
- 三个难题至少能深讲一个，另外两个能讲清基本机制；
- 八张选型卡中任意抽四张可以说明原因和代价；
- 八个故障中任意抽三个可以按“发现—止血—定位—修复—验证—预防”回答；
- 指标全部知道是实测、目标还是估算；
- 遇到不知道的细节能明确边界和验证方法，而不是编造。
