01主干：一次调用的钱和可靠性怎么被管住正本 wiki/topics/LLM与上下文/

分层走一遍：前提（不可靠）→ 窗口（预算）→ 四种手段（装配）→ 三层约束（接住输出）→ 成本与闭环。
主干叙事（一段读完）：这一模块的一条线是 —— 先承认模型不可靠（生成是逐 token 采样，合法结构只是概率上更可能；幻觉是训练统计结构、评测激励、上下文缺失、信息没用上四件事的叠加）， 再承认上下文是有限预算（窗口是容量不是质量，注意力 n² 让每个新 token 都在摊薄预算；而历史每轮重发让成本按平方增长）。于是每一次调用都要做三件事： ① 装配 —— 用选择 / 压缩 / 隔离 / 缓存四种手段，在有限窗口里放下「最小的那组高信号 token」； ② 约束 —— 输出用提示 / 解码 / 事后校验三层，语法靠解码封死、语义靠校验拦住，改动走版本与回归； ③ 记账 —— 同一个 token 有四种价钱，先做无损的（提命中率），再做双赢的（去拐杖），最后才做有损的（压缩）。 而这三件事都用同一把尺子量：每个正确结果的全成本 =（单次成本 + 失败率 × 失败代价）÷ 成功率，并且必须用没参与调优的 held-out 验收。评测结果反过来改 Prompt、调 effort、重选型 —— 这条绿色的回灌线才是闭环。
读法：蓝线是一次调用的主线；橙线是两套控制手段（进去的四种、出来的三层）；紫线是回归验收；绿线是闭环回灌。顺序不能反 —— 不理解第 1 层（不可靠是前提），就会把工程问题当成换模型问题。

      05要能现场算出来的数正本 六张母题卡「一、教材」推导

      每个数都要带推导，只报结果是会被追问倒的。
      平方增长
      12.3M = 20.5×
      40 轮 × 15K：累计 = 15K×(40×41/2) = 12.3M，是最后一轮 prompt 的 (n+1)/2 = 20.5 倍 —— 这个倍数只跟轮数有关，跟每轮多大无关。
      全命中能压到多少
      $100.5 → $11.2
      100 轮、稳定前缀 100K、每轮 2K：不开缓存 20.1M → $100.5；全命中 2.24M → $11.2，降 89%（约 1/9），而模型看到的 token 一个没变。
      一行时间戳值多少
      $28.75
      系统提示 50K 里放个动态时间戳 → 前缀哈希每轮都变 → 永不命中：100 轮多付 5.75M 等价 token。它不报错，你只会看到账单偏高。
      重试的尾部
      6.4% → 0.1%
      最多 3 次尝试，转人工率 = p³：p=40% → 期望 1.56 次、转人工 6.4%；p=10% → 1.11 次、0.1%。失败率降 75%，尾部风险降 64 倍。
      评测集要多大
      200 条 ≈ ±2.1%
      SE = √(p(1−p)/n)，p≈0.9、n=200 → 2.1%。要分辨 2 个点需要约 900 条。所以小集合只能抓大幅回退。
      去掉拐杖值多少
      错误率腰斩
      清掉六类拐杖：成本 −14.6%、准确率 +5.3% → 换算成错误率 10% → 5.2%（相对）或 4.7%（绝对）。删掉 80% 系统提示：40 轮省 256K token（无缓存 $1.28 / 有缓存 $0.128）。
      幻觉账（别看准确率）
      38%
      SimpleQA：A 弃答 52%/准确 22%/错误 26%，B 弃答 1%/准确 24%/错误 75%。每天 1 万次、弃答 $0.5、错误 $10 → $28,600 vs $75,050。准确率低的那个总成本只有 38%。
      选型账
      $0.336 → $0.116
      客服案例：每个正确结果的全成本（含失败代价 $1）从 $0.336 降到 $0.116（34.5%），而单价只降到 1/5 —— 失败代价吃掉了大部分收益。
      effort 曲线是凸的
      $0.465 vs $0.704
      FrontierCode：low 11.5% @ $5.35、max 30.9% @ $19.00 → 低档平均每分 $0.465、边际每分 $0.704（贵 50%）。HLE 最后一档多 0.5 分多花 46%，落在噪声里。

      06八句最容易说错的话正本 母题卡「二、自测」Q4/Q5 纠错题原话

      说对前半句没用，后半句才是判据。
      ✗「窗口 1M 了，不用管上下文」✓ 容量 ≠ 质量（context rot）；且历史重发让成本平方增长。
      ✗「开了缓存，历史消息就不再占窗口了」✓ 缓存只改价格不改占用，命中的前缀照样占窗口、照样消耗注意力。
      ✗「压缩就是把历史总结一下，越短越好」✓ 顺序是先保 recall 再提 precision；压太狠会丢掉「当时看不出、后来才关键」的信息，且不可逆。
      ✗「用了 JSON Schema，下游可以直接信任」✓ 只保证结构与类型；枚举是否存在、ID 是否有效、权限、前置条件 schema 全管不了，refusal / max_tokens 还会绕过。
      ✗「Temperature 设成 0 就确定了」✓ 只是挑概率最高的那个，而它本身受模型版本、浮点非确定性、上下文影响 —— 确定性要从系统设计里要。
      ✗「换了新模型，prompt 先别动」✓ 反了：升级恰是重估 prompt 的最佳时机（为 Claude 5 代删掉 80%+ 系统提示，编码评测无损失）。
      ✗「接了 RAG，幻觉就解决了」✓ 只治来源三（没给信息），可能加重来源四（给了没用上），来源一、二完全不治；检索失败率 ≠ 幻觉率。
      ✗「effort 拉满最保险 / 降本就压缩上下文」✓ 前者最后一档多 0.5 分多 46% 成本且落在噪声里；后者顺序反了 —— 先提命中率（无损）再去拐杖（双赢），压缩是最后手段。
