01主干：怎么进来 → 怎么出去 → 怎么扛住正本 wiki/topics/网络/

三条主线共享一个习惯：先归因（哪一层）→ 再选型（客户端要什么 / 在等还是在算）→ 最后才谈手段。502/504 的归因和 SSE 的定义是 9.9 丢过分的两处。
主干叙事（一段读完）：网络的一条线是「请求怎么进来 → 数据怎么出去 → 用什么姿势扛住很多连接」。 进来：请求穿过的是一条链路（DNS → TCP 三次握手 → HTTP → 网关 → 应用 → 上游），每段失败的样子不一样 —— 502 是上游活着但答错、504 是网关等上游超时，「慢」和「挂」排查方向完全不同；超时分层（内短外长）让错误信息直接告诉你哪层放弃。 出去：推送四选一的判据是客户端要什么 —— 短轮询、长轮询、SSE（HTTP 长连接、单向）、WebSocket（协议升级全双工）；SSE 的生产难度在三个坑：代理缓冲、心跳保活、断线重连要 Last-Event-ID + 递增 sequence 才不漏事件。 扛连接：先问时间花在哪 —— 98% 在等就是 IO 密集，异步收益极大；协程省两笔（等待被利用 + 单位开销小两个数量级），致命坑是协程里跑阻塞代码 = 事件循环停摆（CPU 不高、日志无异、高峰整体变慢）；CPU 密集进线程 / 进程池，GIL 挡不住多进程。
读法：三个大框就是三条主线（怎么进来 / 怎么出去 / 怎么扛住）；橙字是判据与数字（要能现场算），紫字是生产坑（要能举出自己踩过的）；绿字是三个项目的落点。底部一行是三条线的总判据。

      05要能现场算出来的数正本 母题卡「一、教材」推导

      每个数都要带推导，只报结果是会被追问倒的。
      等待占比
      98 / 100
      CPU 2ms、IO 98ms：单核理论「同时」处理 50 个——「要不要异步」先测这个数。
      轮询浪费
      ×100,000
      1000 用户每秒轮询 = 1000 QPS，新进度 1 条/100s：10 万次请求换 1 条——轮询的无效流量账。
      同域连接数
      ≈ 6 条
      HTTP/1.1 浏览器每域名 6 条：1 个 SSE + 8 个请求 → 3 个排队；HTTP/2 多路复用解决。
      TLS 握手
      2 RTT ≈ 100ms
      跨机房 RTT 50ms：每次新建连接多付 100ms——长连接 / 连接池复用的理由。
      线程栈
      8MB（虚拟）
      Linux 默认 ulimit -s = 8192KB，虚拟预留按需提交；真实常驻 ~25KB——先撞 pid 上限不是内存。
      三次握手
      3 次 = 最少
      可靠的最少次数（双方确认能收能发）；四次挥手 = 全双工两方向各自关闭，不能合并。
      502 vs 504
      答错 vs 超时
      502 = 上游活着但响应无效；504 = 网关等上游超时——「慢」和「挂」排查方向完全不同。
      CPU 密集反例
      95% CPU
      图像压缩 400ms 里 CPU 占 380ms——协程零收益，进线程 / 进程池，别塞事件循环。
      心跳保活
      注释行
      SSE 不发心跳会被空闲超时掐断：定期发注释行（: ping）保活，长任务跑一半连接就没了。

      06八句最容易说错的话正本 母题卡「二、自测」纠错题原话

      说对前半句没用，后半句才是判据。
      ✗「502 = 上游不可用」✓ 502 是上游活着但答得不对；完全没起来通常是 504 或连接拒绝——9.9 说反的那句。
      ✗「接口 504 就是服务端挂了，重启就行」✓ 504 是网关等上游超时——服务端可能只是慢；「慢」和「挂」排查方向完全不同。
      ✗「HTTP 无状态，所以每次请求都新建 TCP 连接」✓ 无状态 ≠ 短连接：协议不保存会话状态，但 Keep-Alive / 连接池复用传输层连接。
      ✗「SSE 是短连接 / 普通 HTTP 响应」✓ SSE 是基于 HTTP 的长连接（服务端保持响应不结束）、单向——9.9 当场答错的那句。
      ✗「SSE 自带重连，所以不会丢消息」✓ 能重连 ≠ 不漏事件：要 Last-Event-ID + 递增 sequence，服务端从那里补齐。
      ✗「SSE 就是普通 HTTP 响应，过网关不用配置」✓ 代理默认缓冲（攒着不发）→ 显式关缓冲；不发心跳会被空闲超时掐断。
      ✗「线程默认栈 1MB，10 万线程要 100GB」✓ Linux 默认 8MB 且是虚拟预留、按需提交，真实常驻 ~25KB——先撞 pid 上限不是内存。
      ✗「上 WebSocket 因为它更强」✓ 判据是客户端要什么：单向够用选 SSE、要状态查询选轮询——双向全双工才值 WebSocket。
