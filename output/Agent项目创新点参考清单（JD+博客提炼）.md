## C. EnergyOps 对照结论

**有材料直接支撑**：Hook 链治理（exit 2 阻断）、R0/R1/R2（多级信任）、三道质量门、六层评测+P0 硬门禁（Rubric+硬门禁）、25 MCP 工具（六家 JD 高频）。

**已补上的缺口（2026-09-03）**：Rubric/评测集版本化+发布前回测回归集（8.2）；Offload/Onload 的成本收益表述（6.5）；工单闭环→评测回流即数据飞轮叙事（8.4）。

**仍可用但未写入的**：评估采样控成本（若被追问"评测很贵怎么办"）、Run/Delivery 分离术语（异常结论 SUPPORTED/PARTIAL/UNKNOWN 已隐含）。

## D. 应用到另外两个项目的建议

**深圳数驭穹途**：
- 按 JD Top 8 自查：Agent Loop、副作用控制、Eval、Trace 四项是必答题，项目说明里每项至少要有一个具体机制；
- 数据飞轮叙事优先级最高：业务日志→badcase→回归集→回测发布，如果有真实业务数据流，这是最能区别于 demo 选手的点；
- 成本治理（Token/限流/降级）如果项目没做，面试至少要能讲清楚"如果量上来怎么办"的方案。

**RuleArena（个人项目）**：
- 它天然对应 JD 第 3 条（分层 Eval + Golden Set + 回归门禁）——这是它的主场，要把"规则如何版本化、如何防 game、如何回归"讲成体系；
- 可借用 Rubric 分档+权重+硬门禁+证据解释的表述框架；
- 与 EnergyOps 形成互补叙事：一个证明"业务落地层的 Agent 治理"，一个证明"评测基础设施层的深度"，面试时主动把两个项目串起来讲。

## E. 通用表达原则（三项目共用）

1. 每个创新点都要能回答"没有它会出什么事故/浪费"——从真实失败出发，不从论文出发；
2. 边界即卖点：主动说清"不做什么"（EnergyOps 不做派工调度），比堆功能更显工程判断力；
3. 指标口径要能被追问两层（怎么算的、怎么提升的）；
4. 趋势话术（Agent 从 demo 走向生产、YC W26 约 41.5% Agent 基建类、MCP/Skills/AI Gateway 标准化窗口）放在开场定位和收尾，不混进项目细节。
