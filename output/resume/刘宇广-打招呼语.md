# 刘宇广 — BOSS 打招呼语（四段方向版）

> **这份管什么**：BOSS 上发给 HR 的第一条消息，**按目标岗位选一段贴**。
> 核心规则：开头 18 字是 HR 列表页唯一看到的预览；全文 ≤140 字；每个 HR 是独立会话，所以可以也应该按岗位切。


> 核心规则（来自 HR 视角）：  
> **开头18字**是HR列表页第一眼看到的预览——不要写"您好！"，直接上核心竞争力。  
> **全文最长140字**，适当换行提升可读性，技术名词点到为止（HR看不懂一堆框架名）。  
> **结构**：个人优势 + 到岗/出勤 + 技术匹配度 + 高价值话术 + 收尾。
> **2026-09-20 起为四段方向版**（① Agent 应用 · ② FDE/AI 交付 · ③ AI 评测/测试 · ④ 工程稳定向）——
> **按目标岗位选一段贴**，四段的措辞分别对应四份 PDF 成品的语言体系。选段与自查见文末「使用技巧」。



---

### 四段方向版（2026-09-20 起：按目标岗位选一段贴，别只用一个版本）

> **先分清两件事，别自相矛盾：**
> - **「期望职位」字段只能填一个**（写在最上面的求职期望里）——填多个会被系统匹配降权，这条不变。
> - **「打招呼语」是按公司现贴的**——每个 HR 是独立会话，你发给 A 公司的内容 B 公司看不到。所以打招呼语**可以也应该按岗位切**。
>
> 措辞照 `投递方向与简历侧重.md` 第 6.2 节的四套语言体系写（各方向「面试官第一问 + 该用的词 + 忌讳」），与四份 PDF 成品同源。

#### ① 投 AI 应用 / Agent 开发岗（约 132 字）

```
2段AI实习，Agent平台从设计到上线
金山独立设计实现：固定72条任务集完成率83%提至96%，越权用例拦截100%
Python后端扎实，熟练使用AI编程工具，上手快
可随时到岗、实习半年以上、每周出勤5天；抗压能力强
对该岗位非常感兴趣，希望有机会与您进一步沟通！
```

> 开头18字：「2段AI实习，Agent平台从设计到」——身份+经验直接命中。
> 第一行不写"独立负责"，因为数驭穹图的责任档位是核心开发，两段合并的表述经不起追问；"独立设计实现"只绑定金山。
> `MCP`/`Hook`/`证据契约` 这类 HR 看不懂的词全部撤掉，换成「任务完成率」「越权拦截」这种外行也能感知价值的结果。

#### ② 投 FDE / AI 交付 / 解决方案岗（约 131 字）

```
2段AI实习，做能让客户真正用起来的交付
金山独立交付园区能耗平台：与业务方共建三道验收门，月度结算单可直接交财务核验
对接第三方系统、权限边界可自证；Python后端扎实，上手快
可随时到岗、实习半年以上、每周出勤5天
对交付/解决方案岗位非常感兴趣，期待进一步沟通！
```

> 开头18字：「2段AI实习，做能让客户真正用起」——把"交付"写进预览位。
> **这一段的机制**：② 的忌讳是「用内部术语开路」，所以 `Capability Bundle`/`MCP`/`Hook 链` 一个都不出现，
> 全部换成对方在乎的词——**共建（验收标准）、对接（客户既有系统）、可自证（权限边界）、可交财务核验（交付物形态）**。
> 第二行是整段最重的一句：它同时回答了 FDE 面试官的两个第一问——"验收谁说了算"（共建三道门）和"交付物是什么形态"（能直接给财务的结算单）。

#### ③ 投 AI 评测 / 测试开发岗（约 129 字）

```
2段AI实习＋个人评测项目，专做模型输出的验收
金山建92项单测30项回归；个人项目用双评测集实测，达不到门槛就如实拒绝放行
会写评测集和回归门禁，缺陷能定界到是工程问题还是效果问题
可随时到岗、每周5天、连续实习半年以上
对评测/测试开发岗位非常感兴趣，期待沟通！
```

> 开头18字：「2段AI实习＋个人评测项目，专做模」——把"评测"提到预览位。
> **这一段的机制**：③ 的忌讳是「把业务价值当头条」，所以整段不出现任何"提升 XX%"式的业务数字，
> 只给评测岗真正看的三种能力：**建评测集与回归（92 单测 30 回归）→ 可复现与不通过就拦（双评测集 + 如实拒绝放行）→ 缺陷定界（工程 bug vs 效果缺陷）**。
> "如实拒绝放行"是这一段最值钱的一句——多数候选人只会讲"我把指标做上去了"，**讲"我的东西没过自己的门禁"反而证明门禁是真的**。

#### ④ 投工程稳定向 / 后端岗（约 132 字）

```
2段AI实习，后端与数据链路从设计到上线
金山：查询P95 20.4秒→2.8秒，聚合成功率96.9%→99.6%，人工补数降72%
Python后端扎实，幂等、状态机、失败恢复均做过
可随时到岗、实习半年以上、每周出勤5天；接受轮值
对该岗位非常感兴趣，期待进一步沟通！
```

> 开头18字：「2段AI实习，后端与数据链路从设」——把"后端"提到预览位。
> **这一段的机制**：④ 的忌讳是「拿过度前沿的词当卖点」，所以 `Agent`/`自研`/`运行时` 全部降级，
> 只留**性能、成功率、幂等、状态机、失败恢复**——这一档先看"可靠"，再看好不好管。
> 三处百分比全部写全（20.4 秒 / 96.9% / 72%），因为工程岗 HR 与技术面都吃具体数字，"提升明显"这种说法在这一档是减分项。

#### 四条通用纪律

1. **一段只能配一个方向**。别把两段拼起来发——超 140 字被截断的永远是最后一行（你的收尾话术）。
2. **首行 18 字是唯一真正被阅读的位置**（HR 列表页预览）。四个版本的第一行都刻意把**方向关键词**前置：`Agent` / `交付` / `评测` / `后端`。
3. **数字口径与 PDF 成品一致**，不另起一套。③ 的数字最少是**有意的**（那个方向的忌讳就是堆业务数字）；④ 的数字最全是**有意的**。
4. **每段都不出现学校名**。非 985/211 时，"2段实习"比学校名更能打动 HR——这条对四个方向都成立。

### 使用技巧

- **学校名不放开头**：非985/211时，开头18字优先放"2段实习"而不是学校名——经验比学历更能打动HR
- **按 JD 选段，别只在数字上换词**：四段是四套语言，不是同一段换数字。判据是**岗位面试官的第一问**（见 `投递方向与简历侧重.md` 6.2）——问"架构怎么设计的"用 ①，问"客户拿到手怎么用"用 ②，问"谁说了算、怎么卡住发布"用 ③，问"稳不稳、口径谁定的"用 ④
- **拿不准方向时用 ①**：它的信息密度最均衡，且 Agent 关键词覆盖面最广。**宁可少一次精准，不要发错语言**——发错方向的代价是对方觉得你不懂这岗在干什么
- **超 140 字先删第三行**（技术匹配度那行），它是四行里最可替代的；第一行（预览位）和最后一行（收尾）绝不能删
- **"随时到岗"**：即使实际不能立即到岗也先写上，拿到offer后再协商——HR撤回offer的沉没成本远高于等你几周
- **投递时机**：选HR状态为"刚刚在线"的工作日上午投递，每天手动刷新保持曝光
