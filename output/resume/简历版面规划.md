## 0. 模板形态（2026-09-11 定，魔方简历版式）

从用户实际投递的魔方简历 PDF 逆向复刻，验收标准是「导出后与魔方版《视觉一致、内容更抗追问》」：

| 元素 | 规格 |
|---|---|
| 页边距 | 左右各 8.2pt（≈2.9mm），几乎满版；分区蓝线为全宽 |
| 证件照 | 左上角矩形 67.6 × 90pt（23.8 × 31.75mm），源图 `assets/photo.jpg` |

| 分区标题 | 10.5pt 蓝 `#0047AB` ＋ 下方 0.8pt 全宽蓝线 |

| 正文 | 9pt，行高 1.25，`#212529` |
| 字体栈 | `Arial`（拉丁）→ `Alibaba PuHuiTi 3.0` → `Noto Sans SC` → `Microsoft YaHei`（普惠体本机未安装时自动回退 Noto Sans SC） |
| 页面高度 | 297mm，`overflow:hidden`——**溢出会被静默裁掉，导出后必须验底部内容在不在** |

## 1. 版面总原则

1. **一页版定稿（2026-09-04）**：当前正本为一页。理由：注水凑两页违反焚诀两忌（堆砌不聚焦 / 空洞不量化）。
2. **两页的正当性条件**（将来经历变多可回两页）：有两段以上实习且内容确实撑得起，两页合理；但**第二页必须同样密**，不能后半页空白。
3. 单栏高密度版式（参照 ASu-skills 单栏模板）：不左右分栏、A4、浏览器内编辑、打印导出 PDF。

## 2. 一页版版面预算（当前正本结构）

- **Header 1 行**：姓名 + 岗位名右侧联系方式（2027 届 · 可提前实习 / 邮箱电话 / GitHub 与个人站）
- **教育经历 2 行**：学校 + 专业 + 学历 + 时间到月；GPA/排名仅在拿得出手时占行
- **实习经历 ≈ 2/3 页**：
  - 金山（EnergyOps）：标题行 + project-line 带 role-note（责任档位）+ 一句 summary + 5 条 bullet
  - 数驭穹图：同结构 + 5 条 bullet
  - 更近的放前面
- **项目经历 ≈ 半页**：RuleArena，标题行（个人项目 · 独立设计与实现）+ summary + 4 条 bullet
- **专业技能 3 行**：Agent 架构与工程化 / 后端开发与数据工程 / 工程交付与 AI Coding，每行分类加粗开头

要点：每条 bullet ≤2 行；数字用加粗 `.num`；机制名加粗；经历标题行右侧放该段最硬的一个指标。

**一页是硬约束，但压缩顺序是「先措辞、后删条」（2026-09-11 定）**：内容加不进去时按此顺序回收空间，不删核心 bullet——
1. 压缩措辞（删冗余主语与重复限定语）；
2. 收紧段间距 / 列表间距（各 0.3–0.5pt，肉眼不可辨）；
3. 合并两条同主题 bullet；
4. 最后才降字号（9pt 是下限，再降伤可读性）。

## 3. 两页版预算（备查，回两页时启用）

**Page 1**：基本信息 1 行 → 教育 2-3 行 → 实习 ≈ 2/3 页（每段：标题行右侧最硬指标、背景 1-2 行、4-5 条 bullet）。

**Page 2**：项目 ≈ 半页（介绍 2-3 行 + 4-5 条 bullet + 标题行指标）→ 专业技能 6-8 行四类 → 荣誉奖项（仅含金量高的占行，否则并入教育）。

## 4. 排版硬规则

- 中英文之间加空格；技术名词大小写规范（Python、PostgreSQL、DuckDB、FastAPI、MCP）；
- 不用左右分栏模板；字体字号段落间距一致；零错别字；
- 颜色克制：正文近黑（#1f2328），不加彩色图标；
- `@page A4 / margin 0`，`.page` 自带内边距；打印用 Edge 无头导出：
  `msedge --headless --no-pdf-header-footer --print-to-pdf=输出.pdf 输入.html`
- 导出后必查：pypdf 抽文本确认仍是 1 页、新增口径字样在（防止溢出第二页被截断）；**魔方模板版额外查一条——最后一行的内容（如 `CET-6，能流畅阅读英文技术文档`）必须出现在抽出的文本里**，因为 `.page` 的 `overflow:hidden` 会把溢出内容静默裁掉而不报错。

## 5. 文件命名与投递微调

- **文件命名**：姓名 + 岗位 + 届别（`刘宇广-Agent开发工程师-2027届.pdf`）。
- **按公司微调**：投递前替换 1-2 个关键词顺序对齐 JD（六家核对表高频词：Agent Loop、副作用控制、Eval、Trace、RAG）。只调顺序，不改事实与主线。

## 6. 渠道差异速查

| 维度 | BOSS直聘在线版 | 大厂网申版 | 附件简历（正本） |
|---|---|---|---|
| 对应文件 | `刘宇广-BOSS直聘在线简历.md` 前半 | 同文件后半 | `刘宇广-AI应用开发-2027届.pdf`（魔方模板） |
| 可见性 | 所有 HR 可直接查看，**第一道关卡** | 官网表单 + ATS | 沟通后 HR / 面试前人工复核 |
| 匹配机制 | 参与ES关键词匹配与算法推荐 | ATS 关键词匹配 | 不参与自动匹配 |
| 工作经历结构 | 拆 工作内容/工作业绩/拥有技能 | 单一「工作描述」字段 STAR | 精炼 bullet |
| 字数/行数 | 各字段严格限制（工作描述~500字） | 较宽松（200-400字/段） | 一页版预算（§2） |
| 阅读端 | 手机（自查前2行广告位） | 电脑（HR + ATS） | 电脑 / 打印 |
| 自我评价 | 150-250 字，前 2 行定生死 | 200-350 字完整展示 | 不单独成段 |
| 更新 | 经常微调触发曝光刷新 | 录入一次自动填充 | 按方向微调后重新导出 |

## 7. ATS 与工具检查

- **必做**：`pdftotext`（或 pypdf）抽取 PDF 文本，检查提取顺序和关键词完整性——最简单可靠的 ATS 测试。
- Greenhouse 结论：复杂表格、多栏、图片、页眉页脚、文本框易解析异常——单栏 + 标准标题 + 可选中文本 PDF 最稳。
- 工具定位：Resume Matcher（对 JD 查关键词遗漏，只能重排真实经历）、OpenResume / Reactive Resume（结构检查与多版本维护）。不过度迷信 ATS 得分——技术招聘最终由人阅读。
- Word/WPS：中文精细排版兜底方案。
