## 1. 五份样本各自偷什么招

| 样本 | 偷什么 | 用在哪 |
|---|---|---|
| **牛肉哥（Z.ai 算法实习）** | ①每段经历标题行右侧直接放最硬的指标（`32.6%→46.7%`），HR 3 秒内看到结果；②bullet 结构=**加粗机制名**+一句机制+量化增量（`+2pp`），零空话；③整页无一个"负责"开头的虚句 | 实习经历 bullet 的骨架；每段经历头部的"结果前置" |

| **AgentHub-奶龙（个人项目）** | 技术栈用标签行；项目介绍 3 行=是什么+自研什么+解决什么工程问题；bullet=加粗组件名+实现细节（DAG+Kahn、FTS5、双通道） | RuleArena 的写法（个人项目，组件细节是深度证明） |
| **简历焚诀（雾行，字节后端）** | 全部结构性规则（见第 2 节） | 总纲 |

## 2. 简历焚诀核心规则（本简历的硬约束）

1. **两忌**：忌堆砌不聚焦（每条必须能打动人）；忌空洞不量化（禁用"显著提升""极大提高"）。
2. **STAR 写条目**，Action 和 Result 是重点，Result 必须有数字；S（背景）可省略留到面试讲。
3. **一条不超过两行**；个人职责 ≥3 条；项目 4-5 条 bullet。
4. **项目名不大众化**：EnergyOps / 数驭穹图 / RuleArena 三个名字直接可用，不要退化成"xx 管理系统"。
5. **技能模块**：分类组织、核心加粗前置、体现深度引导提问、不写"精通"、可被项目覆盖的内容不重复占行。
6. **排版细节**：中英文之间加空格；不用左右分栏模板；技术名词大小写规范（Python、PostgreSQL、DuckDB、FastAPI）；字体字号段落间距一致；零错别字。
7. **文件命名**：姓名+岗位+电话。
8. **按公司微调**：投递前替换 1-2 个关键词顺序对齐 JD（六家核对表里的高频词：Agent Loop、副作用控制、Eval、Trace、RAG）。
9. **去 AI 味**：避免"赋能""抓手""闭环思维"式空话和整齐划一的排比句式，写完自己读一遍，别扭的改掉。
10. **两页的正当性**：有两段实习+内容确实撑得起，两页合理；但第二页必须同样密，不能后半页空白。

## 3. 两页版面规划（总行数预算）

**Page 1**
- 基本信息 1 行：姓名 | 电话 | 邮箱 | 求职意向：AI 应用开发 / Agent 开发 |（GitHub 链接，RuleArena 要有像样的 README）
- 教育经历 2-3 行：学校+学院+专业+学历 | 时间到月；GPA/排名（如拿得出手）；1 行核心课程或荣誉（仅当含金量高）
- 实习经历 ≈ 2/3 页：
  - **金山（EnergyOps）**：标题行右侧放最硬指标（如 `Agent 任务完成率 83.3%→95.8%`）；背景 1-2 行；4-5 条 bullet
  - **数驭穹途（数驭穹图）**：同结构，标题行指标（如 `端到端查询成功率 78%→91%`）
  - 哪个近放哪个前面

**Page 2**
- 项目经历（RuleArena）≈ 半页：标题行（个人项目 | 技术负责人）；介绍 2-3 行；4-5 条 bullet；标题行指标（`隐藏漏洞发现率 ≥75%、误报 0、重放 3/3`——只写有 BenchmarkRun 证据的）
- 专业技能 ≈ 6-8 行，四类：语言与后端 / 数据与存储 / AI 与 Agent / 工程与协作
- 荣誉奖项：仅当有含金量高的才占行，否则并入教育经历

## 4. 三项目素材 → 简历条目转换（骨架，数据以项目说明为准）

**金山 EnergyOps**（背景：604 台水电表、17.4 万条读数/日的园区能耗运营，行政无法独立运营）
- 设计四层数据模型+7 类质量状态，可信聚合完整率 96.8%→99.7%
- 封装 25 个 MCP 工具+Capability Bundle 路由，R0/R1/R2 风险分级+Before/After Hook 链治理，任务完成率 83.3%→95.8%、越权拦截 100%
- Offload/Onload 大结果外置为 Artifact，查询 P95 降低 86.3%，输入 Token 随结果规模近似恒定
- 建六层评测体系+P0 硬门禁+Bad Case 回归集，异常研判 18→6 分钟、告警量降 43%
- 结算三道质量门（事实源/预演/责任），月度账单守恒率 100%、全程可审计

**数驭穹图**（背景：中小企业多源数据分散、业务人员依赖数据团队取数）
- Data Agent 六阶段可归因链路+NL2SemQL2SQL 两阶段验证，端到端成功率 78%→91%
- 五层安全边界（入口/能力/调用/执行/输出）+SQL AST 审查+租户注入，300 条对抗用例拦截 100%、误拦 2.7%
- 行业 Domain Pack 语义资产（指标口径+术语+关联+示例）+混合检索，Schema 召回 81%→95%
- 轻量湖仓：Parquet 副本+DuckDB 本地计算+查询路由，分析负载与客户生产库隔离（直查走只读受限账号+熔断降级）
- Artifact 上下文压缩+证据绑定（call_id/fingerprint/hash），Token 成本降 80%，图表证据绑定率 100%

**RuleArena**（背景：电商规则组合风险，传统测试覆盖不到、LLM 审查不能证明）
- 自然语言规则→可确认 RuleSpec→版本冻结，禁止动态求值，歧义人工确认
- Simulator 快速搜索+干净 Sandbox 真实 HTTP 重放+确定性 Oracle 裁决，防自证
- 三策略（价值流/生命周期/边界）+BFS 基线+归一化预算消融，隐藏漏洞发现率 ≥75%、误报 0
- Delta Debugging 1-minimal 反例+同版本重放 3/3+修复回归，反例导出 pytest
- 24 Case 双集（hidden 隔离）+单位确认反例成本消融

**注意**：RuleArena 每条只能写「设计为/已实现」，数据必须等 BenchmarkRun 出来才能写「测得」——简历焚诀的诚信原则和它自己的事实安全口径一致。

## 7. 阿酥（ASu-skills / great-resume）技法融合

来源：github.com/Hisn00w/ASu-skills（great-resume + claim-evidence-ledger），已核对原文。

### 7.1 酥化公式（比 STAR 更强的 bullet 公式）

> **动作 → 系统能力 → 业务价值 → 结果证据 → 个人边界**

比 STAR 多出「系统能力」和「个人边界」两段：前者把技术动作翻译成招聘方理解的系统能力（"封装 25 个 MCP 工具"而不是"写了工具代码"），后者明确这是你做的还是团队的。第 4 节的 bullet 骨架正式成稿时按此公式重写。

### 7.2 岗位定位双版本

先输出 1-3 个岗位定位，区分**稳妥版**（完全被证据支撑）和**进取版**（标注还需补什么证据才能成立）。
- 稳妥版：AI 应用开发工程师——三项目全覆盖，证据齐
- 进取版：Agent 平台/基建方向——RuleArena 的 BenchmarkRun 跑完、GitHub README 完善后才成立

### 7.3 主张—证据账本（本简历必须用）

强主张（主导/负责人/0→1、所有百分比指标）逐条过五段审计：**原始说法 → 建议写法 → 事实证据 → 个人边界 → 风险/待确认**。

状态机：`已确认`（可进终稿）/ `待确认`（只能带【待补】进草稿，导出 PDF 前必须清除）/ `已过期` / `不采用`。

责任分级四档，每条主张先定档：**参与 < 负责模块 < 主导方案或交付 < 项目负责人**。「主导」只有能讲清决策、交付和结果时才允许用。

对本简历的直接约束：
- EnergyOps/数驭穹图的指标（95.8%、91% 等）必须先确认口径和你当时的角色边界——实习身份下哪些是「负责模块」哪些是「主导」，需要你逐条确认；
- RuleArena 的数字全部是门禁目标 → 状态只能「待确认」，终稿写机制不写数字（见第 4 节注意）；
- 指标注明口径和时间，项目总量不能当个人数据。

### 7.4 HR 开场白（投递时用）

80-160 字，三段式：身份和方向 → 一个真实成果（带数字）→ 邀请继续交流。不写模板化排比，不堆 GitHub Star。

### 7.5 制作层

ASu 默认**单栏高密度模板**（18 个 HTML 模板之一，A4 双页、浏览器内编辑、打印导出 PDF）——与我们的两页版面规划兼容。正式制作时可参照其单栏高密度版式（不左右分栏，符合焚诀规则）。

### 7.6 事实边界（与简历焚诀互证的两条加分规则）

- 不把计划做的写成已完成的（RuleArena 数字问题的官方处理方式）；
- 小贡献可以聚合表述（如多个 typo/docs PR → "跨项目文档质量治理与开源协作"），但保留真实链接，未合并写"协作中"。
