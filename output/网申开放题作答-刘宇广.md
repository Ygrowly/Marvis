## 一、作答原则（三条）

1. **答 JD 的「岗位职责」，不答自己的能力清单。** 每条优势都要能指回 JD 里的某一句话；指不回去的，再亮眼也不写。
2. **一条 = 一个可验证的证据 + 一个数字。** 纯形容词（学习能力强 / 沟通能力好 / 热爱技术）零信息量，HR 与面试官都默认过滤。
3. **宁可少一条，不要凑一条。** 两强一真缺口，好过三条都注水——面试官只按写得最虚的那条追问。

## 二、网易互娱（网易游戏） · AI 应用工程师

**题目**：请结合您的专业特长，言简意赅地说明您应聘本职位的三个优势。

### 2.1 主推版（约 390 字，贴合 JD 里「言简意赅」四个字）

> ⚠️ **网申表单是纯文本框，粘 markdown 的 `**` 会原样显示成星号**。两版都放在代码块里，**整块复制**。

```
1）LLM 应用全栈落地：独立打通「自然语言 → 可信查询 → 可交付结果」链路，Top-K Schema 召回 81%→95%，150 条评测集上查询「可执行且口径正确」占比 78%→91%（ChatBI 类场景）。
2）Agent 套件与工具治理：30 个 MCP 工具 + 6 类 Capability Bundle + R0/R1/R2 风险分级 + Hook 校验链，固定任务集完成率 83.3%→95.8%、越权用例拦截 100%。
3）可验证性与成本控制：Agent 上线门禁实测，把重复退款 ¥1920 压到 0、终态正确率 60%→100%；上下文 Token 18.4K→3.6K、百万行查询 P95 12.6s→2.7s。
技术栈 Python / FastAPI / PostgreSQL / Redis；日常用 Claude Code、Codex 做仓库级开发。
```

### 2.2 详版（约 810 字，字数宽松时用；也是面试口述的素材）

```
我应聘这个岗位的三个优势，都对应 JD 里的具体工作内容。

一、LLM 应用的全栈落地能力，尤其在 ChatBI / 数据分析场景
在数驭穹图（企业问数平台）独立设计 Data Agent 六阶段可归因链路（意图路由 → Schema 检索 → 语义解析 → SQL 生成 → 安全校验 → 执行），把自然语言到可信查询、分析解释与结果沉淀整条链路打通；沉淀 3 套行业指标域（65 个指标 + 120 个术语别名）后 Top-K Schema 召回 81%→95%，150 条评测集上「可执行且口径正确」的查询占比 78%→91%。

二、做过 Agent 套件与工具治理，不是只会调模型 API
在 EnergyOps 把查询、设备、规则、告警、导出、结算六类业务能力封装为 30 个 MCP 工具与 6 类 Capability Bundle，配套 R0/R1/R2 操作风险分级和 Before/After Tool Hook 校验链；固定 72 条任务集的 Agent 完成率 83.3%→95.8%，80 条越权用例（跨租户 / 越权限 / 越范围）拦截率 100%。

三、习惯给 AI 效果建可复现的验收标准，并顺手压住成本
个人项目 RuleArena 做业务 Agent 上线前的执行门禁，同一份 Agent 跑两次实测：裸跑组出现 6 张工单重复退款、多退 ¥1920，加运行时门禁后归零、终态正确率 60%→100%；21+17 双评测集暴露出 pass@3 = 57% 而 pass^3 = 7%，据此如实拒绝放行。成本与性能侧：单次分析上下文 Token 18.4K→3.6K，百万行查询 P95 12.6s→2.7s。

技术上以 Python 为主（FastAPI / PostgreSQL / Redis），日常用 Claude Code、Codex 做仓库级开发，上面几套系统本身就是这么写出来的。
```

### 2.3 三条优势 ↔ JD 工作内容对应

| JD 工作内容 | 对应优势 | 主证据 |
|---|---|---|
| 1. 研发管线 AI 应用全栈开发（AI 绘图 / AI 代码 / **ChatBI** / LLMs 应用） | 优势一 | 数驭穹图 Data Agent 六阶段链路 + 150 条评测集 |
| 2. 高并发低延迟 AI 服务架构，优化推理性能与成本 | 优势三（成本与性能半段） | Token 18.4K→3.6K、百万行 P95 12.6s→2.7s、聚合成功率 96.9%→99.6% |
| 3. AI Native 产品交互 | 优势一（弱）| 结果回写协同表格、HITL 确认与风险分级 |
| 4. AI 应用基础设施：**agent 套件** / **模型测评** / 模型路由 | 优势二 + 优势三 | 30 个 MCP 工具 + Capability Bundle；RuleArena 双评测集与门禁 |

**真缺口一条**：**没有 AI 绘图（图像 / 素材生成）与游戏研发管线的直接经验**。JD 第 1 条列举的四个方向里，本人命中 ChatBI、AI 代码、LLMs 应用三项，AI 绘图为零——**不硬凑、不在答案里提**；被直接问到就如实说「没做过图像生成类应用，但同一套工程问题（素材检索、调用编排、效果验收）我做过」，把话题拉回可控区。

## 三、卓望（中国移动控股） · AI 应用开发工程师

**题目来源**：网申表单「附加问题」四道（2026-09-21 截图）。27 届校招 24 人，本科可投，北京 / 广州 / 昆明 / 西安。
**简历用哪份**：**母版 `刘宇广-AI应用开发-2027届.pdf`（2026-09-20 导出版），内容零改动**——JD 核心词 MCP / Prompt / Agent 框架 / RAG / 后端开发 / 性能优化与母版技能行逐条重合，台账本条（C 层）本来就是按 ① 方向标的。

### 3.1 四道题答案（纯文本，整块复制）

**Q1 · 您是如何看待目前所应聘的职位的？**（约 210 字）

```
这个岗位的本质，是把大模型能力工程化成业务系统：用 Agent 框架、Prompt 工程、工作流编排把模型输出的不确定性收进可控的服务边界，再按业务需求交付上线。这正是我过去一年一直在做的事：数驭穹图里我把自然语言问数做成可归因、可验证的分析平台；EnergyOps 里我把六类业务封装成 30 个 MCP 工具给 Agent 受控调用；日常开发我自己就是 Claude Code、Codex 的重度用户，Skills、MCP、工作流编排都用在仓库级实践里。所以对我这不是需要适应的新方向，而是已有工作的专业化延续。
```

**Q2 · 您的下阶段职业目标是什么？**（约 130 字）

```
入职后 1–2 年，在真实业务里独立负责 AI 应用模块从设计、开发到上线的完整闭环，把服务端工程底盘（接口、数据、稳定性、性能）补厚；3–5 年成长为能定方案的 AI 应用工程师，负责工具体系、Agent 平台这类基础设施，让团队的 AI 应用开发更快、更可控。
```

**Q3 · 请用一句话来描述自己。**（约 40 字）

```
我用工程方法把不确定的模型输出，做成生产环境里可验证、可回滚、可评测的 AI 应用。
```

**Q4 · 请分别列出您的三个优点和三个缺点。**（约 230 字）

```
优点：1）动手快、会用 AI 工具放大产出：Claude Code、Codex 重度使用，三套 Agent 系统均独立完成；2）较真、如实：评测显示不可复现就拒绝放行，对自己不利的数据也照报，结论因此可信；3）习惯把模糊需求拆成可度量的指标与口径，再动手写代码。
缺点：1）操作系统、网络等底层基础的深度不如应用层，正在按模块系统补课；2）起步阶段容易把系统设计得过重，有时质量设施先行于交付节奏，正在按「先跑通最小闭环、再补质量设施」调整；3）遇到卡点倾向自己钻研，开口讨论偏晚，在刻意练习更早暴露问题。
```

> ⚠️ **缺点三条必须本人逐条认领后再投**——每一条面试都会被展开追问，哪条不合身就换掉，别硬填。

### 3.2 简历对照（JD ↔ 母版）

| JD 要求 | 母版命中 | 备注 |

## 四、面试追问预案（通用）

三个优势写出去，面试官会顺着**数字**往下问。每题的第一层追问：

| 优势 | 大概率第一问 | 一句话起手（细节查正本） |
|---|---|---|
| 一 | 「150 条评测集怎么来的？『口径正确』谁判的？」 | 判定含人工复核、非全量 golden SQL 对齐，所以简历上的措辞是「可执行且口径正确」而不是「准确率」→ `projects/数驭穹图/17-量化指标与证据口径.md` |
| 一 | 「81%→95% 的召回集多大？Top-K 的 K 是多少？」 | 150 条问题，正确表/字段是否进 Top-K；口径在 `刘宇广-简历量化指标口径.md` 数驭穹图节 |
| 二 | 「80 条越权用例拦截 100%——是线上拦截流量吗？」 | **不是。是 80 条构造用例**（跨租户 / 越权限 / 越范围三类），Before Tool Hook 在执行前校验参数 |
| 二 | 「72 条任务集和线上真实请求什么关系？」 | 固定任务集，同模型、同权限、同数据快照下跑，60 条 → 69 条 |
| 三 | 「¥1920 是怎么算出来的？」 | 15 张工单 × 2 模式 × 3 次重复，真实 Sandbox HTTP + 真实回执；**终态正确率与无资损两项指标并列报，不许合并** |
| 三 | 「pass@3 = 57% 而 pass^3 = 7%，那你这个项目到底成不成？」 | **这是全项目最重要的一条实测**：跑 3 次至少成一次 ≠ 3 次次次都成；恰好是「为什么需要独立门禁」的论据。Release Gate 拒绝放行是**正确行为** |
| 通用 | 「你这些数字是线上监控出来的吗？」 | 分等级：E1 线上日志窗口 / E2 固定回放集或评测集 / E3 设计目标——**三种不能并排说成「统计结果显示」** → `output/主张-证据账本-刘宇广.md` 第 5 节 |
