## 
```plain
lists = [
    1 → 4 → 5,
    1 → 3 → 4,
    2 → 6
]
```

结果：

```plain
1 → 1 → 2 → 3 → 4 → 4 → 5 → 6
```

设：

+ `k` 是链表数量。 
+ `N` 是所有链表的节点总数。





一种做法是使用最小堆。最小堆可以快速取出当前最小的头节点。

主线：

```plain
每条非空链表的头节点入堆
→ 弹出当前最小节点，接入结果
→ 将该节点的 next 放入堆
→ 重复直到堆为空
```



5. 最小堆大小最多为 `k`，维持堆有序时，只需沿堆的高度调整：

```plain
堆高度 = log k
```

所以一次入堆或出堆都是：

```plain
O(log k)
```



6. 所有 `N` 个节点各入堆、出堆一次：

```plain
时间复杂度：O(N log k)
额外空间：O(k)
```

7.  两两分治合并的复杂度同样是： 

```plain
O(N log k)
```

因为共有 `log k` 轮，每一轮所有节点总共被处理一次，即 `O(N)`。

```plain
最小堆：不断选出 k 个候选头中的最小值
两两分治：每轮把链表数量减半
```



最小堆恢复脚本：

每条链表先放一个头节点；弹出最小节点接到结果后，再把它的后继入堆。堆中始终保存每条未处理链表的最小候选。



更准确地说，Python 比较元组时会逐项比较：

```plain
(node.val, node)
```

如果两个节点的 `val` 相同，就会继续比较两个 `ListNode` 对象，而 `ListNode` 默认不能比较大小，会抛出：

```plain
TypeError: '<' not supported between instances of 'ListNode'
```

加入唯一的 `counter`：

```plain
(node.val, counter, node)
```

值相同时会比较整数编号，不会比较节点对象。
